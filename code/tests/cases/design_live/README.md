# 设计点 Live 用例

本目录按功能领域保存 Test 中可播放的 Live 用例。每份 JSON 使用
`tfi.portal-design-live-cases.v1`，`cases` 数组中的条目遵守 TestCase 模型。
测试目录加载时读取这些声明，与从测试源码发现的用例合并；用例声明的实现入口归这个用例所有，不再生成单独的用例。

## 核心功能分工

| 领域 | 主要验收对象 | 声明文件 |
| --- | --- | --- |
| Lineage | Resident 身份与接收/执行状态、队列回执、事件补齐和订阅隔离 | `lineage.json` |
| Chat | 输入与消息生命周期、草稿隔离、恢复及只读交互 | `chat.json` |
| Resource | 资源发现、引用、详情和文件预览 | `resource.json` |
| Workbench | 面板生命周期、布局、标签和编辑器打开协议 | `workbench.json` |
| Test | 用例筛选、实现、执行证据、Gate 和设计点关联 | `testlab.json` |
| WALL | 设计点阅读、筛选、来源与精确定位 | `wall.json` |
| Shell | 全局导航、命令、Inbox 和刷新状态 | `shell.json` |
| UI | 共享控件、表单、焦点、异步动作与关闭保护 | `ui.json` |

扩展覆盖时优先选择尚未绑定的重要设计点。一个用例可以验证多个正常、错误和取消场景，
这些场景不重复计入 Live 总数。生产组件的本地协议验证不等同于真实 Provider 执行、
账号迁移或服务端权限链路验收；用例描述与验证报告必须明确边界。

## 设计点与测试

- `design_point_ref` 使用 WALL 返回的完整设计点 ID，包括来源和点标识。不能用整份设计文档的 ID 代替，也不能根据标题猜测标识。
- 一个设计点对应一个主 TestCase。不同场景、边界条件和验证层放在这个 TestCase 的 `implementations` 中，不重复创建主用例。
- `design_refs` 继续表达文档级参考。它不表示该文档中的每个设计点都已被测试覆盖。
- 未绑定的底层测试可以保留。删除或重构实现前确认其覆盖已经由其他实现承接，不为了减少条目而移除权限、恢复和数据一致性验证。
- 用例 ID 首次分配后保持稳定。新增场景不改变逻辑用例身份；失效绑定需要明确修复，不能静默匹配相似标题。

## Live 验证

每个 Live 使用已登记的页面适配器调用生产组件。步骤应包含明确的操作与可失败的验收条件；仅展示文案、高亮元素或等待一段时间不能作为测试结果。

适配器提供 `ready`、`capture`、`prepare`、`commit` 和 `restore`。执行与取消后恢复原有的焦点、选择、筛选和本地布局；清理由实际创建临时状态的适配器负责。生产 Live 播放器通过静态允许列表按需加载适配器，不接受用例指定任意脚本地址。

同页播放只由当前适配器恢复页面状态，播放器等待恢复完成后退出，不再调用 Test 原点适配器
重复打开用例或重建编辑表单。跨页面返回 Test 时，由原点适配器恢复跨文档的导航与布局。
用户在播放期间继续编辑的草稿不能被演示前快照覆盖。

真实页面 Live 使用 `mode: direct`、`risk: read-only` 和站内目标路径。禁止发送 Resident 消息、消耗模型额度、改变帐号或修改共享业务数据。只读条件无法满足时，不把有副作用的操作标记为只读。

Chat 组件 Live 直接使用 Test 页已加载的生产 Chat Workspace，在临时本地容器中验收。
无需跳转 Lineage 页，避免触发主工作台的初始化、推荐查询或真实 Resident 会话加载。

## 验证证据

- 离线浏览器用例覆盖生产适配器的交互、断言与恢复，并使用隔离的页面数据。
- 目录验证检查实现可发现性、设计点唯一性、声明字段与 Live 能力的一致性。
- 真实 Dev 页面上的播放结果单独记录；离线测试通过和测试收集成功不能写成真实 Live 已通过。
- 并行验证使用各自的静态服务端口与日志路径，不复用不明来源的服务，不运行与所属变更无关的全量测试。
