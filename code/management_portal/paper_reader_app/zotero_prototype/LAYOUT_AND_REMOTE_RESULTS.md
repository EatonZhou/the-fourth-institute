# 多页定位、布局与远程保存模拟验收

本切片只新增直接测试与接口说明，不修改上游补丁、原型宿主、生产阅读器或数据节点文件，未发布。使用此前已通过的保存补丁构建；没有重跑此前的状态机与单页保存 UI 测试。

命令：`node tests/cases/javascript/zotero_reader_layout.cjs`，从 Portal code 根运行，Firefox 和 Chromium 顺序执行。可追加 `Firefox` 或 `Chromium` 仅运行目标浏览器。合成 PDF 由测试内存生成，不读取生产论文、不创建服务端业务记录。

样本含三页，各页 Helvetica 左右两栏文字；第三页原生 `/Rotate 90`。加载两个预置原生便签，分别落在第二、第三页的 `[100,500,122,522]` PDF 坐标。该样本用于定位与布局断言，不代表真实复杂排版或文字阅读顺序验收。

实际断言：

- 从第一页点击第三页、再点击第二页的注释列表 header；等待 Reader 的真实页码输入分别变为 3、2，不仅观察 navigate 调用。
- 等待滚动帧后，目标 `.page` 的真实 DOM 边界与 PDF iframe 视口相交；将便签中心由 PDF 坐标按 0/90 度映射到页面像素，断言中心实际落在可视区域。断言使用 DOM 几何，不依赖截图人工判断。
- 目标页文本层同时出现左栏和右栏标记；第三页渲染宽度大于高度，证明旋转页呈横向。没有由此宣称双栏提取顺序或旋转文字高亮几何已验证。
- 宿主 save 回调返回测试控制的远程确认 Promise。关闭请求在该 Promise 未完成时保持 pending，iframe 保留且 inert；拒绝确认后 iframe 恢复交互，继续输入不同便签文本，再允许保存并重试关闭；最终确认内容为最新输入。
- 测试服务器阻塞 PDF Viewer 的 `viewer.mjs` 响应；公开 host 已创建但 PDF Viewer 尚未完成加载时正常 close，iframe 被移除，之后释放请求，无 pageerror。覆盖模块加载阶段；未覆盖本地 PDF 文件读取/SHA-256 期间、外层 Reader iframe 初始化之前的取消。

首次页码断言未等待异步滚动而读到 1，改为等待真实页码变化。Firefox 初次模块请求检查早于请求抵达，后改为等待服务器观察到阻塞请求，并使用 no-store 避免缓存绕过门控。它们是夹具时序修正，不通过固定睡眠判断持久化成功。最终上述完整命令退出 0；Chromium、Firefox 各输出定位/布局、远程屏障/失败交互、加载中关闭三项通过，包含新增的便签中心可视区域断言。

最小正式持久化与翻译缓存接口草案见 [PERSISTENCE_CONTRACT.md](PERSISTENCE_CONTRACT.md)，明确区分可复用鉴权与当前不兼容的数据格式，包含稳定 ID、附件版本、账号隔离、CAS、幂等重放与缓存访问范围。

未验证：双栏复杂选区和阅读顺序、扫描/OCR、180/270 度旋转、截图像素一致性、真实网络/数据库事务与权限、真实多人并发、位置存储失败、页签强退、长期资源泄漏或原 Firefox 卡死根因。现有原型正常关闭不构成卡死修复证明，正式替换仍未决定。
