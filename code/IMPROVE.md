# Portal 改进计划索引

这里收录值得独立审阅的显著改善。一份 Plan 只叙述一个完整改变，说明用户任务、现状后果、目标体验、实现边界与验收；必要细节在这项改变内部展开。候选按实际价值维护，不按 Design 领域配额补齐。

当前系统事实从 `SPEC.md` 进入对应 Design，并以实际实现核对。Plan 是尚待实施或验证的建议；出现在此处不表示已经授权执行、测试或发布。一个改进可以涉及多个 Design，一份 Design 也可以继续包含多个现行设计点。

## 编写与审阅规则

现行 Plan 编写与索引规范：`decision_9c258743f91e`。创建或修改前读取规范与直接相关的 Design、代码和已有 Plan，先判断是否值得占用一次独立审阅。已实现、失效或仅有维护细节的内容及时退出现行候选；合并只承接相同核心改变，旁支不隐含继承。

`importance` 表达重要度；可选整数 `metaness` 表达抽象层次，取值 1..10。普通直接工程叙述通常取 1..3，跨模型或治理规则可以更高。缺失值合法，WALL 显示默认 1；显式非法值必须诊断。两者含义独立，评分不构成启动或发布审批。

## 维护方式

WALL 对每份当前 Plan 呈现一个改进 Block，文内章节与技术细节不再各自成为候选。审阅时先读完整因果与边界，再判断是否推进；实施后把已成立的系统事实更新到相应 Design，并结束、调整或移出已不再适用的 Plan。

历史迁移说明和 obsolete 资源不进入当前候选。归档、版本和真实来源关系由知识库维护；此索引只负责核心标题、价值与稳定 Plan ID 的导航，不保存另一份方案正文。
