# 知识库审计

审计用于查找可能错误、互相矛盾、过时、重复或表达含糊的条目。默认只读并报告发现，不直接修改正文。

## 审计等级

- 一级：较明确的错误、矛盾、过时内容，以及核心内容高度重复且适合合并的条目。
- 二级：在一级之外，检查缺少关键前提、范围不清或容易导致误操作的表述。

默认使用一级。用户明确要求更细或检查含糊内容时使用二级。

## 工作流

1. 按 `./search.md` 确定项目、目录和条目范围。
2. 提取每个候选条目的核心事实、状态、路径、配置、日期、责任边界和结论。
3. 按主题、对象和时间线比较条目。
4. 重新读取每个候选问题的原文，区分真实冲突与历史阶段、不同视角或不同适用范围。
5. 为每项发现记录类型、严重度、摘要、建议和可定位的证据路径或条目 ID。

只有标题或关键词相似不算重复。问题与答案、讨论与最终决策、不同阶段记录或不同证据来源通常应保留并建立关系。

## 结果与持久化

默认在对话中报告审计范围和发现，不创建文件。

用户要求保存审计结果时：

1. 按 `./knowledge-base-rules.md` 写入 `review` 条目；或
2. 用户要求跟踪待办时，按 `./archive-todo-item.md` 确定 Mailbox 或知识归档目标，不创建失去写入接口的旧 TODO。

Review 保存为知识条目，Mailbox 待办由各自接口管理。处理结论按目标接口支持的字段与正文保存，不混用两种对象的状态。

不得使用额外的自定义 YAML 头部字段承载审计元数据。详细范围、证据、主条目建议、待合并条目和需保留的差异写入正文。

实际承担者按当前部署查询，不假定存在固定命名的审计 Agent。后台自动检查与人工审计的关系见 `./automation.md`。
