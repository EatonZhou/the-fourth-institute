# 资料文件系列整理

用于整理项目 `knowledge_base/material/` 下的资料文件。目标是让同一系列的名称、版本、语言、用途和派生产物归属可以直接判断。

## 文件名

同一系列使用稳定的系列名作为文件名前缀。文件名不能只包含日期、版本号或“最终版”等用途不明的标记。

推荐格式：

```text
<系列名>-V<版本>-<语言>[-<用途>].<扩展名>
<系列名>-<日期>-V<版本>-<语言>[-<用途>].<扩展名>
```

- 系列名可以使用中文、空格和括号。同一系列不得混用多个名称。
- 版本使用 `V1`、`V2.5` 等明确编号。
- 语言使用 `zh`、`cn`、`en` 等稳定代码。
- 用途用于区分同一版本的完整版、精简版、内部版或演示版。
- 日期使用 `YYYYMMDD`，放在版本号之前。日期只能补充时间信息，不能代替版本号。

示例：

```text
项目路演-V1-zh.pptx
项目路演-V2.5-en-full.pptx
项目路演-20260512-V2.5-zh.pptx
项目执行计划-V0.8-en.pptx
```

以下文件名不能说明稳定版本：

```text
20260512.pptx
V2.pptx
final.pptx
新版.pptx
```

如果早期文件只用日期表达版本，不得猜测其版本号。只有人类已经明确版本对应关系，或现有材料能可靠证明时才直接改名；否则生成审查事项，请人类确认。

## 可以共存的文件

以下差异不代表文件重复：

- `V1`、`V2` 是不同历史版本。
- `zh`、`en` 是同一版本的不同语言。
- `full`、`simple`、`internal` 是同一版本的不同用途。

不要因为文件名相似就删除旧版本、语言版本或用途变体。

`final`、`final2`、`new`、`old`、`copy`、`副本`、`最终版` 和 `最新版` 不能作为稳定版本身份。能确定真实版本或用途时改为明确标记；只是重复副本时，先核对内容和引用，再按用户授权删除。

## 目录归属

同一文件系列的主文件放在同一个系列目录或同一子树中，不得散落在资料根目录和多个无关目录。

```text
knowledge_base/material/项目路演/
  项目路演-V1-zh.pptx
  项目路演-V2-zh.pptx
  项目路演-V2-en.pptx
```

一个版本包含多个主文件、派生产物或工作文件时，为该版本建立同名子目录：

```text
knowledge_base/material/项目路演/
  项目路演-V2/
    项目路演-V2-zh.pptx
    项目路演-V2-en.pdf
    项目路演-V2-zh/
      slide_01.png
    _work/
```

目录可以继续嵌套，只要路径能够表达系列和版本归属。

## 主文件与派生产物

PPT、PDF、DOCX、KEY 等是主文件。导出的页图、截图、动图和压缩包通常是派生产物。

每批派生产物放入对应主文件的同名目录，与其他版本分开。多个主文件不得共享一批归属不明的派生产物；确实共享时，用目录名或说明文件写清归属。

系列目录可以使用 `_work/`、`_scratch/`、`_source/` 保存源素材、中间文件和脚本输出。这些目录不代表正式版本，正式版本仍由主文件名表达。

## 整理判断

需要整理：

- 同一系列散落在多个无关目录。
- 同一版本、日期、语言和用途下存在多个内容哈希不同的主文件。
- 文件名只有弱标记，无法判断真实版本关系。
- 主文件与派生产物关系不清。
- 版本序列存在无法解释的跳跃或分叉。

可以保留：

- 明确的历史版本共同存在。
- 同一版本的不同语言共同存在。
- 同一版本的不同用途共同存在。

不确定版本关系时只报告问题，不猜测版本号，也不删除文件。
