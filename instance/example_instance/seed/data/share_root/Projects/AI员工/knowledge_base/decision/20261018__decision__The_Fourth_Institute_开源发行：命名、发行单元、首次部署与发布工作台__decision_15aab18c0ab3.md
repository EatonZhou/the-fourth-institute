# TFI Portal 开源发行：命名、发布内容、首次部署与发布工作台

产品统一使用 TFI Portal。发布者选择要带出的功能和数据，得到一份不带 Git 历史的独立代码仓库、一份发行数据库和安装说明。使用者安装后注册自己的账号，配置自己的 AI Backend，即可使用所附功能和团队。公开仓库为 `EatonZhou/the-fourth-institute`。

## 发布内容

Portal 基础代码随发行版完整保留，不逐项枚举，也不在工作台展示为带出选项。

发布清单分别表达支持哪些资源类型、带出哪些实例，以及 Society 与投影的关联选择。源码可以按清单调整，以安装后可用为准，不要求与开发版本逐字节一致。

功能依赖自动随同带出：选择功能 A 时，A 所依赖的功能 B 无论是否勾选都自动加入，B 的必要功能依赖同样处理，并在清单中显示加入原因；不另要求用户选择或确认 B。依赖仍存在时不能单独排除 B；取消 A 后，保留用户直接选择或仍被其他功能依赖的 B。页面、测试和文档按补齐依赖后的实际功能范围处理。

功能依赖不等于对象选择。带出 A 不自动带出 A 下未选的资源实例，也不沿知识条目的链接复制其他条目；所属 Project、投影所需 Lineage 等已明确的结构关联仍按各自规则处理。

发行版的页面与 UI 按实际带出的功能呈现：未带出的功能不显示对应页面、导航、菜单、设置项、操作按钮及安装提示，共享页面只保留已带出功能的部分。未带出 Resident 向量／语义搜索时，Portal 设置中不出现该功能的开关、模型状态或一键安装入口，普通关键词搜索继续保留。发行版不包含某功能，与已包含但运行时关闭该功能分别处理；后者仍可显示其设置和启用入口。界面与后端对发行版所含功能使用一致的判断，不能只隐藏入口而仍发起缺失功能的请求。打包时随清单处理这些界面和调用，并核对发行版实际显示。

### 目标平台与支持状态

发布配置通过非空、去重的 `target_platforms` 多选目标平台，规范值为 `linux`、`windows`、`macos`。初始新草稿可选 Linux；选择、命名保存、加载、修改与另存均保留同一字段。新执行的不可变配置快照保存该字段，发行工程 manifest 记录 `selected_targets` 与按功能和平台解析的 `support_matrix`。

选定目标、已实现能力和实机验证分别记录。能力状态使用 `implemented`、`incomplete`、`unsupported`；验证状态使用 `not_run`、`passed`、`failed`。缺口列出功能、平台、能力与原因；验证结果附实际系统版本、架构、工程摘要、验证时间与证据。已实现可以仍未验证，勾选某个平台不能使其自动变为已支持或验证通过。

发布目标目录及组合解析由发布后端唯一维护，安装模块提供真实能力事实，页面通过发布 API 展示同一目录，不在浏览器或安装器维护平行枚举和支持表。所选目标缺实现时仍允许保存配置并显示缺口，不静默移除选择。准备可安装产物时，若所选必要功能和平台组合存在未实现能力，执行进入 `needs_configuration` 并列明缺口；可以保留诊断或部分工程，但不能以其代表满足全部目标的产物，不能将执行标为 `succeeded` 或将缺口目标标为可安装成功。能力齐备但缺实机环境时，同时呈现实现状态和未验证状态。

发行工程保留基础代码完整性，按明确的能力依赖携带所选平台的安装资产，不根据目录名猜测或删除共享业务代码；额外保留共用适配代码允许存在。旧保存配置缺少 `target_platforms` 时，编辑入口明确显示其旧版 Linux 范围及迁移来源；历史提交正文、run 快照与正在执行的原配置保持原样，`legacy-effective-linux` 仅作为派生解析事实记入 attempt 证据，不写回原快照，也不因新增平台字段另起同一次测试。

### 同主线的平台适配合同

Linux、Windows 与 macOS 使用同一仓库和主线，共用业务代码、数据模型与 ISA。安装及启动按实际操作系统与架构选择能力实现，不用平台 Git 分支，也不在各业务调用点复制一套流程。公共入口不在模块顶层加载另一个平台专有的模块。

- 进程与进程树由 `management_common.process_runtime` 统一拥有。Linux/macOS 使用独立进程组，Windows 在恢复执行前加入 Job Object；超时、取消与父宿主退出按树回收。旧持久运行缺少有效所有权时保留未知，不能凭裸 PID 杀进程或自动重放。主动脱离 POSIX 进程组的外部程序需要部署侧隔离，普通进程组不宣称能够控制它。
- 交互终端独立于普通管道执行：POSIX PTY 与 Windows ConPTY 使用同一终端接口。Windows 原生命令采用参数向量；批处理包装不能当作 CRT 参数转义，不能安全表达的参数在启动前拒绝，优先调用明确的解释器和入口文件。
- 本机通信通过统一的 local IPC 接口。POSIX 使用 Unix socket；Windows 使用动态回环端口、当前用户私有的端点文件与双向挑战认证；内部业务 RPC 继续执行请求签名及 ISA 权限校验，具体合同见 decision_96a887d83e8a。退出清理只能删除自己这一代的端点。
- 文件锁、私有文件权限、原子替换与资源相对路径由公共文件能力处理。Windows 的 ACL、重解析点及路径大小写不能由 Unix mode 位或字符串前缀判断代替。资源地址仍使用平台无关的分隔符；本机文件路径到执行边界再转换。
- 安装器按实际系统选择 systemd、launchd 或 Windows SCM 生命周期实现。安装所需 Python、PostgreSQL、NATS 及所选功能的外部工具由本次目标参数探测，安装资产与实际架构相符才可执行。原生服务注册和依赖前检失败须保留明确原因并回收本次创建的资源；不能把缺失依赖解释为成功。
- Provider、文章工具与嵌入模型的安装入口复用公共进程及路径能力；原生二进制按系统与架构选择，固定发布资产校验摘要后替换。运行时需要的 `psutil` 属于基础 Python 依赖；Bash、TeX/SyncTeX、Poppler、Provider CLI 等功能依赖按实际使用另行检查。
- 发行工程的三平台能力目录表示已提供实现，验证仍按实际环境单列 `not_run/passed/failed`。Linux 定向回归、静态检查、模拟 Windows/macOS API 的契约测试都不能替代 Windows/macOS 原生安装、启动、交互与停止验证。平台选择页面消费同一目标定义，不另造支持矩阵。

Linux 的服务文件描述符热交接和原生系统的停止/启动是不同能力：Windows/macOS 重启不承诺保留已接收连接；写请求遇到断连继续按原回执与幂等合同确认。依赖 Linux 内核的隔离构建/测试必须选择等效隔离后端并验证依赖可用，缺少隔离能力时明确拒绝执行，不能退化成宿主直接运行。

应用构建与隔离 pytest 使用容器时，清理责任属于独立受管执行进程，不能只依赖 Web／请求进程的 finally 或容器内命令截止时间。执行进程通过父进程生命周期管道识别断开，继续核对归属并回收 daemon 容器；正常退出也不能因阻塞的缓冲 stdin 监视线程而异常终止。应用构建删除容器前必须核对本次随机归属标记、精确名称与完整容器 ID，清理失败或创建结果未知时保留私有计划和回执，提供仅清理、不重放构建的恢复入口；归属改变时拒绝删除。控制文件与凭据不得进入构建挂载或环境。宿主掉电、执行进程同时被强制终止或 daemon 不可用不视为清理成功，后续仍须依据实际归属与回执恢复。

嵌入模型安装等已受理的独立后台安装由其安装进程拥有子进程、结果及清理，Web 退出本身不应取消安装；安装进程退出与失败继续按该任务的原有终态合同处理。三平台的实现审阅、Linux 真实子进程与模拟 daemon 验证分别记录；这些证据不能替代原生 Windows／macOS 与真实 Docker engine 的部署验证。



### 可选功能与流程

发布配置以同一区域提供 Portal 设置中各项功能、Portal System 中的功能和流程，以及 Telepus、Resident 向量／语义搜索等能力的带出选择。候选按当前实际设置、Lineage 成员、组件及流程核实，不只列资源类型或少数示例；同一功能只维护一份选择，已有 TAU 等区域与此共用选择结果。基础代码和权限系统必需支持继续保留，不重复列为可取消项目。

`lineage_ed619225d417`（Portal System）默认随发行版带出，其所属 Project 和必要结构自动包含。该 Lineage 仍是普通 Lineage，不另造特殊系统类型；其中可选功能、流程按本区域的选择带出所需 Resident、组件和连线，未选部分按依赖整理，不因默认带出 Lineage 就复制所有可选流程。此处的按功能选择适用于 Portal System，其他 Lineage 沿用既有规则。经历和 Workspace 内容仍按各自选项处理。

可选功能及 Portal System 的功能与流程分别提供“是否带出”和“安装后默认开启”两个独立设置。同一功能在不同区域出现时共用同一份带出和默认启用状态，不能分别维护相互冲突的开关。未带出的功能不应用默认启用值，页面禁用或隐藏其启用控件；已带出可默认开启，也可默认关闭。默认关闭仍保留功能代码、配置、相关结构及正常启用入口，安装后可由使用者启用。

两项设置贯通命名配置保存、加载、修改与另存、新执行的不可变快照、发行 manifest 及发行副本的初始化配置。发布时只修改发行副本，不改变源站点运行开关，不从源站点复制账号、凭据或本机路径。全新安装按发布配置初始化实际功能和流程的启用状态；升级保留已有站点自行设置的启停状态，发行默认值用于尚无本站设置的新功能，不能覆盖既有选择。

功能代码依赖的自动带出继续按既有规则处理；默认启用另外核对运行依赖，明确冲突、自动推导的原因及最终生效状态，不能生成主功能开启而必要运行依赖关闭的无效配置，也不能仅因被带出就默认启动其全部流程。默认开启按该功能原有启用语义生效；定时或事件流程等待相应触发，不将打包或保存配置变成一次业务执行。需要本站账号、模型或外部服务配置的功能保留所选默认意图，明确实际就绪状态与缺少条件，不将尚未就绪显示为已经运行。

旧配置未含默认启用字段时明确显示未设置及解析来源，按可核实的功能初始化规则处理，不把字段缺失解释为全部开启。历史执行快照和原提交保持原文，兼容解析只记录派生结果。完整发布测试核对安装后的实际启停状态、默认关闭流程不会自动运行，以及升级后本站已有选择得到保留。

### 权限模板与实例

权限系统随基础代码保留。权限模板／方案与权限实例在独立区域选择，候选使用现有权限系统中的真实对象，可选择具体模板和实例并填写范围说明；不以资源或功能选择代替权限内容选择。

打包时只在发行副本中保留所选权限内容，并根据实际带出对象自动删除权限实例中指向未带出主体或资源的节点、表项及关联；保留有效对象的权限语义，不将失效对象引用替换成更宽的授权。所选实例需要的模板和必要结构随同处理，首次管理员初始化沿用现有规则。源站点权限模板、实例和生效状态不变。

### 资源类型与实例

资源区域按系统实际登记的类型组织，例如 paper、repo、device 和各类知识库条目。选择一种类型，表示发行版必须支持该类型，包含所需声明、提供者代码和相关服务。随后展开该类型的实例选择区，使用同一个选择框查找名称或资源 ID：点击输入框即展开当前类型下可读资源的候选列表，输入时动态更新候选；选择候选后加入清单，显示名称及 ID 便于区分同名资源。自然语言范围另行填写。

类型与实例分别选择。只选类型、未指定实例或文字范围时，发行版支持该类型，但不带出该类型的现有业务实例；必要页面与投影运行结构按依赖规则保留，空选择不表示全部带出。已选实例所需的关联数据由执行团队按清单处理，不能把选择一个类型扩大为复制全部现有数据。

选中的外部资源连同实际内容一起带出，Repo 包括代码，不只保留登记信息或指向源位置的链接；发行副本中的地址适配安装环境，源站点凭据不带出。Device 暂时只允许选择保留类型支持，不提供设备实例带出选择，也不因文字范围、旧草稿或其他关联而带出设备实例；旧选择保留为可见说明，明确本次不带出。

带出归属于 Project 的资源实例时，自动带出其所属 Project，保留原有归属并在清单中显示加入原因。只带出该 Project 及必要关联，不自动带出项目下的其他资源或 Lineage。取消资源后，仍被其他已选内容需要或由用户明确选择的 Project 继续保留；自然语言范围在解析出具体资源后按同一规则处理。

Project、Lineage、Resident 等也属于资源体系，其基础支持随 Society 保留，具体内容集中在 Society 区域选择；Workspace 基础支持固定保留，其内容随 Lineage 下的 Resident 配置，不提供独立 Workspace 带出入口。Workbench 投影使用关联投影区域选择，同一对象不要求重复勾选。

### 资源类型、页面与投影 Lineage 依赖

包含资源类型时，同时包含该类型在 Resource 及相关入口下所需的页面、投影和后台 Lineage，并继续补齐 Lineage 所属 Project 与必要结构。该关系属于类型功能的必要依赖，不要求发布者在 Society 或投影区域重复勾选；即使只保留类型支持、没有选择业务实例，也需要保留这些页面与运行结构。

只要实际包含任一知识库类型，就自动带出 Knowledge Base Lineage `lineage_5db9a65f2fcc`；包含 `paper` 类型时，自动带出 Paper Lineage `lineage_e1ed41b295b0`。知识库类型按实际资源类型登记、页面及提供者归属识别，不按名称或目录猜测。此规则同样适用于由其他依赖自动加入的类型，例如带出 SPEC.md／IMPROVE.md 所选正文而加入的 decision／plan 类型。

类型、页面、投影、Lineage 及 Project 的依赖关系由发布侧统一解析，页面、保存配置、新执行快照和发行 manifest 使用一致的结果及加入原因。同一 Lineage 被多个类型或页面需要时只包含一次；任一依赖仍存在时不能单独撤掉该必要 Lineage。取消类型或页面后，仍有其他依赖或用户手动选择的对象继续保留，仅移除已无来源的自动加入项。其他资源类型按真实页面与投影关联使用同一规则；关联缺失时明确缺口，不生成有页面而缺少其后台 Lineage 的完整产物声明。

自动加入的 Lineage 按普通 Society 规则带出成员和必要结构；所属 Project 不因此带出其他无关 Lineage 或业务实例。类型下的业务数据仍按实例选择处理，Lineage 工作历史、Workspace 成果和额外绑定仍按各自选项处理，默认启用状态继续遵循独立设置。类型支持的依赖补齐不自动执行流程，也不复制源站点全部知识条目或 Paper 数据。

### Society 与关联投影

Society 区域先选择 Project，再选择项目下的 Lineage，并逐个决定是否保留工作历史。选择 Project 不自动选择全部 Lineage。选中 Lineage 默认带出其中全部 Resident，以及所需 Family、组件、连线等结构，不要求逐项拼装。

选中 Lineage 后展示其关联投影，可选择是否一同带出。工作台也提供直接选择 Workbench 投影的入口；投影依附一个或多个 Lineage，直接选择投影会自动加入它依赖的 Lineage 及所属 Project，并显示加入原因。两处入口编辑同一份清单。投影仍被选中时，其必要 Lineage 不能单独排除；取消投影后，用户明确选择的 Lineage 继续保留。

自动加入 Lineage 不自动带出工作历史，是否保留经历仍单独决定。投影所需的界面代码、配置和关联数据随投影带出。关联无法核实时明确显示待处理，不把缺少后台 Lineage 的投影当作完整选择。

Projects 页面是否提供仍可单独决定；不提供页面及导航入口时，Project 后端资源、相关服务和项目归属能力继续保留，也不影响已选 Project、Lineage 数据。

### 发行后的阶段进展

阶段进展的空初始化优先于该汇报 Workspace 的成果带出选择；即使选择整个 Workspace，也不得重新夹带上述源站进展历史。初始化只作用于新发行数据，不删除或改写源 Portal 的记录；安装后的新报告沿本站原生索引正常积累，升级保留本站已经产生的阶段进展。发布依赖冻结使用空初始化声明与必要格式资料，不跟随源站持续增长的报告索引变化。

### SPEC.md 与 IMPROVE.md

SPEC.md、IMPROVE.md 分别作为独立区域选择是否带出，不再使用笼统的“规范索引”选项。选择 SPEC.md 后，按实际索引的大模块展开规范条目，可选择整个模块或模块下的具体规范，并提供全选和模块内全选。IMPROVE.md 同样支持选择索引内的具体改进 Plan 及全选；按源索引已有分组呈现，未分组时直接展示条目，不虚构模块归属。两个区域均可补充文字范围。

所选知识条目再次关联的其他条目，只有用户也选择带出时才包含，不沿知识链接递归扩展范围。打包时在发行副本中调整条目元数据的 links 和正文资源链接：目标已带出的链接保留并适配发行地址；未带出的目标移除链接或改为普通文字，不留下指向未发行资源或源站点的失效跳转。此处理不取消既定的所属 Project、必要结构等带出规则。

发布时按选择带出规范与 Plan 正文，并修改发行副本中的 SPEC.md、IMPROVE.md 索引，使索引与实际文档一致。源索引、源文档及其链接不变。带出 WALL 时，它读取发行版的索引与文档，规范及改进展示随上述选择变化，不再保留已排除条目的旧展示数据。选择改进 Plan 只带出文档，不表示实施该计划。

### 发布模块与安装模块

发布模块由本 Family 的 Resident 结合现有工具、组件和脚本完成，消费发布配置并生成可安装的发行工程，包括所选代码、发行数据库、资源实际内容、Resident 文件、安装入口与必要说明。Resident 负责自然语言范围解析、功能依赖及未知关联的判断，组织确定性处理并核对结果；不能只生成任务描述就视为已完成发布。代码与 UI、测试与文档、索引与链接、权限副本、Workspace 绑定、Repo 内容及 Device 排除等均按本文规则落实到发行副本，源站点不变。

发布模块与安装模块分别承担产物生成和目标系统部署职责，完整发布测试复用这两个模块，不另建一套测试专用的导出或安装流程。实施完成需以实际产物和实际启动验证为据；规范与页面选项完成不代表这些模块已经实现。

### 平台适配与安装前检查

三平台共用同一仓库主线、业务逻辑、领域数据、消息协议和配置／运行身份。业务与安装编排依赖稳定的能力接口，平台差异集中在对应能力实现；共用 POSIX 或已有跨平台实现继续复用，不复制三套安装业务流程。

- 常驻服务生命周期复用 `scripts/portal_service_control.py`；服务注册与卸载资产归安装服务适配，实例拓扑来自本次安装描述，不读取源 Dev／Release 布局。已有服务控制接口不代表常驻服务已可安装。
- 临时后台作业复用 `scripts/portal_background_jobs.py`，任务持久状态仍归调用领域；后台启动不替代 Windows 常驻服务安装。
- 文件锁复用 `management_common/file_lock.py`，保持跨进程互斥，不以进程内锁代替；安装入口不得顶层依赖 `fcntl`。
- 本地 IPC 的端点、监听和连接由既有 transport 负责适配，上层协议、错误、超时与认证保持一致。逐项处理 AF_UNIX、端点路径长度和服务发现；替代传输继续限定本地范围并保留身份认证。
- 路径及依赖由 `portal_paths` 与安装参数负责，按实际系统和架构探测路径及 PostgreSQL、NATS、Python 等依赖；命令转义归对应服务适配，不把 systemd 字符限制扩为通用路径约束。

安装器在任何安装落盘、服务或数据库修改之前，识别实际操作系统与架构，核对工程目标声明、所选功能能力及依赖矩阵；未选择或不支持时明确原因并停止。随后按需加载实际平台的实现，平台专有模块懒导入；在其他平台查看帮助、解析目标或导入通用入口，不应因顶层专有模块导入而崩溃。没有等价 reload 或 signal 能力时明确不支持，不隐式替换为中断任务的重启。普通权限体系和源实例隔离继续保留。

### 全新安装、升级与依赖获取

首版安装模块同时支持全新安装和已有站点升级，两种模式由同一安装模块提供，复用平台适配和服务管理。全新安装初始化独立站点并导入发行数据库；升级明确识别目标已有安装、当前版本和目标版本，保留本站用户、账号凭据、业务数据、资源、Workspace 内容及本地配置，不重新执行首个管理员初始化，也不以发行数据库整库覆盖本站数据库。发行内容中的初始化数据与已有对象发生冲突时，按明确的迁移规则处理；不能以升级为由重置或静默删除本站数据。

升级先核对版本兼容、依赖与数据库迁移要求，准备可恢复的代码、配置和数据备份，再按既有运行机制协调写入与任务、执行迁移并切换服务，最后检查启动和功能。安装模块记录迁移及安装阶段，重试不得重复导入数据或重复执行已完成的迁移。失败时保留错误及恢复入口；代码与数据库必须保持相容，不能只回退代码却继续使用不兼容的新数据库。无法自动恢复时，明确当前状态和所需恢复步骤，不把部分完成报告为升级成功。具体支持的升级起点和迁移范围在发行结果与安装说明中记录。

安装与升级允许联网获取所需依赖，首版不要求提供完整离线依赖包。发行工程记录依赖约束、可用锁定信息和获取来源；安装结果记录实际解析及安装的依赖版本、来源和目标平台／架构，可获取时保留制品校验值。记录不得包含源站点凭据或带认证信息的下载地址。下载或依赖安装失败需可诊断、可重试，并保留已安装站点的可恢复状态。

相关安装、升级及维护规则统一进入 SPEC.md 对应规范与必要安装说明；runbooks 已合并到 SPEC.md，不再建立独立 runbooks。

### 已有工程的代码修复与升级声明

同一不可变运行快照允许从精确 SHA256 指定的既有工程接续独立代码修复 attempt。producer 先验证来源 manifest、运行身份、选择摘要和完整 inventory，复用其 SQL 与 data；完成后再次核对 SQL 摘要和 data inventory。修复不重新选择或导出研究资料，不覆写旧工程、快照或旧验收记录。代码变更本身不表示数据库或已有站点兼容。

需要已有站点升级时，调用方在既有代码修复入口显式提供 upgrade 声明。该声明的 `from_manifest_sha256` 必须仅包含本次复用工程的完整 manifest SHA256；`migrations` 必须是显式有序列表。空列表表示发布者已检查实际数据库和持久配置合同、确认无需数据库迁移，不由 producer 从“仅代码变更”推断或自动填入。未提供新声明时保持原有继承行为；来源工程没有声明时，新工程也不产生升级许可。

迁移项包含唯一稳定 ID、工程内的 `code/` 专用 SQL 相对路径和精确 SHA256。ID 只允许 1–120 个字母、数字、下划线、点和连字符；拒绝越界路径、发行初始化 SQL、非法标识与摘要不符。producer 在改变运行状态前校验声明结构、精确起点和源码 SQL 字节；生成 manifest 时再按实际工程 inventory 验证，防止复制或物化改变迁移字节。CLI 的 `--upgrade-declaration` 只用于同时指定 `--data-manifest` 与 `--data-manifest-sha256` 的 generate 入口；非法组合不触发生成。

安装器沿既有 upgrade 入口再次验证已安装 manifest 属于声明起点、迁移 inventory、数据库主版本和依赖，之后才准备备份及切换。升级保留既有安装身份、数据库、配置、账号、Backend 凭据、业务文件与草稿，不导入发行初始化 SQL。源码发布、候选生成、升级预检与目标真实使用分别留证；前一阶段通过不替代后一阶段验收。

### 完整发布测试

选择已保存的配置后，可发起完整发布测试，并单独选择是否使用 TAU。每次完整发布测试必须映射到本 Family 中一个实际 Resident，由其全程指挥监督；页面显示负责者、执行状态、阶段结果、产物位置和测试系统访问入口。固定脚本可以执行步骤，不能替代负责 Resident 对整次运行的判断和问题处理。

负责 Resident 按该配置调用发布模块生成工程，再调用安装脚本，在当前系统的独立安装目录、数据库、数据根目录、服务标识和端口安装并上线，避免覆盖或连接到当前 Portal 的运行数据。核对安装、启动和所选功能的实际使用，处理遇到的问题并保留错误与修正记录。只有发布、安装和实际检查达到预期时才报告成功；未完成、失败或尚缺外部配置的部分明确记录，不以脚本退出或页面构建成功代替完整验证。

完整发布测试同时记录全新安装与升级路径的验证结果。升级验证使用独立测试安装中的已支持旧版本及测试数据，检查账号、配置和业务数据保留、迁移、重试与失败恢复；不直接升级当前 Portal。没有可用旧版本、平台环境或其他条件时，明确该路径未验证及原因，不以全新安装成功代替升级成功。

完整发布测试按平台分别记录验证结果，只在实际匹配的系统上执行安装验证。当前主机上的 Linux 测试不能代表 Windows 或 macOS；缺少对应系统环境时记录 `not_run` 及原因，不用模拟单测或静态检查替代实机结果。平台实现完成后仍须分轮检查能力接口、完整调用链、平台专有导入及失败清理，并运行现有环境可执行的检查；未实测部分保持明确。平台能力补充沿既有执行与重试继续，不重写旧运行快照。

选择 TAU 时，对已上线的测试系统执行真实使用验证，并将发现的问题纳入本次结果。此选项控制验证方式，与发行配置中“带出 TAU 功能”分别保存；不能为了测试而擅自把 TAU 加入发行内容。测试所需账号和 Backend 使用测试环境自身配置，不复制源站点凭据。测试实例的运行位置、服务状态及停止清理方式随结果提供，清理仅针对该次测试实例。

## 首次部署与初始化

- **按安装说明部署。** 安装工具复用已有的依赖安装、数据目录配置和服务管理能力，导入发行数据库并启动 Portal。具体依赖和操作由安装工具及对应部署文档维护。
- **首次打开 Portal 时注册自己的账号。** 首个账号成为本站管理员。服务使用本机安装环境的操作系统账号运行，无需为发布携带账号或要求使用者另建专用系统账号。
- **配置自己的 AI Backend。** 管理员通过现有页面登记自己的账号并设为站点默认；需要不同执行配置的团队再按需配置 Backend 角色。站点名、语言、主题和 Project 按需设置。
- **遇到安装问题时，建议使用自己的 AI agent 协助解决。** 源码全部开放，AI agent 可以阅读说明、源码和报错，调整依赖与配置，必要时修改源码以适应本机环境。

页面标题、登录邀请、邮件和指引使用配置的站点名，默认 `TFI Portal`。本机目录与连接配置由安装环境提供，沿用已有配置能力。

### 规范运行名称与本站部署配置

进程只读取和注入 `PORTAL_*` 规范环境变量。取消旧环境变量读取，`deployment.compatibility.environment_aliases` 即使残留也不产生别名效果；规范变量的显式空值不得回退到旧值。Resident 身份由规范字段表达，提交的身份必须完整、合法且符合调用者授权，不能从旧字段补齐、猜测或静默切换身份。

本站部署配置仍是服务名、数据库连接、私有文件和目录的权威来源，取消旧环境变量读取不取消这些显式配置，也不重新初始化既有数据库或账号。格式标签必须精确等于当前规范值及版本；旧格式前缀、旧身份头、旧浏览器标识和历史摘要回退均取消，配置不能重新启用。`format_namespaces` 的公开结果为空；`domain_values` 仅保存明确的本站部署参数，其配置字段名不表示支持旧协议。已有部署参数按单一明确来源读取，不根据文件存在与否尝试旧名称。浏览器不接收旧标识或格式映射，测试入口仍须识别实际生产环境并拒绝误用生产库。

旧 Seed 标记、调用计划摘要和相关状态目录按一次性迁移处理。先回读已执行记录、备份与实际当前状态，可转换的标记和摘要迁移或补上当前标记，可搬迁的状态目录保留内容和有效锁；不可迁移的旧项只在明确识别、保存必要备份并排除当前引用后清理。每类记录对象、原因、结果和残留引用；已迁移对象不得盲目重复处理。业务正文、用户消息、稳定资源 ID、格式版本、整个数据根及账号凭据不属于命名清理范围。一次性工具所需旧值来自显式本站配置或私有操作材料，源码不得通过硬编码、拼接或编码保留旧品牌或具体源用户名。

验收扫描修正后的当前仓库及解压文本，重建范本引用摘要，定向验证规范环境变量、旧变量不再生效、本站部署配置读取和身份边界，并回读三类旧项的实际结果。固定源码与生成来源后重新生成发行包；历史发行目录的人工修补不能替代根修。隔离测试、已有迁移回执、实际回读和未完成的平台或生成验证分别记录，不以任一项替代全部完成。

## 已有能力与相关规范

资源类型声明随所选功能的代码提供，Portal 启动时读取。管理员在“资源类型”分栏查看和启停类型，无需重新登记声明。用户通过 Resource 页面或相应功能入口添加具体资源，例如登记一个 Git 仓库；发行数据库已有的资源记录随导入保留。

声明、提供者绑定、状态和登记权限见 decision_355ed742bca5；Resource ID 与地址规则见 decision_4a9ba5dfada6。

### AI Backend

发行内容提供 Provider 接入代码。使用者在“AI Backend”分栏登记自己的订阅账号或模型 API。通常使用站点默认账号即可；团队需要不同模型或账号时，再配置角色映射。登录与凭据处理复用现有功能。

账号与角色管理见 decision_7956d7cb4bde；模型 API 见 decision_6c2f91a7d84e；Provider 运行时安装与更新见 decision_e587fe1c472e。

### 数据目录与安装

数据目录配置已由 `management_common/portal_paths.py` 实现，管理共享资料、临时运行数据、实例、账户数据和密钥五个根目录，可在 Portal 管理的“数据目录”分栏修改。新安装默认使用源码目录下的 `portal_data/`，相对路径以安装目录为基准。

目录迁移与平台服务管理沿用现有实现，具体规则见 decision_850e6248d680、decision_8b510cbd9c58；用户与管理员指引见 decision_3286d4167180。发行安装工具复用这些能力。

### 站点配置

站点名读取安装目录下的 `config/site.json`，可通过 `PORTAL_SITE_CONFIG` 指定其他文件，默认名称为 `TFI Portal`。修改后刷新页面生效，页面与认证展示使用同一名称；名称和语言设置不改变已有认证凭据。

页面接收公开站点名、稳定安装命名空间 `storage_namespace` 及 `paths.share_root`、`paths.staging_root`、`paths.test_results_root` 三项目录，用于原生文件链接与预览；账号目录、密钥目录和其他部署配置不进入页面。前两项来自数据目录配置，测试产物目录由 `deployment.native_ui.test_results_root` 指定，未指定时使用安装目录下的 `test-results`。非法目录明确报错。

配置读取和站点名展示已实现，非法配置应明确报错。发行安装器按“发布模块与安装模块”要求建设；其实现和验证状态以实际交付为准。站点配置编辑页面另按对应任务推进。


### 浏览器状态的安装身份

`config/site.json` 的 `deployment.installation_id` 由首次安装生成并持久保存；安装重试沿用已有值，升级沿用原站点配置，不使用发布 run、build ID、站点名或版本号隔离草稿。站点配置领域对该身份生成 SHA256 `storage_namespace` 供浏览器使用，不暴露原始配置或秘密。存量安装与源码站点未配置此字段时，使用其稳定 `deployment.source_root`（未配置则源码根）的规范绝对路径派生同类摘要；Release 构建目录不参与。新安装生成独立身份，即使未来复用原目录也不自动接管旧浏览器数据。

`PortalState.storage` 对 localStorage/sessionStorage 统一加安装命名空间，现有用户、页面、版本逻辑键不变。未知安装归属的历史裸键留存但不自动恢复，不清空草稿；同一安装身份的正常布局与未发送草稿保持可恢复。命名空间只用于本地状态隔离，不替代认证、资源权限或服务器对象存在性检查。Workbench 绑定 404 与明确 URL 优先规则见 `decision_4348ed990621`、`decision_79de71d9890d`。

## 安装种子的运行隔离

发行数据库只携带 `lineage_meta`、`agent_store_meta`、`registry_meta` 的 `schema` 版本。源实例的定时租约、运行持有者、已完成的运行归一化标记以及其他运行元数据不得成为新安装的初始状态；新实例由对应拥有者自行初始化和获取租约。导出不能修改源实例状态。

当前规范、默认业务提示和可执行脚本必须指向发行代码与目标实例目录；不得要求读取源站主机用户名或旧产品的隐式用户目录。需要保留的历史证据和不可变构建产物保持原字节及哈希，其历史文字不作为新安装的默认路径或兼容承诺。
