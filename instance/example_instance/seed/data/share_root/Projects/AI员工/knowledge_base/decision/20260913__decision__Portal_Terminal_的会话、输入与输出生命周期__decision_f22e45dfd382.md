# Portal Terminal 的会话、输入与输出生命周期

Portal Terminal 是在网页里使用的命令行终端。用户可以在 Workbench 的 Terminal 面板中，在某个工作目录下打开一个 shell；也可以在设备详情中，通过 SSH 打开一台已登记设备的远程 shell。无论出现在哪个页面，终端的启动、输入、输出显示、窗口大小和关闭都由同一个共享组件和同一个服务端模块处理。

本 Design 说明终端会话是什么、输入和输出怎样在浏览器与服务端之间传递、遇到网络问题时怎样避免重复执行命令，以及终端怎样随面板显示、隐藏和关闭。

## 基本概念

- **终端会话**：服务端为一次终端启动创建的 shell 进程及其状态，有自己的会话 ID。它与 Resident 对话中的 Provider Session 是两回事。会话属于启动它的登录用户，其他用户即使知道会话 ID 也无法读写。会话 6 小时没有被访问时，服务端清理它。shell 退出后保留输出，直到下一次读取返回最后的增量内容和 `alive: false`，随后清理会话。
- **PTY（伪终端）**：服务端给 shell 进程提供的“虚拟终端设备”。shell 通过它读取键盘输入、写出屏幕输出，程序因此能像在真实终端中一样运行。
- **输出游标**：一个计数，表示这个会话从开始到现在一共输出了多少个字符（按 Unicode 码点计）。浏览器每次读取时带上自己已显示到的位置，服务端只返回之后的新输出。
- **宿主**：嵌入终端的页面或面板。宿主提供启动目标（工作目录或设备）、已登录的请求通道和显示区域。

## 用户看到的行为

- **打开面板后终端启动，显示 shell 输出。** Workspace 终端在宿主给定的工作目录中启动；设备终端连接到宿主给定的设备，连接方式和凭据见 decision_d397f2d99f89。页面不根据当前目录推断用户或 Resident 身份。
- **终端启动完成前按下的键会保留。** 启动完成后按顺序发送。
- **长段粘贴会分批发送，顺序不变。** 浏览器每次最多发送 1024 个字符，控制字符的顺序保持原样。服务端拒绝单次超过 8192 个字符的输入并报错，不截断。
- **发送失败时，剩余输入不会自动重发。** 发生写入错误，或网络中断导致不知道命令是否已经送达时，浏览器丢弃这次之后排队的输入并显示错误。这样一条命令不会被执行两次，也不会意外补上回车。服务端内部继续写入尚未完成的字节；全部写入才返回成功，遇到错误直接失败，响应不提供部分写入重发协议。
- **输出按顺序追加，不重复、不回退。** 浏览器只显示游标之后的新输出，忽略重叠片段和晚到的旧结果。
- **很久没读取时，可能只看到最近的输出。** 服务端为每个会话最多保留最近 200,000 个字符的输出；更早的部分被丢弃，游标照常递增。
- **隐藏或暂停面板后，终端停止读取输出。** 重新显示、启动或恢复后继续读取。浏览器可见时大约每 0.9 秒读取一次。
- **调整面板大小时，终端窗口大小随之改变。** 短时间内的多次调整合并为一次，尺寸适配保留当前键盘焦点。打开终端面板或用户明确操作时才聚焦终端。
- **shell 退出后显示最后的输出和“会话已结束”。** 读取返回 `alive: false` 或会话不存在（404）时清空客户端会话标识并停止轮询。
- **重启终端会开始一个新会话。** 旧会话中尚未发送的输入被丢弃；重启期间输入的内容等新会话启动后发送。重启失败时显示错误，不补发旧输入。显示区和游标在新会话开始时清空。
- **关闭终端只结束这个进程。** 设备上保存的 SSH 密码等长期凭据保持不变。

- **选中文字后可以用快捷键复制。** Ctrl+C、Ctrl+Shift+C 或 macOS 的 ⌘C 复制当前终端选区；没有选区时 Ctrl+C 继续发送中断信号，Ctrl+Shift+C 不发送输入。
- **右键单击直接粘贴剪贴板文字。** Ctrl+Shift+V 提供同样操作，Ctrl+V / ⌘V 保留浏览器原生粘贴。Shift+右键保留浏览器菜单。
- **剪贴板访问失败有明确提示。** 浏览器未授权读取或当前页面不支持剪贴板 API 时，使用 Portal 统一通知提示允许访问或改用 Ctrl+V / ⌘V；不会把失败说明写进终端输出。
- **粘贴内容遵循终端的输入规则。** 使用终端自身的粘贴接口归一换行并遵循程序启用的 bracketed paste（用控制序列标出粘贴边界）；组件不额外添加回车。剪贴板文字原有的换行仍会进入终端。
- **未完成的剪贴板读取只服务原来的活动终端。** 读取期间切换目标、重启、隐藏、关闭或失焦后，丢弃晚到的文字；一次新的粘贴请求取代尚未完成的旧请求。

## 实现

### 参与的部分

| 部分 | 负责 |
| --- | --- |
| 宿主页面或面板 | 提供启动目标、请求通道、显示区域，以及面板的显示、隐藏和尺寸变化 |
| 浏览器终端控制器（`portal_terminal.js`） | 终端显示实例、待发送输入、定时读取、合并尺寸变化，以及丢弃旧会话的晚到结果 |
| 终端服务（`local_terminal_backend.py`） | shell 进程、PTY、会话归属和输出缓冲区 |
| Workspace 与 Folder 服务 | 工作目录的身份和访问检查（decision_8838269736d3、decision_ccb99a00eebd） |
| Device 服务 | 设备的连接信息和 SSH 凭据（decision_d397f2d99f89） |

浏览器通过 `/api/terminal/start`、`/api/terminal/input`、`/api/terminal/control` 和 `/api/terminal/read` 使用终端；Agent Workbench 的本地终端使用 `/api/agent-workbench/local-terminal/` 下同样四个操作。每个请求都按当前登录用户核对会话归属。设备凭据只在服务端读取，不进入浏览器请求或响应。终端中的进程仍受操作系统和运行环境的权限限制；在界面上选择目录不会创建新的 Workspace 绑定。

启动终端及通过 `restart` 新建 shell 都受正式 `OpenTerminal` 权限检查；设备与本地主机的 HTTP 启动入口复用同一服务边界。权限系统启用时按当前方案判断（默认仅 Portal 管理员），关闭时仍要求有效登录 User。会话归属检查继续用于已有会话的读写和控制，知道会话 ID 或能查看目录不授予新建 shell 权限。

### 选区与剪贴板

共享终端控制器在自己的挂载区域监听复制快捷键和右键事件，在 xterm 处理控制键或移动输入节点之前区分复制与中断。选区由 xterm 提供，复制复用 `PortalUI.copyText`，失败提示复用 `PortalUI.toast`；各宿主不重复实现剪贴板逻辑。终端的悬停提示与无障碍描述列出快捷键。

主动粘贴只在用户按键或右键操作时读取剪贴板。读取结果需核对会话代次、最近粘贴请求、面板活动状态与焦点，再调用 xterm 的 `paste` 接口，生成的输入继续走既有排队与分批发送流程。控制器销毁时移除监听，关闭和重启通过会话代次使旧读取失效，暂停时使未完成粘贴请求失效。

### 输出的解码与游标

服务端分段读取 shell 输出的字节，按 UTF-8 增量解码，一个字符的字节被拆在两次读取之间时，先保留等下一段。游标按会话累计输出的字符数计，只增不减；缓冲区丢弃旧输出时，只移动保留区间的起点。浏览器请求的游标早于保留区间时，服务端返回当前保留的全部输出和最新游标。

### 旧结果怎样被丢弃

控制器为每次启动或切换目标记一个递增的请求编号。关闭面板或切换目标时编号加一，旧目标尚未开始的启动被取消；终端依赖的脚本还在加载时关闭，脚本加载完成后也不会再创建会话。旧会话的读写结果晚到时，因编号不符而被忽略。启动完成后才发现面板已关闭的会话，由控制器负责关闭。

尺寸变化通过 Workbench 共享的尺寸适配协议同步；关闭和重启时清除旧会话尚未发出的尺寸变化。终端依赖的静态脚本加载失败可以重试，已成功加载的继续复用，失败的脚本节点被移除，不妨碍下次加载。组件释放时清理计时器、待发送输入和显示实例。

### 与相邻 Design 的分工

Workbench 面板的实例、可见性和布局恢复见 decision_538e155e1102；面板把目标、是否处于活动状态和尺寸交给终端控制器，会话、字节流和输入失败的处理始终由终端组件负责，不随宿主变化。组件的依赖和封装边界见 decision_741b04821171。
