# Portal 实例协议

规范所有者：实例安装与生命周期模块。

## 实例是什么

实例是一个独立运行的 Portal 站点。它包含一整套业务内容，例如用户、权限、Resident、对话、知识、Lineage、Workspace，以及为这套内容运行的全部服务和数据。

- **核心是数据库**：每个实例有一个数据库。数据库记录引用、必须与数据库保持一致的文件，都属于这个实例。
- **判定规则**：一样东西如果必须和数据库一起备份、迁移、恢复才能保持一致，它属于实例。多个实例或人可以同时使用、不需要彼此协调的东西，属于主机层或代码层。
- **实例之间**：不共享可写状态。一个实例需要另一个实例的内容时，通过对方的网络接口访问，不读写对方的目录或数据库。
- **一台主机上的实例**：可以运行多个。测试框架为一次完整测试搭建的站点也是实例，按本协议创建，用完退役。单元测试在共享测试数据库中用 schema 隔离的夹具不是实例。

## 三层归属

### 代码层

代码层是发行版，包括：
- 应用代码；
- 数据库迁移定义；
- 按版本复用的依赖，例如 Python 环境、Node、PostgreSQL、NATS、TeX、浏览器、Provider CLI 程序。

规则如下：
- **只读**：多个实例可以同时使用同一份代码层。实例的服务进程只读代码层，代码层也不记录任何实例的位置。开发者修改的 Dev 代码树也属于代码层，由开发流程管理。
- **自带的实例内容**：代码层可以携带应写入实例的内容，例如核心 Skill 的新版本。创建或升级实例时，由对应步骤把它们写入实例；写入后就成为实例数据，按实例数据管理。

### 主机层

主机层由主机和运行服务的操作系统用户拥有，可被多个实例和人共同使用，包括：
- 订阅账号目录，见「执行账号目录」；
- 模型权重、数据集等大型资料；
- pip、uv、conda 包、Hugging Face、PyTorch 等通用下载缓存；
- 人的 SSH 与 Git 身份；
- 系统级配置，例如开机时创建的目录、文件共享、防火墙。

规则如下：
- **引用**：实例只登记对主机资源的引用，不移动、不删除它们。
- **共用时的互斥**：多个实例同时使用同一主机资源而需要互斥时，用主机级锁协调。
- **系统配置**：由主机管理员维护。安装器只报告实例需要的系统配置，不直接修改。

### 实例层

以下内容由实例独占：
- 数据库集群和 NATS；
- 清单、站点设置与密钥；
- 业务文件根（share、staging）；
- Workspace、Git 仓库与 worktree、上传文件；
- 运行文件，即 socket、锁、日志、临时文件；
- 服务进程的 HOME；
- 维护与迁移记录；
- 服务单元和端口。

## 实例内的部署

一个实例运行一组后端服务（Resource、Society、Execution、Worker 等）和若干部署。部署是用某一份代码对外提供网页和接口的入口：
- **Release 部署**：每个实例都有。
- **Dev 部署**：可选，供开发使用。

部署之间的边界如下：
- **共用**：各部署共用实例的数据库、数据和后端服务。
- **各自拥有**：代码引用、网页端口、socket，以及部署自己的运行文件。
- **后端服务用哪份代码**：有 Dev 部署时使用 Dev 部署的代码，没有时使用 Release 部署的代码。

两个部署之间的发布流程见《Portal 共享运行基础与 Dev 到 Release 的发布流程》，路由规则见《Portal Dev 与 Release 部署、用户路由与服务控制面》。

用词约定：
- 进程通过 `PORTAL_DEPLOYMENT` 得知自己属于哪个部署，取值为 `release` 或 `dev`。
- “实例”只指整个站点，不用来称呼部署。
- 实例级的配置统称“实例配置”，不称为“部署配置”。

## 示例实例

`instance/example_instance/` 是随开源代码发布的示例实例。

- **仓库中的内容**：仓库里只保存它的发布内容 `seed/`，包括数据库导出、文件、文件清单和完整性摘要，不含账号、密钥或运行产物。
- **内容来源**：发布内容由导出工具从来源实例生成并脱敏。
- **完整性**：发布内容带文件清单、摘要、数据库格式和资源路径映射。准备脚本 `prepare_install.py` 在安装前校验这些内容，并从当前代码组装安装工程；它不修改任何运行中的数据库。

在发行目录中安装示例实例时：
- 安装器在同一目录下生成清单、数据库、数据和运行文件，这些都由 Git 忽略。
- 示例实例取得自己的 instance_id，此后和其他实例一样运行和维护。

同一份发布内容也可以在其他位置创建更多实例，每个实例有自己的名称和 instance_id。

可选案例：
- 目前的可选案例是元胞自动机研究项目，创建时可以不装。示例中的基础平台内容（AI员工 项目、内置 Skill、开发工具）保留。
- 不装可选案例时，项目、团队、Resident、Workspace、代码、资料和投影一并排除，SQL、文件清单和选择记录同步筛选。

安装程序默认创建后立即启动，也可以选择只创建不启动。

## 身份与清单

### 身份

每个实例有以下标识：

- **`instance_id`**：
  - 创建时生成，此后不变；迁移到新路径或新主机后也不变。
  - 从另一个实例复制出新站点（例如测试实例）时，生成新的 ID。
  - 浏览器本地存储等按实例隔离的数据，以它作为命名空间。
  - 已有实例沿用原来的 `installation_id` 作为 instance_id。
- **名称**：在一台主机上唯一，用来选择实例，也是默认的目录名。
- **服务名前缀**：创建时确定并写入清单，此后不变，在主机上唯一。服务名为 `<前缀>-<组件>`。

### 实例根目录下的三类配置

实例根目录下的 `instance.json` 是实例的清单，也是实例基础配置的唯一来源。它记录：

- **身份**：instance_id、名称、创建时间和来源（示例实例的版本，或迁移来源）。
- **部署**：每个部署的 ID、类型、代码根和网页端口。
- **网络**：监听地址、实例入口端口、PostgreSQL 与 NATS 端口。
- **服务**：服务名前缀和服务清单，包括入口网关。
- **依赖**：所用 Python 环境、PostgreSQL、NATS 等程序的位置。
- **数据根**：share、staging、secrets 的位置。默认在实例根目录内；放在实例之外的必须写明绝对路径。
- **主机资源引用**：所用的模型与数据目录、通用缓存目录等主机资源的位置。
- **运行限制**：是否允许执行业务（迁移切换完成前不允许）、是否启用定时源。

另外两类配置：
- **站点设置**：`site.json` 保存认证、备份、Provider、Pulse、通知等功能设置，不含路径。
- **密钥**：数据库连接串、签名密钥、外部服务凭据放在 secrets 数据根，不写进清单或站点设置。

### 读取清单

- **统一入口**：由一个模块读取和校验清单。服务、脚本、测试、安装器和桌面启动器都通过它取得路径与设置。
- **环境变量**：
  - 服务进程只接收 `PORTAL_INSTANCE_ROOT`，网页进程另加 `PORTAL_DEPLOYMENT`；
  - 命令行工具用 `--instance <名称>` 或 `PORTAL_INSTANCE_ROOT` 选择实例。
- **不使用的来源**：
  - 不从当前目录、进程的 HOME 或用户级全局配置推导实例位置；
  - 不接受逐项路径环境变量覆盖清单。

## 目录布局

```text
<实例根目录>/
  instance.json        清单
  site.json            站点设置
  secrets/             密钥（secrets 数据根的默认位置）
  database/            PostgreSQL 集群
  data/
    share/             知识库、项目、Agent 等业务文件（share 数据根的默认位置）
    staging/           实验与运行产物（staging 数据根的默认位置）
    repositories/      Git 仓库
    worktrees/         Git worktree
    uploads/           上传文件
    provider-state/    Portal 为 Provider 运行保存的本实例状态
  deployments/<部署>/  该部署的 socket、锁和签名密钥
  runtime/             运行文件：socket、PID、锁、日志、临时文件
  home/                服务进程的 HOME
  maintenance/         创建、升级、迁移、备份与核验的记录和回执
```

示例实例的根目录另有 `seed/`，存放它的发布内容。

- **外部数据根**：数据根可以放在实例根目录之外，例如让人直接访问的共享目录。这样的数据根由声明它的实例独占：
  - 同一路径不能被两个实例声明；
  - 不能与代码层、主机资源或其他实例的根目录重叠；
  - 不能是软链接。
- **路径的保存方式**：结构化数据中的路径以数据根为基准保存。历史上保存了绝对路径的结构化绑定，迁移时由迁移工具更正，不对消息正文做字符串替换。
- **不可移植的内容**：`runtime/` 中的进程、socket 和锁不可移植。迁移不复制它们，启动时重建。

## 服务进程的 HOME 与工作环境

程序按环境变量 `HOME`（即 `~`）决定把配置、登录状态和缓存写到哪里，例如 `~/.config`、`~/.ssh`、`~/.cache`。实例启动服务时把 `HOME` 设为 `<实例根目录>/home`，这个目录称为服务 HOME。服务以及由它启动的进程，包括 Resident 调用的 Provider CLI 和 Resident 在终端里运行的命令，看到的 `~` 都是它。

服务 HOME 与运行服务的操作系统用户的主目录（例如 Linux 上的 `/home/<用户>`）是两个目录。后者是人登录主机时的 `~`，属于主机层。一台主机上的每个实例各有自己的服务 HOME，彼此的工具配置不会互相覆盖。

Windows 同时设置 `USERPROFILE`、`APPDATA` 和 `LOCALAPPDATA`。

- **HOME 里放什么**：只放工具的配置和登录状态，例如 Git 配置、SSH known_hosts、CLI 设置。
- **Resident 的实验环境**：conda 环境、虚拟环境、编译产物等放在 Workspace 或 staging。
- **通用下载缓存**：放在主机的缓存目录，位置记在清单的主机资源引用中，由服务环境中的缓存变量指向它。
- **订阅账号的位置**：由账号登记决定，与 HOME 无关。

## 与主机层的接口

### 本机实例登记

一台主机上可以装多个实例。运行服务的操作系统用户有一份本机实例登记 `~/.config/tfi/instances.json`，只记录本机装了哪些实例：每个实例的名称和实例根目录。`~` 取操作系统用户记录中的主目录：Linux 和 macOS 取 passwd 条目，Windows 取用户配置目录。

模型与数据目录、通用缓存目录等主机资源不记在这里，由各实例在自己的清单中登记引用。

使用方式：
- **登记与注销**：创建实例时登记，退役时注销。修改登记时持有主机锁。
- **查找实例**：安装器、管理界面和命令行工具都从本机实例登记查找实例，不扫描代码目录。
- **实例放在哪里**：新实例默认放在发行目录的 `instance/<名称>`，与 `code/` 并列。主机管理员可以在创建时指定其他位置，例如服务器上的 `/var/lib/tfi/instances/<名称>`。

### 端口与服务名

- **主机内唯一**：实例的端口和服务名前缀在主机上唯一。创建实例或修改端口前，安装器读取本机实例登记中所有实例的清单检查冲突。
- **服务单元都带前缀**：实例的服务单元都使用 `<前缀>-<组件>` 命名，包括入口网关。生命周期操作按清单中的服务清单启停，不处理清单以外的单元。

### 主机锁

共用主机资源的互斥用主机级锁协调，例如：
- 账号目录的常驻进程；
- 共享依赖的准备；
- 本机实例登记的修改。

锁文件放在被保护资源所在的主机目录中，不放进任何实例。

### 执行账号目录

订阅登录类执行账号（Codex、Claude Code、Kimi Code、Antigravity 等）各有一个 Provider 原生目录，例如 Codex 的 `CODEX_HOME`、Claude Code 的 `CLAUDE_CONFIG_DIR`。目录里是登录凭据、会话记录，以及 Provider 自己的数据库和锁。

这个目录属于主机：同一台主机上的多个实例和人在终端里直接运行的 CLI，只要用同一个目录，就共享同一份登录和会话。实例只保存账号登记，并在登记中记录目录的绝对路径。API Key 类和服务类账号没有账号目录，key 由实例的 secrets 保存。

- **默认位置**：放在运行服务的操作系统用户主目录下，按 Provider 分开：`~/.codex-accounts/<名称>`、`~/.claude-accounts/<名称>`、`~/.kimi-accounts/<名称>`、`~/.antigravity-accounts/<名称>`。
  - `~` 的取法与本机实例登记相同，不取进程的 `HOME`。
  - 名称默认取 account_id 去掉 `<provider>_` 前缀，例如 `codex_five` 对应 `~/.codex-accounts/five`。
  - 主机管理员可以登记其他位置。
- **登记**：账号登记保存目录的规范绝对路径，不能是软链接。启动 Provider 时，只用这个路径设置 `CODEX_HOME`、`CLAUDE_CONFIG_DIR` 等变量；不从实例目录或 `HOME` 推导路径，也不靠修改 Unix `HOME` 来选择账号。
- **创建与接入**：
  - 新建订阅账号时，Portal 在默认位置创建空目录，再进入登录流程。
  - 接入主机上已经登录的目录时，直接登记这个路径，不复制凭据文件。复制会让两处各持一份 refresh token，一方刷新后另一方就失效。
- **删除**：删除登记不删除目录。Portal 不移动、不改名账号目录，目录的整理由主机管理员负责。
- **目录内容**：账号目录只放 Provider 自己写的文件。Portal 的索引备份、启动锁、socket 和作业记录放在实例 runtime 下。
- **常驻进程**：一个账号目录在一台主机上最多运行一个 Portal 管理的常驻进程，例如 Codex app-server、Kimi server。
  - 启动前，在 Provider 根目录（如 `~/.codex-accounts/`）中取得以目录名命名的主机级锁。
  - 目录已被另一个实例的常驻进程占用时，后启动的实例报告冲突，不并行启动。
  - 终端里直接运行的 CLI 不受此限制。
- **会话**：Provider 的会话记录留在账号目录，实例数据库保存会话 ID 与 Resident 的绑定。Portal 清理会话时，只处理本实例登记过的会话。
- **额度**：额度读数来自上游账号，多个实例登记同一目录时读到同一份额度。并发占用由各实例分别计算。

## 生命周期

### 通用规则

- **实例锁与回执**：每个生命周期操作都持有实例锁，结果写入 `maintenance/` 中的回执。
- **合规检查**：每个操作结束时运行合规检查，检查结果也写进回执。

### 各项操作

- **创建**：来源有两种：示例实例的发布内容，或另一个实例的一致性备份（迁移）。
  - 创建会写出清单、初始化数据库与数据、安装服务单元、写入本机实例登记。
  - 创建完成后服务处于停止状态。安装程序可以紧接着启动，但两步分开记录。
  - 从示例实例创建后，由首次管理员初始化建立第一个账号。从备份创建时，保留原有的用户、历史和阶段进展。
- **启动、停止、状态**：
  - 只操作清单中登记的服务；停止时保留全部数据。
  - 清单不允许业务执行时，启动拒绝运行业务服务的入口。
  - 同一业务数据库复制出的两个实例，不能同时消费复制来的待办任务、定时器或外部入口。
- **升级**：
  - 把部署指向新版本的代码层，执行数据库迁移，再写入代码层携带的实例内容。
  - 升级不重新导入示例内容，不清空历史，也不用示例的 SQL 代替升级迁移。
  - 同一份代码层被多个实例使用时，更新前检查所有使用者的代码和 schema 兼容性，必要时安排共同停机。
  - 每个实例分别记录自己已应用的迁移。
- **备份**：
  - 备份范围是实例层：数据库用 PostgreSQL 一致性备份，再加数据根和配置。
  - 回执记录所用代码版本和登记的主机资源引用，不复制代码层和主机资源本身。
- **迁移**：换路径或换主机，见「迁移与切换」。
- **复制**：从一个实例的一致性备份生成新实例，用于测试或演练。
  - 新实例取得新的 instance_id。
  - 默认禁止执行业务和定时源，不连接原实例的外部入口，例如通知和 Telegram。
- **退役**：
  - 停止服务、删除服务单元、从本机实例登记中注销，删除实例根目录及其中的数据库。
  - 放在实例之外的数据根，只在明确选择时删除。
  - 主机资源不受影响，例如账号目录、模型和缓存。

## 隔离规则

- **路径来源**：实例代码只从清单取得路径和身份。
- **不写其他层**：不写其他实例的目录、数据库和服务，不写代码层，不移动主机资源。
- **服务环境**：服务单元只带清单所需的环境变量，不继承其他实例的数据库地址、socket、HOME 或凭据。
- **导出内容**：实例导出的内容（示例实例的发布内容、备份）不含主机资源，也不含其他实例的路径。

## 合规检查

安装器提供 `check`，按实例名称或实例根目录检查实例是否符合本协议。检查项：

- 清单的格式和必填项；
- 目录布局；外部数据根是否独占、是否与其他位置重叠、是否为软链接；
- 端口和服务名前缀在主机上是否唯一；
- 服务单元的环境变量是否只有协议允许的那些，并与清单一致；
- 配置和结构化绑定中是否有指向不存在位置的绝对路径；
- 订阅账号登记是否指向存在的、非软链接的目录；
- 服务 HOME 中有没有大型缓存（这一项只报告，不判为失败）。

生命周期操作、测试和管理界面使用同一个检查。

## 安装器的实现要求

### 健康检查失败时的诊断

服务健康检查失败时，安装器在停止服务前保存：
- 观察结果；
- 各组件日志的位置。

错误信息要求：
- 指出失败的服务或检查项；
- 保留 HTTP 错误响应中的组件诊断。

已退出组件的日志末尾片段（有长度上限）同时写入诊断文件和主安装日志，保留退出异常供定位。只看到服务为 inactive 或连接被拒绝时，不能断言具体根因。

### Windows 用户态服务

- **失败判定**：监督进程已退出时，直接报告失败；仍在启动的服务，继续在期限内检查。
- **就绪检查**：启动 web 后进入整体就绪检查，显示未通过的项目和已等待的时间。
  - HTTP 检查须保留状态码。
  - 网页检查失败时，即使进程仍存活，也保留 web 日志末尾的一段，不能只报告“未就绪”。

### 公开 HTML 的目录投影

- 按部署主机的原生路径语义验证。
- Windows 的反斜杠只在校验分隔符和输出时规范为正斜杠。
- 输出使用已解析目录的 as_posix，不能因为 WindowsPath 的字符串形式而拒绝登录页。
- 保留以下拒绝规则：目录穿越、控制字符、文件系统根、不完整的 Windows 盘符路径。

### Windows 本地 TCP 通信元数据

- 必须发布在私有 DACL 目录中。普通 mkdir 的 mode 不能代替 Windows ACL。
- 默认缓存使用新的叶目录 `TFI/Portal/ipc-v2`。旧的继承权限目录保留，但不放宽它的验证。
- Python 与 Node 使用同一套创建和寻址规则。显式配置的路径仍须通过原有的私有权限检查。

### `4ac9224` 预览版的专用修复器

适用于已完成准备和数据库导入的 `4ac9224` 预览版。

执行步骤：
1. 校验版本、状态和模块摘要。
2. 取得启动锁，经正式生命周期停止实例。
3. 备份通信模块后原子替换。

限制：
- 不得改写原工程清单、重置安装进度或重新导入数据库。
- 其他版本、修改过的代码和不完整的状态都拒绝修复。

### Windows 安装向导与发行包

- **案例选项**：写入实例前提供“安装 Lenia 预置案例”选项，默认勾选。
- **构建**：
  - 构建器提前生成两种包：已筛选 SQL、文件和清单的基础包，以及完整案例包。
  - 安装向导只释放所选的包；启动器在解压前读取选择，不先解压完整案例再筛选。
  - 公开的示例实例内容保持不变。
  - 构建器必须校验带案例与不带案例两种工程的完整性。
- **路径长度**：
  - 准备工程使用较短的 `.build/w/engineering` 路径。
  - 只有所选内容的解压、临时及最终路径确实超过系统默认限制时，才请求长路径授权，不能无条件要求管理员修改系统设置。
- **选项何时生效**：安装选项只在首次创建时生效。安装重试沿用原选择，不能通过更改选项重新导入或删除已安装的数据。

## 管理界面中的实例控制

Portal 管理在网络设置之后提供「Portal 实例」。

- **权限**：只有当前站点的 Portal 管理员可以读取同一主机的实例列表，并提交启动、关闭请求。权限系统关闭时也不放宽这个限制。
- **服务器接受的输入**：只有实例名称和 start/stop。不接受客户端指定的路径、命令，也不接受删除或安装操作。
- **列出哪些实例**：只列出本机实例登记中、并且通过清单校验的实例。

实例状态：
- **来源**：按清单中的服务读取，区分运行、部分服务运行、关闭和无法读取。
- **限制**：创建或迁移未完成的实例不可启动。关闭时保留数据库、账号登记、对话和其他持久内容。
- **访问地址**：网页服务运行时，展示监听地址对应的主机 IP 与端口，不把通配地址当成可访问的网址。只监听本机的会明确标注。显示地址不代表已经验证客户端到主机的网络连通。

控制作业：
- **执行方式**：生命周期规则由安装器维护。界面通过独立的控制作业调用安装器的 start/stop。
- **作业环境**：使用操作系统服务所有者的环境，不继承当前实例的 HOME、数据库连接或 socket 配置。
- **Linux**：作业使用独立的 systemd 用户单元，所以关闭当前网页所在的实例时，作业仍能完成。
- **作业记录**：属于目标实例的 runtime，保留失败信息，并拒绝同时接受重复操作。
- **关闭提示**：关闭当前实例前，提示连接将断开。全部实例关闭后，需要从服务器的安装器或桌面启动器重新启动。

## 迁移与切换

迁移采用“复制、校验、切换”的顺序，源文件和原数据库保留作为回退依据。

- **数据库**：必须使用 PostgreSQL 一致性备份，不能复制正在写入的数据库文件冒充备份。
- **必须保留的内容**：
  - instance_id、对象 ID；
  - 用户密码哈希、TOTP 与会话密钥；
  - Provider 账号登记与会话绑定；
  - Resident 对话；
  - Workspace；
  - Device 凭据及授权关系。
- **路径**：只更正清单和结构化绑定中的路径，不对历史消息正文做任意字符串替换。
- **主机资源**：订阅账号目录等主机资源不随实例复制。
  - 换主机时，主机管理员先在新主机上准备这些资源，例如复制账号目录。
  - 迁移再更新实例中的登记路径。

切换过程：
- **预复制**：源站继续运行。
- **最终切换**：停止或隔离源站写入，补齐文件增量，取得与文件一致的最终数据库状态。
- **不能重复消费**：新旧站不能同时消费同一业务任务、定时器或外部入口。
- **切换前的限制**：切换核验完成前，清单中的业务执行保持关闭。
- **不复制的状态**：进程、socket 和锁不可移植，从持久的任务与会话记录恢复。

差异处理：
- 停用 RoboLab 与语义向量搜索，表示不启动对应功能，不授权删除原始历史数据。
- 以下情况必须记录实际差异，解决或交给用户决定，不得标记为完全等价：
  - 不可读取的文件；
  - 无法移植的正在运行的进程；
  - 外部设备身份；
  - 浏览器认证来源的限制。

## 验收与回退

核验至少包括：

- 用户、Resident、对话、消息及关键资源的 ID、数量和内容校验；
- 原用户登录、原 Resident 历史读取与实际续聊；
- Provider 账号、已有 Workspace、Paper/Article、Device 连接与资源访问；
- 新端口可从局域网访问，源站与新站没有重复消费任务；
- 合规检查通过，公共代码没有运行时写入，示例实例的发布内容没有被实例数据污染。

只有 HTTP 健康、数据库行数一致或复制成功，都不等于迁移完成。

验收失败时：
- 停止新实例的业务执行，按切换记录恢复源站。
- 切换后产生的新业务数据，先保存并处理，不能直接回退到旧快照而丢弃新输入。
- 迁移记录与数据库备份保持私有。
