# 共享代码与实例状态隔离

规范所有者：实例安装与生命周期模块。

## 目标与布局

所有 Portal 实例使用同一份应用代码和数据库迁移定义。实例之间共享结构与行为，
各自保有用户、权限、账号、对话、知识库、Paper、Article、Workspace、Device 和运行状态。
结构相同不意味着业务数据相同，不通过数据库行同步维持代码一致。

```text
code/                                 共享应用、脚本、数据库迁移
instance/
  example_instance/
    seed/                             可发布的初始 SQL、资源及完整性清单
    config/ data/ runtime/ home/       安装后产生，Git 忽略
  dirtybase_instance/                 私有实例，整体 Git 忽略
    installation.json                 实例身份、共享代码位置、服务与依赖
    config/                           路径、站点、数据库连接和私有配置
    data/database/                    持久 PostgreSQL 集群
    data/{share,staging,instances,accounts,secrets}/
    runtime/                          Socket、PID、临时文件和运行日志
    home/                             该实例的用户态配置与工具状态
    maintenance/                      私有迁移、备份、核验与恢复记录
.build/                               可再生成的发行工程，Git 忽略
dependencies/                         可复用的版本化依赖，Git 忽略
```

共享代码中不得写入业务数据、凭据或运行产物。实例不得私自复制并维护应用代码。
安装器只在旧独立工程兼容模式保留实例内 `code/`；新结构通过
`shared_code_root` 指向公共代码，所有服务工作目录与启动脚本使用该位置。
`tfi_instance_layout.py` 是这些路径的唯一解释者。

## 发布与初始化

Git 默认忽略 `instance/*`，仅允许提交 `example_instance/` 的模板与 seed。
该目录的实际 `config/data/runtime/home/maintenance` 同样忽略。
seed 必须有文件清单、摘要、数据库格式和资源路径映射，不包含现用账号或密钥。
`prepare_install.py` 验证 seed，并从当前共享代码组装独立工程；不会修改运行数据库。
工程声明使用 `installer.entrypoint` 指向代码内的安装入口。准备完成前必须通过正式
安装器同一份只读结构与文件完整性校验；校验失败不得替换已有可用工程。
Windows 打包同样从实际待打包的代码和压缩 seed 运行该准备流程，成功后才生成安装包。
安装状态尚未建立时，桌面重试可重新生成工程缓存；已有安装状态仍绑定原工程，
恢复不能替换其声明或重新导入数据。
桌面解压 seed 时逐文件原子替换，最后写入完整清单作为完成标记。仅当完成标记与
压缩包原清单一致时跳过解压；中断留下的不完整标记必须允许恢复，资料完整性仍由
正式工程校验核对。

公开示例使用简短的存储路径。当前架构资料在所属 Workspace 的 `architecture/`
下按 `model/`、`explore/`、`catalog/` 组织，不叠加原打包目录和 Workspace 名称。
动画的条目身份与存储文件名分别管理，资源 ID、条目标题和实验标识保持稳定。
路径整理必须同步正文链接、数据库引用、文件摘要和工作台应用索引；应用内容变化
后重新计算产物摘要。整理过程只作用于待发布 seed，不移动已安装实例中的资料。
`code/scripts/tfi_compact_example.py` 在独立输出目录生成整理结果，验证后才更新公开 seed。

首次安装才可导入示例数据并执行首次用户初始化。重复启动、升级和老实例迁移不得
重新导入 seed，不得清空历史或生成替代身份。示例安装的阶段进展从空白开始；
主机实例迁移保留已有阶段进展及其他历史。

工作区路径约束同时接受 POSIX、Windows 盘符和 UNC 的绝对路径；相对路径和
文件系统、盘符或共享根目录不可作为 Workspace。登记路径统一以正斜杠保存，
保持导入、身份查找及子目录查询一致。公开 SQL 与运行时表初始化
使用同一约束，旧约束由工作区存储模块在事务内迁移，保留已登记身份和数据。
跨平台发行验证须实际导入完整示例 SQL，覆盖中文、空格和 Windows 换行；
仅校验文件摘要或模拟导入命令不能证明数据库可恢复。导入失败回滚本次事务，
保留数据库及诊断，后续操作不得自动覆盖已有数据库。

Windows 桌面安装成功后自动准备 `example_instance`，完成服务就绪检查后打开
Portal 网页。首次使用通过账号服务生成首管注册邀请；已有账号时直接进入正常
页面，不重置账号或密码。桌面入口只显示暂时的准备进度和失败后的重试、日志入口；
日常双击同一图标自动启动并打开网页，不要求用户选择实例或分别操作启动与打开。
共享平台的多实例能力继续由正式安装命令和管理功能提供。
Windows 安装包携带固定摘要的 PostgreSQL、NATS 和 Node.js 原始归档，
放入共享 `dependencies/native/archives/`；构建时校验摘要和归档结构，
安装时复用同一正式依赖安装入口，核验摘要后解压并探测程序。
缺失归档的下载采用有限重试和持久 `.part` 缓存，支持 HTTP Range；
服务器返回完整响应时重新写入，完整摘要通过后才发布为可安装归档。
依赖声明保留全部已发布功能的 profiles，安装器仅以 `core` 作为启动必需的
Python 包集合；核心环境核验失败阻止启动。其他 profiles 按功能使用时检查，
缺失不阻止安装，也不改写功能声明或删除资料。安装记录区分已验证的核心 profiles、
完整声明和未保证就绪的可选 profiles。共享 Python 环境按核心准备输入复用。
TeX 由用户自行安装，安装器及通用 bootstrap 不下载 TinyTeX、宏包或 TexLab。
Article 资料预检允许缺少工具，实际编译才要求对应编译器和 latexmk，
语言服务单独要求 TexLab；工具加入运行环境后重新检测，无需重建实例。
浏览器、测试、模型等扩展工具不进入首次自动准备，可在需要时显式配置。
依赖引导的阶段进度使用 stderr 中的
`@TFI_PROGRESS` JSON 记录，安装器只转发新增进度，stdout 保持机器接口契约。
启动器显示当前组件、下载大小或阶段，失败时显示错误 JSON 的原因；
完整诊断留在日志，不把调用栈截断后作为用户提示。
安装器捕获原生命令输出时先保留字节，再按 UTF-8、当前系统本地编码依次解码；
无法识别的诊断字节以转义形式保留，不能用解码异常遮蔽程序的实际退出码。
Windows 的本地编码取系统 ANSI 代码页，不随 Python UTF-8 模式改变。
Windows SCM 服务查询与启停、PostgreSQL 初始化、数据库导入、原生依赖探测与 Article 的 TeX/TexLab 检查使用
`management_common.native_output` 的统一输出边界，包括 kpsewhich 返回的中文路径、
TeX 包清单与试编译诊断。非零退出码仍按失败处理，失败诊断存为 UTF-8 日志。
首次安装在创建实例状态前也会查询 SCM，服务不存在只依据退出码 1060 判断，
不能把本地化诊断中的数字当作服务不存在的证据。
Python 控制进程的 stdout 与 stderr 分别捕获：成功 stdout 严格按 UTF-8 解码，
stderr 按原生诊断解码；失败进程保留实际退出码与两路诊断。
依赖引导、依赖 doctor 和安装初始化共用此边界，JSON、SQL 与 seed 文件继续保持严格校验。
安装命令失败时，stderr 输出异常类型及文件、行号、函数名组成的调用栈，
由启动器保存到本地安装日志；不记录局部变量、命令参数和源代码行。
stdout 保持结构化错误 JSON，包含 `error_type`，供启动器显示原因与重试。
Windows 用户态服务依据进程句柄的存活状态与创建时间判断归属，不能把应用退出码
当作进程仍存活的证据。卸载器停止自己管理的实例；只有当前安装路径仍持有公共登记
时才移除快捷方式与卸载登记，避免影响另一个目录中的新安装。
卸载向导默认保留实例数据与缓存；用户可勾选“同时删除实例和缓存”，再次确认后删除当前
安装目录 `instance/` 下的所有实例，包括数据库、账号、对话、资源和示例 seed，
并清理 `.build/` 的准备文件与日志、`dependencies/` 的共享运行时和依赖缓存。
先核对所有实例归属、数据路径以及这两个缓存树，再停止全部实例，调用正式安装器的 `cleanup`。
任何停止失败均不开始删除；实例清理过程中失败则保留平台文件并报告部分完成。
不自动删除外部数据根、链接、junction 或无安装归属记录的未知目录。
尚未生成安装状态、只有 seed 的默认示例允许清理。缓存也拒绝链接与 junction；
停止全部实例后，Python 使用 Windows 扩展路径清理 `.build/` 中的深层准备缓存，
再调用实例清理；缓存清理失败时保留实例数据与平台程序以便诊断和重试。
`.build/windows/` 的启动锁和日志以及 `dependencies/` 的运行时由 NSIS
等待 Python 辅助进程退出、释放文件后删除。
卸载器切换至临时工作目录，最后只尝试移除空安装目录，不递归删除整个安装根目录。
原生安装器和卸载器同时声明 Windows 长路径支持，避免 Python 可生成的长路径无法被原生清理。
文件占用或用户自行添加的文件造成目录残留时，返回失败状态，提示中列出实际残留项目名称，
卸载详情中列出完整顶层路径；没有可枚举子项时说明目录本身可能被占用，不把未知原因判定为成功。
只有安装目录确实移除后才报告完整清理成功；默认保留数据的卸载继续保留缓存与日志。

Windows 构建入口、NSIS 脚本、运行时固定清单与图标统一位于
`code/scripts/windows/`；公开 seed 路径整理使用 `code/scripts/tfi_compact_example.py`。
这些是发行构建素材，实例生命周期继续调用正式安装器，不建立第二套安装服务。
安装、实例管理和 Windows 回归用例位于 `code/tests/cases/`，以源码 docstring 声明
`operations.deployment` 分类及本 Design，沿用 Portal Test Catalog、测试工作台与
`code/pytest.ini` 的 pytest 入口。Windows 实机验收仍单独记录。

## 实例运行与依赖

每个实例具有独立数据库、NATS、服务名称、端口、Socket、配置和五个数据根。
应用只从该实例显式配置取得数据位置，不依靠当前工作目录选择数据。
LAN 访问由实例的监听地址及端口决定，不强制仅允许服务器本机。
实例可复用已经安装且验证可用的 Python、Provider CLI 和其他依赖；
账号与会话状态的位置必须明确，凭据不得进入公共代码或示例 seed。

基础平台只需准备一次。共享模式的自动依赖放在仓库 `dependencies/`：
原生程序按平台、版本及发布摘要复用，Python 环境按依赖声明和 profile 复用，
与实例的 seed 内容无关；跨实例准备使用共享锁。显式传入的现有程序仍可直接使用。
TeX 和浏览器程序同样放在共享依赖目录；账号、浏览器登录状态和编译结果属于实例。
Node 包沿工具既有的模块解析位置安装于共享代码的 `node_modules/`，由 Git 忽略；
打包及共享源码完整性检查统一排除这些已安装依赖和 Python/测试缓存。
每个新实例只初始化自己的配置与数据；已完成初始化的实例使用安装器
`start --root <实例目录>`、`stop --root <实例目录>`、`status --root <实例目录>`。
这些生命周期操作不得再次导入 seed。不同端口的实例可以同时运行；由同一业务
数据库克隆的迁移实例必须完成切换核验，不能并发执行复制来的待办任务。
迁移记录中 `business_execution_allowed=false` 时，实例启动和业务服务入口拒绝执行。

数据库结构由共享迁移定义管理；不同实例分别记录已应用迁移。
同一共享目录更新前应检查所有使用者的代码及 schema 兼容性，必要时安排共同停机。
现有独立工程的整体替换升级不得用于共享目录。不得因升级一个实例而删除或
覆盖公共代码，也不得将示例 SQL 当作升级迁移。

## 管理界面中的实例控制

Portal 管理在网络设置之后提供「Portal 实例」。仅当前站点的 Portal 管理员可以
读取同一平台的已安装实例列表和提交启动、关闭请求；权限系统关闭也不放宽此限制。
服务器只接受实例名称和 start/stop，不接受客户端指定路径、命令、删除或安装操作。
目录发现限定于平台 `instance/` 的直接子目录，拒绝软链接和绑定其他代码目录的实例。
示例 seed 尚未安装时不作为可运行实例列出。

实例状态根据安装器所属服务读取，区分运行、部分服务运行、关闭和无法读取。
安装或迁移未完成的实例不可启动；关闭保留数据库、账号、对话和其他持久内容。
网页服务运行时展示监听地址对应的主机 IP 与端口，不把通配地址当成可访问网址。
本机限定监听会明确标注；显示地址不意味着已经验证客户端到主机的网络连通性。

生命周期规则仍由安装器唯一维护。界面通过独立控制作业调用安装器 start/stop，
使用操作系统服务所有者环境，不能继承当前实例的 HOME、数据库连接或 Socket 配置。
Linux 作业使用独立 systemd 用户单元；关闭当前网页所在实例时，作业仍可完成。
作业记录属于目标实例 runtime，保留失败信息并拒绝同时接受重复操作。
关闭当前实例前提示连接将断开；全部实例关闭后需从服务器安装器或桌面启动器启动。

## 主机迁移与切换

迁移采用复制、校验、切换顺序，源文件和原数据库保留作为回退依据。
数据库必须使用 PostgreSQL 一致性备份，不能复制正在写入的数据库文件冒充备份。
保留对象 ID、用户密码哈希、TOTP/会话密钥、Provider 账号与会话、Resident 对话、
Workspace、Device 凭据及授权关系。路径迁移仅更正配置与结构化绑定，
不对历史消息正文做任意字符串替换。

预复制期间源站继续运行；最终切换需要停止或隔离源站写入，补齐文件增量并获得
与文件一致的最终数据库状态。新旧站不得同时消费同一业务任务、定时器或外部入口。
进程、Socket 和锁不是可移植状态；应从持久任务与会话记录恢复。

停用 RoboLab 与语义向量搜索表示不启动对应功能，不授权删除原始历史数据。
发现不可读取文件、无法移植的正在运行进程、外部设备身份或浏览器认证来源限制时，
必须记录实际差异，解决或交用户决定，不得标记为完全等价。

## 验收与回退

核验至少包括：

- 用户、Resident、对话、消息及关键资源的 ID、数量和内容校验；
- 原用户登录、原 Resident 历史读取与实际续聊；
- Provider 账号、已有 Workspace、Paper/Article、Device 连接与资源访问；
- 新端口从 LAN 访问，源站与新站不存在重复任务消费；
- 私有实例文件 Git 忽略，公共代码没有运行时写入，示例 seed 未被实例污染。

仅 HTTP 健康、数据库行数或复制成功不等价于完成迁移。
验收失败时停止新实例的业务执行，按切换记录恢复源站；切换后的新业务数据应先
保存并处理，不能直接回退旧快照而丢弃新输入。迁移记录与数据库备份保持私有。
