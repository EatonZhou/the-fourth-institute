# Portal Overlay、表单与 Toolbar 通用交互

Portal 页面在业务内容周围反复用到同一批交互：弹出菜单、确认框、结果通知、搜索框、筛选条件摘要和工具栏。如果每个页面各自处理“哪个浮层在最上面”“按 Esc 关哪一个”“焦点回到哪里”“窄屏放不下的按钮去哪里”，就会出现两个浮层被同时关闭、对话框被页面遮住、重要按钮被挤出屏幕这类问题。本文说明 Portal 用哪几个共享前端模块统一处理这些交互。

对用户，这些模块保证：最上层的界面先响应，对话框中的键盘焦点不会跑到页面后面，每个操作都有结果通知，当前筛选条件始终可见，窄屏上仍能找到重要动作。对页面开发者，它们提供统一的打开、关闭和销毁方式。字段的值、请求发给谁、权限判断和成功后怎样更新数据，仍由业务页面负责。组件体系的总体结构和响应式模式见 decision_741b04821171。

## 先认识可见对象

| 名称 | 用户看到的是什么 |
|---|---|
| 浮层（Overlay） | 暂时盖在业务内容上方的界面的统称，包括下面的弹出面板、对话框和通知 |
| 弹出面板（Popover） | 贴着按钮或鼠标位置展开的小面板，例如菜单和筛选面板 |
| 对话框（Dialog） | 要求用户集中处理的窗口，用来确认、输入或编辑 |
| 背景 | 对话框或弹出面板外侧、隔开页面内容的区域；有些浮层允许点击背景关闭 |
| 通知（Toast） | 页面角落短暂出现的操作结果，不抢键盘焦点，也不挡住下方的点击；带复制和关闭按钮，失败时还可以带“重试” |
| 忙碌按钮 | 请求进行中被禁用、显示进行状态的原按钮，结束后恢复原样 |
| 修改动作（Mutation） | 一次会改变服务端数据或页面业务状态的异步操作，例如保存、删除 |
| 搜索框 | 带搜索图标、可读标签和清除按钮的文本输入框 |
| 筛选摘要 | 用一排紧凑标签（chip）列出当前生效的筛选条件的区域 |
| 工具栏（Toolbar） | 水平排列页面动作的按钮条；空间不够时把次要动作收进“更多操作”菜单，或允许横向滚动、换行 |
| Board 工具栏 | 列表页和卡片页用的工具栏，由页面在 HTML 中声明搜索、筛选和动作，模块自动组装 |

## 设计点

### 多个浮层只由最上层响应

- **浮层按固定的层级排列，同一层中最近打开的在上面。** 层级从低到高是：页面中固定的粘附内容、弹出面板、对话框、通知、关键提示（例如 Web 重启提示）。
- **按 Esc 只关闭最上层、且允许用 Esc 关闭的浮层。** 这次按键不会再传给下层浮层或页面。
- **只有在背景上完整地点一次鼠标左键，才可能关闭浮层。** 按下和松开都在背景上、移动不超过 6 像素、浮层在最上层、且它允许点击背景关闭时才关闭，所以在输入框里拖选文字拖到背景外不会误关。
- **浮层始终留在可视区域内。** 按钮或鼠标附近放不下时，自动换到另一侧，并限制浮层的最大宽高。

### 弹出面板和对话框保持位置与焦点

- **打开和关闭弹出面板时，触发按钮同步显示展开状态。** 按钮带菜单语义和 `aria-expanded`；已经打开时再次打开只重新定位并提到最上层。
- **用 Esc 关闭弹出面板后，焦点回到触发按钮。** 点击外部关闭时不强制移动焦点。
- **消息等大区域触发的右键菜单，仅菜单面板内部属于保留打开的区域。** 调用方通过 `closeOnTrigger: true` 声明点击触发区域或定位锚点也属于外部点击，由共享 Popover 的捕获阶段监听统一关闭；菜单内部点击不关闭，继续交给菜单操作。普通按钮 Popover 默认保留触发按钮与锚点的内部点击语义，便于调用方处理再次点击按钮的开关行为。
- **对话框打开后，键盘焦点留在对话框内。** 按 Tab 在最上层对话框的控件之间循环；没有可聚焦的控件时聚焦对话框本身。
- **对话框成功关闭时同步恢复页面和焦点。** 页面恢复滚动，焦点默认回到打开前的元素，随后即可销毁对话框。关闭流程已经把焦点交给其他控件或其他浮层时，保留新的焦点；关闭后的输入不再被旧对话框移动焦点。
- **关闭有未保存修改的对话框时，只询问一次。** 系统弹出“放弃未保存的修改？”确认框；连续多次按 Esc 或点关闭，也只出现一个确认框。用户选择“放弃修改”后对话框关闭。

### 每个修改动作都有完整反馈

- **同一个动作正在执行时，重复触发不会重复提交。** 页面给动作一个标识；标识相同的动作在执行中再次触发，共用正在进行的那一次。
- **动作开始、成功和失败都有反馈。** 执行中按钮进入忙碌状态（默认文案“处理中…”）；成功时可以显示成功通知；失败时显示错误通知。
- **失败通知默认带“重试”按钮。** 点击后先移除这条通知，再用相同设置重新执行；页面也可以关闭默认的错误通知或重试按钮。
- **动作结束后按钮总会恢复。** 进入忙碌前已经被禁用的按钮，结束后仍然禁用。
- **操作文案按统一格式生成。** 成功为“<动作>“<对象>”成功。”，失败为“<动作>失败：<原因>”，确认为“确定要<动作>“<对象>”吗？”；常用动作名有刷新、删除、取消、保存。页面切走或关闭时被浏览器中断的请求不弹错误通知。

### 搜索、筛选和窄屏工具栏

- **点击搜索框的清除按钮，等同于用户把内容删光。** 输入框清空后依次触发 input 和 change 事件，焦点回到输入框，页面照常收到变化。
- **筛选摘要实时列出当前条件。** 默认标题为“当前筛选”；筛选已生效但没有可列出的具体条件时显示“已应用”；清除某个条件后重新计算摘要。
- **工具栏空间不够时，先收起次要动作。** 在“菜单”模式下，优先级低的动作先移进“更多操作”菜单，同一优先级中排在后面的先移；关键动作永远不移。
- **“更多操作”菜单只在用户真正执行了动作后才关闭。** 点击菜单中的输入控件或不可用的动作时，菜单保持打开。
- **工具栏被销毁时，把仍属于它的按钮还给页面。** 按钮回到原来的位置，“更多操作”按钮和菜单被移除；页面已经删除或移到别处的按钮不会被放回。工具栏所在区域从页面上移除时自动销毁。

### 复制文本

- **页面复制文本都经过同一个复制入口，在 HTTP 内网地址上也能用。** 浏览器支持剪贴板接口时直接写入；接口不存在或被拒绝时，改用临时文本框执行复制。
- **复制内容保持原样。** 缩进、空格和换行都保留；临时文本框用完即删，焦点回到原处，页面不滚动。
- **只有真正复制成功，页面才提示“已复制”。** 两种方式都失败时提示“无法自动复制，请手动选择并复制。”；要复制的内容为空时提示“<名称> 暂不可用。”。
- 使用这个入口的地方包括：Repo 的 ID、提交 SHA、分支、文件路径、文件内容、Remote 和检出路径，资源 ID，账号恢复码，聊天中的单条消息、全部回复和附件路径。

### 弹窗中的表单布局

- **普通弹窗表单的标题、字段和操作按钮对齐在同一条左右边线上。** 弹窗内容边距在桌面为 16px，宽度不超过 680px 的窄屏为 12px。表单内的底部按钮区只保留与上方内容的间距，不再加水平边距。
- **短表单按内容决定高度。** 即使在窄屏上也不纵向撑满屏幕，多余空间不会拉高下拉框或加大行距。
- **长表单在弹窗内滚动。** 弹窗有最大高度，字段和底部按钮都能滚动到。
- 工作台、编辑器等需要占满空间的面板、页面内嵌的表单，以及节点菜单中的设置卡片，按各自的布局规则排列，不使用上面的自然高度规则。

## 实现：五个共享模块

| 模块 | 全局对象 | 负责什么 |
|---|---|---|
| 浮层协调 | `PortalOverlay` | 浮层层级、Esc 与背景点击、定位、弹出面板的开关 |
| 通用反馈 | `PortalUI` | 对话框控制器、确认框、输入框、忙碌按钮、通知、修改动作、复制文本、操作文案 |
| 表单增强 | `PortalFormControls` | 筛选下拉、筛选摘要、可清除输入框、搜索框 |
| 工具栏编排 | `PortalToolbar` | 动作优先级、“更多操作”菜单、滚动与换行、布局观察和销毁 |
| Board 适配 | `PortalBoardToolbar` | 读取页面声明的 Board 工具栏，把搜索、筛选和动作交给前三个模块 |

一次修改动作的过程：页面把真正发请求的函数交给 `PortalUI.runMutation`。它登记动作标识，把按钮设为忙碌并通知页面“执行中”，然后等待请求完成；成功时通知页面“成功”并显示成功通知，失败时通知页面“失败”并显示带重试的错误通知；最后恢复按钮、调用页面的收尾函数，并清除这次动作的登记。`PortalOverlay` 只负责通知和对话框的层级，不关心业务是否成功。

## 接口：浮层与弹出面板

### 加载与就绪

`portal_overlay.js` 在公开 `PortalOverlay` 接口后发出 `portal:overlay-ready` 事件；已加载模块重新安装窗口监听时也发出该事件。消费方可以立即使用已存在的接口，或在事件到达后初始化依赖浮层的控件，并自行保证挂载幂等。

主题外观在早期应用。若 Overlay 脚本加载失败或尚未就绪，主题菜单暂缓创建，已保存的主题和重启通知初始化继续执行。Overlay 后续就绪且文档解析完成后，同页挂载一个可用菜单；重复就绪通知不会创建重复入口。这一通知本身不重试脚本下载。

### 浮层登记

- 层级名称从低到高为 `sticky`、`popover`、`dialog`、`toast`、`critical`；未知名称按 `dialog` 处理。
- 隐藏的、已经离开页面的、以及没有打开的原生 `<dialog>` 不参与排序。无效元素登记时返回 `null`；同一元素重复登记只更新原记录。
- 每次层级变化时，模块在元素上写入层级、顺序和是否最上层，在页面根元素上写入活动浮层数量，并发出 `portal:overlaychange` 事件（带数量和最上层元素）。
- 浮层位于局部层叠上下文中时，模块同时提升它的宿主，避免业务区域的 `z-index` 压住高层浮层。
- 登记返回的控制器提供 `activate()`、`deactivate()`、`update()`、`destroy()`；`destroy()` 清除写入的属性、宿主提升和监听。
- 原生 `<dialog>` 的浏览器取消事件总被拦截，只有它在最上层且允许 Esc 关闭时，才请求页面关闭它。

### 定位

- `positionAnchored` 把面板贴着按钮放置，默认在按钮下方、右端对齐；距视口边缘至少 8 像素，与按钮间隔 6 像素。按钮无效或不可见时返回 `null`。
- 上下空间不够时换到另一侧，再把位置限制在视口内，并把最大宽高限制在可用空间内，至少留 120 像素。
- `positionAtPoint` 把面板放在鼠标位置附近，默认在鼠标上方、水平居中，上方放不下时放到下方；边距、间隔和尺寸限制与上面相同。

### 三种弹出面板

- **贴按钮的面板**（`bindPopover`）：需要有效的触发按钮和面板，否则返回 `null`。默认允许 Esc 和点击外部关闭，并给按钮加上 `aria-haspopup="menu"`、同步 `aria-expanded`。设置 `portal: true` 时，面板打开期间移到 `<body>` 下，关闭后放回原处。窗口尺寸变化或面板外滚动时重新定位；触发按钮离开页面时自动关闭。嵌套的面板排在父浮层之上。
- **动态面板**（`bindDynamicPopover`）：每次打开时重新查找触发按钮和面板，适合按钮会被重新渲染的列表；旧按钮已经离开页面时，焦点回到新的按钮。打开和关闭可以通知页面，销毁时关闭并解除绑定。
- **浮动面板**（`bindFloatingPopover`）：面板默认移到 `<body>` 下，允许点击外部关闭，随滚动重新定位；设置 `closeOnScroll: true` 时改为滚动即关闭。Home 的账号详情就是这种面板。

## 接口：对话框、通知与修改动作

### 对话框控制器

- `createDialogController(options)` 需要有效的弹窗元素，并要求 `PortalOverlay` 已经加载。打开时给 `<body>` 加 `modalOpen` 类、给弹窗加 `open` 类（都可配置）。
- `beforeOpen` 或 `beforeClose` 返回 `false` 时阻止打开或关闭；只识别同步返回值。
- 提供 `dirty` 函数时，关闭前检查是否有未保存修改。有修改时调用 `confirmDiscard`（默认为上面的“放弃未保存的修改？”确认框）；等待回答期间的其他关闭请求被忽略，用户确认后强制关闭。
- 原生 `<dialog>` 用 `showModal()` 和 `close()` 开关；普通元素用 `hidden` 属性和类名开关。元素原本带 `aria-hidden` 时同步更新。
- 打开时记住原焦点，在下一帧确认对话框仍打开且位于最上层后，聚焦指定目标或第一个可聚焦控件。
- 对话框控制器持有打开时的初始聚焦任务；每次开关和销毁都取消尚未执行的任务。关闭在返回前同步恢复焦点：原目标仍在页面中，当前焦点留在关闭的对话框内、已退回页面主体或停在已隐藏的元素上（例如刚确认的“放弃未保存的修改？”确认框按钮），并且原目标位于剩余最上层浮层内（或没有其他浮层）时，聚焦原目标。关闭回调已选中的其他可见控件保持焦点。
- `open()` 和 `close()` 返回是否真的改变了状态；`destroy()` 解除键盘和浮层绑定，恢复页面滚动，清除可见状态。

### 确认框与输入框

- `PortalUI.confirm(options)` 显示 Portal 自己的确认框，返回 `true`（确认）或 `false`（取消、Esc 或点击背景）。选项包括 `title`（默认“请确认”）、`message`、`description`、`metadata`（逐行列出的标签和值）、`cancelLabel`（默认“取消”）、`confirmLabel`（默认“确认”）和 `tone`（`primary`、`danger` 或 `warning`）。多个确认请求依次排队显示。
- `PortalUI.confirmAction(action, target, options)` 按统一文案生成确认框；动作为删除时默认使用 `danger` 样式。
- 确认框的正文和说明完整展示长标题、路径与连续字符串，超出当前宽度时折行，不在容器边界截断。
- `PortalUI.prompt(options)` 显示输入框，确认时返回输入值，取消时返回 `null`；同样排队显示。

### 忙碌按钮与通知

- `setButtonBusy(button, busy, label)` 第一次进入忙碌时保存按钮的内容、禁用状态、提示和无障碍标签，然后设置 `aria-busy="true"` 并禁用；退出时恢复保存的状态。重复进入忙碌不会覆盖最初保存的状态。
- 忙碌文案和图标分开显示，遵守按钮自身的响应式文字布局：纯图标按钮和窄工具栏按钮保留图标和原来的宽度，进行状态通过悬停提示和无障碍标签给出；文字按钮显示进行中的文案。切换状态时文字不溢出，也不挤压相邻按钮。
- `toast(message, kind, options)` 显示通知。通知区是一个实时播报区域：错误通知使用 `role="alert"`，其他通知使用 `role="status"`。`options.key` 相同的通知原地更新；`options.retry` 添加重试按钮（文字可用 `retryLabel` 修改）；每条通知都有关闭按钮，有文字的通知还在文字后面带复制图标按钮：点击后经复制入口把通知当前显示的文字写入剪贴板，复制成功时图标变为对勾、提示变为“已复制”，通知不关闭，计时照常。错误通知默认显示 7 秒，其他 3.6 秒；`duration` 小于等于 0 时一直显示。通知本体不接收指针事件，只有复制、“重试”和关闭按钮可以点击，所以被通知盖住的页面控件仍然可以操作。

### 修改动作

- `runMutation(options)` 必须提供 `run` 函数，否则返回失败。`key` 相同的动作在执行中共用同一个 Promise。
- 可选项：`button` 与 `busyLabel`（忙碌按钮）、`onStateChange`（收到 `running`、`success` 或 `error`）、`onSuccess`、`onError`、`onFinally`、`successMessage`、`errorMessage`（字符串或函数）、`action`（生成默认错误文案的动作名）、`notifyError: false`（不显示错误通知）、`retry`（`false` 去掉重试，函数则替换默认重试）、`retryLabel`、`rethrow: true`（失败时抛出异常，默认返回 `null`）。

### 其他工具

`PortalUI` 还提供 `errorMessage`、`successMessage`、`confirmMessage`、`actionLabel`（统一文案）、`alertError`（显示错误通知，但忽略页面离开时被中断的请求）、`isNavigationFetchError`、`formatDateTime`、`formatBytes`、`clampNumber`、`preserveScrollPosition`（重画时保留滚动位置）和 `loadCurrentUser`（读取当前用户并填入页面上的用户名位置）。

## 接口：表单与工具栏

### 表单增强

- `bindFilterDropdown` 需要有效的按钮和面板，无效时返回一个空的释放函数。默认在按钮下方打开，支持 Esc 和点击外部关闭，并同步类名、ARIA 状态和 `hidden`。返回的释放函数还带 `open`、`close`、`toggle`、`isOpen`。
- `bindFilterSummary` 的条目可以是简单值或对象；“是否生效”可以是布尔值或函数。清除操作可以返回 Promise，完成后在下一个微任务重新计算摘要。无效的根元素返回空的释放函数。
- 可清除输入框自动增强 `text` 和 `search` 类型的输入框（禁用的不增强）：`search` 类型总是增强；`text` 类型在它的名称、标签或所在区域看起来是搜索或筛选框时增强（中英文关键词，例如 search、filter、搜索、筛选、关键词）。`data-portal-clearable="0"` 或 `"1"` 可以强制关闭或打开。包装元素保留输入框原来的弹性布局、宽度和对齐。
- 搜索框的宿主必须包含一个输入框。同一宿主重复挂载返回原实例；没有声明类型时设为 `search`，并补上可读标签、图标和清除按钮。搜索框通过 `PortalUIPrimitives.registerEnhancer` 接入共享插入发现机制；全页扫描与监听的唯一归属见 decision_741b04821171，表单模块不另建全页观察器。

### 工具栏

- 每个根元素只创建一个控制器，无效元素返回 `null`。页面中带 `data-portal-toolbar` 的元素自动挂载，后来插入的也会挂载。
- 动作用 `data-portal-toolbar-item` 标记，用 `data-portal-toolbar-priority` 声明优先级：`low`、`normal`、`high`、`critical` 分别对应 25、50、75、100，也可以直接写数字，默认 `normal`。
- 溢出方式有三种：`menu` 把低优先级动作移进“更多操作”菜单，保持它们原来的相对顺序，不溢出时隐藏“更多操作”按钮；`scroll` 和 `wrap` 只标记是否溢出，由样式滚动或换行，不移动动作。每次重新布局只移动位置需要改变的动作；仍在原位的动作不重新插入，其中正获得焦点的控件（例如刚按 Esc 关闭菜单后回到的触发按钮）不会因布局失去焦点。
- 控制器观察根元素和父元素的尺寸，以及动作的隐藏、样式、`aria-busy`、禁用状态和增删。`refresh()` 合并到下一次布局；每次布局先确认动作仍在这个工具栏和原来的锚点位置，再发现新增的动作。页面从外部移除的动作不再被观察，窄屏变回宽屏时也不会被重新插入。
- `destroy()` 取消尚未执行的布局，断开观察和“更多操作”菜单，把仍属于这个工具栏的动作放回原位，删除锚点、“更多操作”按钮和菜单。销毁后旧的回调不会再改动页面。已经离开页面的工具栏由文档级挂载器按同样的方式释放，重新插入时创建新实例。

### Board 工具栏

- 页面中带 `data-portal-board-toolbar` 的元素（包括后来插入的）自动挂载。搜索区域交给搜索框模块，动作交给工具栏模块。
- 没有标为主要（`is-primary`）的动作默认使用低调样式；筛选动作自动带筛选图标；刷新动作自动带刷新图标、提示和可读名称。带 `data-portal-board-filter-auto` 的筛选按钮自动绑定筛选下拉，同一个按钮只绑定一次。
- 控制器公开 `element`、`search`、`actions` 和 `refresh()`。
- Board 工具栏没有销毁方法，只用于长期存在的页面。会被卸载的工作台要使用它，需要先补上释放观察器和子组件的方法。

## 已知限制

- 对话框的 `beforeOpen` 与 `beforeClose` 只支持同步返回值。要支持异步判断，需要先规定并发关闭和焦点恢复的顺序。
- Board 工具栏缺少销毁方法（见上文）。
