# Portal 前端组件系统、命令与生命周期

Portal 的各个页面反复出现同一批可见对象：图标、按钮、输入框、状态标记、卡片、列表、详情区域、工具栏，以及由多个面板组成的工作台。Portal 前端组件系统为它们提供共同的样式、交互规则和释放方式：用户在不同页面得到一致的反馈，页面开发者组合已有的能力，而不是各自重写。

本文说明组件系统的层次：从设计变量和基础控件，到命令、共享选择、面板包、工作台和页面内导航；每一层认识什么、状态归谁、页面怎样接入。它也规定跨页面复用一项业务能力时，谁负责定义它的含义。Resource、Resident、预览等业务内容由各自的领域组件解释；页面选择要显示的对象、组合组件，并通过领域组件公开的接口执行业务动作。

相邻 Design：面板包与工作台的精确协议见 decision_538e155e1102；浮层、表单和工具栏的交互见 decision_b3022c27d22f；编辑区的打开规则见 decision_79de71d9890d；浏览器请求客户端见 decision_daba6706a788。

## 先认识可见对象和技术概念

| 概念 | 用户看到什么，开发者用它做什么 |
|---|---|
| 设计变量 | 一组有名字的颜色、间距、字体、圆角、控件高度、内容宽度、阴影和层级值（源码中称 design token）。页面按名字使用，得到统一的尺度 |
| 图标 | 按钮或文字旁的示意图形。名字有效时显示安全的 SVG，名字未知时不显示任何图形 |
| 按钮 | 执行动作或跳转的控件，有主要、危险、警告、低调、激活、紧凑和纯图标几种外观 |
| 字段 | 带标签的输入框、下拉框或多行文本框 |
| 状态标记 | 用颜色和文字表示对象状态的小标签；颜色的类别称为色调（tone） |
| 异步状态 | 内容还在加载、结果为空或读取失败时，占据内容区域的提示 |
| 卡片与列表 | 摘要显示多个业务对象的容器。组件系统提供外观，显示哪些字段、怎样排序由页面决定 |
| 详情区域 | 用户选中一项后查看正文、属性或相关内容的较大区域 |
| 命令 | 可以由快捷键或页面按钮触发的一项动作；全局资源搜索只登记打开入口，不展示命令结果 |
| 命令作用域 | 一组命令和它们所用上下文的独立空间。不同工作台可以各有同名的局部命令 |
| 工作台（Workbench） | 在一个页面区域中组合多个可开关的面板、布局、命令和共享选择的容器 |
| 面板 | 工作台中的一个功能区域，例如导航、编辑区或预览；有稳定的 ID 和自己的生命周期 |
| 面板包（Panel Package） | 一种面板的完整说明和创建函数，规定显示、尺寸、实例数量、共享选择、命令和状态保存方式 |
| 共享选择（Workbench Context） | 工作台中各面板协作所需的当前选择，例如当前对话、当前文档，按通道（channel）分组 |
| 页面内导航 | 在同一个页面中切换侧栏视图的控件，不负责全站主导航 |
| 生命周期 | 组件从创建、连接、恢复、显示、隐藏到销毁的顺序，以及其中一步出错时怎样隔离 |

## 业务能力由谁定义、怎样复用

### 按业务职责划分复用边界

**业务能力**是围绕一种业务对象的一组稳定操作，例如读取某个 Resident 的对话、发送消息、引用内容和管理会话。每种能力有一个负责方，由它规定这些操作的含义、状态限制、成功结果和失败结果。组件按这种职责划分边界；页面位置只决定能力显示在哪里。

- **同一种含义只由一个负责方定义。** 跨页面复用时，行为、状态限制和接口一起复用；修正一个行为时，所有入口通过同一份实现得到修正。只有外观相似、业务含义不同的对象才各自实现。
- **一起变化的规则放在一起，各自变化的职责分开封装。** 上传校验、消息渲染、会话状态和工作台编排可以各有模块，通过稳定接口协作；一个负责方不要求把所有代码写进同一个大文件。
- **调用方只依赖公开接口。** 页面和其他组件通过输入参数、命令、事件和能力声明使用业务能力，不访问私有 DOM、内部状态或实现细节。底层传输和 Provider 适配可以改变，上层业务含义保持不变。

### 以 Resident 对话为例

Resident 是长期存在的 Agent 身份；Chat Workspace 是用户与 Resident 对话的共享组件。Article、Society、Paper 等页面作为宿主，提供放置组件的位置和业务上下文。Society 页面同样使用这个共享组件，没有另一套供其他页面复制的对话实现。

| 负责方 | 负责什么 | 交给别人什么 |
|---|---|---|
| 页面宿主 | 选择 Resident，安排容器和布局，准备页面的业务上下文，连接公开的面板协作接口 | 消息发送、图片处理、引用显示、会话菜单及其状态规则交给共享对话组件和领域服务 |
| 共享 Chat Workspace | 统一的头部、消息与输入区、附件和引用交互、命令入口、加载与错误提示；管理实例自己的临时状态和订阅 | 身份、权限、对话记录和会话状态由领域服务决定；打开资源交给统一打开协议 |
| Resident 领域服务 | Resident 与 Lineage 的归属、权限判断、会话与消息的真实状态、输入和控制操作的结果 | 页面位置和视觉布局交给宿主和共享组件；底层执行交给对应的适配层 |

宿主先确定目标 Resident 并准备要附带的上下文，共享对话组件按公开接口绑定这个 Resident 的数据和可用操作。用户发送后，组件按服务端的确认更新界面；失败时显示错误并保留可以恢复的输入。页面上下文使用统一的引用或约定的初始输入（例如 Article 的文件位置和首轮任务说明），不另建一种发送协议或无法管理的引用控件。同一个 Resident 的身份、Lineage 归属和操作权限不随宿主页面变化。对话的数据、草稿、交互和运行状态规则见 decision_f560803947c6。

### 完整封装与允许的差异

- **组件同时负责交互和内部呈现。** 封装包括脚本行为、DOM 结构、CSS、排版、状态处理、接口、错误提示和生命周期。脚本已经共享、但内部样式被页面改写，仍然算封装不完整。
- **宿主只控制组件的外部布局。** 页面决定位置、可用宽高和面板组合，通过声明的参数或主题变量配置组件；不用页面 ID、私有选择器或不受限制的 Markdown 样式改变组件内部的排版和行为。
- **相同条件下表现一致。** 相同的 Resident、操作者、权限、会话状态、输入、能力和可用空间，得到相同的对话行为和显示。差异只来自这些明确的条件，以及共享的主题、语言和无障碍偏好。
- **响应式布局按实际可用空间调整。** 例如对话头部的副标题有空间时与标题同行，空间不够时换行，变宽后恢复同行；各页面不自定换行规则。
- **状态按归属保存。** 滚动位置、焦点和临时的忙碌状态属于组件实例；草稿按共享规则以所有者和对话标识保存；消息、权限和会话状态以领域服务为准。同一个 Resident 的多个实例互不干扰临时状态，也不用过时的快照覆盖较新的数据。
- **失败由负责方统一处理。** 加载、上传、发送、权限不足和能力缺失都有明确提示，并限制影响范围；不因某个页面调用失败而改用其他身份、跳过校验或悄悄换成行为不同的页面私有实现。

### 怎样检验架构是否健康

- **看一次职责变化要改几处。** 修正图片上传规则，应只改上传负责方和它的接口测试；调整 Article 的初始上下文，应只改上下文准备逻辑；在新页面放置已有的对话组件，主要是增加组合和绑定。一个单一职责的修正反复波及多个无关页面时，要检查是否存在重复实现、接口泄漏或样式越界。
- **接口不变时，调用方不用改。** 底层实现替换后仍满足原接口；业务含义真的变化时，显式更新接口并迁移调用方，不积累按页面名称判断的兼容分支。
- **行为正确和架构健康分别检验。** 行为测试检查发送、看图、引用、菜单、权限和恢复的结果；架构检查验证负责方唯一、依赖方向、样式作用范围、状态边界和释放。一个页面的测试通过不能代替另一项检验。
- **跨宿主检查覆盖真实组合。** 在相同的输入和权限下，放在实际页面样式和容器中检查共享行为，并检查宽窄切换和失败情况；优先断言可见内容、可操作性、自然换行和不溢出，不只靠固定像素的截图。
- **可用能力与已接入范围分开记录。** 共享层提供了某个接口，不等于每个宿主都接入了。以宿主的实际接入代码和验证记录说明使用者、已验证行为与缺口；“任意页面都能打开任意 Resident 的对话”是可组合性要求，具体入口要接入并验证后才能宣称支持。

## 设计点

### 用户可以依赖的共同体验

- **相同的动作使用相同的外观和状态提示。** 按钮的禁用与忙碌（`aria-busy`）、状态标记、加载、空结果、错误、通知、工具栏和详情区域都使用公共样式。
- **文本放进组件生成的 HTML 前先转义。** 标签、值、占位文字和选项中的普通文字不会变成可执行的标记。
- **图标随页面变化自动更新。** 后插入页面的图标位置、图标名字的修改和清空都会被处理；名字无效时移除旧图标。
- **窄屏使用统一的响应模式。** 视口宽度不超过 820 像素时进入移动模式，详情区域和工作台按公共规则调整；页面不各自判断这个断点。具有文件、正文、对话等多个区域的详情面板，还按面板自身可用宽度调整：宽度不超过 1040 像素时使用公共区域切换栏，默认显示正文，文件与对话仍可切换访问；恢复充足宽度后显示多栏。横屏和桌面内的窄弹窗同样遵循此规则，Chat 加载不能挤压或覆盖正文。
- **用户选择减少动态效果时，共享动画随之减少。** 公共样式按浏览器的“减少动态效果”设置统一缩短或去掉过渡与动画。
- **一个面板出错不会拖垮整个工作台。** 某个面板在连接、恢复、接收共享选择、显示或隐藏时出错，其他面板照常可用。
- **无效或格式不符的保存状态不会交给面板。** 工作台只恢复当前布局格式下的合法面板，面板只收到自己类型、且格式版本完全相同的状态。

### 页面开发者可以依赖的组合规则

- **所有页面用同一套设计变量。** 间距档位为 4、8、12、16、20、24 像素（`--portal-space-1` 至 `--portal-space-6`），控件高度、圆角、最大内容宽度、阴影和层级也统一定义。
- **页面样式只管页面布局和业务显示。** `portal_design_system.css`、`portal_components.css` 和 `portal_workbench.css` 负责共享组件的内部结构；架构测试阻止页面样式覆盖受保护的内部选择器。
- **基础控件按语义生成。** 有链接地址的按钮生成链接，没有的生成 `type="button"` 的按钮；字段支持输入框、下拉框和多行文本框。
- **每个命令作用域独立登记，命令的可见和可用实时计算。** 同一作用域内命令 ID 唯一，作用域销毁时命令一起释放；当前选择或权限变化后，列表和快捷键按新的上下文计算。执行中的命令不会被重复执行。
- **面板只收到它声明过的共享选择通道。** 其他领域的选择不会传给无关面板；值没有真正改变时不通知。
- **一种面板先登记面板包，再创建实例。** 实例引用已登记的类型和稳定的面板 ID，不能替换包的创建函数；包声明是否允许同时打开多个实例。
- **工作台按固定顺序让面板就绪。** 先连接，再恢复格式相符的状态，然后发送过滤后的共享选择；可见的面板收到“显示”，不可见的收到“隐藏”。
- **隐藏的面板重新显示时有唯一的回退规则。** 原来的位置还在时放回原处；原位置已经消失时，如果当前宽度放不下现有布局加上这个面板的最小宽度，就放进活动标签组，放得下就在右侧新建一个水平分栏；没有任何布局时新建一个标签组。结果写进工作台布局，之后不再重新推测。
- **工作台销毁时，一起清理命令作用域、共享选择的订阅和所有面板。**

## 实现：从基础到页面

```text
设计变量和共享 CSS
  → 图标、按钮、字段、状态标记和异步状态
  → 命令注册表与共享选择
  → 面板包及其领域面板
  → 工作台编排与页面内导航
  → 业务页面组合卡片、列表、详情和局部操作
```

| 组件 | 全局对象 | 负责什么 |
|---|---|---|
| 基础构造 | `PortalUIPrimitives` | 文本转义、元素查找、静态资源地址、图标、状态标记、按钮、字段、异步状态、随机 ID、页面插入增强注册表 |
| 响应模式 | `PortalResponsive` | 820 像素断点、根元素标记、快照和订阅 |
| 命令注册表 | `PortalCommandRegistry` | 作用域、命令信息、上下文、排序、快捷键、防重复执行 |
| 共享选择 | `PortalWorkbenchContext` | 共享选择的读写、修订号和按通道订阅 |
| 工作台 | `PortalWorkbench` | 面板包登记、面板实例、布局、命令、共享选择传递、状态恢复和销毁 |
| 页面内导航 | `PortalNavigation` | 同一页面内侧栏视图的切换与恢复，以及对应的面板包 |
| 通用反馈 | `PortalUI` | 对话框、通知、修改动作、复制、日期与字节格式化（decision_b3022c27d22f） |

每一类变化在对应的组件中处理：图标画法改基础构造，命令权限改命令注册表，面板状态格式改对应的面板包，业务字段改领域面板和页面。

### 基础构造与响应模式

- `escapeHtml` 是 HTML 文本转义的唯一实现，页面的同名函数只能调用它。
- `elementOf` 把 Element、元素 id 或选择器解析为页面中的元素（其他值得到 `null`）；`staticAssetUrl` 给按需加载的脚本和样式加上页面的发布标记（`portal_v`），使它们与页面同一版本。浮层、对话框、表单控件、详情外壳、资源标题、看板外壳、导航、设置和 Chat 都调用这两项，不保留自己的副本；加载这些模块的页面都加载 `portal_ui_primitives.js`。
- `loadAsset(path, { ready })` 是按需加载脚本和样式的唯一入口：每个文件只插入一个带发布标记的标签，所有调用方共享同一个 Promise。页面标记里已经声明的文件视为已加载；调用方给出 `ready()` 且它不成立时，说明声明的副本没有到达，会重新加载。导航、设置、Chat 和 HATG 加载器都通过它加载头像组件、Package 和 HATG 脚本，因此一处加载过的文件不会让另一处等待一个已经发生过的 `load` 事件。
- `objectOf(value)` 读取应为对象的字段，缺失或不是普通对象时得到 `{}`。Repo、Resource 页面读取资源记录的 `attributes` 与 `source`，Project 页面和资源链接卡片读取契约字段，都使用它。
- 图标：`iconHtml`、`createIcon`（返回 DOM 节点）、`mountIcon`（同一位置重复调用时更新原图标，不叠加）、`mountIcons`；名字先经过别名表（`canonicalIconName`）。通过共享插入增强注册表处理新插入的节点，以及 `data-portal-icon`、`data-portal-icon-class` 属性的变化；名字清空或无效时移除旧图标，附加的类名过滤掉非法字符。
- `toneForStatus` 比较状态前统一空白、连字符和下划线，未知状态为 `neutral`；`statusHtml` 生成状态标记。
- `buttonHtml`、`fieldHtml` 生成按钮和字段，标签、值、占位文字和选项都经过转义。

- `asyncStateHtml` 与 `renderAsyncState`：状态只有 `loading`、`empty`、`error`（未知按 `empty`），密度只有 `panel`、`compact`、`inline`（未知按 `panel`）；`error` 使用 `role="alert"` 并可带重试，其他使用 `role="status"`。
- `randomUUID()` 为请求关联 ID、幂等键和临时界面身份生成 UUID v4。它使用 `crypto.getRandomValues`，在 HTTP 内网地址上也能用（`crypto.randomUUID` 只在 HTTPS 下可用），不退回时间戳或普通伪随机数。Projection 宿主为每个内嵌页面分配独立的随机通道，并按通道和递增请求号核对消息来源。
- `PortalResponsive`：视口宽度不超过 820 像素时为 `mobile`，否则为 `desktop`，并写入根元素的 `data-portal-viewport`。它公开 `mode`、`isMobile()`、`snapshot()`（返回 `mode`、`mobile`、`compact`）和 `subscribe(listener, options)`（默认立即发送一次当前快照，返回取消函数）；模式真正改变时发出 `portal:responsive-change`。`PortalResponsive` 与 `PortalUI` 在同一个脚本 `portal_ui.js` 中安装。
- `PortalUI.formatBytes` 与 `PortalUI.formatDateTime` 分别是字节单位换算和日期本地化的唯一实现；页面可以用薄包装选择精度和空值显示，不复制换算表或本地化逻辑。

### 页面插入增强与释放

聊天流式输出和工作台挂载会持续插入 DOM。全页插入发现由 `PortalUIPrimitives` 唯一持有的 `MutationObserver` 负责，组件按选择器登记自己的增强操作，避免同一子树被多个组件分别遍历。尺寸监听和组件内部的属性监听仍由各实例管理。

- `registerEnhancer({ id, selector, enhance, remove, attributes, content })` 要求唯一的登记 ID、有效选择器和 `enhance(element)`。登记后只为新登记扫描已有页面；后续通知在微任务中合批，合并嵌套的插入根节点，以组合选择器遍历一次，并对每个登记、每个元素去重。
- 组件的增强函数接收命中的单个元素，重复调用应保持幂等。图标、表单、工具栏、详情外壳、资源标签与 Chip、图片预览、按钮提示、导航头部、“我的 Mailbox”入口对输入区的避让及 Markdown 数学和 Mermaid 都通过此入口接入。
- `attributes` 显式列出需要跟踪的属性；属性删除后，曾由该登记增强过的元素仍会收到通知。设置 `content: true` 后，后代增删或文字变化通知最近的匹配元素，用于按钮文字与 Mermaid 源码更新。
- 合批结束时已经脱离文档的新增元素不增强。移除的子树仅在仍脱离文档时调用 `remove(element)`，同一文档内移动不会销毁实例；重新插入后重新增强。Toolbar 和详情外壳在移除时释放实例，“我的 Mailbox”入口对新增和移除的输入区分别登记和取消尺寸监听。
- 返回的注销函数可重复调用，立即使该次登记的待处理回调失效；同 ID 再登记属于新生命周期，旧注销函数不影响新登记。实例销毁时调用注销函数并释放自身监听；页面常驻组件的登记与文档同寿命。全部注销后断开共享观察器。
- 单个增强或移除回调失败时记录组件 ID 与错误，其余回调继续执行。使用增强器的页面在调用方之前加载 `portal_ui_primitives.js`。页头增强器在导航脚本加载时登记，在解析阶段建立 `.portalNavTop`，供后续页面脚本创建工作台 chrome；导航的数据读取与交互初始化仍在页面就绪时执行。
- 自动挂载由组件的声明属性触发。Toolbar 的 `data-portal-toolbar` 表示请求自动挂载；`.portalToolbar` 仅表示实例的呈现，可用于发现手动挂载实例的移除。手动实例销毁后，残留样式类不能触发重新挂载。

### Panel 内容头部

头部的配色与排版分开组合。标准内容头部、HATG 专用工具栏与 Paper 主工作区的标题和选项栏，共享同一头部表面样式：底色取主题的 panel-2、文字取 text、分隔线取 border。工具栏不能通过透明背景露出画布颜色；切换浅色、深色或其他主题时，头部配色同步更新。HATG 保留图编辑操作与 Context／Workspace 切换的专用布局；Paper 主工作区保留资源身份、Details、模式选项卡及操作区的专用布局。这些组合头部不因此套用标准头部高度。

组件内容头部和 Workbench 的拖拽页签分别承担业务识别与布局编辑职责。内容头部统一使用标题、可选辅助信息、操作区三个槽位；布局固定或解锁不改变其排版，也不重建正文。

共享内容头部的最小高度为 64px，内边距为上下 10px、左右 12px。单行标题垂直居中；标题与辅助信息上下排列，间距为 4px；操作区垂直居中。标题使用同一字号、行高与字重。常规宽度下，单行与双行头部保持同一基线。窄面板中的身份信息和按钮可换行并撑高头部，完整信息、可复制身份与操作可达性优先于强制等高。

这套排版由共享组件样式持有，调用方仅提供内容与动作。页面不得另设头部高度、内边距或覆盖标题排版，也不得用减去某个头部像素高度的方式计算正文空间；正文通过弹性布局承接剩余区域。当前接入 Navigation、Chat、Terminal、Paper Library、Article 侧栏与 Projection 内容头部。Home 自有卡片、编辑器工具栏和 Workbench 拖拽页签属于各自的语义对象，不套用内容头部高度。

头部的行为契约包括单行与双行头部、辅助信息、操作区的几何对齐，窄宽度下身份信息完整，以及真实 Society 页面中固定与可调整两种布局的一致性。共享样式边界由架构检查约束；几何、可见性和实际布局需要对应的浏览器观察证据，不能由静态检查推定通过。

### 命令注册表

- `createScope({id, context})` 要求 ID 非空且不重复。模块加载时创建根作用域 `portal`；工作台各自创建 `workbench.<ID>` 作用域。`dispose()` 清空作用域中的命令并移除作用域。
- 命令必须有 `id` 和 `execute`。默认值：标题为 ID，说明和图标为空，分类为 `General`，优先级 0，快捷键为空（`keybindings` 接受字符串或数组，丢弃空值），`allowInInput` 和 `allowConcurrent` 为 `false`。
- 作用域的上下文可以是对象或函数；执行时传入的覆盖值优先，最终上下文总带 `commandScope`。`execute` 收到冻结的命令、上下文、参数、事件、来源（默认 `api`）和作用域。
- `list` 默认不包含不可见的命令（`includeHidden` 可以包含），按优先级从高到低、同优先级按登记顺序排列。
- 执行未登记的命令抛出错误；不可见或不可用时返回 `false`；不允许并发的命令在执行中再次执行返回 `false`，异常结束也会恢复忙碌计数。
- 登记、注销、上下文和忙碌变化都发出 `portal:commands-change`。
- **Portal 全局快捷键优先于页面、工作台和编辑器快捷键。** 根作用域 `portal` 登记全局命令；其他作用域登记局部命令。全局命令在 window 的键盘捕获阶段选出，命中可用命令后阻止浏览器默认动作并停止事件传播，页面监听和 Monaco、终端等控件不会再次处理同一按键。局部命令在 document 冒泡阶段处理未被消费的事件。数字 `priority` 只解决同一层级内的冲突，局部命令不能靠更高数字覆盖全局命令。
- 快捷键写法统一为 Ctrl、Meta、Alt、Shift 加主键；主键可使用字符或物理键代码，例如 `Ctrl+K`、`Ctrl+Backquote`。同层级内只选择可见、可用且符合输入范围的命令，按优先级从高到低、登记顺序从早到晚选出一个。没有匹配时保留浏览器及页面处理；已消费事件不重复执行。
- 在输入框、下拉框、多行文本框、可编辑内容和 `role="textbox"` 元素中，只触发 `allowInInput: true` 的命令；判断覆盖事件路径中的 Shadow DOM 输入元素。输入法组字中的事件（`isComposing` 或键码 229）不触发命令。执行异常记录到控制台，监听继续工作。
- 新增全局快捷键必须在根作用域登记，由同一调度器处理。页面通过领域接口提供动作实现，不另设按键拦截来覆盖全局命令。共享弹层的 Escape 关闭由 PortalOverlay 在 window 捕获阶段独立拥有，见 decision_b3022c27d22f。
- 忙碌计数和注销函数属于具体的一次登记。同名作用域重建，或命令注销后重新登记，新登记不继承旧的忙碌状态；旧的执行可以完成，但不能改变新登记的计数，旧的注销函数也不能注销同名的新命令。

### 共享选择

- `PortalWorkbenchContext.create({workbenchId, initial})` 创建一个工作台的共享选择。`get`、`snapshot`（带 `workbenchId`、`revision` 和 `values`）读取；`set`、`patch`（只合并给出的顶层字段）、`replace`（整体替换）、`select`（只写五个标准选择通道）写入。值没有真正改变（按 `Object.is` 比较）时不通知、不增加修订号。
- 每次变化通知订阅了相关通道的监听，并在 `document` 上发出 `portal:workbench-context-change`；变化中带有改变的通道、来源和原因。监听出错时记录到控制台，其他监听照常收到。
- `dispose()` 后清空全部订阅，之后的写入和订阅都不生效；读取快照仍然安全，其他工作台不受影响。
- 五个标准选择通道和面板怎样使用共享选择，见 decision_538e155e1102。

### 面板包与工作台

组件层负责公开可组合的运行对象，Workbench 负责登记、编排和释放面板实例。面板包的字段、创建前提、尺寸下限、生命周期、失败隔离与状态恢复封套，以 decision_538e155e1102 为唯一正文。全局命令优先级和共享选择的跨组件规则仍由本 Design 拥有。

### 页面内导航

- `PortalNavigation.mount({root, views, variant, activeView, label})` 需要有效的根元素。`variant: "lineage"` 使用 Society 工作台的四个侧栏视图：`agents`（Lineages）、`chatrooms`（Chatroom）、`favorites`（My Favorite）和 `workspaces`（个人 Workspace）。无效的视图 ID 回到第一项。
- 控制器提供 `snapshot`、`restore`、`setContext`、`show`、`destroy`；切换视图时可以选择是否发出业务变化事件。
- 导航作为面板包 `navigation` 接入工作台：版本 1，单实例，能力为 `view-select`、`snapshot`、`restore`。

### 大型页面的状态模块

Society 工作台和 Lineage 图面板（HATG Panel）的状态分成三层，每层只有一个负责方：

| 层 | Society 工作台 | Lineage 图面板 |
|---|---|---|
| 初始状态 | `PortalLineageWorkbenchState` | `PortalHatgPanelState` |
| 页面状态保存与页面级监听的注册、清理 | `PortalLineageWorkbenchController` | `PortalHatgPanelController`（把工作台交给它的页面状态收束为读、写、延迟写和监听生命周期） |
| 可复用的业务状态变化 | `PortalLineageWorkbenchFeatures`（历史请求、固定目标、转发选择） | `PortalHatgPanelFeatures`（画布选择、连线草稿、放置预留） |

主视图通过这些模块改变状态，不复制状态机。两个控制器不提供通用的 `transition(任意函数)` 入口；状态变化按业务命名，放进对应的功能模块。状态模块必须先于主控制器加载，缺少依赖时直接失败。

## 加载与验证

- 组件通过浏览器全局对象和脚本加载顺序连接。使用工作台的页面先加载编辑区打开服务、命令注册表、共享选择，再加载工作台；使用全局资源搜索的页面先加载命令注册表，以登记打开搜索的快捷键。缺少前置模块时在登记处失败。每个模块只在全局对象不存在时安装，重复加载保留原实例。
- 架构测试（`tests/cases/test_portal_component_architecture.py`）检查主题提供方、共享组件的样式边界、导航宿主和内容头部负责方。`test_portal_dom_contracts.py` 调用 Node/DOM 用例检查命令优先级、输入法与输入框策略以及共享确认框。上述检查不等于完整浏览器契约或组件接入矩阵；共享选择、面板登记、生命周期、状态恢复及实际页面接入的浏览器行为，仍须按实际取得的证据报告。
- Portal 同时支持 HTTPS 和 HTTP 内网访问。浏览器兼容性要求包括真实的非 HTTPS 地址、WebKit，以及不支持 `moveBefore` 时的面板挂载与布局恢复；这些要求不表示当前已有对应的自动检查或通过证据。

## 各层不负责什么

设计变量和基础控件不解释业务对象；命令注册表不实现按钮或面板；共享选择不保存业务数据；面板包实现领域面板，工作台编排实例，页面负责当前选择、布局和组合偏好；业务状态及其限制由对应的服务或领域组件管理。

将来改用 JavaScript 模块加载时，需要保持现有的公开接口、前置依赖和“重复加载不重复安装”的行为。
