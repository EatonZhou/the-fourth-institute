# Portal Shell、共享站点顶栏、全局导航与账号设置

页面和顶栏入口统一命名为 **Society**，中文翻译显示 **社群**；相关服务称为 **SocietyService**。资源实体仍称 **Lineage**，创建、绑定、Fork 等资源操作不改名。既有 `/lineage` 地址、资源类型/ID及导航和布局持久化标识继续兼容；页面名称与资源名称分别翻译。

TFI Portal 由许多业务页面组成。每个页面有自己的列表、卡片、详情、筛选和操作；页面外侧还需要一套始终一致的站点界面，让用户知道自己在哪里、可以去哪里、以哪个账号操作，以及怎样调整全局显示。Portal Shell 就是这层站点外壳。

本文负责主导航、二级导航、账号菜单、版本入口、主题、动效偏好、Settings 宿主、Board 页面公共外壳和全站重启通知。对用户，它提供跨页面的稳定方向感和账号级设置入口。对页面开发者，它提供可挂载的公共外壳，页面无需复制导航、身份与全局菜单。业务内容、局部工具和领域权限仍归各页面与服务所有。

## 先认识用户看到的区域

| 可见对象 | 所在位置与用途 |
|---|---|
| 站点顶栏 | 页面顶部的全局区域，容纳品牌、主导航、搜索入口和账号菜单。业务页可以在共享扩展槽加入只属于该页面的工具，但不能改写顶栏结构与样式。 |
| 主导航 | 顶栏中的一级模块入口，例如 Resource、Project、Society、Paper 和 Workbenches。 |
| 二级导航 | 指向主模块内部具体页面的入口。当前模块可以在顶栏中直接显示；悬停其他主模块时会出现临时浮层。 |
| 导航项 | 带文字标签并可点击跳转的单个入口。活动状态表示当前页面所属模块或当前二级页面。 |
| 更多导航 | 主导航容器有入口标签被裁切时显示的按钮；展开后仅列出当前标签文字未完整显示的主导航项。 |
| 账号菜单 | 顶栏中显示当前用户名的入口。展开后提供版本、Settings、获得授权时的 Management、新用户指引和退出。 |
| 主题控件 | 改变 Portal 色彩外观的按钮与选择浮层。 |
| 动效控件 | 决定界面动画跟随系统、完整显示或减少显示的账号偏好。 |
| Settings 面板 | 编辑账号级界面偏好的内容区，可以作为独立页面，也可以嵌入账号菜单。 |
| Board 页面 | 以列表、卡片和筛选为主的业务页面。Board Shell 为它提供统一外壳和常用控件连接。 |
| 全局收件入口 | 顶层 Shell 中的“我的 Mailbox”，即当前用户的 User Mailbox（decision_15f7df737ed5），收纳对话和通知。 |
| 重启通知 | Web 服务即将重启或正在恢复时覆盖在页面上的最高优先级提示。 |

这里的浮层指暂时显示在页面内容上方的菜单或面板。Overlay 是统一管理浮层层级与关闭规则的组件，详见 decision_b3022c27d22f；Shell 使用它，但不重新定义浮层协议。

## 设计点

### 在所有业务页面间移动

- **主导航使用一致的模块顺序和活动状态。** 用户在不同页面看到同一组站点入口；当前模块和当前二级入口会根据页面地址标记。
- **“更多”只列出标签文字当前被裁切的主导航项。** 标签文字完全隐藏或部分超出导航容器左右边界的入口按当前主导航顺序列入菜单，文字已经完整显示的入口不重复列出；链接末尾用于分隔符和点击区域的留白被裁切，不会使已显示标签重复进入菜单。横向滚动、容器尺寸变化或导航内容重排后，已展开菜单同步更新；全部入口标签完整可见时隐藏按钮并关闭该菜单。
- **悬停主模块会稳定显示二级入口。** 延迟打开和延迟关闭减少指针短暂经过造成的闪烁；浮层会限制在视口内。
- **Escape 和外部点击可以退出二级菜单。** Escape 关闭后把键盘焦点还给触发入口。
- **用户可以拖拽调整主导航顺序。** 同一页面中的多个导航宿主同步重排，刷新后从本浏览器恢复。
- **新模块不会因旧排序记录消失。** 保存顺序保留尚未加载的工作台 ID 并移除重复项；渲染时只显示当前登记的模块，新增加的默认模块追加到末尾。
- **已发布的自定义工作台可以进入全局导航。** Shell 读取当前用户可见的工作台目录，排除内置、未发布和声明隐藏的条目；声明顶层展示的自定义工作台最多追加四项，全部可导航条目同时进入 Workbenches 二级菜单。收到工作台变化事件后重新读取目录和渲染；导航曝光不替代目标页面自身的访问控制。
- **Portal 开发投影是共享内置导航。** 固定主导航入口 `/development` 解析 Portal 的 `development` 权威工作台登记，不取个人扩展列表，不占自定义工作台的四个顶部名额。原资源地址 `/workbenches/view?id=…` 与内置入口都选中 Portal 开发投影；region 深链接不改变导航身份。启用的内置工作台对当前可读用户进入目录的内置组，维护 owner 与访问账号的个人排序、草稿保持各自职责。

### 识别账号并调整显示

- **账号入口位于顶栏最右端。** 主题与全局搜索位于头像、用户名和版本标识之前，DOM 顺序与可见顺序一致，键盘按相同顺序移动。主题、搜索的异步挂载不得把入口追加到账号右侧。以 `defer` 加载脚本的页面（Workbenches、Portal 开发投影）可能先挂载搜索再生成顶栏，搜索入口在文档解析完成后加入顶栏。
- **全局搜索在所有宽度只显示放大镜。** 保留搜索快捷键、悬浮提示与无障碍名称。工作台固定按钮、隐藏面板恢复入口同样使用图标与提示，工作区名称在布局按钮提示和布局选择中查看。
- **语言选择属于账号偏好。** Shell 在账号菜单及 Settings 外观区域承载语言选择器；可选语言、原版显示和历史 `auto` 值的兼容规则统一见 decision_27253e25f016。布局弹层只承载工作台操作。

- **账号入口支持鼠标悬停展开菜单。** 用户名、头像与版本标识所在的共享入口使用同一个浮层；悬停不移动键盘焦点。鼠标离开入口后保留 140 毫秒用于进入菜单，停留在菜单内或菜单内仍有键盘焦点时保持展开；只由悬停打开的菜单在离开后关闭。点击已悬停展开的入口会固定展开，再次点击关闭；触屏与键盘继续按点击、Enter 和 Escape 操作。所有业务页复用同一账号菜单行为。
- **账号菜单底部依次是 Menu、获得授权时的 Portal Management、Guide 和 Log out。** Guide 在新标签页打开公开的 `/guide`（decision_3286d4167180）。
- **新账号在顶栏下方看到一次欢迎卡片。** 账号创建后 14 天内、偏好 `onboarding.welcome_dismissed` 不为 true 时，Shell 在右上角显示“欢迎加入 Portal”，提供打开新用户指引、和本人 Ask Me Anything 对话、知道了；打开指引或点“知道了”后写入该偏好，所有页面与设备不再显示。卡片由 `PortalNav` 统一渲染，页面不各自实现。
- **账号菜单显示当前服务端会话用户。** 身份来自页面可信启动数据或 `/api/me`，浏览器会话存储只记住最近用户名，不能充当权限真值。
- **退出或显式清除会移除客户端身份。** 旧用户名和旧偏好不会继续驱动 Shell。
- **浏览器历史恢复会重新确认身份。** 页面从前进后退缓存恢复时，`PortalIdentity` 绕过内存 Promise 强制读取 `/api/me`，成功后发布 `portal:history-restored`；页面据此继续使用当前服务端身份，而不是恢复缓存中的旧账号。失败只发布对应错误事件，不伪造匿名或沿用未经确认的权限。
- **用户可以选择八种主题。** 自动、浅色、深色、火焰、深海、森林、科幻和月行者模式会同步按钮文字、图标和无障碍状态。
- **Moon Walker 同时提供配色与场景。** 星尘、月面和脚印由共享主题宿主显示，在普通页面和占满视口的工作台中都可见；装饰不参与点击、键盘导航或读屏，不改变业务布局与运行状态。切换到其他主题时移除场景，刷新后按保存的主题恢复。
- **用户可以选择三种动效模式。** 跟随系统、完整动效和减少动效会跨页面恢复；跟随系统时采用操作系统的减少动态效果设置。
- **账号级偏好保存失败会回滚控件。** 控件恢复原值、解除禁用并显示错误，用户不会看到只在本地假装成功的选择。

### 使用版本、Settings 和管理入口

- **账号菜单列出服务端登记的 Dev 与 Release 入口。** 当前版本标为活动项；普通用户也能看到已登记版本。
- **版本切换有独立忙碌和错误反馈。** 请求进行时对应控件禁用；成功后重载当前页面，失败后恢复控件并保留可见错误。
- **Settings 可作为独立页面或账号菜单内面板。** 两个入口共享同一面板能力，默认打开 Settings。三个标签依次为 Settings（头像、密码、两步验证、Passkeys、个人访问令牌）、Appearance（Auto 配色、语言、动效）和 Package（当前用户的个人背包与权限配置，decision_5bc3fdfc7eec）。Settings 每项占一行：左侧是名称和当前状态，右侧是操作按钮；头像选择、密码表单、验证器设置与管理、Passkey 注册表单只在点击“编辑头像”“更改密码”“设置身份验证器”“管理”“添加 Passkey”后于该行下方展开，取消或完成后收起。有未保存的头像、表单、令牌或背包修改时，切换标签前先确认是否放弃；有操作正在处理时提示稍后再切换。标签支持方向键与 Home/End；窄屏与 Resident Menu 一样保留左侧分栏，配色控件与预览按上下顺序排列。
- **Appearance 提供 Auto 模式的个人配色。** 用户可选预设色、自定义十六进制颜色，并在 0%–100% 范围内调整自己的消息气泡不透明度，默认 18%；0% 融入背景，100% 与发送按钮的主题色一致。主题层同时推导气泡内正文、引用、链接、资源标签和内嵌区域的可读配色；收到的消息继续保持中性色。预览包含双方消息、引用、链接和发送按钮，使用与页面相同的配色投影与共享消息样式。拖动时先更新预览，完成一次选择后自动保存到当前账号，页面随后采用该选择；失败回滚并在控件旁显示可重试的错误。恢复默认是一次正常保存。动效选择的保存中、成功与失败提示放在动效控件旁的预留状态区域，不能用顶部通栏提示推移菜单内容。
- **引用底色可跟随气泡或自定义。** Appearance 在气泡不透明度后提供“引用底色”，默认跟随气泡；深色气泡和深色外观中的引用区进一步压暗，引用文字独立适配底色。选择“自定义”后显示取色器与颜色值，实时预览自己的消息中的引用底色，完成选择后保存到账号；更换主题色或气泡不透明度时保留自定义引用色。切回“跟随气泡”只恢复引用的自动配色，“恢复默认”清除全部自定义配色。引用、资源标签和代码区域各自保留适当的视觉层次，不能为加深引用一并压暗其他区域。
- **Auto 配色适配系统明暗，显式主题保留原有配色。** 颜色由主题层分别推导浅色、深色强调色及按钮文字色，保证文字可读性。当前不是 Auto 模式时，Appearance 仍可预览、保存，并提供“使用 Auto”入口。新配色不影响其他用户；刷新、重开 Menu 和同账号其他设备加载偏好后继续采用已保存值。
- **个人访问令牌在 Settings 的最后一行签发和撤销。** 展开“Personal access tokens”时读取 `ListUserAccessTokens`；用户填写名称和有效天数（1–365，默认 90）后，浏览器在本地生成 `dbu_` 开头的令牌，只把 SHA-256 摘要随 `CreateUserAccessToken` 提交，令牌原文只在这里显示一次并可以复制。列表显示每个令牌的名称、状态和到期日，有效令牌可以用 `RevokeUserAccessToken` 撤销；令牌不能修改（decision_6eac174d85bf）。
- **安全设置仍由安全领域处理。** Settings 只提供入口和宿主；安全状态与安全操作由专用接口负责。
- **Management 只对服务端授权账号可见。** `/api/me` 的 `access.allows` 报告调用者能否通过页面关心的指令（CreateUser、GetExecutionSettings、UpdateProviderAccount、OpenTerminal），`access.user_category` 给出调用者的 User 分类；能通过 CreateUser 或 GetExecutionSettings 时显示入口；权限系统关闭时任何已登录 User 都看到入口（decision_b820faf42218）；菜单是否显示不能代替管理接口自身授权。
- **切换账号面板后，旧请求的返回结果不能覆盖新选择。** 较早的 Settings 或 Management 加载结果按此规则隔离；加载失败在警报区域显示。

### 服务重启期间保持可理解状态

Shell 承载全站重启提示，并为它提供最高优先级浮层。通知读取、倒计时、健康探测、登录页例外，以及后台可见性和 `pagehide` / BFCache 恢复的区别，由 decision_f25266e5a0e7“Web 重启衔接”唯一规定；业务页面复用共享实现。

## 页面开发者如何接入

### 统一页面边框布局

Portal Shell 统一拥有业务页面与视口、共享顶栏之间的外侧留白。页面声明 `portalPageFrame` 宿主，共享组件样式使用一处 `--portal-page-gap` 定义四边间距，当前均为 6px；页面不得声明自身的外侧 margin、padding、居中宽度上限或按屏幕尺寸覆盖这组间距。内部列表、工具栏、面板和可读内容的排版仍属于业务页面。

Resource 等页面的二级导航使用 `portalPageHeaderFrame`，由同一组件控制上方与左右留白，底部不额外增加间距；紧接的内容宿主负责内容上方和底部留白。独立页面与嵌入式面板区分：嵌入内容不再叠加页面边框。

占满视口的工作台把共享页面边框放在外层，把 Workbench 根放在内层；共享 Workbench 视口布局根据实际导航位置计算可用高度。Paper 等页面不另设导航高度公式或工作台外侧 insets，避免绝对定位的工作台绕过页面 padding，以及不同页面的内容边缘不一致。

- **页面只声明共享站点顶栏宿主和当前模块。** 页面使用带 `data-portal-site-header` 与 `data-portal-nav-active` 的 `portalSiteHeader` 空宿主，页面根元素使用 `portalBoardShell`；`PortalNav.renderSiteHeader()` 唯一生成品牌、`portalNavShell`、模块导航、账号菜单和退出入口，`portal_components.css` 唯一负责显示格式。页面可以让宿主参与自身的 flex 或 grid 布局，但不得复制或覆盖顶栏内部结构。
- **页面工具通过扩展槽与站点顶栏组合。** Society 等工作台可以在主导航与账号菜单之间加入自己的工具；不使用该能力的 Resource 等页面不会显示这些工具。局部筛选、分类页签和业务操作位于共享顶栏之外，即使与顶栏一起吸附也不成为全局导航的一部分。
- **声明式宿主可以重复挂载。** 重复挂载不会生成第二套交互；页面注册新的二级导航定义后，可以要求已有 Shell 重新渲染。
- **Board 页面可以挂载公共外壳。** Board Shell 为页面主体增加统一样式，并提供共享请求客户端、字节与日期格式化、复选框、单选框、搜索和筛选绑定。页面继续拥有业务数据和局部动作。
- **可卸载页面需要销毁 Board Shell。** 销毁会释放页面级监听和控件连接，重新挂载不会叠加事件处理器。
- **“我的 Mailbox”入口只在顶层 Shell 建立一次。** Shell 按需发现和加载依赖；已有实例直接复用，iframe 不重复创建入口。

## 白盒机制：组件职责与加载流程

| 组件 | 源码名称 | 负责的状态 |
|---|---|---|
| 全局导航与账号宿主 | `PortalNav` | 共享站点顶栏的内容装配、主导航定义、活动状态、二级浮层、用户排序、账号菜单、版本面板和重启提示。 |
| 身份与账号偏好客户端 | `PortalIdentity` | 当前身份快照、身份加载、服务端偏好缓存、批量保存和 UI Association 请求包装。 |
| 主题宿主 | `portal_theme.js` | 读取主题、投影根元素、挂载选择器与唯一的主题装饰场景；场景样式和素材由 `portal_themes.css` 拥有。 |
| 动效宿主 | `PortalMotion` | 解释 system、full、reduced 三种动效模式并投影到页面根元素。 |
| Board 公共外壳 | `PortalBoardShell` | Board 页面的公共 class、格式化、请求 client 和表单绑定生命周期。 |
| Settings 面板 | `PortalSettingsPanel` | 把账号偏好和安全入口挂到指定宿主，协调控件保存与失败回滚。 |

页面模板负责共享脚本的依赖顺序：先执行 `portal_theme.js`，再执行 `portal_nav.js`。`PortalTheme` 在脚本求值时同步注册配色 API，导航随后同步调用 `normalizeAutoColors` 初始化偏好。所有原生宿主（包括 Workbenches 与 Board）都遵守此顺序；使用 `defer` 时两者保留文档顺序，不能以 `async` 破坏依赖。动态入口若加载导航，也必须等待主题执行完成。页面启动监测只记录模板资源和初始化结果，不重排脚本、不替代依赖装配；导航不复制主题规则，也不以捕获异常或默认值掩盖未加载的 owner。

页面加载后，导航组件先扫描 `data-portal-site-header` 空宿主并生成标准顶栏，再挂载模块导航和账号菜单。该顺序保证每个页面得到同一份 DOM、POST logout 和无障碍标签；重复挂载通过宿主标记保持幂等。身份组件先使用可信启动数据；缺失时请求当前会话。Shell 根据身份加载偏好和授权入口，再挂载主题、动效、Settings 与通知。用户修改账号偏好时，只把本次改变的字段交给身份组件。身份组件在内存深合并连续补丁，再批量提交服务端；服务端结果成为最终状态，旧标签页的未修改字段不会覆盖其他标签页的新值。用户拖拽导航时，顺序由 Page State 写入当前浏览器，见 decision_9f6135cbbb22。

## 精确协议和限制

### 导航定义、活动状态和排序

- 主模块由核心入口和已安装功能的入口按次序值合并，默认顺序为 Resource、Project、Society、Paper、RoboLab、Workbenches、Portal 开发投影。Project、Paper 和 RoboLab 由各自功能登记（`web.navigation`，decision_15aab18c0ab3），页面从 Web 写入的前端清单读取；Portal 不带某个功能时不出现它的入口，RoboLab 只在 Dev 中出现。WALL 与 Test 是 Portal 开发投影中的视图，Workbenches 提供已登记工作台的总目录。
- RoboLab 功能同时登记 `/cloud-lab`、`/cloud-lab/` 的页面路由及前端静态子路径，避免直接进入 Portal Router 的站点绕过独立代理后落入文件兜底并返回 404。前端读取部署已有的构建目录，可由 `deployment.robolab.frontend_root` 指定；根目录外的路径和缺失资源文件返回 404，无扩展名的内部页面回到 SPA 入口。该适配只提供前端，`/cloud-lab-api/` 的后端请求与 WebSocket 继续由部署代理转发，不随语言或前端路由修改其网络配置。
- Resource 二级入口按资源类型登记列出（Knowledge、Skill、Repo、Article、Experiment、Device 等），之后是功能登记在 Resource 下的页面，例如 Resource Backup 的 Backup。Research Map 在 Project 的 Research 页面查看。
- 当前地址匹配内置工作台或已登记的顶部个人工作台时，由该工作台标签显示唯一的活动状态（含 aria-current），替代页面声明的 Workbenches 目录高亮。匹配使用目标 pathname 和必要查询参数（包括工作台 ID）；区域参数与行内锚点不改变工作台身份。目录页以及没有对应顶部标签的工作台仍沿用页面声明的模块状态，不生成未登记入口，也不主动转移键盘焦点。
- 二级导航定义要求非空 module ID；每个 item 都必须提供 ID、label 和 href。活动状态同时检查当前 pathname 和目标要求的查询参数。
- 悬停打开延迟 90 毫秒，关闭延迟 180 毫秒。浮层默认放在触发器下方起始侧，视口边距 12 像素，间隔 9 像素。
- “更多”的裁切范围以所属主导航容器的内侧可视区域为准，比较各导航链接的标签文字内容边界，允许 1 CSS 像素的舍入误差；文字左右任一侧超出范围即纳入菜单。链接布局盒中只承载分隔符或点击区域的尾部留白不参与判断。菜单使用现有链接的名称、目标地址和当前排列顺序，并沿用二级导航的活动状态与 Overlay 关闭规则。该筛选仅适用于“更多”；各模块二级菜单继续按自己的定义提供入口。
- 点击“更多”或在按钮上按 ArrowDown 时根据当前布局生成菜单，ArrowDown 将焦点移到第一项。展开期间，导航滚动、尺寸变化、字体就绪与条目增删重排触发重新计算；仍被裁切的原焦点项保留焦点，菜单仍有项目且原焦点项变为完整可见而从菜单移除时，焦点回到“更多”按钮。Escape 关闭菜单并返回触发按钮。
- 导航排序保存在 `portal-nav` Page State。历史模块名 `knowledge` 迁移为 `resource`；保存时保留尚未登记到当前列表的模块 ID，重复模块只保留第一次。渲染时跳过尚未加载的模块；工作台目录加载完成后，沿用保存的位置显示这些模块，新默认模块追加到末尾。
- 拖拽以目标项中点判断插入前后。drag end 立即持久化，并在随后 250 毫秒抑制拖拽产生的误点击。
- 页面点击、拖拽开始、窗口 resize 或滚动会关闭或重新定位导航与账号浮层。

### 只读页面导航

PortalNav.openPage 统一处理宿主发起的页面体验入口。可导航目录只来自服务端路由中显式声明的精确 GET 文档，不从顶栏是否显示、API 路径前缀或调用方提供的白名单推断。目录不是访问授权，目标页面仍负责当前用户的权限检查。外源、协议相对、脚本/data、用户凭据、歧义路径以及未登记的 API/下载/登出地址不能成为页面入口。

页面宿主拥有已装配的局部视图，可通过 handleCurrent 回调原地处理同一对象的导航：返回 true 表示已处理，false 表示布局等条件拒绝，null 表示交给普通页面导航。false 不得触发整页刷新兜底。投影 Workbench 通过此合同保留 iframe、草稿与 focus 并打开区域或门面对话；Shell 不解释区域业务。

其他已登记目标在当前标签普通导航。结果 {opened, mode, url} 只表示原地操作结果或页面导航已发起，不代表目标已加载、已授权或完成业务。调用方不得把导航回执当作业务执行回执；导航不提交业务动作，也不放宽投影隔离。

### 身份与偏好

- `PortalIdentity` 优先读取页面 bootstrap；缺失时请求 `/api/me`。同一周期的并发 `load()` 共享 Promise；成功在内存缓存并发布 `portal:identity-changed`，失败清除进行中 Promise以便重试。`load({force: true})` 清除旧 Promise 后重新读取。
- `pageshow` 的 `persisted: true` 表示文档从浏览器前进后退缓存恢复。此时身份客户端执行强制读取；成功事件携带新的身份快照和 `persisted: true`，失败事件携带错误且不把失败结果写成当前身份。普通首次显示不重复读取。
- sessionStorage 键只保存最近用户名。`peek()` 返回深拷贝快照；`clear()` 清除身份、偏好读取状态和最近用户名。退出请求结束后调用 clear。
- `loadPreferences()` 以 `cache: no-store` 请求 `/api/preferences`。并发读取共享 Promise，内存缓存默认 5,000 毫秒，`force` 绕过；缺失 preferences 按空对象处理。
- 偏好读取开始时记录本地 revision。返回时 revision 已变化，则保留较新的本地状态。
- `savePreferences(patch)` 对补丁做递归对象合并，默认在 1,500 毫秒窗口批量保存，延迟下限 250 毫秒。同批调用者等待同一结果；保存期间到达的新补丁进入下一批。
- 成功时优先采用服务端返回的完整 preferences；响应缺失时采用本地合并。失败会拒绝本批全部等待者。

### 主题与动效

- 主题源码值为 `auto`、`light`、`dark`、`fire`、`deepsea`、`forest`、`scifi`、`moonwalker`；未知值回退 `auto`。
- 非 auto 主题保存在 `tfi.portal.theme`，并写入根元素 `data-portal-theme`。auto 删除本地键并跟随系统配色；light 使用浅色 `color-scheme`，其他显式主题使用深色。
- 主题按钮循环模式，主题选择器同步文字、图标和 ARIA 状态。
- `PortalMotion` 支持 `system`、`full`、`reduced`，把选择写入根元素数据属性。服务端偏好读取失败时回退 system。
- Moon Walker 场景只依赖主题和动效偏好，不读取卡片类型、页面私有选择器或执行状态。主题初始投影可早于 body；DOM 就绪后补齐场景，重复挂载保持单实例。场景采用不捕获输入的固定装饰层，低强度混色保持文字可读，菜单和对话框继续处于更高层级；装饰不影响页面尺寸。
- `full` 播放星尘漂移与脚印动画，即使系统请求减少动态效果；`reduced` 停止这些动画但保留静态背景；`system` 跟随系统设置及其变化。装饰表达主题氛围，不能被解释为任务正在运行。素材随主题代码一起发布，不能因页面模板未直接引用而删除。
- Mailbox 中运行 Resident 的状态标记可消费主题提供的运行图案：Moon Walker 用同一脚印素材逐步显现，替换圆点并保留“运行中”文字；减少动效时显示静态脚印。适用范围同时包含主会话条目 `resident-main` 和派生 Resident 条目 `resident`，与会话列表生产投影一致。是否运行由 Mailbox 既有 Resident 状态投影决定，结束运行后移除该标记。其他主题沿用圆点，排队、终态、未读和聊天室标记保持各自含义。主题只提供图案与动画变量，Mailbox 组件拥有标记的结构、空间与状态适用范围；背景场景不读取这些状态。
- `appearance.auto_colors` 可选，包含 `accent`（空字符串为默认，否则为六位十六进制颜色）、`quote_color`（空字符串为跟随气泡，否则为引用底色的六位十六进制颜色）与 `bubble_intensity`（0–100 的不透明度整数，默认 18；保持原字段以兼容已保存值）。服务端校验并按字段合并，修改颜色不能覆盖语言、动效或其他偏好。`PortalTheme` 唯一拥有配色规范化和明暗色推导；`paintAutoColors(target, value)` 同时服务页面根节点和局部预览，只有 Auto 样式消费这些变量。共享消息气泡通过局部文本与表面变量保证全量填色时正文和嵌入内容仍然可读；引用拥有独立的底色、文字色变量，预览与真实消息共用；不对整条消息设置透明度。身份切换或清除时重新投影当前账号的偏好。

### 账号菜单与 Settings

- 账号菜单根据服务端部署状态列出 Dev 和 Release，并标记当前版本。版本入口不按普通用户身份隐藏。部署状态读取失败时显示错误，不生成未登记的版本按钮。
- Settings 和 Management 面板在同一账号运行期可以复用；请求序号阻止旧响应覆盖新面板。错误显示在 `role=alert` 区域。
- `/settings` 提供独立宿主。`PortalSettingsPanel.mount(host)` 只接受有效宿主；无效宿主不创建实例。
- Settings 偏好使用乐观更新。保存期间禁用相关输入；失败恢复先前值并显示通知。

## 公开接口

- `PortalNav.mount()`：扫描声明式宿主并挂载 Shell；`PortalNav` 也负责注册二级导航、重新渲染、维护排序和账号菜单。
- `PortalIdentity`：提供身份 `peek`、`load`、`clear`；偏好 `loadPreferences`、`updatePreferences`、`savePreferences`；以及 UI Association 的 list、put、remove 请求包装。
- `PortalTheme`：主题 `mode`、`setMode`，以及 Auto 配色 `normalizeAutoColors`、`paintAutoColors`；`portal_theme.js` 自动挂载主题并订阅账号偏好。`PortalMotion` 提供动效 `apply`、当前 mode 和 modes。
- `PortalBoardShell`：创建 Board 公共外壳和 client，并提供格式化、表单绑定与 `PortalBoardShell.destroy()` 生命周期。
- `PortalSettingsPanel`：把账号偏好和安全入口挂载到独立页面或账号菜单宿主；个人访问令牌区域由 `portal_user_enrollment.js` 的 `mountEnrollment` 提供，Management 中的用户邀请使用同一个组件。

## 窄屏导航

共享站点顶栏在窄屏仍保持单行：模块导航负责水平裁切并通过“更多导航”暴露不可见入口；全局搜索入口在所有宽度保留同一纯图标按钮、悬浮提示与无障碍名称，不能挤压或裁切“更多导航”和账号控件。
