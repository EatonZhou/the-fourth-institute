# 迭代统一知识库口径

该流程适用于用户通过问答识别知识库偏差，再逐轮修订定义、实现说明和相关条目。

## 工作流

1. 先按 `./search.md` 读取当前知识库并回答，不提前加入理想版本。
2. 根据用户反馈区分概念定义偏差、工程实现偏差、表达问题和结构缺口。
3. 明确哪些反馈要写入知识库，哪些只用于解释。
4. 用户要求修改后，先读 `./knowledge-base-rules.md` 和 `./modify-entry.md`。
5. 优先修改核心定义、当前 Design 或其他事实来源，再更新引用这些口径的思考和问答条目。
6. 新增项目概念时创建独立 `concept` 条目，不只在其他文档中零散提及。
7. 全文搜索相关术语和旧说法，清理仍会造成冲突的残留。

最终文稿直接表达统一后的口径，不保留“纠正前文”或对话过程。用户举例默认用于澄清意图，不自动逐字写入。
