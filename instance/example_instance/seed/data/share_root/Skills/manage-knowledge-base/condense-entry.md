# 凝练知识库条目

凝练用于压缩冗余表达，同时保持原意、事实、范围、语气、结构意图和约束不变。

## 默认行为

- 用户没有明确要求写回时，只给预览或差异。
- 未指定范围时先选一至五个候选条目，不批量修改全库。
- 保留 YAML 头部原文，只处理正文。
- 默认跳过 `todo`、索引、示例、过短条目，以及以代码、配置、表格或逐字引用为主的条目。

## 凝练规则

- 不新增或删除事实、结论、数字、日期、名称、路径、命令、链接、风险、限制、责任边界、触发条件和失败语义。
- 不把假设改成事实，不改变确定程度、适用范围、时态、主客体、因果、优先级或执行顺序。
- 保留 Markdown 层级和承担分类作用的列表。
- 可以删除重复句、空泛铺垫、同义反复和不承载信息的连接词。
- 可以合并相邻且语义重复的段落，但不能削弱结构信号。

## 校验与写回

1. 对比原文和新文，确认实质信息完整。
2. 核对网址、行内代码、路径、数字、日期和术语。
3. 核对标题、列表、引用块和关键分组。
4. 改动收益很小时不建议写回。
5. 有任何语义不确定时放弃该条并说明原因。

用户明确要求应用修改后，按 `./knowledge-base-rules.md` 和 `./modify-entry.md` 写回，并复查 YAML 头部、正文和差异。
