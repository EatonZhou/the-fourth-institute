# 对话驱动的 Portal 主页与右侧展示区（目标设计）

> 目标设计规范。本期在现有 Home 中新增可使用的双栏组件，保留当前 Home 的默认布局、原有组件与入口。本文定义组件的交互和验收要求，尚不表示功能已上线。

## Home 内双栏组件的基本模型

Home 中新增“对话与展示”双栏组件，在组件内部以个人门面 Resident 的对话作为统一入口。用户在左侧表达意图、提出问题、委托工作和跟进结果；右侧展示当前对话需要用户阅读、理解或操作的对象。门面 Resident 是用户持续对话的个人助手入口，可以协调不同领域的能力，具体执行仍归属于实际负责的任务与团队。

组件通过 Home 现有组件机制接入，用户可按现有方式添加或打开。不得把本期实现变为整个 Home 的替换，也不得将其强设为首次进入的默认布局；需要更大空间时可展开组件，并能返回原 Home 状态。

左侧直接使用共用 Chat 组件，宿主沿用统一面板底色。Home 不为聊天内容叠加独立底色、遮罩或主题渐变；消息、输入区与工具栏的外观由共用 Chat 和主题负责。

左侧保持对话连续性，右侧随任务变化。打开一个项目、文件或团队的展示，不隐式更换左侧对话对象，也不把个人对话历史复制给所展示的团队。需要进入另一段对话时，应提供明确入口并显示对方身份。

右侧是左侧的展示与操作空间。它既可承载已有文件的预览，也可承载按任务生成的解释页面，以及 Project 研究地图、Lineage 地图等现有工作视图。用户应能直接在右侧阅读、选择、播放和操作，不必把每个简单动作重新描述成一句话。

Project 是组织研究目标与方向的项目；Lineage 是承担工作的团队；地图节点是保留问题、进展、判断依据与下一步的探索入口。团队视图统一名为“地图 / Map”，项目视图继续区分为“研究地图 / Research Map”，展示协议中的 `frontier` 与 `map` 视图值保持不变。研究地图呈现项目方向，地图视图呈现可进一步理解和介入的工作前沿；二者沿用各自的对象与状态含义。

## 右侧的三种展示用途

| 用途 | 触发情境 | 展示方式 |
| --- | --- | --- |
| 资源预览 | 点击左侧文件或可预览链接；要求打开一个资源 | 使用已有 Preview 与文档会话，保留原有阅读、编辑和保存能力 |
| 任务汇报与解释 | 询问任务、Lineage 或 Project 的状态、进展、机制与问题 | 生成面向阅读和交互的 HTML 页面，按需组合视频、交互组件、图片与文字 |
| 项目地图与团队地图 | 要求查看或制作项目 map、查看团队地图、定位某个方向 | 打开对应原生地图或地图视图，聚焦相关对象，支持继续操作 |

右侧始终显示当前对象的名称和所属范围。报告还显示资料核对时间和来源入口，便于区分实时工作状态与某次汇报快照。

进入页面尚未选择具体展示目标时，右侧显示未选择展示的提示及打开入口，不默认读取文件、汇报或地图。此前保存的展示仅作为“更多 → 历史”中的可选入口；用户明确选中后才创建适配器、读取内容并检查当前权限，不能因旧目标失效或被拒绝而在进入页面时自行报错。当前请求产生的有效展示结果仍按展示协议处理。

### 文件和链接沿用已有预览能力

点击左侧的文件或资源引用时，右侧直接打开对应预览，不另建一套文件阅读器。文档的草稿、保存状态、错误提示与引用操作由已有 Document Session（文档会话）维护。

链接先解析目标并检查访问权限。站内可预览对象进入右侧；外部网页仅在支持安全嵌入时内嵌显示，否则提供明确的外部打开入口。失效、无权限或格式不支持时说明原因，不把失败显示为空白页。

文件读取失败由预览适配器统一呈现一张提示，显示当前目标地址，并区分访问被拒绝、文件不存在和其他读取失败；原始错误可展开查看。提示提供重试、打开其他内容和关闭当前展示的操作，外层容器不重复显示错误和重试按钮。预览自行重试、权限变化和从历史恢复后的核验结果须同步更新展示历史状态；读取成功后移除失败提示。失败期间不展示上次读取的正文；未保存草稿仍按文档会话规则保留和保护。

## 面向理解的汇报模板

汇报围绕读者当前的问题组织。页面先让人知道汇报对象和主要结论，再用合适的表达形式解释背景、证据、变化与可采取的行动。表达顺序不照搬内部日志或 Agent 的工作过程。

页面采用以下可组合结构：

```text
HTML 汇报页面
├─ 对象、主要结论、核对时间与来源入口
├─ 讲解视频                    可选，优先考虑
├─ 交互组件                    可选
└─ 图片与文字解释              可选
```

视频、交互组件、图片与文字均可省略，省略后不留下空框。视频优先表示在适合解释过程、机制或复杂进展时优先选用，不要求简单状态回答也制作视频。页面不为填满模板而生成内容。

四种表达方式分别服务不同理解需求：

| 表达方式 | 适用内容 | 要求 |
| --- | --- | --- |
| 清晰文字 | 结论、限定条件、证据与待决定事项 | 使用具体对象和明确动词，必要术语先解释，避免内部日志堆积 |
| 图示 | 结构、关系、因果与状态差异 | 对象、连接与图例有确定含义，并能回到来源 |
| 交互 HTML | 选择范围、比较方案、探索参数和定位问题 | 用户操作产生可解释的反馈，区分本地演示与真实变更 |
| 配音讲解视频 | 随时间展开的机制、推理和跨阶段进展 | 通过画面变化建立直觉，配音解释画面所表达的关系 |

清晰表达可以借鉴受控语言减少歧义的原则，不要求中文正文套用航空维修英语的语法规范。

### 视频采用具有视觉推理的配音讲解

视频优先参考 3Blue1Brown 式的讲解方法：从具体问题出发，逐步构造可辨认的对象，通过运动、变换、对比和局部放大说明关系，让配音与画面共同推进推理。沿用 Portal 自身的视觉身份与合适的授权配音，不冒充特定创作者。

视频中的动画应解释真实机制或明确标注的假设。不能以装饰动画、大量文字翻页或无意义连线替代解释，也不能为了流畅补造事实、数值、进展或因果关系。

镜头按理解目标组织：具体对象、向量或矩阵等表示、关键运算、结果与反例形成连续关系；同一符号、颜色、尺度跨镜头保持含义。镜头运动和高亮服务于当前叙述，不把固定节点图与移动粒子作为所有主题的默认视频。参考[3Blue1Brown Attention in transformers](https://www.3blue1brown.com/lessons/attention/)的视觉推理与制作认真程度，复杂度适合解释任务。

每镜头明确当前状态、新增操作及对应旁白。关键运算展示来源、逐项变化与中间结果，最终结论随解释完成后揭示；归一化显示共同分母，零贡献不以运动暗示有效贡献。图形、算式、字幕和旁白共用可复算事实源。比较时明确改变及保持的条件，重置须在画面交代；高亮绑定实际语义和音轨时间。先制作可播放样稿，再按真实音轨展开全片和阅读停顿；超长时精简无关内容或拆章，窄栏中的密集细节提供局部放大与可核对图文。

音轨的语言、音色与节奏依题材选择，按真实音轨编排字幕和镜头、保留阅读停顿并检查混音。作者提交固定音频文件及其内容摘要，检查者按实际成片判断。

播放器提供播放、暂停、定位与字幕，支持静音阅读以及文字要点或讲解文本。内嵌播放的活动字幕在画面下方按页面字号呈现，避免覆盖图形和数值；原生字幕开关继续控制显示，跳转同步当前句。支持元素全屏的浏览器提供“全屏观看”和“退出全屏”：视频与字幕整体放大，竖向视窗字幕在图下，横向视窗将字幕放在图旁，长句可滚动阅读，避免再次遮挡坐标与当前读数。切换字幕句时滚动回句首。元素全屏的播放、暂停、进度、静音、音量、字幕开关与退出操作排列在图外，暂停时不以原生控制条遮挡底部坐标和读数；退出后恢复页面播放器控件。系统视频全屏或画中画的兼容路径保留原生字幕轨，退出后恢复页面字幕；关闭和隐藏释放字幕及全屏监听与媒体资源。较长内容提供章节定位；页面不自动有声播放。关键结论和行动入口应能在不看完整视频的情况下找到。

页面先提供已核实的结论、交互和图文，视频通过“生成讲解视频”按钮按需生成。打开页面、回读材料或恢复历史均不启动生成。用户显式点击后才在后台生成，生成中、失败和可重试状态明确，视频失败不阻塞其他内容。成功的讲解视频、字幕和讲稿持久保存，再次打开同版直接恢复。播放中的版本保持稳定；有新进展时提示更新，不在播放中途替换内容。

### 进展汇报说明已经发生什么以及哪里需要介入

任务汇报按需要覆盖目标、当前状态、相对上次的变化、证据与产物、阻塞或不确定性、下一步，以及需要用户判断的事项。Lineage 汇报可按工作线组织，Project 汇报可按研究方向组织。没有可靠数据的部分省略或标为未知。

已受理、执行中、已有回复、已完成和失败应依据负责系统的实际记录显示。已有回复不能自动等同于目标完成；候选方案、预测和待办也不显示为已经实现的结果。

生成报告引用某次资料快照，并记录对象、来源修订或可获得的版本信息与核对时间。底层状态变化后提示汇报可能过期，允许重新生成。历史报告继续表达其生成时的情况。再次打开或来源变化时先核对原快照来源的访问权限；内容仍可读但版本已变时提示可更新，由用户选择刷新。播放与普通阅读都不触发静默替换，撤权则立即隐藏对应内容。

### 持久汇报与固定版本

一份已生成汇报具有正式资源身份与递增修订。首次在 Home 明确打开时保存，原聊天动作和历史条目固定引用当时版本。再次进入后，用户从历史明确选中时读取同版正文及已生成的视频、字幕和导出，不重新生成；显式刷新另开新版本，旧条目保持原样。稳定消息来源绑定在服务端按主体隔离，不能只依赖浏览器内存。生成结果的目录归属、权限与删除遵守[汇报资源、版本与成果目录](/r/decision_e3ced6d30f6b)。

## 左侧如何控制右侧

左侧可以要求生成展示、打开对象、切换视图、聚焦节点和返回此前展示。涉及对象修改时，通过负责该对象的既有能力执行，右侧根据实际结果更新；展示意图本身不证明业务操作成功。

展示控制至少表达目标对象、视图用途、需要聚焦的位置、关联对话请求和结果版本。展示意图由当前个人门面对话的结构化结果传递，不增加独立的业务指令或事实服务。

对话提交时附带本次展示请求标识；门面在 `portal-home-display` JSON 围栏中返回 `portal-home-display/v1` 协议、`request_id`、递增 `version`、`action`、`view` 和 `target`。容器仅接收当前对话中与已提交请求匹配的 Agent 输出，对动作、视图和领域目标做白名单校验。结果只声明展示意图，不执行返回的 HTML 或脚本。发送失败的请求不能消费后续成功提交的确认。

展示协议是容器与对话之间的内部数据，不能把其 JSON、请求标识或目标字段作为聊天正文直接展示。Home 对话中的有效 Agent 展示结果呈现为明确命名、可用键盘操作的紧凑动作，例如“预览幻灯片”“查看汇报”或“打开研究地图”，点击后沿已有展示容器和原生组件打开对象。普通 Markdown 代码、用户粘贴的代码不转换成展示操作；未完成、无效或不支持的协议不能执行。识别和校验由同一展示协议职责拥有，Chat 只提供消息呈现扩展，不另建协议解释或业务事实。

历史消息中的动作允许用户明确点击重新打开；这是一次新的手动展示选择，仍受当前资源权限与文档会话保护，不把旧请求重新算作当前自动结果。当前请求的自动消费继续校验发送确认、请求归属和版本，固定展示、草稿和手动选择仍能阻止迟到结果自动抢占。

| 用户行为 | 右侧响应 |
| --- | --- |
| 点击左侧某份文件 | 打开对应 Preview，保持左侧对话 |
| “汇报这个 Lineage 最近的进展” | 展示该团队的汇报页面，并提供来源与地图入口 |
| “做一下这个 Project 的 map” | 切换到该项目地图；准备或执行修改期间显示实际状态，成功后展示已保存结果 |
| “看看这个地图节点为什么卡住了” | 聚焦该地图节点，展示依据、进展与下一步；复杂问题可另开解释视图 |
| “回到刚才的文件” | 恢复相应文档会话与阅读位置 |

用户对右侧的直接操作与左侧控制共同使用同一个展示状态。用户在右侧选中的对象，可通过明确可见的“对话引用／当前选择”带回左侧；传递对象引用和必要上下文，不自动发送整个页面、其他标签内容或私人历史。

右侧保留稳定的返回、最近展示、固定视图及在原页面打开入口。播放、缩放、筛选、节点选择和普通文档操作可直接完成，不强迫用户通过聊天执行所有交互。

### 自动切换遵守用户当前意图

用户明确点击或要求展示时，可以直接切换。与当前请求相关的异步结果，仅在当前展示未被用户主动改变、固定或编辑时自动打开；否则提示结果已准备好，等待用户选择。

同一请求的新版本可更新其展示，旧请求的迟到结果不能覆盖新请求或用户手动选择的视图。返回历史时恢复文档位置、地图选择与缩放等相应状态。

固定的视图不被自动替换。存在未保存编辑时，切换应保留原文档会话；确实无法保留时，先提供保存、放弃或取消选项。后台生成失败不关闭仍可用的当前页面。

## 项目地图与团队地图的展示和操作

Project 地图复用研究地图与探索图层，Lineage 复用地图画布。主页负责将它们显示在右侧并定位对象，原生视图继续负责节点含义、布局、选择、编辑与修订。

地图中保留项目方向、负责团队、工作线与地图节点之间的区别。地图节点表示可理解和介入的问题，不能因展示或选择地图节点而隐式启动任务、暂停执行或新增审批。

用户在左侧讨论一个具体方向时，右侧可聚焦该方向及相关地图节点；用户在右侧切换选择时，左侧可明确引用该对象继续讨论。对象名称有歧义时，先确认具体对象，不凭名称切换到另一项目。

研究方向或地图节点的修改使用原有版本校验、权限与执行回执。并发冲突保留用户草稿并提示重新核对；部分团队读取失败时标出缺失范围，不将其解释为没有进展。

## 组件职责与状态归属

| 责任方 | 拥有的事实与职责 |
| --- | --- |
| 个人门面与对话 | 用户意图、对话连续性、对展示的请求及说明 |
| 主页展示容器 | 当前展示目标、历史、固定状态、切换顺序与异步结果归属 |
| Preview／Document Session | 文件呈现、文档草稿、保存状态与阅读位置 |
| 原生项目地图与团队地图组件 | 图的交互、对象选择，以及对现有领域能力的调用 |
| 任务、Project、Lineage 与资源服务 | 实际业务状态、版本、权限、执行结果和资源内容 |
| 汇报生成与呈现 | 基于可读资料生成的解释、素材、来源清单及快照版本 |

每个历史展示条目持有独立根节点和组件实例。容器负责显示、隐藏及最终销毁；适配器接收取消信号与请求标识，销毁或取消后的结果不能回写页面。隐藏时停止定时读取和播放，恢复时重新核对权限并保留领域组件的草稿、阅读位置或镜头。

Web 进程更新可能触发当前地址的页面重载。展示容器在当前用户的当前浏览器标签内保留经过校验的历史目标与顺序、固定状态和布局；新文档启动时不恢复活动目标，不创建历史目标的适配器或发起读取。用户从历史明确选择后才按当前权限打开对象。旧版本保存的活动目标同样降为历史入口，不自动打开。持久状态不保存报告正文、凭据或聊天内容，不重放业务操作或重新提交对话。用户主动关闭组件或切换身份时按相应边界清理，禁止跨身份恢复。通过浏览器页面缓存返回时保留现存实例，避免额外销毁导致草稿与展示状态丢失。文档草稿仍由 Document Session 负责，不能另建一套草稿真值。

生成的 HTML、视频和图示都是对业务事实的表达。它们不另存一份可自行决定任务完成状态的事实，也不重复实现文件权限或地图修改规则。

交互汇报中的演示控件只影响演示状态。需要真实提交的控件明确说明对象和动作，并经由已有宿主能力及权限检查执行。生成页面不能直接持有凭据或绕过业务接口。

主页复用已有投影协议与原生组件边界。显示一个对象不扩大调用者权限；生成汇报时读取权限与再次打开来源时的权限都须检查。权限变化后的内容不能通过旧缓存继续泄露。

## 小屏幕与可访问性

组件在桌面采用左右分区并允许调整宽度；布局随组件可用空间调整，避免挤压 Home 其他内容。小屏幕可以在“对话”和“展示”之间切换，保持同一对话、目标对象和阅读状态；返回对话后能继续讨论当前对象。

正文、图示和操作支持放大及键盘访问，控件具有明确名称。图示提供必要文字解释，视频提供字幕，减少动画偏好不影响读取关键内容。加载与生成过程均有可理解的状态提示。

## 验收情境

1. 从左侧点击文件后，右侧打开既有预览；编辑未保存时接收另一任务结果，原草稿仍可恢复。
2. 请求某团队进展后，先显示可核实结论，随后按需补充视频或交互组件；不选用的模块不占空白。
3. 视频能用配音与连续画面说明过程，字幕和文字要点可独立阅读；失败后仍能查看报告和来源。
4. 左侧提出项目地图请求后，右侧进入正确项目并聚焦相关对象；修改结果与正式地图修订一致。
5. 用户固定当前文件或手动切换地图后，较早请求的完成回调只提示可查看，不抢占当前展示。
6. 汇报明确区分执行中、已有回复和已完成，显示核对时间；数据缺失与权限失败均有说明。
7. 右侧选择地图节点后可以在左侧明确引用继续讨论；选择本身不触发任务执行。
8. 小屏幕在对话与展示之间往返后，内容、草稿与上下文保持连续。

## Resident 的呈现判断与生成入口

Resident 依据本次输入的有效汇报策略判断是否主动制作材料。主动性为 0 时不额外生成汇报；低、中、高以不同提示调节生成判断，依次偏向少量关键成果、确有理解收益的成果、主动识别值得呈现的成果。高主动性仍由 Resident 判断，不按每条请求固定生成。普通答复、业务最终交付和用户明确要求的汇报不受主动性 0 限制。用户明确限定格式、取消生成或不切换右侧时遵从其指令。策略的唯一责任方是 Society 的 Resident 设置；Home 每次发送读取设置供展示上下文使用，不覆盖服务端按真实转交链为当前输入选择的策略。

聊天中的简短文字已足以回答时直接回答，不为每个问题生成文件。用户明确要求只用文字、不创建文件或不切换右侧时遵从其限制；已有合适材料可直接打开。生成材料后，聊天保留关键结论和产物入口。生成与自动切换分开处理：固定视图、未保存草稿、手动选择及迟到保护持续生效，准备好材料不意味着可以抢占当前展示。

主题足够明确且材料有助于理解时，个人门面通过正式工具在自身有写权限的 Workspace 制作完整解释包。包由独立目录中的清单、交互文档、图文材料及可选的视频计划构成；材料已保存、回读并核对摘要后，才输出本次 request_id 对应的 explanation 指令。概念解释不虚构 Project、Lineage 或任务来源。已有来源的成果汇报继续使用 report_ID 与固定 revision。

解释包的清单使用 portal-explanation/v1，具有标题、摘要、正整数修订，按需要引用 video、video_plan、interaction、supplement 和 sources。文件引用携带真实 Workspace 文件地址和字节 SHA-256；explanation 展示目标同样由清单地址与摘要组成。历史保存固定引用，不保存正文、脚本、凭据或临时下载链接。新解释使用新目录，不覆盖历史材料；原文件内容发生变化时拒绝把新字节当成旧版显示，明确提示用户选择新的解释版本。

解释页的 HTML 宿主只组织一个“图文解释”正文区，视频讲解另列。图文解释把文字、图片、公式、图表与交互组织为同一条叙事，支持选择、比较、关联高亮、参数变化及计算结果反馈；必要的背景、推导、结论和适用边界直接放在对应图解附近，不在交互图解下再复制一个“图片与文字解释补充”区。清单中的 interaction 是完整交互正文，supplement 是纯图文正文或交互读取失败时的静态可读副本：两者同时存在时正常只呈现 interaction，没有 interaction 时在同一个“图文解释”区呈现 supplement；交互读取失败时保留错误与重试，并在该区读取可用静态副本。素材字段不对应两个页面章节，来源与延伸阅读可独立保留。旧固定包与审核记录不改写。图表、词语、矩阵和算式可共享选择状态并联动。交互的复杂度由理解任务决定，使用本地完整可视化库时保留许可信息和依赖，不以一个无实际作用的控件充当完整交互。

普通 Preview 保持既有文档与代码呈现边界。解释包中的自包含 HTML/CSS/JS 由专用解释适配器运行于不透明来源的隔离框架，不能读取父页面、凭据或站点存储，不能联网或外部导航。父宿主只负责合法资源读取、摘要核对、生命周期和模块组合；交互计算只拥有本地演示状态。依赖随包保存或以内联形式提供，生成页面不能直接调用业务写接口。无需为概念演示开放任意 HTML 文件的执行。

video_plan 是声明式的视觉讲解与配音时间计划，不是后端任意脚本。按需生成服务在当前主体权限下读取清单、计划与引用材料，核对固定摘要，检查成果目标的写入权限，再启动有界生成。媒体归原解释包的持久成果目录，同版并发请求复用同一任务和成果。页面隐藏时停止任务状态读取、音视频播放和交互运行，后台任务可安全完成；再次打开按当前权限核对并恢复。删除 Workspace 或解释包时按其原有文件与目录生命周期清理成果，缓存回收不删除正式媒体。

计算画面使用 scene.visual 的封闭声明合同：点积与缩放、指数归一化、逐维加权累加、单条件对照、因果矩阵、输入投影、多头拼接与输出投影、机制索引，以及通用数值图形 plot。数学操作由后端依据输入推导；plot 绘制固定来源样本、坐标、轨迹、波形和游标，作者说明模型、初值、单位、采样依据和误差，独立检查核对主题事实。plot 明确区分音轨秒与数据参数，trace 使用线性数据时钟，samples 保留离散样本，linear 只在同段内插值；缺测断线、视窗固定、暂停与跳转可重建。每镜最多4系列、4视窗，每系列最多16段、2048样本，全计划最多8192样本且仍受512KiB限制。plot 的轴、图例与主读数使用作者声明的物理名称和单位。可选 data.readout 从 parameter、x、y 中选择不重复的非空列表，默认只显示 x/y；平面轨迹需要时间时显式追加 parameter，不凭数值相等猜测物理量同义。画面去除实现前缀和模式标签，保留近似数值、单位与缺测信息，采样和插值依据写入配套解释。样本和绘制成功不能替代真实主题的内容验收。画面事件使用真实音轨中的绝对秒，并绑定字幕 cue，静默片段显式标记。作者不提交可执行渲染脚本，也不以周期轮播模拟语义高亮；窄栏成片必须读清坐标、关键数值与字幕。完整字段、维度与时间边界见 `/static/home_explanation_video_contract.md`，创作入口为 `/static/home_explanation_authoring.md`。

计划引用同包固定MP3或PCM16 WAV，包含address/sha256及真实字幕cues。媒体服务按当前主体检查文件权限、固定摘要、格式及时间范围；生成前和发布成果前核对实际音轨字节。计划顶层可保留创作注释，但只有已验证的渲染字段进入渲染器。场景及visual继续使用封闭字段合同。MP3由受管解码器转换，派生WAV记录独立摘要与实际时长。已有音轨、创作附件和ready视频保留原件，通过普通资源权限读取。新视频任务在受理前检查必需的音轨输入。

报告内置的概览动画生成字幕与画面，按阅读时间编排并明确标注无配音。解释页接受固定音轨，按上述媒体合同合成有声视频。视频编码使用编码器与字体。

句内动画依据同版固定音轨的实际语义时间安排；没有足够对齐依据时保留未对齐，不从字数或旧音轨倒推。作者选择能表达因果步骤的时刻，独立检查者在正常速度成片中核对可读停顿与步骤衔接；合法时间戳不等于讲解节奏或音质通过。

生成工具、写权限或回读失败时，说明实际失败并保留可用模块，不发出虚假的生成成功指令，也不把仅完成图文或修改提示称为完整解释页交付。真实模型是否按内容需要制作有效交互，仍须独立通过合法门面路径检查。

宿主必须将上述呈现判断和生成指导放进每次原生聊天发送的 submissionContext，不按用户措辞在前端筛选是否附加，并继续按当前请求、目标白名单、固定/草稿/手选及迟到隔离规则接收结果。原生发送夹具仅证明上下文到达和安全边界，真实个人门面是否生成、回读并自动打开仍须按授权身份验收。


## 汇报与视频的质量档位

汇报主动性与汇报质量分别保存，可在 Resident 菜单的设置中调整。settings.reporting 的 initiative 使用 off、low、medium、high；quality 使用 low、medium、high。默认 off/medium。Family 门面拥有自己的策略，实际承接者根据经过核验的转交关系消费该策略；设置不复制到成员，也不改变 Router 的模型参数。保存从下一次输入生效，不追改已送达上下文或已保存成果。

| 质量 | 汇报 | 视频 |
| --- | --- | --- |
| 低 | 清楚的 Markdown | 作者自由选择表达方式 |
| 中 | 现有交互网页模板 | 将 3Blue1Brown 式概念递进、图形变换、稳定视觉语义与节奏提示交给作者，形成实际分镜 |
| 高 | 沿既有解释页质量参照，由独立 Resident 操作固定版并审核 | 对齐 3Blue1Brown 式解释质量，由独立 Resident 实际播放固定成片并审核 |

视频按钮单独选择 low/medium/high，选择参与固定媒体的身份。切档不能直接借用另一档的 ready 结果；读取旧报告或旧媒体使用其原档位，不被当前设置覆盖。medium/high 的新视频都先交给负责 Resident 做正式分镜创作或修改任务；已有合法 visual.events 也不跳过这一阶段。任务记录来源摘要、实际负责者、质量和指导内容；只有实际语义分镜改变并形成新固定版，才可提交作者完成证明。只保存 guidance、提高分辨率或改变 quality 标签不表示质量提高。Portal 仍只消费固定的普通音轨与视觉计划，不因此新增配音工具。

审核由同一个持久 ReviewService 保存固定对象、摘要、作者、请求者、独立检查者、证据和状态。生成完成、送检受理和质量通过分别展示；只有检查者以本人身份提交与固定摘要匹配的 passed 及可回读证据才表示该版通过。送检、读取、取消和 verdict 使用既有 HTTP 与 Resident 客户端，不新增 HATG 指令。

视频送审同时交接该版 manifest、video_plan、计划引用的原音轨、交互和图文补充，以及本次成片、字幕、讲稿和封面。作者可通过 manifest.review_assets 明确选择本次必要的来源、对齐与计算材料，构建入口用可重复的 --review-asset 固定包内文件摘要；额外最多32项，总计最多40个文件。提交者须对全部选定来源有当前读取权，服务仅冻结这些字节，不扫描目录或授予整个 Workspace。补依赖产生新 manifest 与新审查，旧 blocked 轮及其固定选择保留；同包 resume 仅恢复原选择，不能原地增加材料或借旧结论覆盖新版本。

显式送审交接选定清单及其列明的固定依赖。服务以提交者当前权限读取与核对字节，将受控副本交给指定检查者，不授予原 Workspace 读取权，不扫描目录，也不从外网补依赖。检查者通过正式导出入口取得本轮副本并实际操作，报告和证据以固定副本反向交给请求者。每次读取重新检查参与主体、交接有效期与撤回状态；检查者在终态、取消、撤回或到期后停止取得副本，原请求者保留审计读取。原私有资源继续按原 ACL 保护。依赖缺漏须由作者补清单；原引用无权读取时，使用已明确交付的副本完成检查。

因权限、交接或检查能力产生的 blocked，在前提恢复后由原请求者显式 resume 同一固定作品，创建新的审核 ID 与轮次，保留旧结论和阻塞证据；旧轮迟到结论不得影响新轮。内容整改仍须新固定摘要并关联 previous_review_id。导出、查询和历史恢复不自动续审，显式取消禁止恢复，原请求者可在期限结束后明确发起新轮。宿主持续显示真实状态与可操作的反馈，不用未检查、受理或恢复动作替代通过。

changes_requested 带具体意见回到可核实的负责修改者；作者修改真正的交互图、叙事、分镜、字幕或音轨，保存新固定版并关联上一次审核重新送检。复审继续到达标、用户取消或有具体原因无法继续，不用固定轮数替代质量判定。传输失败的有限重试与作品修订轮次分开。旧版 passed 不适用于改版或变更字节，普通 GET、历史恢复不重新生成或送检。

### 正式来源与修改权限

Home 传入 `origin_context={resident_id,message_id,fence_index}`；报告服务以当前 actor 读取正式消息，核对 `portal-home-display` 围栏、目标与稳定 origin_key，再保存可核验的负责 Resident。普通代码围栏不占用展示序号，摘要使用与浏览器相同的文本规范。User 创建者保持原值；无可靠来源的 User 报告等待指定作者，不猜 AMA、活跃成员或请求体自报作者。

来源关联不授予写权。负责 Resident 必须用本人权限经正式 UpdateResource 修改；缺权明确返回资源、动作与主体，版本、媒体和投递不推进。持权请求者可通过正式授权入口委托，审核者不转借 User 凭据。独立审核排除作者、请求者及负责修改者。

模板报告带 authoring_id 提交实际 presentation 修改，保留来源拓扑；新的 revision 才能完成作者任务。解释视频由作者将新固定 manifest 经 `POST /api/home-explanation/media/authoring` 回填；服务核验本人、源摘要、质量、未取消任务和真实分镜语义变化。仅改变标题、注释、JSON 排版或质量标签不算完成。回填成功后再显式生成新版本，读取及重开不投递任务。

中、高质量解释页即使尚未保存 video_plan，也保留“生成解释视频”入口。点击后由媒体服务向负责 Resident 投递分镜和固定音轨准备任务，展示实际创作进度；普通打开、刷新与历史恢复只读取现有状态。已有视频计划仍走同一显式入口，缺少配音工具或来源权限时反馈具体阻塞，不以隐藏按钮代替状态说明。

合法成果读者按固定清单地址与 SHA 读取同一作品的正式审核状态和具体反馈，服务不因读取者变化重算作者或新建审核。提交时认证作者与负责修改的 Resident 持久绑定，User 点击视频也沿此关联交给原负责者。普通读者只见最小状态投影；取消、恢复、重试和证据读取按服务返回的 capabilities 显示，不暴露私有 subject、检查者身份或交接证据。刷新失败保留已知状态和操作权限。证据副本仍仅向被授权的原请求者或本轮检查者开放；阅读作品不扩大私人 Workspace 的权限。

高质量解释页的页头展示与当前清单地址和 SHA 绑定的独立审核状态、具体反馈及证据入口。宿主通过只读查询恢复作者提交的检查；尚未送检明确显示未检查，并提供显式补送入口。已提交不显示为通过，整改和阻塞持续可见；修改后用新固定版关联旧检查，不能借用旧版结论。作者接收到的 high 设置必须写入清单与构建参数，不能沿用 medium 默认值造成降档。构建命令要求显式填写质量参数；省略时在生成清单前拒绝，避免遗漏参数绕过高质量送检。

## 跨题材创作标准与独立检查

独立检查先核对用户已经委托的理解任务，再识别页面必须讲清的核心关系；作者自行缩小的局部目标不能替代原要求。事实与数值正确性、读者理解体验分别提供证据。涉及演化、连续变化或多对象关联时，页面须让读者观察过程、定位当前状态与差异，并在适合时通过控制条件检验关系。外层按钮、折叠区或旁支小实验不能代替核心机制的表达，静态数表可作为核对材料。检查者实际完成关键观察或干预，指出仍需读者自行想象的步骤和具体缺口；不得以控件存在或局部算数正确作为整体通过依据。简单事实保持简单表达，不以D3、动画或控件数量作为门槛。旧固定版的结论保留原范围；发现用户目标尚未满足时，以新固定修订和关联复审接续。

作者指南位于 Portal 同源 /static/home_explanation_authoring.md。三个参照为 [Transformer Circuits Global Workspace](https://transformer-circuits.pub/2026/workspace/index.html)、[Distill Paths Perspective on Value Learning](https://distill.pub/2019/paths-perspective-on-value-learning/) 和 [Distill Handwriting](https://distill.pub/2016/handwriting/)。学习其图文论证、可检验操作与因果反馈；不把某个主题、固定布局、D3、视频或控件数量作为质量门槛。简单事情采用清楚而完整的简单表达，复杂关系提供足以理解的交互与材料。

高质量请求的两类检查者属于实际负责 Resident 自己的直接 Family，分别承担“生成内容审核”和“视频内容审核”。Society 负责 Family 解析、真实成员生命周期与按角色幂等补齐；首次实际 high 请求进入时一次确保两类成员存在，后续请求复用同一 Family 的对应成员。显式 high 创作、生成和送审入口使用同一能力补齐，普通 GET、历史恢复、设置保存和提示预览不创建成员。用户选择 high 所要求的固定审核角色由该请求创建，不等同于授权 steward 自由调整其他组织成员。

Family 归属取自服务端已核验的负责 Resident，不取外部转发者、开发团队、Workspace owner 或客户端指定的 Family。User 发起生成时沿正式来源绑定定位负责 Resident；无法确定负责人或 Family 时保留具体错误，不按名称猜测 AMA。角色创建使用稳定 Family/角色标识，并发和中断重试不重复创建；页面与视频审核者相互独立，且都不得是作者、请求者或负责修改者。创建经现有 Society 生命周期加入真实名册，继承该 Family 的组织与私人保护；不通过新增显示行、临时借调或放宽私域 ACL 模拟成员。

作者接受自然语言的高质量页面或视频制作请求后，在创作开始前调用正式 `POST /api/home-explanation/reviews/prepare`；客户端为 `submit_explanation_review.py --resident-id <本人> --prepare page|video --quality high --task <理解任务>`。此入口只以实际鉴权 Resident 本人确定 Family，不接受替代负责者或 Family 参数，复用 Society 的同一角色准备能力；返回成员就绪，不生成作品、不创建审核记录、不派发审核或表示质量通过。结构化视频创作请求由服务在向作者派工前自动执行相同准备。单纯保存 high 偏好或不含制作行为的普通聊天不扩充成员。

高质量解释包由作者使用 build_explanation_package.py 构建与送检；已有高质量清单经 submit_explanation_review.py 送检。低、中质量不强制另发独立审核。ReviewService 只向已确定 Family 的对应审核角色投递；显式指定审核者同样须符合本 Family、角色和独立性要求，不再全局 SearchResidents 按名称发现，不含本站检查者 ID。私人 Family 成员无需进入公开找人候选才能收到审核。创建或权限失败保留具体失败状态，不回退到外部检查者或以 submitted 冒充通过。已有固定审查保留原检查者、资产、结论与历史，不因修复机制自动迁移、重送或恢复；新固定版或显式新审查轮次才使用当前 Family 的角色。

检查者实际打开固定版并操作，围绕理解任务检查事实、来源、图形语义、关键互动与联动反馈、信息层次、可访问性和性能。视频尚未由用户点击生成时不要求补做视频。报告记录版本、实际操作、截图、发现与未验范围，结论分 passed、changes_requested、blocked。作者回读同一清单摘要对应的报告，修复意见形成新固定版再送检；受理回执不等于检查通过，权限不足明确前提。普通打开、恢复历史或页面刷新不触发新的检查。该流程检查生成作品，不接管产品正式 User TAU。

高质量视频编码完成后，生成服务以实际生成主体经同一 Family 审核角色入口与正式投递触发独立视频检查，固定清单、视频、字幕与讲稿的地址和摘要。检查者不继承生成者凭据，以自己的权限真实播放并检查解释质量、数学与视觉对应、镜头连续性、字幕与旁白同步；只有实际听辨才能评价音质。页面检查不替代成片检查。检查投递状态 pending、submitted、submission_failed、not_requested 与生成状态分开；submitted 不表示通过。权限或服务故障不撤销已保存视频，允许显式重试检查且不重新编码；普通 GET、历史恢复不重复发消息，浏览器不能自报 passed。报告必须匹配该成片摘要，修改产生新版。

生成计划及固定音轨必须与清单位于同一 Workspace、同一包目录。音轨场景 start/end 与逐句 cues 使用实际时间；每次媒体请求重新鉴权来源，不能通过视频生成跨目录复制更私有材料。
