# 汇报资源、版本与成果目录

新汇报保存作者使用正式解释模板完成的固定解释包，以及支撑作品的来源和表达产物。来源快照只作为证据或历史资料，不自动拼装为新的交付汇报。用户从对话、展示历史或资源链接再次进入同一版本，继续阅读与播放。报告领域拥有保存、版本和成果生命周期；Home 只管理展示与引用。Task、Lineage、Project 仍是工作事实的唯一责任方，报告快照不回写这些事实。

## 身份和引用

每份汇报使用统一类型 report，根身份为 report_<12位小写十六进制>。同一报告使用递增正整数 revision 表示版本。report_ID/revision/N 指向固定版本，report_ID/revision/N/file/<文件名> 指向该版本的成果。省略版本的根引用可解析最新版本，展示后固定实际解析的版本。

一次保存固定目标、来源及其修订或内容摘要、核对时间、正文、交互解释所用结构。来源变化不自动覆盖这些内容。显式“刷新为新版本”读取新资料、追加版本，并保留旧引用及旧媒体。修改以最新修订为并发前提；发生冲突要求重新读取，不能覆盖别人的新版。

版本登记提交是对外可读的界限。刷新与关联导出共用追加版本的写入流程，在报告锁和目录登记事务内重新核验并发前提及来源权限。文件已落盘而登记回滚或进程中断时，下一编号的未登记文件仍是准备产物；重试清除该准备产物后按本次合法请求重新构建。已登记版本、原消息绑定及其媒体始终保留。新建只登记作者已完成的固定解释包；预留身份或未登记的来源快照文件不能恢复退役的自动创建路径。解释包登记仍按固定地址、内容摘要及既有事务合同恢复。

## 作者交付与再次打开

新汇报只通过固定解释包登记，包正文、交互及质量要求由解释创作域负责。Report 域不再从 Task、Lineage、Project 或消息来源合成另一份交付页，不因为打开展示意图、选择质量、点击保存或持有来源链接而自动创建作品。前端与正式 ResourceService 登记共用这条约束；User 代为操作不构成另一套新建入口。

`POST /api/home-report/explanations` 继续接受固定 `address` 与 `sha256`，返回正式 Report 身份与修订；已有固定包登记不是新创作，不重新生成、送审或改写旧质量。汇报设置由标准 Resident Prompt 表达创作要求，不作为服务端权限或业务受理条件。用户请求的目标 Resident 开启汇报时，协作成员的设置不阻止执行；构建、登记、修订、审核和媒体服务不检查汇报开关，不增加配置准入接口或专用“生成汇报”HATG Instruction。来源权限、实际身份、负责者证明、固定摘要与版本并发规则仍分别核验。

旧来源目标的直接新登记、没有既有绑定的 `POST /api/home-report/save` 及非 Report 目标的 `GET /api/home-report` 返回 `422 report.authored_package_required`，明确要求完成固定解释包登记；没有自动兜底页或自动创作投递。来源访问、固定包摘要和 Report 访问权限仍逐项独立核验。

兼容仅针对已经登记的历史 Report。再次点击原消息按原 actor 隔离的来源键读取已绑定版本；旧 save 操作可只读复用已有绑定，不新建、不刷新、不提交审核。缺失来源、权限撤销及删除墓碑保留原失败含义。已登记版本的下载、显式保存与 CAS 追加修订继续服务历史资料，新的写入或媒体创作仍遵守原资源权限、身份、摘要与版本规则；不把这些兼容操作推广为新汇报创建入口。

历史来源快照的呈现、导出与编辑仅消费已经存在的固定身份；当这些资源完成显式迁移或删除后，其兼容实现可退役。没有自动批量迁移、私域重生或审核结论移签。Home 的历史仅保存引用与展示意图，GET 不写入成果。

## 成果与目录

报告拥有 features:home-reports/<report_ID>/ 目录，版本成果位于其编号子目录。报告登记明确拥有路径，复用统一目录归属、注销与后台清理。正文 JSON、可阅读 HTML、来源快照与核对时间，以及已生成的视频、字幕、讲稿、章节、音轨和导出清单属于相应版本。

已完成的报告成果属于对象资料，随报告显式删除；不受临时缓存的七天期限或数量淘汰影响。生成过程的临时文件与已发布成果分开，成功后原子发布。失败、取消或进程中断必须保留可辨认状态；重试不能覆盖仍在读取的成功文件。

关联的 PPT 等导出记录明确来源和归属：报告自身生成的导出属于该版本；已有外部成果通过明确导入或资源引用关联，不因聊天里出现一个链接而自动复制。删除引用不删除外部对象。文件清单保存相对地址及内容摘要；不存在或摘要不符的已登记成果明确报错，不能伪装成“从未生成”。

报告概览动画的必需媒体为 MP4、字幕、海报、讲稿和 reasoning；它不内置合成语音。narration.wav 是真实存在时才登记、复制和取摘要的可选历史音轨；没有该文件时不显示音轨下载，直接读取返回不存在。缺少必需文件或出现不安全链接仍拒绝发布。解释页自己的有声视频另按固定音轨合同生成。

原有临时媒体只在主体、报告快照、源权限和文件完整性均可核对时迁入。已清理或不能归属的旧文件不能声称恢复成功。

## 展示和媒体恢复

打开固定版本时同时读取成果状态。已有视频直接呈现播放器；在生成的任务继续显示状态；失败保留重试入口。读取及恢复不隐式重新生成。文字先呈现，不等待配音或视频。

刷新打开新历史条目，旧条目及正在播放的媒体保持原版本。Host 使用 report 目标及 revision，报告组件通过 onReference 回传固定引用；来源请求键由 Host 传入，持久绑定及其判断由报告领域维护。对话协议的请求确认、固定展示、草稿、手动选择和迟到结果保护继续适用。

## 固定质量与独立审核

下述来源快照修订的兼容规则只作用于已登记历史资源；新作品的内容格式、质量与独立审核由正式解释包合同唯一决定。

每个修订固定 quality、format 与作者关联。quality=low 以 Markdown 交付；medium 采用交互网页；high 在交互作品保存后交给独立 Resident 审核。既有未注明质量的版本按原展示合同兼容，不反向改写旧版本。来源摘要与作品摘要分别保留，内容、交互或质量改变均生成新作品摘要。

同一消息来源键的首次保存已绑定质量后，另一个档位不能覆盖该绑定；显式刷新或修改通过 expected_revision 追加新修订，旧消息仍打开原修订。报告内容修改支持真正改变交互呈现与分镜，不能把高质量修订退化为只换一段 Markdown。修改不伪造来源中的事实、节点或关系。

视频的 low/medium/high 与报告质量分别选择，固定报告修订、媒体质量和资产摘要共同确定成果。重开只读取既有任务与成果，不编码、不送检。不同档位不串 ready 状态；取消、失败、恢复与迟到回执保持原对象归属。

报告和视频复用独立审核权威。审核固定作者、请求者、负责修改者的正式关联、检查者及作品摘要；只读者不能伪造作者身份或自审。检查者以自己的权限操作或播放固定版，用结构化 verdict 与实际证据给出 passed、changes_requested 或 blocked。受理、生成完成及检查通过独立呈现。无法确认负责修改者时说明缺口，不按资源标题或“当前忙碌”猜测。

否决意见经可靠投递交回作者，实际修改以新修订和新摘要进入复审；上一轮关联可追溯，旧通过不能转移，取消及明确阻塞保持真实状态。修订轮数不代替质量要求；网络投递重试有界并保留受理回执。通过后引用字节变更时原结论失效。报告权限和原来源当前权限在读取、送检与检查回填时仍须核验。

### 正式来源与修改权限

Home 传入 `origin_context={resident_id,message_id,fence_index}`；报告服务以当前 actor 读取正式消息，核对 `portal-home-display` 围栏、目标与稳定 origin_key，再保存可核验的负责 Resident。普通代码围栏不占用展示序号，摘要使用与浏览器相同的文本规范。User 创建者保持原值；无可靠来源的 User 报告等待指定作者，不猜 AMA、活跃成员或请求体自报作者。

来源关联不授予写权。负责 Resident 必须用本人权限经正式 UpdateResource 修改；缺权明确返回资源、动作与主体，版本、媒体和投递不推进。持权请求者可通过正式授权入口委托，审核者不转借 User 凭据。独立审核排除作者、请求者及负责修改者。

模板报告带 authoring_id 提交实际 presentation 修改，保留来源拓扑；新的 revision 才能完成作者任务。解释视频由作者将新固定 manifest 经 `POST /api/home-explanation/media/authoring` 回填；服务核验本人、源摘要、质量、未取消任务和真实分镜语义变化。仅改变标题、注释、JSON 排版或质量标签不算完成。回填成功后再显式生成新版本，读取及重开不投递任务。

## 权限和生命周期

汇报的创建归属由认证创建者固定。Resident 创建的报告位于该 Resident 的 R 树位置之下，随其 Lineage 和 Project 或个人 AMA 的归属管理；User 直接创建的报告位于该 User 的个人空间。登记前按相同父节点检查 RegisterResource 的协作权限，登记后从服务写入的 created_by 派生同一归属。请求体中的作者、项目或归属字段不能替换认证创建者，来源消息的负责 Resident 也不代替创建者。既有报告按保存的创建者恢复归属；缺少合法创建者的导入记录保留默认落点。报告来源当前权限仍独立核验。

访问时以实际主体核验报告权限及原快照所引用来源的当前权限，包括正文、媒体分段、字幕和导出下载。报告不是绕过源权限的副本。写入、刷新、生成、关联与删除遵守对应正式权限；不得把持有链接或资源摘要当作授权。不同主体的来源绑定彼此隔离，分享使用既有资源授权机制。

显式删除走报告资源的正式注销：身份立即不可再使用，拥有文件进入既有后台清理，失败保留待重试回执。清理检查完整的登记归属，不能将权限过滤后的空结果当作没有嵌套登记。在途生成必须隔离，不能复活已注销身份或重新创建其目录。删除报告不删除其来源对象或目录外关联资源。

## 固定解释包也使用汇报身份

作者编写的 `portal-explanation/v1` 包是新汇报的唯一内容入口，登记为 `report_ID`；不再把存储包的 `workspace_ID` 当作汇报身份，不新增平行资源类型。汇报修订保存 `content_kind=explanation` 与固定 `explanation_target={address,sha256}`，指向经过当前权限和摘要核验的解释包。正式引用始终为 `view=report,target={kind:report,id,revision}`，地址、搜索、共享 Chat 入口及 Preview 标识均使用该汇报 ID。

显式登记走 `POST /api/home-report/explanations`，请求仅接受固定包地址和摘要；创建者来自实际认证主体。相同创建者与固定包重复提交复用同一资源。跨主体的发现、复用与分享仍须遵守报告及全部来源的当前权限，持有地址或摘要不能替代授权。`GET /api/home-report/explanations` 只定位已有可读引用，缺少登记返回明确不存在；GET、历史恢复和设置保存不创建资源。

正式构建客户端在保存固定包并执行所要求的独立送检后登记汇报，返回服务给出的 ID 与修订。已有包通过同一登记入口补关联，不重建包、不覆盖摘要、不自动生成或送审。旧 `view=explanation` 按钮在显式打开时先查已有绑定，未登记时才调用正式登记；历史恢复仅查。已登记包的 Workspace 文件链接可只读解析为正式汇报引用。普通文件不因标题或目录名被猜测成汇报。

汇报域拥有资源身份、修订、权限及生命周期。解释域继续唯一拥有固定包解析、交互沙箱、页面检查、讲解视频及其原作者任务关联。报告读取重核来源；共享报告呈现组件按内容形态委托既有解释呈现组件，不复制另一套页面或视频状态。旧视频的 job、字节及质量档位、原始审核记录和原包到后继包的结果关联全部保持原值；登记不把 medium 视频或已受理审核升格为 high 通过。

报告删除只清理报告拥有的登记文件，不删除源 Workspace 包、独立审核记录或原媒体。这个取舍保留固定成果的历史与权限边界，同时补齐面向读者的汇报身份；Workspace 仍是存储来源，不承担汇报资源的角色。

## 责任边界

资源发现、统一地址、有效权限和目录清理复用既有 ResourceService 与目录协议。报告保存解释快照，不建立第二套任务、地图或文档事实。Home 不解析文件夹来寻找媒体，不以本地缓存猜测某次报告的归属。Workspace 可作为来源或关联成果，不为每个报告复制源 Workspace。
