# 目录与路径协议

Portal 在主机上为各种对象保存文件，例如项目资料、Resident 的身份文件和工作目录、代码仓库、论文和上传的附件。本协议规定以下几件事：
- 这些目录放在哪里；
- Portal 怎样记录它们；
- 什么时候删除它们；
- 在别处怎样引用其中的文件。

《Portal 实例协议》（decision_d88306d0bd17）管理整个实例，包括实例根目录、各个区域，以及整个实例的备份、搬迁和退役。本协议管理实例里的单个对象。例如删除一个 Resident 时，它的目录怎样处理，由本协议规定。

本协议遵循三条原则：

- **谁创建，谁清理。** Portal 自己创建的目录跟着所属对象一起删除。原本就有的目录接入 Portal 后，Portal 只记下位置；注销时不删除里面的文件。
- **删除是彻底的。** 对象删除后，它的目录连同里面的一切永久删除，不进回收站，也不因为别处还在引用而保留。这样不会积累没人负责的文件。误删后的恢复依靠主机自己的备份。
- **引用跟着对象走。** 需要长期有效的文件引用写成“对象 ID 加相对路径”，目录搬走以后引用仍然有效。

## 基本概念

**区域。** 区域是实例保存文件的几个顶层位置，由实例协议定义：
- projects：项目；
- lineages：不属于任何项目的 Lineage；
- skills：共享 Skill；
- papers：论文库；
- uploads：上传文件；
- features：各功能自己的数据；
- provider-state：Provider 为本实例保存的状态。

区域里的位置写成“区域:相对路径”，例如 `projects:<项目>/knowledge_base/`。区域整体搬到别处后，这种写法不用修改。

**对象与对象目录。** 对象是 Portal 管理的东西，例如 Project、Lineage、Resident、Workspace、代码仓库（Repo）、文稿（Article）、论文（Paper）、Skill、对话和测试运行。很多对象有一个目录保存自己的文件，这个目录称为对象目录。例如 Resident 的对象目录叫 Resident Folder，里面保存：
- 身份说明 `resident.md`；
- 工作日记 `diary.md`；
- 运行资料 `runtime/`。

**登记。** 登记是实例数据库里的一条记录，写明三件事：一个目录在哪里、属于哪个对象、来源是什么。Portal 只管理登记过的目录：知道它在哪里，并在对象删除时处理它。没有登记的目录，Portal 不记录也不管理；只有当它位于某个 Portal 创建的目录里面时，才会随外层目录一起删除。

本文中，“注销”指删除登记记录，“删除文件”指删除主机上的文件。

**所属对象。** 登记写明目录属于哪个对象，这个对象删除时，Portal 按来源处理目录。所属只决定目录什么时候删除，不决定谁能访问或修改它；权限仍按权限方案判断。

所属和关联是两回事。例如一篇 Paper 可以关联到某个 Project，但 Paper 的目录属于 Paper 自己，删除 Project 只解除这层关联。

**来源。** 每条登记都记录目录是怎么来的，只有两种：

- **接入的现成目录。** 用户或 Agent 通过“接入”操作，把一个已经存在的目录登记给某个对象。例如用户把自己的代码仓库 `/home/<用户>/myrepo` 登记为 Repo。即使这个目录原本是 Portal 为别的对象创建的，通过接入操作再次登记时也记为接入。
- **Portal 创建。** 其余登记都记为 Portal 创建，包括两种情况：
  - Portal 为对象新建的目录，例如新建 Resident 时生成的 Resident Folder；
  - Portal 扫描自己管理的目录时发现并登记的资源，见下文“扫描发现的资源”。

来源由登记方式决定，与目录在区域内还是区域外无关。

**Workspace 与绑定。**
- **Workspace** 是登记过的工作目录。
  - 每个 Resident 有一个自有 Workspace，即 Resident Folder 下的 `workspace/`。它在新建 Resident 时由 Portal 创建，作为 Resident 的默认工作目录。
  - Resident 还可以使用额外的 Workspace，例如一个任务目录，或者用户自己的代码目录。
- **绑定**表示某个 Resident 使用某个 Workspace：Resident 启动时，Portal 告诉它有哪些工作目录可用。
  - 绑定只表示使用，不改变目录属于谁；解除绑定也不删除目录。
  - 登记和绑定都不改变主机上的文件权限。Resident 实际能读写哪里，由主机权限和运行环境决定。

**未登记目录。** 未登记目录是 Agent 或人自己在主机上建立、没有登记的目录。这里的 Agent 包括 Resident，以及 Resident 启动的工具。

## 目录一览

下表列出各种对象目录的默认位置、所属对象和删除时机。表中的 Lineage Folder、Resident Folder 指第二、三行的目录。

|目录|默认位置|属于|来源|什么时候删除|
|---|---|---|---|---|
|Project 目录，含知识库 `knowledge_base/`|`projects:<项目>/`|Project|Portal 创建|删除 Project 时|
|Lineage Folder|属于项目的在 `projects:<项目>/agents/<Lineage ID>/`，其他在 `lineages:<Lineage ID>/`|Lineage|Portal 创建|删除 Lineage 时|
|Resident Folder|`<Lineage Folder>/residents/<Resident ID>/`|Resident|Portal 创建|删除 Resident 时|
|自有 Workspace|`<Resident Folder>/workspace/`|Resident|Portal 创建|删除 Resident 时|
|额外 Workspace|创建者指定，可以在区域内，也可以在主机上任意位置|创建时指定的 Resident、Lineage、Project，或者 Workspace 自己|两种都可能|所属对象删除时|
|交接副本|`<Lineage Folder>/handoff-workspaces/<交接 ID>/<项>/`|副本 Workspace 自己|Portal 创建|删除这个副本或所在 Lineage 时|
|Repo、Article 源码|项目目录内，或主机上任意位置|Repo、Article|两种都可能|删除 Repo、Article 时|
|Paper 包|`papers:items/<年>/<包>/`|Paper|Portal 创建|删除 Paper 时|
|Skill|`skills:<名称>/`，或项目知识库的 `skill/` 下|Skill|Portal 创建|删除 Skill 时|
|上传文件|`uploads:upload_<ID>/`|上传它的对话或对象|Portal 创建|可直接删除；所属对象删除时；上传后一直没有用到的，7 天后删除|
|主机执行账号目录|主机用户选定的位置|主机|按接入对待|从不删除|

上传文件是普通文件，Resident 可通过系统工具修改或删除内容文件，也可删除整个上传目录，不需要专用 HATG 删除指令。既有目录维护任务只检查上传根目录下已登记的直接子目录：根目录可访问且保持原身份时，整目录缺失，或稳定的已完成元数据所指内容文件缺失，才注销保留登记并让既有清理队列删除剩余元数据、转录等文件。未完成上传、缺失或变化中的元数据、根目录不可访问及 I/O 错误保留登记。创建上传时，空目录与登记在同一事务内准备，避免创建间隙被误判为删除。正常修改已存在的内容文件不改变其生命周期；原消息和文档引用仍保留，后续访问按文件不存在处理。

**“两种都可能”的目录按登记里的来源处理。** Portal 创建的随所属对象删除，接入的只注销。

**额外 Workspace 可以属于它自己。** 这种 Workspace 不跟随任何对象，只在有人直接删除它时删除。它如果位于某个 Portal 创建的目录里面，仍会随外层目录删除，见下文“外层目录优先”。

**主机执行账号目录按接入对待。** 这个目录保存 Codex、Claude 等订阅账号的登录信息和会话记录，属于主机。同一台主机上的多个实例，以及人在终端里直接运行的命令行工具，可以共用同一个账号目录。

登记账号时如果目录还不存在，Portal 会先创建一个空目录，但仍按接入对待：Portal 只登记，注销账号只删登记，从不删除或移动这个目录。

**扫描发现的资源记为 Portal 创建。** 知识条目、Skill、文稿等资源，有一部分是 Portal 扫描自己管理的目录时自动登记的：Agent 或人直接在项目知识库、skills 区域等位置写好文件，Portal 扫描发现后登记。

这类登记没有经过接入操作，所以记为 Portal 创建。删除这类资源时也删除它的文件；如果只注销，下次扫描又会把它登记回来。不想让 Portal 删除的目录，应放在 Portal 管理的目录之外，再通过接入操作登记。

## 删除

**删除一个对象时，Portal 删除它创建的目录，连同里面的全部内容。** 目录里的东西一并删除，包括：
- 嵌套登记的 Repo、Article 和 Workspace；
- 后来接入登记的现成目录；
- 用户或 Agent 手动放进去的文件。

这些嵌套登记同时注销，其他 Resident 指向这些目录的绑定同时解除。

例如删除一个 Project 时，会一并删除：
- 项目目录下的知识库、代码仓库；
- 各个 Lineage Folder，以及其中所有 Resident；
- 以上各项的全部登记。

**外层目录优先。** 位于 Portal 创建目录里面的一切，都随外层目录删除，不管里面的登记来源是什么、属于谁。例如一个接入的 Repo 放在某个 Resident 的自有 Workspace 里，删除这个 Resident 时，Repo 的文件也一起删除，Repo 的登记同时注销。

**直接注销接入的现成目录时，只删除登记，文件原样保留。** 例如用户把 `/home/<用户>/myrepo` 接入为 Repo，后来注销这个 Repo，目录和里面的文件都还在。Portal 后来在这个目录里创建的子对象也不受影响，仍然随各自的所属对象删除；例如在接入的工作目录里克隆了一个 Repo，这个克隆随 Repo 删除。

**删除时不考虑引用。** 以下引用都不会让目录保留下来：
- 其他 Resident 的绑定；
- 其他对象里的链接；
- 消息里提到的路径；
- 删除过程中新出现的引用。

引用方之后再访问，会得到“对象已删除”或“文件不存在”。

**删除 Project、Lineage 或 Resident 时，先终止其下正在运行的工作，再删除。** Resident 正在进行的回合、Lineage 中正在执行的流程都直接终止，终止情况如实记录，然后照常删除。Portal 不等它们自然结束，否则长任务会把删除无限推迟。

**删除 Workspace 时，不终止正在使用它的其他 Resident。** 这些 Resident 的绑定被解除，正在进行的执行继续运行，之后读写这个目录会得到文件不存在的错误。

**先注销，再在后台删除文件。** 删除请求分两步完成：

1. **注销。** 删除请求先在数据库里注销对象、嵌套登记和绑定。注销后对象立刻从各个列表中消失，不能再打开或绑定。
2. **后台删除文件。** 文件由后台清理任务删除。删除失败会自动重试，Portal 重启后继续，直到删完。

删除结果分两部分报告：登记是否已经注销；文件删到了哪一步，失败原因是什么。例如文件被占用时，结果显示“登记已注销，文件清理待重试”。登记注销以后，不会因为文件删不掉而恢复。

**Portal 直接删除文件，不经过回收站。** Portal 不自建回收目录，也不检查主机有没有回收站；程序删除的文件不会进入操作系统的回收站。误删后的恢复由主机负责，例如主机用户的定期备份。

**删除不沿软链接进行，也不删除区域根和实例根。**
- 目录里的软链接只删链接本身，链接指向的目标原样保留。
- 如果登记的位置恰好是某个区域的根目录、实例根目录或它们的上级目录，说明登记有误。Portal 拒绝删除文件，并报告这条登记。

**有权删除对象，就能删除它目录里的全部内容。** 删除权限按当前权限方案判断。目录里嵌套的资源不再逐个检查权限。

## 按期限清理的文件

有些文件会在对象存在期间不断增加，例如临时文件、缓存、测试证据和旧版本的构建结果。只靠对象删除来清理，它们会越积越多，所以按期限清理。

**Portal 的每个功能写文件时，都要说明文件属于哪一类，Portal 按类别自动清理。** 一个文件只属于一类，由写它的功能决定。例如测试运行中途写出、结束后就不再需要的日志属于运行临时文件；作为测试结论依据保存下来的日志属于测试证据。

|类别|例子|清理规则|
|---|---|---|
|运行临时文件|一次运行中途写出的文件，默认放在 `<实例根>/runtime/tmp/<服务>/<运行 ID>/`|运行结束后立即删除，无论成功、失败还是被终止|
|测试证据|测试的截图、日志和结论，存放在测试框架为这次运行保存的记录中|运行结束 7 天后删除|
|缓存|文稿构建缓存（`<实例根>/cache/` 下）、工具缓存|每种缓存设有容量上限，超出时先删最久没用的；删掉的内容可以重新生成|
|构建产物|工作台应用的构建结果，`features:projection_applications/<摘要>/`|保留每个应用的当前版本和上一版本，更旧的版本在被替换 7 天后删除|
|后台任务产物|某个功能为一次后台任务生成的中间文件|任务结束 7 天后删除|
|Provider 会话残留|`provider-state:<provider>/` 中已结束会话留下的文件|会话结束 30 天后删除|
|对象资料|其余属于某个对象的数据，例如对话的工作目录、Paper 的工作区|随所属对象删除，不按时间删除|

这些类别适用于 Portal 各功能自己写的文件，不论文件放在哪个对象目录里。Agent 在工作中自己写的文件不按类别清理，随所在目录处理。例如 Resident Folder 的 `runtime/` 里：
- 临时文件在运行结束时删除；
- 缓存按容量清理；
- 其余是对象资料，随 Resident 删除。

**多个工作台应用共用的构建产物，有应用在用就保留。** 构建产物按内容摘要存放，内容相同的产物只存一份。只要还有任一应用的当前版本或上一版本在使用这份产物，它就保留。

**期限可以延长，不能取消。** 功能可以为自己的后台任务产物、缓存等声明更长的期限或更大的容量，但每类文件都必须有删除时机，不能无限保留。测试证据固定保留 7 天。所属对象先被删除时，这些文件随对象一起删除。

**测试证据不放在被测对象的目录里。** 测试结束时被测对象会立即删除，证据如果放在它们的目录里会被一起删掉，因此证据保存在测试运行记录中，按自己的 7 天期限删除。

## 路径写法

**保存目录位置时，在区域内就写“区域:相对路径”，在区域外就写规范绝对路径。**
- 规范绝对路径指解析掉软链接和 `..` 以后的完整路径。
- 所有保存目录位置的字段都按这一条规则选择写法。目录从区域内移到区域外，或反过来移动时，写法随之改变。
- 详细规则见实例协议中的“路径的两条规则”。

**引用登记目录里的文件，写成“对象 ID 加相对路径”。** 例如一份报告记录交付物的位置：

```json
{"workspace_id": "workspace_0123456789ab", "relative_path": "reports/result.md"}
```

Workspace 搬到别处以后，这条引用仍然指向同一个文件，不用改写。Repo、Article 等其他登记目录里的文件，同样用各自的对象 ID 加相对路径引用。

**相对路径统一用 `/` 分隔，不能用 `..` 或软链接跳出对象目录。** 这样同一条引用在 Linux、macOS 和 Windows 上含义相同。

**打开引用时，先找对象，再找文件。**
1. 负责该对象的服务先确认对象存在、调用者有权访问。
2. 再到对象的当前位置下找这个相对路径。

三种失败分别报告：对象不存在或已删除、无权访问、文件不存在。服务不会退回去按旧的绝对路径查找。

**消息和文档正文里手写的路径不会自动更新。** 对象移动以后，历史消息或文档里写的绝对路径可能打不开。需要长期有效的引用，使用上面的对象 ID 加相对路径写法。

## 创建与接入

**Portal 只在空位置创建目录。** 创建对象目录前，Portal 先做两项检查：
- 调用者对所属对象有权限；
- 目标位置上还没有文件。

目标位置已经存在时创建失败，用户可以改为接入这个现成目录。这样 Portal 不会把别人的文件记成自己创建的，以后也就不会误删。

**正在清理的位置不能再用。** 一个对象删除后，它的目录在后台删完之前，这个位置不能用来创建新目录，也不能接入。否则后台清理可能删掉新对象的文件。

**目录和登记都就绪，对象才算创建完成。** 创建中途失败时，可以用同一个操作 ID 重试。重试沿用同一个对象和同一个目录，不会重复创建。

**未完成的创建可以明确撤销。** 管理该对象的服务保存冻结的创建请求、已分配的身份及其父对象。对父 Lineage 有 `@viewer` 权限可以通过 `GetResourceCreation(lineage_id, resource_id)` 读取 Resident 创建状态；有 `@contributor` 权限可以通过 `CancelResourceCreation` 撤销尚未登记或恢复的创建。服务核对父对象与冻结请求的真实归属，不以调用者提交的路径作为清理依据。

撤销先持久记录调用者与受理时间，并封闭原创建操作。原操作不能继续登记、覆盖撤销状态或用同一操作 ID 重试。撤销受理与文件清理分别报告：`cancelled=true` 表示撤销已经受理，`cleanup_complete=true` 才表示文件清理完成。写入者仍活跃、结束证据不足或文件身份不匹配时，清理保持 pending，返回具体原因；已受理的撤销不回退。后续调用可以重试清理。

Creation 是创建文件、占位及清理的唯一责任方。它在删除前取得写入与原生子进程的排他执行准入，核验结束证据，再按已保存的文件身份删除；外来替换目录保持原样。占位一直保留到所有清理完成。撤销本身不能伪造旧 writer 的结束回执，也不能仅凭时间经过、失败状态或空闲锁认定写入已停止。

缺少旧 writer 元数据时，调用者可附 `originating_instruction_id`，仅作为原创建指令的引用。管理对象的服务在原操作与创建锁内读取权威执行回执，核对原调用者、指令、冻结分配和 Creation 操作之间的身份链。只有已证明正常退出且文件初始化完全同步的责任链，才能作为结束证据：普通 Resident 创建没有来源派生、Provider 会话克隆、Git 或后台写入，原指令以父 Lineage 版本冲突正常返回未提交时，服务保存该正常退出的证据并允许 Creation 取得新的清理 writer。中断结算、未知提交状态、身份不符或可能遗留异步写入均不能用此证明清理安全；已有 writer 元数据仍按其自身证据核验，不被该途径覆盖。

**接入要求目录已经存在。**
- 接入只增加一条来源为“接入”的登记，Portal 不移动、不改名这个目录。
- Resident 可以在接入的 Workspace 里正常工作，但注销时 Portal 不删除其中任何文件。
- 接入的目录不能位于本机其他实例的实例根目录或区域内，见实例协议。

**Portal 也可以在区域外创建目录。** 任务需要大容量磁盘或主机上的特定位置时，可以让 Portal 在那里创建一个 Workspace，来源记为 Portal 创建，并照常指定所属对象。它和区域内的 Workspace 一样，随所属对象删除。

## 移动

**移动目录时，对象 ID 不变，登记改到新位置。** 用“对象 ID 加相对路径”写的引用不需要改写。

**登记始终指向文件实际所在的位置。** 移动按以下顺序进行：
1. 把文件放到新位置；
2. 把登记改到新位置；
3. 删除旧位置的文件。

在第 2 步之前失败，Portal 删掉新位置上不完整的副本，登记仍指向旧位置。在第 2 步之后旧位置删除失败，由后台清理任务重试。

**移动进度记在数据库里，Portal 重启后从中断处继续。** 中断在第 2 步之前，就删掉不完整的副本，重新开始；中断在第 2 步之后，就继续删除旧位置。

**目录里的嵌套登记一起改到新位置。** 例如移动一个 Workspace，它里面登记的 Repo 位置也同时改为新路径，第 2 步对它们一并完成。

**跨文件系统移动前，先终止正在这个目录里工作的执行。** 同一文件系统内的移动是一次改名，瞬间完成。跨文件系统时只能先复制再删除，复制期间写入旧位置的内容不会带到新位置。因此 Portal 先终止正在使用这个目录的执行，再开始复制。

**Portal 只移动自己创建的目录。** 接入的现成目录由它的主人自己移动，移动后更新登记里的位置。

**依赖旧位置的记录由负责的服务同时更新。** 例如 Resident 的默认工作目录、Provider 会话里记下的工作目录、Git 工作树之间的链接。这些记录没有全部更新完时，移动不报告完成。

区域整体搬迁和实例整根搬迁由实例协议规定。

## Portal 生成的文件

**Portal 只覆盖自己生成的文件。** 有些文件由 Portal 根据数据库内容生成，例如 Resident Folder 里列出已绑定 Workspace 的 `workspaces.md`。
- 数据库内容变化时，Portal 重新生成这些文件；写入失败会自动重试。
- 人或 Agent 写的文件，例如 `resident.md`、`diary.md`，Portal 不覆盖。
- 要修改生成文件反映的内容，先修改对应的数据库记录（例如绑定），再由 Portal 重新生成。

## 协作中的目录

**多个 Resident 共用的任务目录，建议做成一个 Workspace，由任务发起方拥有，各参与方绑定。** 发起方可以是一个 Resident，也可以是一个 Lineage。
- 任务结束后直接删除这个 Workspace；或者在删除发起方时，它也会一起删除。
- 绑定只是让参与方启动时知道这个目录。参与方即使没有绑定，只要主机权限允许，也能访问这个目录。

**Context fork 有自己的 Workspace，并继承父节点的额外绑定。** Context fork 是复制一个 Resident 的上下文得到的新 Resident。
- 它有自己新建的自有 Workspace。
- 它也绑定父节点绑定的其他 Workspace；父节点的自有 Workspace 不继承。
- 删除 fork 只删除 fork 自己的目录。

**交接副本是独立的 Workspace。** Lineage 中一个成员把工作目录交给另一个成员时，Portal 可以在 Lineage Folder 的 `handoff-workspaces/` 下复制一份，登记为新的 Workspace。
- 删除交接记录只删除交接关系。
- 副本可以单独删除，也随所在 Lineage 删除。

## 未登记的目录

**Agent 可以在主机上自由创建目录、留下文件，Portal 不限制、不追踪，也不清理。** 这些目录由创建它的 Agent 或主机所有者负责清理。

**希望 Portal 负责清理的任务目录，建议在开始时就让 Portal 创建为 Workspace。** 任务目录指 Agent 为某个任务创建的目录，用来存放数据、产物和协作材料。由 Portal 创建的 Workspace 会随所属对象删除，不会遗留。如果目录已经建好，事后接入只会登记为“接入的现成目录”，Portal 仍然不会删除它，清理还是由创建者负责。

例如，几个 Resident 协作完成一次实例安装，把监督记录和验收证据放在主机 HOME 下的一个目录里。
- 如果这个目录没有登记，任务结束后需要由发起任务的 Agent 自己删除。
- 如果一开始就让 Portal 在那里创建一个属于发起方的 Workspace，那么任务结束时删除这个 Workspace，或者删除发起方时，目录都会一并删除。

**放进 Portal 创建目录里的未登记文件，随目录一起删除。** 例如 Agent 在自有 Workspace 里随手建的子目录，会在删除 Resident 时一起删除。

## 测试与实验

**单元测试使用临时实例，结束后整体删除。** 每次测试为自己准备三样东西：
- 一个只有清单的临时实例根目录；
- 一个独立的数据库 schema；
- 若干临时目录。

测试结束后全部删除，测试过程不读写真实实例的文件和数据。

**在真实实例上运行的测试，结束时删除本次创建的全部对象。** 这类测试包括由 Resident 执行的真实页面验收，以及开发工作台中的设计点测试。

每次测试运行有一个运行 ID。本次创建的 Project、Lineage、Resident、Workspace 和各种资源都记在这个运行 ID 下，后台为这次运行创建的对象也一样。运行结束时：
- Portal 终止其中仍在运行的工作，删除这些对象及其目录；
- 夹具目录（为测试准备的样本文件）立即删除；
- 截图、日志和结论等测试证据保留 7 天后删除。

测试框架长期使用的固定 Resident 属于框架本身，不随单次运行删除。

**完整站点测试搭建的是一个独立实例，测试结束后按实例协议退役。**

**实验文件建议放在 Workspace 里。** Resident 做实验时产生的数据、脚本和结果，建议放在为这次实验登记的 Workspace 中，实验结束后删除这个 Workspace 即可清理干净。

实验记录（experiment 知识条目）是知识资源，按知识库规则管理；删除实验记录时，它的伴随文件一起删除。

## 实例层面的处理

**实例退役时，所有对象都被删除，Portal 在区域外创建的目录也一起删除。** 接入的现成目录和主机执行账号目录保留。

**Portal 在区域外创建的目录不在实例备份里。**
- 实例备份和整根搬迁只处理实例根目录和各个区域，见实例协议。
- 区域外由 Portal 创建的目录如果需要备份，由主机负责。
- 实例换到另一台主机时，由操作者在新主机上准备好这些目录，再更新登记里的位置。

## 不同操作系统

**在大小写不敏感的文件系统上，只差大小写的两个名字视为同一个位置。** macOS 和 Windows 默认是这种文件系统。创建时遇到这种情况，按目标位置已经存在处理。

**文件名含有当前系统不允许的字符时，创建失败并报告原因。** 例如 Windows 不允许文件名中出现 `:`。

**文件被占用导致删除失败时，按删除失败处理，由后台重试。** Windows 上正在被程序打开的文件通常无法删除。

## 实现方式

**登记由管理对象的组件保存在实例数据库中。**
- Lineage、Resident 及其成员关系由 SocietyService 保存，它是管理 Lineage 与 Resident 的服务。Resident 对 Workspace 的绑定也由它保存。
- Workspace 的身份、位置、来源和生命周期由 WorkspaceStore 保存，它是 Workspace 的登记表。新建 Resident 时，自有 Workspace 的登记和 Resident、绑定在同一次数据库写入中完成。
- 项目里的资源由 ResourceService 编排，它负责资源的统一登记、读取和删除。
- 论文包由 PaperStore 管理，它是论文库的存储。

一条登记至少包含对象 ID、位置、来源和所属对象。

**删除分为前台的注销和后台的文件清理。**

```text
删除请求
  → 检查删除权限
  → 终止其下正在运行的工作（删除 Project、Lineage、Resident 时）
  → 注销对象、嵌套登记和绑定，同时记下要删除的目录   ← 删除请求在这里返回
  → 后台清理任务逐个删除记下的目录
       失败：记录原因，稍后重试；Portal 重启后继续
       完成：记录完成时间
```

注销和“记下要删除的目录”在同一次数据库写入中完成。即使 Portal 在注销后立刻重启，清理任务也不会丢失。

后台清理任务只删除记下的目录。每删一个目录前，再确认它不是区域根、实例根或它们的上级目录；遇到软链接只删链接本身。

记下的待删目录同时起到占位作用：创建和接入时查到目标位置在待删列表中就拒绝；扫描登记资源时跳过待删目录，不会把正在删除的资源重新登记回来。

**到期清理按各功能的声明执行。** 每个功能声明自己的文件类别和期限；Portal 定时找出到期的文件并删除，删除失败同样会重试。

**打开文件引用由管理该对象的服务完成。** 打开 `{对象 ID, relative_path}` 形式的引用时，按以下步骤进行：
1. 管理该对象的服务查登记，得到对象目录的当前位置；
2. 拼接相对路径；
3. 确认结果仍在对象目录内。
