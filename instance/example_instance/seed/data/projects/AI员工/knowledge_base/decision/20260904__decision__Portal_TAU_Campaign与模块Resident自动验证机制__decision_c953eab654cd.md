# Portal TAU Campaign 与模块 Resident 自动验证机制

TAU（Test by Agent Use）让 Agent 从真实用户入口使用产品，完整走过一个用户目标，写下过程、问题和性能体验。确定性自动化测试负责可重复的程序断言；TAU 提供真实使用反馈。

## 用例与 Campaign

用例以用户目标、用户会怎样操作、要留意什么和报告什么组织正文。操作指向用户能够识别的页面、控件和反馈，不把内部字段、特定 DOM role 或网络请求必然出现当作业务完成条件。实现声明提供稳定用例身份、模块、任务说明及所需夹具。

全部选中实现为 TAU 时组成一个 Campaign，共用运行 ID、冻结计划和汇总报告。不同模块并发，同一模块依目录顺序执行；一个用例受阻不影响其他用例。并发预算限制资源占用，调度排队时间单独记录。

## 执行身份与准备

TAU 职责绑定指定执行团队；每个模块复用独立 Resident 和执行槽位。模块占用覆盖发送、观察和清理，取得模块锁后再取得全局名额。成员通过普通 Resident 和 Lineage 能力创建、配置与释放。

受控测试账号用于登录本次指定实例和部署（Dev 或 Release）。准备阶段核对实例、目标地址、身份、运行能力和请求指定的账号设置。公共任务说明不预设 Dev；汇总目标依据各用例保存的实际预检身份，缺失或不同部署分别明确记录。缺少权限、错误目标或未具备运行条件时不执行业务动作，报告流程未开始及原因。身份检查保障操作对象正确，不评价产品体验。

运行请求可以冻结本次账号、模型、推理强度、权限预设和逐例补充要求。只配置本次有权控制的执行成员，不修改全局默认值和产品已有业务成员。模块切换账号前等待原工作结束，实际设置回读一致后发送；账号额度不足记录前提限制。

运行明确禁止付费 credits 时，Codex 业务动作使用显式的原生额度前提（require_native_quota）：在发送或推进初始化恢复之前刷新原账号，要求原生额度新鲜、可知且严格为正，并继续核对当前执行门。既有 Session 的开放 gate、ready 或付费 override 不代表本次运行允许付费；额度耗尽、未知或陈旧时不发送，也不调用可能推进初始化的交互回调。交互后重新读取时仍应用同一限制。该策略只约束本次测试调用，不撤销其他任务已有的合法 Session 授权，不修改全局保护或共享业务绑定；普通 API 业务保持登记的 Provider 和原计费契约。

暂停准入只拒绝新 Campaign，已接收的工作继续完成、恢复和清理。更换模块执行者先释放旧槽位及专属流程；忙碌或释放未完成时保留原槽位，不重复发送。

## 真实使用与恢复

Agent 先使用产品，遇到问题后再结合源码和 Design 诊断。页面加载时正常等待用户需要的内容，不把加载中、定位器歧义或暂时断线直接当成产品缺陷。菜单、表单和目录按实际产品交互操作；目录可以从正式文件入口读取，缓存命中时不强求出现新请求。

框架保存目标身份、原请求和幂等键，受理后保存实际消息 ID。中断后接续同一请求或输入，不因回执丢失、观察超时或缺少材料重发业务。请求是否受理不明时先只读核对；取消回执与实际执行终止分别记录。

Campaign 由独立执行进程承接。Web 重启不取消已有工作；执行进程退出后由接管者恢复原计划和已受理输入。冻结计划确保用例正文改动不改变在途任务。构建变化作为运行上下文记录，正常发布不改变使用报告结论；重新连接时核对目标身份后继续。

浏览器和辅助进程属于本用例，使用受控启动器和独立上下文。用例结束关闭自建进程，框架回收遗留进程；不终止其他用例或框架父进程。Windows 执行器与 Web 生命周期分离，平台能力缺项写入运行限制。

## TAU 使用报告

TAU 让 Agent 像真实用户一样完整使用产品，再报告使用中的问题。每个用例产出一份使用报告，包含三部分：

- **过程**：用户目标、实际操作、流程是否走完；未走完时写明停在哪一步及原因。
- **问题清单**：每条写现象、发生步骤、截图或原始响应，以及严重程度。问题分为产品问题、用例问题、执行偏差和工具问题；严重程度分为阻断（无法继续）、影响使用和小问题。
- **性能体验**：关键步骤的耗时，哪里慢、慢多少；优先记录创建、首次加载、关键操作、删除与重启后恢复。

计时、截图、原始响应和因果关系是帮助理解问题的材料。没有记录的写“未记录”，可补充观察并说明取得时间；不伪造原始记录，不以材料完整性给用例判通过或失败。没有录下截图也可以报告实际看到的现象。

用例步骤、等待条件或接口用法与产品设计不符时，修正用例并在报告归入用例问题。模型没有按用例操作归入执行偏差；辅助脚本或观察工具出错归入工具问题并修工具。它们不计为产品问题。

发布和重启是正常使用环境的一部分。短暂报错后等待、刷新或重新连接，能够继续就记录恢复过程和耗时，不列为产品问题。重启后操作仍卡死、数据丢失或必须人工处理才列为产品问题。网络中断本身也不代表产品故障；无法继续时说明环境限制和停留步骤。

报告不要求每步原样一次成功，不要求完整计时或因果链，也不因漏记材料安排重跑。验证修复时按受影响的真实用户行为选择复验范围。

## 记录格式与呈现

Agent 使用 `PORTAL_TAU_RESULT:` 输出机器可读使用报告。`process` 保存 `status`（`completed`、`blocked`、`not_started`）、操作步骤 `steps`、停止位置 `stopped_at` 与原因 `reason`；`issues` 每项保存 `category`（`product`、`case`、`execution`、`tool`）、`severity`（`blocking`、`impact`、`minor`）、`symptom`、`step` 与 `evidence`；`performance` 保存关键步骤耗时与体验，`evidence_gaps` 说明未记录的材料。

产出使用报告的用例记录为 `reported`，不生成 TAU PASS/FAIL。框架的排队、执行、取消和异常状态只描述运行管理，不代表产品质量。没有结构化报告时保留实际输出，并说明报告缺项或工具问题，不从缺证据推断产品故障。

Campaign 按模块汇总过程完成情况、四类问题和严重程度。Test 页呈现三部分报告、已知限制和可用材料；产品问题数量独立于工具问题和用例问题，不能混成失败率。截图、响应和耗时可以打开查阅，未记录项直接显示未记录。

## 临时对象与清理

默认复用正式绑定的团队，只在隔离图修改、创建或删除团队等确有需要的用例声明独立团队理由。停止、重置和 Fork 使用本用例的临时成员，保护执行者、固定团队和其他用户对象。

新建对象通过运行生命周期关联精确 ID；回收标记包含运行和模块身份。关联表示清理责任，不授予权限。清理通过正式产品接口核对归属、状态和授权，先停止本用例工作，再回收业务对象、成员、团队和 Workspace，最后删除独占夹具目录。输入资源、搜索结果和既有对象不进入自动回收范围。

删除请求保存参数和幂等键，中断后恢复同一次请求。清理不成功时保留目标和原因供重试，不把未知结果当作已删除。清理恢复不要求重跑用例。证据留在运行产物目录，业务夹具放在允许登记资源的区域；运行目录不能绑定为 Workspace。文件与目录的生命周期遵循目录协议。独占夹具也复用目录协议的原生删除能力，包括Windows只读Git对象；原生样例同时验证删除当前链接、保留其他链接的内容和只读属性，权限或占用错误不得冒充已清理。

## 公共提示与辅助函数

公共提示和辅助函数按代码管理。改变之后先过固定小样例，再发布并供后续 Run 使用。样例覆盖真实产品控件、身份定位、正常加载、菜单表单、目录缓存、工具观察和重启恢复；等待条件必须由产品真实交互支持。辅助观察缺失时返回未记录或工具问题，不能阻断正常业务流程。

新增工具缺陷纳入固定回归，验证修复前后的行为。样例验证工具与提示本身，不替代真实用户使用报告，也不要求为漏记材料反复重跑。诊断需要精确身份时保留请求 ID、资源 ID 和时间等材料，材料的用途与产品结果分别说明。
