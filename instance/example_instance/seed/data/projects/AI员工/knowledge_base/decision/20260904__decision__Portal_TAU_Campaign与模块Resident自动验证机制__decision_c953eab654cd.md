# Portal TAU Campaign 与模块 Resident 自动验证机制

TAU（Test by Agent Use）是 Portal 测试框架登记的真实使用执行方式：由一个 Agent 像真实用户一样，用受控账号 `portal-test` 登录当前 Dev，在真实页面上完成一项用户目标，保存截图和操作记录，然后再阅读源码和 SPEC 诊断发现的问题。它补充确定性的 pytest 验证。原独立 Playwright 界面测试套件已删除；TAU 自己的可选 Playwright 运行时仍用于真实页面操作，二者不能混为同一执行入口。选测预算及非例行发布门禁的约束统一见 `decision_6febe7bb57f9`。

本 Design 说明一次 TAU 运行怎样按功能模块组织、每个模块由哪个 Resident 执行、执行中断后怎样恢复、Agent 必须遵守的测试协议、测试中创建的临时对象怎样回收，以及报告包含什么。测试条目、运行计划和运行记录的通用规则见 `decision_8273271b67b1`；Test 工作区中的 TAU 面板见 `decision_f2a6a5dd4646`。

## 基本概念

- **TAU 用例**：带 `tau` 实现的测试条目。实现中的 `task_prompt` 是交给 Agent 的任务说明；TAU 用例的定义保存在 `tests/cases/tau_cases.json`，并同步到测试目录。
- **TAU Campaign**：全部实现都是 `tau` 的一次运行。它只有一个运行 ID（`testrun_…`）、一条运行记录和一份汇总报告。
- **模块组**：Campaign 中属于同一功能模块的用例。每组由该模块的 Resident 按目录顺序依次执行。
- **统一团队与模块 Resident**：Portal 职责 `tau` 指向 Portal 的软件工程核心开发团队（`lineage_8794980b1bb7`，模板见 decision_78134209e5c9），界面仍称 `TAU Lineage`；所有模块执行 Resident 均属于这个团队，模块名称用于区分 Resident。团队中的测试成员统一负责选测、Campaign 调度、失败分类和验证结论，回归执行成员负责回归运行与失败复现；团队不另设 TAU Leader。`tau` 职责绑定通过受控的配置读写入口切换并回读，与 Test 工作台的 main 绑定分别维护。团队和成员通过普通创建、迁移与职责登记指令管理，不新增 TAU 专属类型或指令。
- **执行槽位（slot）**：模块与执行身份之间的绑定记录，保存在测试框架实例目录的 `tau-residents.json` 中，包含模块 ID、槽位 ID、Resident ID、Lineage ID，以及可选的指定账号和速度设置。
- **结论（verdict）**：Agent 在用例结束时输出的机器可读结果，以 `PORTAL_TAU_RESULT:` 标记开头。
- **证据目录**：每个用例在本次运行产物目录中的专属子目录，截图、操作记录和辅助文件都保存在这里。

## 设计点

### Campaign 的组织

- **不同模块的用例并发执行，同一模块内按顺序执行。** 同一个 Resident 依次处理本模块的用例，可以延续之前形成的理解；不同模块并发，缩短跨领域验证的时间。
- **默认最多同时运行 8 个模块。** 环境变量 `PORTAL_TEST_TAU_MAX_PARALLEL_MODULES` 可以调整，运行请求中的 `max_parallel_modules` 可以为单次 Campaign 指定，取值都限制在 1 到 32 之间。这个上限约束测试框架自身的资源占用；Portal 的执行调度器和账号并发限制仍可能让任务排队。
- **一个用例失败不影响其他用例。** 失败的用例记录结构化结果后，同模块继续执行后续用例，其他模块照常完成。
- **Campaign 结束后生成汇总报告。** 报告按模块列出每个用例的结论、体验、诊断和证据（见“报告”一节）。

### 模块 Resident

- **每个模块首次运行只在统一团队中创建 Resident，之后持续复用。** 框架以 `portal-test` 身份读取 `tau` 职责绑定，再按稳定执行槽位创建普通 Resident。绑定缺失、无权读取或已有成员尚未迁入目标时明确失败，不自动创建备用团队。正式迁移保留 Resident 身份与历史，下次准备执行时以权威成员归属刷新槽位中缓存的 Lineage ID。
- **TAU 目标团队通过应用配置读取和切换。** `tau` 的目标 Lineage 保存在应用配置表 `application_targets` 的 `tau` 一行中，应用名由 Test 功能声明（`application.targets`），由维护者在主机上用 `scripts/application_target.py` 读取和修改（decision_6591e7793116“应用配置与执行身份”），没有对应的 ISA 指令。切换团队的顺序是：先把 `tau` 设为暂停接收；暂停生效后，新的 TAU Campaign 在登记前明确拒绝，已经接收的 Campaign 照常运行、恢复和收尾；等待相关工作结束后切换目标并回读；验证完成后恢复接收。切换只改变 TAU 的目标团队，Test 与 WALL 工作台的 main 绑定分别维护，不随之改变。
- **模块共享团队，各自独立执行。** 同一团队内的创建和工作流修改使用已有团队锁串行提交，模型执行继续按 Campaign 的模块并发预算推进。每位模块 Resident 有自己的对话、执行槽位和工作流。
<!-- wall: {"key": "8ee6b7053fc74a0d"} -->
- **模块更换遵循明确请求或关闭身份恢复条件。** 用户显式“更换”与下一条的不可用身份替换都使用执行槽位规则：先通过公共释放流程处理旧槽位的 Resident 及其专属流程，再写入新槽位。原成员忙碌或释放失败时保留原槽位供重试，不在其上重复发送。成功后下一次运行在目标团队创建新成员；已经发生的 Run 保留当时身份与证据，但不承诺被释放 Resident 仍可作为活动成员打开。槽位文件的持久化规则见下文。
- **模块 Resident 无法继续接收输入时，框架自动换用新槽位。** 如果账号和速度配置完成后 Resident 仍处于关闭状态，框架保留该模块的账号与速度设置，换用新的槽位，在发送用例之前创建并准备好新 Resident 再继续执行，不把这种关闭当作整批运行的配置失败。
- **所有 TAU 执行都使用 `portal-test` 身份。** 无论谁发起运行，模块 Resident 都以 `portal-test` 登录、检查目标和调用 Resident；全部 Resident 共用这个账号和同一个 Dev，不建立测试数据隔离。
- **框架在统一团队中为每个模块 Resident 安装“TAU 模块验收”工作流。** 工作流由一个手动触发事件、一个调用 `DeliverMessage` 的效果和目标模块 Resident 组成，固定提示要求真实操作、保存证据和按结果协议返回；每个用例作为一次触发送达，本次的用例、运行和证据目录只写入这一次输入（工作流的一般形式见 `decision_4adcc1ff2f2c`）。框架在提交后立即保存返回的消息 ID，恢复时等待同一条消息，不重复提交。

### 账号与运行设置

<!-- wall: {"key": "3beaa524234351a5"} -->
- **可以为模块长期指定 Codex 账号和速度。** 通过 `decision_8273271b67b1` 所述接口认证的调用者通过 `POST /test/api/tau/resident/configure` 提交 `module_ids`、已登记的 Codex 账号 `backend_route_id` 和布尔值 `fast`（`true` 使用 `priority` 速度）。配置保留 Resident、团队和槽位，校验后立即返回；需要换账号的模块如果有排队、运行中或正在取消的 TAU 运行，请求被拒绝。尚未创建的模块 Resident 在首次运行时使用保存的配置。
- **发送第一个用例前，框架核对模块 Resident 的实际账号和速度。** 需要换账号时，框架通过 `RestartSession` 以“智能”上下文策略为 Resident 开启新的会话，带来源会话代次和稳定的幂等键，并等待 Resident 已有的工作结束；原会话保留在原账号上。账号已经一致时只更新运行设置。已有一次指向其他账号的迁移正在进行时，配置准备失败，不覆盖那次迁移。准备过程响应取消，迁移失败时给出明确错误，不提前执行测试。
- **执行账号到达额度保留线时，模块准备立即失败。** 额度保留会暂停该账号全部 Resident 的新工作，重启或换用新槽位都无法恢复；框架发现模块的指定账号处于保留状态时，不发送用例、不替换模块 Resident，结果中写明账号和剩余额度，额度恢复或改用其他账号后重跑。读取不到额度时不阻止运行。
- **没有发出的用例记为 `unsupported`。** 模块账号与 Campaign 指定账号不一致、账号或速度配置没有就绪、Resident 的实际运行设置与要求不符时，用例没有交给 Resident，结果状态为 `unsupported`，失败分类为 `precondition`（见 decision_8273271b67b1）。这些结果只说明运行前提没有满足；已经发出的用例按 Resident 的结论记录。
- **`GET /test/api/tau/residents?module=…` 报告每个模块的实际状态。** 返回实际账号、速度、迁移状态和 `ready`；只有配置一致且没有未完成的迁移时 `ready` 为真，运行才会发送用例。
- **单次 Campaign 可以指定账号和 Resident 运行设置。** 运行请求的 `implementation` 可以带 `resident_account_id`（已登记的 Codex 账号）和 `resident_runtime`（`model`、`reasoning_effort`、`permission_preset` 中的一项或多项，权限预设为 `default`、`auto-review` 或 `full-access`；需要同时指定账号）。它们只用于纯 TAU 运行，写入冻结的计划并参与计划 ID 的计算。发送每个用例前，框架用 `UpdateResidentSettings` 调整模块 Resident，再用 `GetResidentSettings` 回读核对，不一致就不发送。任务说明同时要求本用例调用、创建或 Fork 的全部 Codex Resident 使用同一账号和设置并保存核对证据；独立 API 模型保留原来的提供方和模型。页面提供账号或设置选择时显式选择；页面没有提供的选择（例如 Fork 沿用来源设置、新建表单中没有的项）不是用例步骤，也不算覆盖缺口，发送前用 `GetResidentSettings` 核对，不一致再用 `UpdateResidentSettings` 调整。产品在被测流程中自行创建并立即启动的成员（例如 WALL 分配的工作成员），以及产品已绑定、本用例无权修改的共享业务成员（例如论文绑定的 Research Chat Resident），记录实际账号与设置后照常使用，不因此判定失败，也不为迎合约束修改它们或产品默认值。该要求不修改全局默认账号或无关成员；无法满足时如实报告，不换其他账号重试。
- **发起者可以为本次选中的 TAU 用例补充运行要求。** 请求的 `implementation.case_instructions` 是按用例 ID 索引的非空字符串字典；框架去掉首尾空白，仅接受本次选中的纯 TAU 用例，非 TAU 或未选中用例的补充要求使计划校验失败。规范化要求写入冻结请求及对应的 selected 项并参与 `plan_id` 计算，只传入对应用例的任务说明和 `run-context.json`，不修改 Catalog 用例正文、站点默认或账号登记。
- **运行例外必须逐步明确。** 补充要求可以明确授权当前用例中需要跨账号等行为的具体步骤；这些步骤按该要求执行，其余步骤继续遵守本轮默认约束，不把例外扩展为任意失败备用路线。任务说明要求完成后核验指定的恢复状态并保存证据；这不替代正式权限检查，也不自动证明恢复已经完成。将例外冻结在当前 Run 的依据是：跨账号验收需要可复查的发起者约束，同时不得把一次验收的例外写回共享用例或扩大到其它用例。

### 执行与恢复

- **发送前保存请求，受理后保存实际输入。** 运行记录先持久保存目标 `resident_id`、`lineage_id`、稳定 `request_id` 和完整工作流/原指令定位；此时 `submission_state=pending`，请求 ID 不能当作输入 ID。正式回执或校验过的原 TriggerPath 确认实际 `message_id` 后改为 `submitted`，只观察这条输入。
- **丢回执时只读恢复，不重复提交。** 服务中断、指令失败但提交状态未知或执行进程退出后，按保存的原请求定位读取指令和实际 TriggerPath；没有实际输入回执时保持待确认，不选最新活动输入，不重发 TriggerEvent 或业务消息。暂时不可达、未找到或因果歧义不证明未受理。确认受理后继续观察同一输入；只有明确未受理证据才能结束为未发送。
<!-- wall: {"key": "e4b0008d749a3ca6"} -->
- **Campaign 在独立的测试执行单元中运行，发布和 Web 重启不打断它。** 执行单元的启动、宿主身份、进程退出判定和重启节流统一见 `decision_8273271b67b1`；TAU 单元不进沙箱，以 Web 相同的服务路由调用模块 Resident，用例仍作用于当前真实 Dev。
<!-- wall: {"key": "d3c72b53c9520f35"} -->
- **执行单元在 Campaign 结束前退出时，未完成的 TAU 运行继续。** 在通用进程身份规则确认可以接管后，新执行进程按原计划及已记录的 Resident、Lineage、请求和输入身份继续观察，不重新读取工作树中的任务定义，不丢弃执行与证据。分组因恢复准备出错而标为 error，但仍保存有效调用身份时，也继续恢复原调用。已经提交的调用不再检查源码摘要；尚未提交的用例仍须通过摘要检查。开发 pytest 使用独立状态目录，导入框架入口不恢复或修改正式 Campaign。
- **取消回执与执行终止事实分别记录。** 测试结束时的执行终止与对象目录清理按《目录与路径协议》（decision_4aa13bc21e8e）处理。用户取消或外层不可恢复错误后，只能撤回已确认的实际输入；取消回执为 cancelling、取消失败、queue item not found、目标构建检查失败均不能证明输入终止。未确认受理或终态时保留 active_invocation 与真实状态，不写完成时间或伪造用例终态；接管者先恢复原请求，再终止实际输入并如实记录结果。
- **准备身份和安装工作流时，暂时不可用不算失败。** SocietyService 或 ResourceService 暂时不可用、同一指令仍在执行时，框架继续核对原来的请求；明确拒绝和取消立即结束。模块 Resident 的创建与工作流安装共用同一把团队修改锁，避免并发准备时争用版本。

### Dev 目标检查

公共浏览器启动器在认证 `/api/me` 成功后、创建首个可导航页面之前，比较 `run-context.json` 的初始构建与实际构建。发生变化时，它原子追加 `build_observations`，记录实际构建、读取时间、记录时间及 `authenticated_browser_launch` 来源；初始构建和本次用例身份保持原值。`tau-browser-launch.json` 同时保存初始/实际构建与读取时间。连续启动看到同一个最新构建时不重复追加，身份校验失败时不记录为有效构建观察。Agent 核对这份先于导航的原始回执，无需事后补写构建变化。

部署、断线或页面恢复后，执行者在继续业务操作前调用 `portal.verifyIdentity()`，以当前浏览器认证重新读取 `/api/me`。启动与显式复核都将实际身份、构建、HTTP 状态、原调用起止与耗时追加到 `tau-browser-identity.jsonl`；显式复核标记为 `explicit_recovery`。错误身份立即拒绝，合法构建变化追加到 `build_observations`，初始构建保持不变。框架自动引用并保留该原始日志，后续查询不能补造此前恢复时的身份或构建证据。

- **运行前后都检查 Dev 目标。** 运行前，框架从实例登记表找到唯一的 Dev，确认它的 Web 运行的是当前激活的 Dev 代码标识、当前 `/development?view=test` 页面可访问，且其通过 `/development/native-views` 加载的 Test 组件提供要求的指纹、`portal-test` 会话的用户和构建都来自这个 Dev；任一项不符就不运行。用例结束后再检查一次：实例、地址或用户变了，结论改为失败；只是 Dev 正常重载导致代码标识变化时，记录变化并保留原结论。
- **传输故障和校验失败分开处理。** 连接中断和 HTTP 502、503、504 视为暂时不可用，继续等待。同一 Dev 的激活标识、Web 健康和 portal-test 身份响应在正常重载中可能暂时处于不同构建；框架记录首次构建差异，最多等待 60 秒重新验证，只有完整校验通过后才继续，不重复投递已提交输入。持续构建不一致、构建标识缺失、错误实例或用户、HTTP 401 和 403 拒绝运行。错误证据只记录阶段、构建标识、异常类型和状态码，不记录凭据或响应正文。
- **首次检查结果与已提交的输入一起保存。** 框架重启后另记一次恢复检查，仍与首次的构建比较；旧输入没有首次检查记录时明确标为 `not_recorded`，构建变化记为未知。

## 公共提示与测试辅助函数的验证

- **公共提示和测试辅助函数按代码管理。** 每次修改后，先运行仓库中的固定小样例，全部通过后才发布，并用于后续正式 Run。
- **固定小样例在几分钟内验证主要测试行为。** 样例使用原生页面或组件的真实浏览器定向测试，以及隔离服务测试，覆盖 Chat 就绪与身份、完整 Session ID、相对定位、Fork 后 Editor 发现、菜单到表单、Family 夹具隔离和原调用终态读取；运行使用统一固定命令，失败、跳过和缺少依赖均不算通过。
- **提示的每项等待条件必须有实际页面依据。** 新增或改变字段、元素、状态与定位条件时，对应样例证明它由原生页面提供，并验证正确身份、加载过程和失败分支；可选显示能力不能成为普遍就绪门禁。样例不得手造产品没有的字段来满足提示。
- **新发现的辅助问题先成为回归样例。** 对应检查在修复前的代码或提示上复现失败，修复后通过，并纳入固定组；证据分别保存原失败和修复后的结果。
- **自然语言提示的审查与执行样例共同确认语义。** 修改者逐项将改变的条件映射到样例的原生入口和断言；措辞检查只防止已知错误原样回归，不替代行为验证。原生组件测试核对显示和交互契约，隔离服务测试核对身份、名册与终态契约。
- **固定组通过不替代正式 TAU 验收。** 发布记录保留样例命令、结果及所测提示版本，正式 Run 继续采集本次业务、视觉、原动作计时、首次刷新与清理证据，历史失败不回填。

## Agent 的测试协议

- **先作为用户完成任务，再诊断。** Resident 先在真实页面上完成用户目标，记录如何找到入口、做了哪些操作、看到什么反馈、等待和试错、如何恢复以及最终结果；遇到问题或完成体验后，才阅读源码和 SPEC 诊断原因。
- **加载中的区域没有结论。** 页面区域仍显示加载态（`aria-busy="true"`、“正在读取…”“正在加载…”、英文 Reading/Loading 等文字或进度指示）时，Resident 先等待加载结束再枚举控件和截图，并记录实际等待时长；不得据此判定入口缺失、内容为空、服务不可用或刷新后卡住。同一区域超过 60 秒仍在加载，才把持续加载连同时长记为产品事实。定位同时命中多个元素引起的严格模式错误属于辅助脚本错误，不能当作等待超时。 就绪判断应同时核对该区域的预期内容已出现，不以某一个加载词消失代表完成。辅助脚本过早截图或关闭浏览器时保留原证据，修复辅助步骤后只补只读观察；不得重放已受理的业务输入，也不得把辅助错误改写为产品失败。
- **结论必须机器可读并有证据。** 结论包含 `status`、`summary`、`issues`、`evidence`、`visual_review`、`user_experience` 和 `diagnosis`。证据必须是本次证据目录中真实存在的文件；界面类用例至少要有一张实际查看过的 PNG 或 JPEG 截图。证据不存在、越出证据目录或缺少截图时，框架把结论改为失败。每个用例开始操作前，Resident 在本次证据目录写入并回读运行标记，在 `run-context.json` 记录操作时实际读取的构建；报告不能引用其他运行的证据。
- **已经被系统接收的工作要观察到真正的终态。** 业务系统确认接收了 job、输入、消息或调用后，Resident 持续观察同一个 ID 直到成功、失败或明确不可恢复；固定时长只记录为性能数据，不作为失败阈值、观察上限或另起任务的理由。排队、运行中和暂时不可达都不是终态。
- **Resident 不递归启动测试，不使用其他浏览器配置。** 除非用例本身验证这项能力，Resident 不启动 Test 运行或 TAU Campaign。需要浏览器时在本用例的证据目录中启动受控的辅助进程，不连接默认或固定的调试端口；复用浏览器前核对本用例的启动回执、进程和动态地址。用例结束时关闭自己创建的页面、浏览器上下文和进程，框架再按证据目录回收遗留进程，并保护框架自身及其父进程。
- **同一用例的消息内容在 Dev 重启前后保持不变。** 发送给 Resident 的内容不包含会变化的构建标识；起止构建由框架的运行前后检查分别保存。
- **只读的业务用例从当前产品入口发现测试对象。** 它们在本轮开始时找到正式对象并记下 ID，不依赖可能已被删除的历史资源；缺少所需的图、调用或产物时报告前置条件不满足，不降低验收要求。

临时上传使用独立的清理入口：本用例新建的 `CreateUpload.upload_id` 写入 `test-fixtures.json.uploads` 字符串数组，框架调用内部上传文件清理，不经过 HATG 指令，也不检查上传者权限。上传句柄不放入正式资源 `resources` 清单；删除失败时保留句柄和文件供恢复，只有删除成功或明确不存在才移出清单。

### 工具运行时的页面观察

公共网络观察器区分资源解析、文件存在性探测（`meta=1`）与正文读取，记录目标地址的 SHA-256 摘要以关联同一目标的多次请求，不保存文件路径、资源地址、任意查询值或响应正文。HTTP 错误发生时立即刷新原 frame/document 的观察采样；这些事实只用于诊断，不自动豁免错误，也不改写原请求状态。 Resident 页面读请求按当前公开完整路由和对应的单一身份参数识别目标：projection、navigation-target、session-restart-options、watchboard 使用 id，forward-targets 与运行配置目录使用 resident_id。身份只保留摘要；公开 ISA 的单 Resident 读取与生命周期操作使用显式 resident_id 关联。缺失、无效或重复身份参数，以及未登记的路径或操作，均不推断目标。请求与响应仍以独立 request_id 连接，目标相同只证明关联，不证明错误原因；删除回执、目标消失及界面结果需分别取证。

工具运行中停止的验收由公共浏览器辅助函数 `waitForRunningActivity` 等待目标 Chat 的可见运行证据。页面同时打开多个 Chat 时，调用方通过 `scope` 传入已确认身份的目标面板；存在多个候选活动卡片时，等待器明确报错。它读取运行摘要，或点击可见摘要展开详情，再检查工具标题与 `running` 状态。命令行、原生动态工具和 MCP 工具均可提供这一运行证据；等待器不能只匹配 `Command started` 而忽略 `Tool:`、`Tool progress:` 或 `MCP:`。已经完成的工具条目不满足运行前置条件。 `scope` 可以位于同一浏览器的另一页面；等待器从该目标确定页面身份，内部详情定位和页面关闭检查均使用目标页面。默认入口页面关闭不会中断仍然存在的目标 Chat 等待。

文档重载或 Chat 重建后，等待器重新解析目标定位并展开当前详情，返回当时可见的文字及浏览器时钟时间。调用方继续负责把观察结果与本轮输入、页面和请求关联，看到目标工具运行后立即提交停止操作。等待超时保留为取证失败；公共等待器只读取界面和展开详情，不发送或重发业务输入，也不把之后的补充样本计作原样本成功。

一次清理尝试中的传输重试复用相同幂等键；修复删除责任方后重新清理，使用新的尝试键，以免重放先前已确定失败的指令。只删除原清单中的精确对象，已完成的删除按领域规则幂等确认。

复用模块执行者前，框架重试该模块已结束用例的失败清理；另一个模块仍在运行不阻止这项恢复。仍在运行的同一模块不可被清理。删除失败的资源及原失败记录保留，成功的清理回执防止重复回收。

模块执行期间的跨进程互斥覆盖调用、等待与清理；取得模块锁后才取得全局测试名额，等待同一模块不占全局名额。扫描失败清理时，已删除或因报告保留上限淘汰的终止 Run 不阻塞新执行；通用保留上限见 `decision_8273271b67b1`。恢复清理成功只更新清理回执，不改原测试失败结论。

## 临时对象的创建与回收

- **默认复用固定团队，不为测试新建团队。** 业务验收使用产品真实的固定绑定，并记录实际执行身份；导航、筛选和显示检查复用已有对象。
- **需要独立对话、停止、重置或同团队 Fork 样本时，在统一 TAU Lineage 中创建临时 Resident。** 执行者自己和已有成员不作为破坏性测试的对象；产品创建的业务成员按正常规则绑定；删除本用例的测试条目和工程时，由产品清理相应成员。
- **只有声明了理由的用例才能创建独立临时团队。** 只有验证建队、删除团队、Fork 出新团队或需要隔离修改整张图的用例，才在实现中填写 `lineage_fixture`（非空的理由，且实现必须声明 `external-side-effects`）。这个声明进入冻结的计划和计划 ID，并写入任务说明；没有声明的用例被明确告知不得新建团队。投影工坊反投影测试的隔离目标图可以是样本，生成和反投影的执行者仍必须是工坊真实绑定的团队。
- **临时对象的标题必须带回收标记。** 标记为 `[TAU:<运行 ID>:<模块 ID>]`，从创建、Fork 到重命名都保留；Resident 同时记录必要性、正式 ID 和创建回执，恢复时复用已有对象。标记只用于回收，不代表获得了建队授权。
- **每个模块结束后，框架回收本模块的临时对象。** 用例先通过正常页面或已有指令清理自己创建的对象；模块无论成功、失败、异常还是取消，框架都分页查找带本运行和模块标记的独立团队，并在统一 TAU Lineage 中查找带本运行与模块完整标记的成员。独立团队用 `DeleteLineage` 删除，固定团队中的临时成员按精确 ID 通过公共投影释放流程删除，同时清理已登记归属于该成员的 Event、Effect 和连线；底层使用已有 HATG 指令。
- **删除前逐项核对身份和状态。** 临时成员通过 ResourceService 核对创建者为 `portal-test` 或已登记的模块执行者，通过 Resident 和 Lineage 查询核对完整标记、所在团队和执行状态。独立团队核对创建者为 `portal-test`、标题包含本运行和模块的完整标记、所有成员的执行状态；Lineage 不保存独立的 Owner 字段。所有已登记的执行者、核心团队的正式成员、原 TAU 团队保留的 Leader、固定团队本身、业务团队以及其他运行或模块的对象都不在删除范围内。正式指令照常进行实时权限检查。删除时的执行终止按《目录与路径协议》（decision_4aa13bc21e8e）处理。
- **删除请求持久保存，中断后继续同一个请求。** 删除前保存精确目标 ID、请求参数和稳定幂等键，保存回执后再次确认目标已不在活动查询结果中；回执丢失时重发同一请求，已完成的用例不重跑。回收在模块发布最终状态之前完成；混合执行方式的运行同样回收 TAU 模块的对象。
- **无法回收的对象保留并报告。** 执行终止和清理失败的重试按《目录与路径协议》（decision_4aa13bc21e8e）处理。所属或标记改变、无法读取或删除未完成的对象保留待核验与重试，在模块结果和运行报告中记录 ID 和错误。没有声明却发现了带标记的独立团队时，仍在授权范围内回收，同时把这次违规计为错误。回收不额外调用模型；没有按约定加标记的对象不会通过模糊名称匹配被删除。

### 测试样本与文件的生命周期

TAU 执行器以及由页面调用的 Paper、Resident Discovery 从所选实例 manifest 获取正式代码目录作为业务 cwd，不从加载模块的临时源码副本推导。因此候选构建检查不会将 candidate-source 或 maintenance 的一次性路径持久绑定给固定 Resident。新建测试内容只使用本用例的区域内夹具目录。

TAU 每个用例负责清理自己创建的业务条目、工程、资源及辅助脚本，完成、失败和取消遵循同一清理路径。可修改的样例工程和来源文件位于实例 features 区域内、由本用例独占的夹具目录；框架将位置写入 `run-context.json.fixture_dir`。证据和 `helpers/` 留在 runtime 的用例目录，禁止将 runtime 目录或其子目录登记、绑定为 Workspace。夹具归属回执保留证据目录及目录设备号/inode，恢复与删除前重新核对；缺失回执、符号链接或替换目录不被接管。测试夹具、辅助脚本及证据文件的删除与保留按《目录与路径协议》（decision_4aa13bc21e8e）处理。脚本和样例工程不因被报告引用而永久保留。

产品负责业务对象关联身份的生命周期。TAU 在 WALL 中创建的测试条目也按正常规则分配 Resident；清理先停止本用例发起的工作，通过 WALL 删除条目、取消工程登记，由 WALL 回收关联 Resident 和绑定，随后删除样例目录。固定团队、其他用例工程及人类既有对象不在清理范围内。

框架为每个 Run／用例创建持久的资源生命周期，写入 `run-context.json`，并在投递前关联本用例的执行 Resident。公共浏览器助手让页面及 API 请求携带该标识，ISA 调用上下文和以调用者身份认证的 ResourceService RPC 继续传递同一关联。领域服务使用自身身份发布已有资源的内部描述符投影时，不携带调用者的生命周期或身份；服务身份仍由签名和对应 RPC 入口校验。关联只表示清理责任，不授予权限；调用者仍使用真实身份接受产品授权检查。恢复已投递的用例时补齐关联，保留原有构建与证据信息；存在运行上下文却缺少关联的浏览器不得静默执行。

资源 ID 分配入口在关联范围内自动登记本次新建资源；登记独立提交，即使创建请求失败或响应丢失也保留待清理记录。读取、刷新、更新或重试既有资源不会把输入资源收为测试样本。普通运行未关联测试生命周期时，不登记为测试资源。Resident 自有 Workspace 随 Resident 回收，用户通知与执行历史按产品规则保留。

清理时的执行终止与生命周期封闭按《目录与路径协议》（decision_4aa13bc21e8e）处理。封闭后新请求被拒绝，避免删除快照形成后继续创建样本。请求使用独立的共享锁连接，不占用资源记录的连接池；清理以非阻塞方式尝试取得独占锁，避免排队中的清理锁阻塞尚未结束的嵌套 RPC。运行结束时的执行终止、对象注销和目录清理按《目录与路径协议》（decision_4aa13bc21e8e）处理。框架对正式资源统一调用 `UnregisterResource`，由各领域的删除适配器执行产品原有流程：搜索复用页面的删除操作并停止其正在运行的一代；Paper 回收业务绑定、评审与文件；Resident 释放专属投影流程；独立 Lineage 删除所属图。先删除业务资源，再清理其余 Resident 和 Lineage；已由页面或父资源删除的对象允许重复清理，权限错误和删除未完成不得当作成功。每项成功后记录回执；失败项持久记录并重试，样本文件、脚本与生命周期完成状态按《目录与路径协议》（decision_4aa13bc21e8e）处理；框架同时解除执行 Resident 与本用例的关联，使后续普通调用恢复正常；显式携带已完成生命周期标识的迟到请求仍被拒绝。

框架按工程根目录与本用例区域夹具目录的包含关系发现独立 WALL 样本工程；恢复旧用例时也检查原证据目录内的样本工程；在已有工程中新建的墙面条目尚无独立资源 ID，仍需把精确工程和 Block 地址保存到 `test-fixtures.json.wall_items`。Lineage 内部组件、实例和连线也不作为根资源注销：通过图编辑删除或随临时 Lineage 回收，具体 ID 与回执保存为证据。禁止为清理单个用例而清空共享账号的 User Mailbox。

WALL 后台作业可能在原 HTTP 调用生命周期上下文结束后分配 Workspace。完成产品清理后，框架还从权威 WorkspaceStore 查找本用例独占夹具目录（包括有归属回执的独立 Git 夹具）下仍活跃的登记，不依赖搜索索引，也不以目录仍存在为条件。发现只限定注销候选；不继承本次作用域的登记不获得自动解绑权限，仍使用正式 UnregisterResource 并执行产品授权检查；引用和绑定按《目录与路径协议》（decision_4aa13bc21e8e）处理。这一步不扫描或回收用例目录之外的历史 Workspace。

Workspace 新分配的 ID 也归入本用例资源生命周期，不能因 Resident 自有目录通常随身份回收而跳过全部 Workspace。清理先释放业务对象、Resident 与 Lineage，最后注销 Workspace；已随身份删除的登记视为完成。若 Workspace 仍被绑定，只对本次生命周期的执行成员或本次新分配的 Resident 使用正式 `UnbindWorkspace`，随后用新的幂等键重试 `UnregisterResource`。本次创建对象的注销、绑定解除和目录清理按《目录与路径协议》（decision_4aa13bc21e8e）处理，继续执行产品授权检查。权限拒绝保留失败并重试，不绕过权限。旧清单中的 Workspace 不自动获得解绑授权。

历史 `test-fixtures.json.resources` 仅作为恢复兼容入口，必须是正式资源 ID 字符串数组，并与自动记录去重后走同一删除路径；新用例无需手写资源清单。禁止登记输入资源、搜索结果、固定团队或其他既有对象。无效清单的清理失败与重试按《目录与路径协议》（decision_4aa13bc21e8e）处理。“已删除”声明不能替代产品状态。框架清理回执记录生命周期标识、释放资源 ID、工程和文件清理结果。

用例在结束时清理自建样本。需要先生成再验证恢复的流程在同一个用例中分阶段执行：生成阶段记录精确资源、输入、回复及产物 ID，恢复阶段通过独立页面重新获取真实显示和响应证据，最后由框架通过产品生命周期清理样本。Paper 的 AI 生成与只读恢复共用一个自建论文，恢复阶段不发起新的 AI 或修改绑定。阶段间身份文件只用于定位，不能替代恢复阶段的证据。用例之间不依赖尚未完成的 Run 或已经进入清理的临时资源，不维护跨用例交接清单。

清理顺序为回收辅助进程、终止并清理业务样本、删除样例文件和脚本；执行终止、持久清理重试、运行临时文件清理和证据保留按《目录与路径协议》（decision_4aa13bc21e8e）处理。清理失败如实记为 error，不能返回 passed；报告解析失败或用例取消不免除清理责任。

## 实现说明

### 可用条件

`tau.py#TauConfig.unavailable_reason` 定义安装层的可用检查：未通过 `PORTAL_TEST_TAU_ENABLED` 禁用；宿主具有 Windows 原生 Job 执行器及进程身份依赖，或 Linux、`systemd-run` 与 `/proc`；受控 `portal-test` 浏览器登录状态是普通文件并禁止组或其他用户访问；Node.js、TAU 专用 Playwright 与匹配的 Chromium 可用；部署登记中能解析唯一 Dev。缺项返回具体原因，不生成通过结论。登录状态由 `PORTAL_TEST_STORAGE_STATE` 显式指定，默认使用实例 `runtime/test-framework/test-actor-storage-state.json`。专用运行时在 `management_portal/test_framework/tau_runtime/`，由 `scripts/bootstrap_portal install tau` 安装、`doctor tau` 检查，普通 core/test 安装不携带它。Windows 执行器由独立 Job 承载，受管浏览器由其 Job 与持久化租约核验、回收；没有 Job 身份的外部辅助进程仍保留为清理失败，不凭 PID 猜测归属。macOS Campaign 启动尚未接入。执行者默认 Codex，`PORTAL_TEST_TAU_PROVIDER`、`PORTAL_TEST_TAU_MODEL` 可调整；只读取上述规范变量；旧的 AGENT_USE/AGENT_PROVIDER/AGENT_MODEL 环境别名不再读取，规范变量存在但为空也不回退旧变量。安装检查通过后仍须满足本 Design 的目标、账号额度、模块配置和运行准入条件，可用不等于已执行。

### 团队迁移

迁移通过普通 `MoveLineageObjects` 将 Resident、事件源、Effect 和内部连线一起移动，保留对象 ID、会话与运行游标。框架的工作流绑定在确认原有完整对象和连线已经位于新团队后更新归属；对象缺失或连接改变时停止，不重复生成工作流。确认工作区转移完成、源团队为空后，通过 `DeleteLineage` 清理旧团队。

### 执行槽位文件

`tau-residents.json`（schema `tfi.portal-tau-residents.v1`，权限 `0600`）按模块 ID 保存：`slot_id`、`resident_id`、`lineage_id`、`backend_route_id`、`runtime_options`（`service_tier`）、`configuration_id`（每次改变账号或速度时重新生成，用作迁移的幂等键）、`changed_by` 和 `updated_at`。Resident 查找范围保持 `portal-tau:portal-test:<模块>:<槽位>`；已有 `lineage_scope` 字符串只保留请求兼容性，实际团队统一由 Portal 的 `tau` 职责绑定决定。创建回执按预期槽位检查，槽位已轮换时拒绝旧回执覆盖。“更换”先完整释放原槽位 Resident 及其专属流程、调用关联，再写入一个只带新槽位（和可选账号）的新记录；原成员忙碌或清理失败时保留原槽位，允许重试；自动换用新槽位时保留原来的账号、速度和配置 ID。多个 Test 运行进程可能同时写这个文件：每次读改写都持有一把跨进程共享的文件锁（同一进程内可重入），每次写入使用各自的临时文件，因此一个运行刚记录的 Resident 不会被另一个运行按旧副本覆盖。

### 一个模块组的执行过程

```text
模块组开始
  → 读取 tau 职责绑定与执行槽位；没有身份时只在统一团队创建 Resident
  → 核对账号与速度（必要时 RestartSession 迁移并等待）
  → 按 Campaign 要求调整并核对 Resident 运行设置
  → 安装“TAU 模块验收”工作流
  → 对每个用例：
       运行前 Dev 检查 → 记录目标身份 → 触发工作流送达任务
       → 等待同一消息到终态 → 解析结论并校验证据 → 运行后 Dev 检查
  → 回收本模块的临时对象
  → 写入模块最终状态
```

共享 TAU 浏览器助手在首次页面导航前为本用例的浏览器上下文安装被动观测。每个实际请求具有独立身份，同 URL 并发请求和重定向的各次请求分别记录；日志保存方法、脱敏路径、资源类型、页面、frame 和文档实例、观察起止时刻、响应状态及实际失败码，并保存导航、卸载、frame 分离、页面关闭与 PortalEvents 关闭回执。文档切换期间无法确认请求归属、销毁时无法送达关闭回执或没有唯一传输身份时，明确保留未知与观测缺口；不凭 URL 或时间接近豁免取消，也不把所有 ERR_ABORTED 归为正常。

Portal 连接拥有者在实际关闭事件流或取消指令请求时立即发出内容无关的关闭回执；浏览器观察器当场追加到日志，并按同一请求、frame 和文档的传输身份关联。周期性和卸载时的缓冲读取只作补充，相同回执去重。页面销毁仍可能阻止消息送达，缺失回执时继续保留未知，不根据跳转本身推断某次请求的取消原因。

同一观测保存文档内标准 PerformanceObserver 实际提供的资源时序及其时间基准。未暴露、尚未开始或不能可靠关联的字段标为不可用；浏览器等待与传输时序不代表后端执行分段。采集结束时仍缺少终态的请求记录为 pending，不推断它已到服务器，不伪造成功、取消或超时。事件逐次追加到本 Run 的 tau-browser-observations.jsonl，正常 finally 收尾记录采集结束；框架在结果入库与证据清理前引用并保留这份标准证据。辅助进程中断前已落盘的事实仍保留，中断后的未知状态不补造。

浏览器助手提供 `action(name, callback, { page })` 记录原 UI 动作。名称使用静态步骤标签，callback 包含实际操作及就绪检查；在原动作开始和结束追加唯一 action ID、frame/document 身份与实际毫秒耗时。观察期间把同一页面（含子 frame）的请求 ID 关联到该显式动作作用域；导航保留前后文档身份，没有请求的动作保留空数组。同页不允许重叠或嵌套动作，异常保留失败及安全诊断并原样返回给调用者，不重试业务操作。作用域关联仅表示请求在该动作观察期间出现，后台请求可能同时发生，不能推断因果或据此豁免取消。其他标签页需显式传入 page，Helper API 调用和 Harness RTT 仍独立取证。

浏览器助手提供 `requestId(request)`，仅查询已经观察到的实际 Playwright Request 对象，返回公共日志中的唯一请求 ID；未观察的对象返回 null，不创建新记录。用例可用 `response.request()` 或 requestfailed 事件自身的 Request，把必要的非敏感响应诊断关联到确切请求，不依据 URL 或时间推断匹配。该关联不自动证明失败或取消原因，也不改变公共日志的内容限制。

公共浏览器助手统一处理异常取证。页面未处理异常记录错误类别及堆栈中的源码行列；仅当前静态脚本白名单中的路径可直接保留，其他来源只保存脱敏标记与路径散列，匿名脚本只保存行列。不记录异常消息、函数名、URL 主机、用户信息或查询参数。Playwright 的页面异常事件只提供页面身份，无法证明具体 frame 或文档归属时明确保留未知；这些位置供第二阶段定位，不自动判定责任方或改写验收结论。

辅助脚本在控制台、结果 JSON 和顶层异常出口使用同一个安全诊断序列化器，仅输出允许的错误类别、连接错误码和脱敏位置。身份读取与指令调用的传输异常在公共助手边界转换为新的安全错误，不携带原库异常、cause、请求头或调用日志，不因转换而增加自动重试。已经受理的业务调用继续按原身份观察。观察器的文档随机标识在普通 HTTP 与安全上下文中均可生成，观察本身不向页面引入安全上下文依赖。

公共观测对 `/api/agent-conversations` 和 `/api/scheduled-triggered` 按完整静态路由保留端点名称，避免不同公共索引请求都退化成同一个脱敏路径。此规则不允许任意子路径或查询值透传；未知路径段继续脱敏，节点侧 Request 记录与浏览器 ResourceTiming 使用同一规则。它仅恢复后续取样的端点区别，不补填旧记录，也不据端点名称推断具体目标、响应正文或故障原因。

公共观测只保存允许的内容无关字段，不保存任意 headers、Cookie、token、任意 URL query、请求或聊天正文。允许提取的诊断标识仅限产品生成、不含业务内容的事件流查询字段 portal_stream_id 与指令请求头 X-Portal-Request-ID，分别对应关闭回执的 stream_id 和 transport_id。HTTP 重试使用新的请求标识，业务幂等键不作为传输标识；只有同一 frame/document 中恰好一个请求匹配时才记录 request_id。原生重连产生多个候选时仍保持未知；失败记录不因关联存在而自动改写为成功。选中指令的名称与显式请求人数可以从参数在内存中提取，不保存参数及 Resident ID。 Resident 详情读取、重启选项读取以及白名单内的 Resident 生命周期指令，另保存经过规范 ID 校验的目标 SHA-256 与操作类型。相同目标在读取、删除、清空和重启之间使用相同散列，便于把具体失败请求与原始业务回执关联；原 ID、其他参数和响应正文仍不进入公共观察日志。未知指令与无效目标不产生目标散列。散列匹配只证明目标一致，删除是否成功、失败发生阶段及因果关系仍须由该请求的实际回执和生命周期事实确认，不自动豁免 404。观测不更改请求参数、结果、取消、重试或业务判断；它不能替代执行者当场记录的每次原 Harness 工具调用 RTT、UI 原动作到 ready 的计时、视觉取证及原有功能和性能验收条件。


原工具 RTT 在调用发生时逐条追加到本用例 harness-tool-rtt.jsonl，保留调用身份、工具名、起止时间、耗时及成功或失败类别。并行批次分别记录各原调用；成功、失败、恢复及只读诊断采用同一流程。记录不包含原始参数或敏感正文，不仅保存在编排内存中，也不在报告阶段用后续重跑补造。取证维护写入单独标明，不把它计为产品延迟；工具入口无法提供原调用计时的限制必须明确记录。原有 UI 计时、功能和性能验收条件继续有效。

共享浏览器助手在每次 `portal.instruction` 开始与结束时自动追加 `tau-helper-calls.jsonl`，保存独立 call_id、静态指令名、辅助进程身份、墙钟起止、单调时钟耗时和成功/失败。失败另保留规范错误码、HTTP 状态及安全网络诊断，不保存错误消息或 details 正文。`inputState` 与 `waitForInput` 内部的每次 GetInputState 同样独立记录，并行调用不能用一条批次耗时代替。该耗时包含同一幂等指令内部的等待与重试；HTTP 尝试与后端执行时间继续保持各自口径。 APIRequestContext 不产生页面 Request 事件，故共享助手在同一日志中另记每次实际 HTTP 尝试：用新的 X-Portal-Request-ID 关联 request_started 与 request_finished，并保留 attempt、原始起止、单调时钟耗时、HTTP 状态及经过格式校验的 instruction_id、status、replayed。重试沿用业务幂等键而不复用传输 ID；API 请求不借用页面 frame/document。未取得响应或回执时字段保持未知，后续成功不覆盖前次失败。日志不保存参数、响应正文、幂等键、Cookie 或 token；异常原样返回，只有开始而无终点的调用保留为中断缺口。框架在结果入库和证据清理前自动引用本用例内的原日志。通过这些助手完成的调用无需用例额外包装；其他工具及直接 request 调用仍需现场独立采样。

TAU 发起调用前先取得模块 Resident 与已有职责 Lineage 的明确绑定，再通过当前 Resident 调用接口投递。框架传入的参数由真实接口签名校验；不再传递创建团队用的 lineage_title 或 project_id。新建执行者通过公开的 `permission_preset=full-access` 指定运行权限，具体 sandbox 配置由 Resident 运行设置解析。模块归属由职责绑定决定，已有 Resident 的权限由目标 Resident 检查。


### 长期测试进程跨数据库迁移

TAU 执行器可能跨越多次 Dev 发布。解析应用已配置的 Lineage 或 Resident 时，仅在只读事务中查询配置表与目标身份表所需的明确列，目标已删除或未配置仍显式失败；这类读取不初始化、迁移或校验整个 Lineage schema。Resident 的当前 Lineage 与其身份在同一个查询中读取。数据库结构的严格校验和迁移由拥有写入职责的 Lineage 存储保留。已有测试执行器因旧代码需要重启时，框架沿保存的 active invocation 和原 message_id 恢复等待，不重新投递已经提交的用例；旧失败报告保留，修复后的补测单独登记。

已保存的 active invocation 在执行器进程退出后继续占用其模块；新 Campaign 不得仅因进程锁释放而向同一模块 Resident 发送新用例。待恢复的旧调用优先取得执行容量，新调用等待期间不占模块锁或全局测试槽。已取消的旧调用仍进入原调用的撤回与回收路径，不得仅把 Campaign 标为 cancelled 后遗留工作。



### Windows 本机验收边界

Windows 原生 TAU 必须由目标安装自己的 Test 框架调度，使用在该机器注册的可用 Codex 账号、测试用户、目标配置与模块 Resident。另一台机器的 TAU 对 Windows 页面发起操作不能替代此验收。原生 CI 可以验证执行器脱离 Web、互斥、取消、崩溃恢复及受管 Chromium，但使用隔离桩且没有实际模型调用时仅记录为基础链路验证。预检输出核心用例清单与缺项；没有正式 Campaign 就保持 `campaign_status=not_started`、执行用例数为零，不写通过结论。
