# 模型 × 硬件投影示例

这是业务片段，不是一个独立站点。Portal 提供页面模板、主题、组件容器、身份和 SDK。

- 模型行来自绑定 Lineage 中真实的「模型 Steward」成员，不补造十二个模型。
- 示例有 A100 / Thor / RTX4090 三列，模型增多时自动扩展行。平台目录和正式实验地址由此业务示例的数据映射维护，不进入 Lineage schema。
- `data.js` 只从同一实验报告的性能表解析数据；同输入契约且成对的 p50 才计算加速比。不跨硬件、模型或实验窗口拼数。
- 字段缺失、没有验收、阻塞和资源无权读取分别显示；Resident 运行状态不是实验完成度。
- 点击单元格查看性能分层、逐方法研究记录与可追溯原文；本页面没有启动实验的隐含动作。
- 构建：依次将 `style.css`、`content.html`、`data.js`、`app.js` 合为内联 style/业务片段/script，再使用正常工作台 update/publish API。不得加载外部 JS/CSS 或自建品牌导航。

## 业务比较与验收口径

该示例的模型、硬件目录和测量解释属于本示例，不进入通用 Lineage 投影规范或 SDK。模型行随真实授权目录增长，不能为了形成十二行而补造不存在的模型。单元格内分开呈现正式登记实验、候选测量、独立验收和 Resident 实时状态。

加速比只比较相同模型、硬件、输入、精度和测量口径的成对数据。单方法的 PyTorch／FlashRT 实现比较不能冒充相对未优化模型的语义优化收益；根报告和机器测量按当前 actor 通过 ResourceService 读取。缺失、阻塞、无权访问或过时证据均明确显示，不伪造零延迟、最佳值或完成百分比。

筛选、方法下钻、组合与草稿属于本地业务交互，不隐含启动 GPU 实验。对应页面已使用 Portal 业务片段模板；示例布局与业务数据的进一步演进在本目录维护，通用双向整理机制见 `decision_f67ae5e70793`。
