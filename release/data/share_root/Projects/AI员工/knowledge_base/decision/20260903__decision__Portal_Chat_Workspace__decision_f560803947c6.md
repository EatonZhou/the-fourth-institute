# Portal Chat Workspace

Chat Workspace 是 Portal 中所有聊天区域共用的组件。用户在 Society 页面与 Resident 对话、在 WALL 讨论设计点、在 Paper 页面研究论文、在知识条目旁提问时，看到的消息列表、输入框、附件、运行提示和队列，都由它呈现。页面只需要告诉它“当前在和哪个对象聊天”，并提供服务端生成的界面数据。

本 Design 说明一个聊天区域里有什么、用户怎样输入和阅读、草稿怎样保存和恢复，以及页面怎样接入这个组件。相邻的内容由这些 Design 负责：

- 消息的顺序、Resident 的输入队列和运行状态：decision_c524c775e0be。
- 聊天中的提问、审批和“本轮修改”卡片：decision_1e2eb869bc10。
- 输入框下方的运行设置（模型、推理强度、速度、权限、协作模式）：decision_8b2fa224616b。
- Session 重启与迁移：decision_c47a13e8b962。
- 跨页面的会话摘要和未读提醒：Conversation Store（decision_18abbdef3da3）与 User Mailbox（decision_15f7df737ed5）。
- 图片的插入和查看：decision_dca903d71575；文件链接与 Preview：decision_61e50306cc79。

## 基本概念

- **聊天目标（target）**：当前聊天的对象，由类型 `kind` 和 ID 组成，可以附带所属 Lineage。`kind` 取 `resident`、`workspace` 或 `knowledge_item`。一个聊天区域同一时刻只有一个目标。
- **宿主页面**：嵌入 Chat Workspace 的页面，如 Society 页面、WALL 或 Paper 页面。宿主决定当前目标，负责上传文件、执行动作和显示整体错误。
- **Workspace 实例**：页面上的一个聊天区域。一个页面可以有多个 Chat 面板，每个面板是一个实例；多个实例可以显示同一个 Resident 的对话，但各自保存自己的草稿、附件、滚动位置和按钮状态。
- **界面数据（合同）**：服务端为一个聊天目标生成的快照，格式名为 `portal.chat_workspace.v3`，说明这个聊天应该显示什么、允许做什么。它是为界面整理的读取结果，消息本身保存在会话存储中。浏览器只按它显示，不自行判断权限。
- **Composer**：输入区域，由可编辑输入框、发送按钮，以及按能力出现的 Stop、Auto、附件、引用（Refs）和运行设置控件组成。
- **草稿作用域（history scope）**：决定草稿和输入历史归属的键。同一作用域共用一份草稿，不同作用域互不影响。
- **工作状态、人工接单与执行保护**：`work_state` 描述当前工作；`intake_state` 是人工开关；`execution_gate` 是服务端给出的有效执行保护状态。三者不能相互推断，统一投影与缺字段处理见 decision_18abbdef3da3。

## 用户看到的区域

- **标题区**显示聊天名称和副标题。普通 Resident 聊天在这里以纯文本显示执行账号（Account）和 Resident ID，双击任一项复制完整值。Family 门面不运行 Provider，也不对应执行账号；标题区显示 Family 门面标识、成员数量和 Resident ID，不显示 backend 账号，即使注册配置或历史 Session 数据含有账号字段。内部 Router、steward 和业务成员的账号在各自的会话或 Family 状态表中显示。Provider Session ID 在右上角齿轮打开的 Resident Menu → Settings 中以紧凑信息行显示，并提供完整复制；它不占标题区。 已打开的 Menu 订阅当前 Resident 的身份投影，Session 绑定变化后同步更新显示与复制值；解绑后禁用复制，关闭或切换 Resident 时解除旧订阅。Resident ID 不做成链接，避免用户想复制时跳离对话。
- **消息区**按顺序显示人类、Agent 和 Portal 消息。连续的 Agent 回复在视觉上合成一组，每条消息仍有自己的 ID 和菜单。
- **运行状态条**显示启动中、等待容量、重连、压缩、正在停止等当前活动。它只反映当前状态，不写入消息历史。
- **更早历史入口**按服务端给出的位置加载更早的消息；加载中、失败和重试只显示在消息区内。
- **Composer**，见“基本概念”。
- **附件托盘**显示图片和文件的缩略图、名称、路径、上传进度、失败、重试和移除。
- **引用**：随下一条消息发送的选中文字或上下文对象。从消息或 Preview 中选中的文字可以成为一个引用附件。
- **队列**显示已经发送、但 Resident 还没开始处理的消息，并按服务端允许的操作提供“立即注入”和“删除”；Resident 聊天中有两条以上排队消息时，还可以合并、拆分和调整顺序。

界面标签、状态和操作提示遵循当前界面语言，语言偏好与翻译边界统一见 decision_27253e25f016。消息正文、资源名称、身份 ID、模型 ID 与斜杠命令保持原值；本篇不另设“聊天只用中文”或控件永久保留英文的例外。

## 界面数据的内容

| 部分 | 决定的内容 |
| --- | --- |
| `workspace_key` | 这个聊天区域的身份，缺省为 `chat_workspace` |
| `surface` | 聊天来自哪个页面，缺省为空 |
| `title` / `subtitle` / `header` | 标题区和身份信息，标题缺省为 `Chat Workspace` |
| `target` | 当前聊天目标 |
| `messages` / `messages_ref` | 直接给出的消息，或读取完整消息的引用 |
| `runtime` | 是否有正在进行的活动及其详情 |
| `rendering` | 空状态文字、人类名称和 Agent 名称（缺省 `Codex`） |
| `composer` | 输入提示、能否发送和添加附件、草稿作用域、斜杠命令和运行设置 |
| `actions` | 可执行的动作：发送、停止、重启会话、设置等 |
| `history` | 更早历史的入口和位置 |
| `capabilities` | 宿主页面可以显示的功能 |

服务端生成界面数据时，目标类型未知、ID 为空、消息缺少 ID 或 ID 重复，都会让整份数据生成失败，页面收到错误。

Composer 的缺省值：输入提示为 `Ctrl/⌘ + Enter 发送；右键消息可引用、转发；/portal-help 查看指令`；`can_send=true`、`requires_text=false`、`can_stop=false`、`can_attach=true`、`refs_enabled=true`；草稿作用域依次取 `workspace_key`、`surface`，都没有时为 `default`。只有输入含义特殊的页面才改写提示。输入提示只显示在空输入框里；输入框下方的说明行只放运行设置摘要或与提示不同的状态说明（如“等待服务恢复…”），和输入提示相同的说明不再重复显示。服务端的缺省数据里没有 `can_auto`：宿主提供了 Auto 处理函数且没有关闭它时，才显示 Auto。页面可以收紧这些能力，浏览器不能在本地重新放宽。

## 设计点

- **消息头显示发送者头像与名称。** User 使用其当前上传头像或选定的精灵头像；Resident 使用其稳定身份绑定的头像。消息来源身份决定头像归属，显示名称不作为身份键。头像与名称并列，连续 Agent 输出沿用分组首条消息的头像；Portal 系统提示和执行错误保持原有标题。头像属于动态公开展示资料，不写入消息历史。所有聊天宿主使用共享头像组件，重复发送者与多个面板共用有界缓存；读取失败或图片加载失败时保留名称首字母，不阻塞消息、发送、草稿或滚动。用户更新头像后同步更新已经显示的消息头。
- **已登录有效 User 可以读取发送者的头像元数据和用户头像图片。** 公开头像响应只包含头像，不包含邮箱、角色、登录凭据或其他账号资料；上传和修改头像仍只针对调用者自身，并要求同源。Resident 的既有头像同样对所有有效登录用户公开，不要求对应节点的读取权限；这个入口只读取已保存的装饰性头像绑定，不返回节点资料，不会为未知 ID 创建新绑定。头像图片继续使用带版本的地址以及私有、禁止缓存响应。

### 加载与切换目标

- **每次主动打开 Resident Menu 都重新读取当前 Resident 的身份投影。** 菜单关闭期间发生的 Session 替换或解绑，在再次打开时反映到 Settings 的 Session 显示与复制值；不能把上次显示的缓存值当作当前绑定。菜单打开后的身份通知继续通过共享订阅更新。

Chat Workspace 的区域可访问名称由当前标题元素提供，切换 Resident 后同步变化。目标已删除或不可访问时，只使用当前目标的标题或 Resident ID；不能回退到上一个 Resident 的名称。过期的协议响应不得恢复旧目标的标题、内容或可用操作。

- **可见 Chat 呈现新的未读回复时重新确认阅读。** Home 与 HATG 使用同一共享观察器；本地收件箱条目缺失或尚未更新时，以 Chat 已呈现的协议快照判断新的未读内容。已确认的同一快照不因重复渲染而重复提交；阅读请求等待期间又收到新的未读快照时，旧请求的回执只确认它开始时的快照，随后继续确认新内容。隐藏、加载中或尚未完成目标切换的 Chat 不确认阅读。

- **第一份界面数据到达前只显示加载状态，不显示可编辑的输入框。** 加载失败时显示不可编辑的错误状态，旧目标和错误界面都不能发送消息。
- **切换目标期间，旧目标可以继续显示，但所有操作暂停。** 新目标的界面数据和会话快照都准备好后，宿主一次性切换过去。晚到的旧目标结果由宿主按目标或修订号丢弃；组件自己只跳过内容完全相同的重复数据。
- **同一目标的数据刷新保留输入框本身。** 焦点、选区和正在进行的输入法组合保持不变，能力变化只增删对应的控件。
- **创建、Fork 或 Session 绑定在后台完成后，已打开的聊天自动更新身份信息。** 用户不需要重新选择 Resident。Resident 还没有 Provider Session 时，聊天在第一次收到运行状态变化后重新读取一次身份，更新会话身份；Session ID 在 Resident Menu 的 Settings 中查看。之后普通的运行和消息通知不再重复读取身份。
- **一个页面元素只归一个 Workspace 实例。** 在同一元素上再次创建时，先销毁旧实例。实例 ID 优先使用宿主给出的值，否则由 Workbench 和面板身份推出。

### 消息显示与阅读位置

- **人类消息的气泡只承载消息内容。** 头像、作者和时间组成无底色的消息头，位于气泡上方；引用回复、正文、图片与附件位于气泡内，来源、用量等消息注记位于气泡外。气泡按正文自然宽度收窄，短消息不因作者或时间较长而撑宽；使用随主题变化的纯色填充，不显示边框，保留紧凑内边距和 12 像素圆角。气泡底色与聊天背景保持清晰层次：发出的消息使用较明显的主题色底，收到的人类消息使用中性色底，明暗主题均保证正文易读。整条消息上限为消息区可用宽度的 86% 且不超过 760 像素，窄栏中的消息头可以换行。长文本自然换行，图片按气泡宽度缩放，代码和表格在内容区内滚动。共享消息组件负责气泡、消息头和收发方向的呈现，Chatroom 只根据当前用户标记收件方向，不在页面层覆写气泡样式。Portal 与错误消息保留提示卡片，连续 Agent 回复保留阅读分组布局。
- **同一人类用户短时间内连续发言共用消息头。** 共享消息渲染层按发送者的稳定身份分组，不按显示名称判断；一组只在第一条显示头像、名称和时间。同组从第一条消息起最多跨度 5 分钟，时间必须有效且顺序不倒退；换人、跨日、系统提示、缺少身份或时间时重新显示消息头。延迟接单的消息保留单独的接单与发出时间。后续人类气泡收紧间距，悬停仍可查看各条消息的时间，辅助阅读标签保留作者与时间。每条消息的 ID、正文、引用、复制、转发和未读含义保持独立，加载旧历史或修改消息后按完整顺序重新确定分组边界。
- **同一 Agent 的连续回复组共用消息头，不受时间窗口限制。** 头像、名称和时间只显示在组首，后续各段以细线分隔；间隔超过 5 分钟、跨日或时间缺失都不会单独拆分连续输出。新的人类请求、其他发送者、系统提示、不同 Family 请求以及有明确收件人的独立消息形成边界。普通回复的消息头和中间输出折叠使用同一个回复组边界；Family 工作整体折叠按下条规则，普通回复折叠后仅剩末条可见时，该条显示消息头；再次展开恢复组首消息头。后续段落的时间保留在悬停与辅助阅读标签中，单条复制、引用和转发仍按各条消息 ID 执行。Resident Chat 和 Chatroom 使用同一共享实现。
- **Family 工作可整体折叠。** 门面输出按 `family_reply.request_message_id` 的原请求身份归组，与普通连续回复的中间输出折叠分开。第一条工作回复在时间旁提供可用鼠标和键盘操作的总折叠按钮；收起后保留该工作消息头、进度摘要与停止等控制，隐藏本请求所有正文、附件、后续回复和运行详情。展开恢复原内容与各条消息操作。交错请求互不影响；当前 Workspace 实例按请求记住选择，持续输出、完成及加载更早历史不冲掉选择或产生重复组头。显式定位被收起的回复会展开其所属工作。折叠是只读呈现，不改变消息身份、任务状态或其他宿主实例。
- **Resident 消息头的头像和名称共同链接到该 Resident 的对话。** 名称使用 Resource 名称标签（decision_e5f66e2f6a5e）。聊天从消息的来源身份取 Resident ID，缺少时使用已有的作者 ID 字段；不根据显示名称猜测 Resident。头像和名称属于同一个原生链接，支持鼠标点击、键盘 Enter 和新标签页打开；链接沿用消息头的主题色、字体与尺寸，并提供悬停和键盘焦点提示。所有共享 Chat 宿主（包括 Chatroom）使用同一实现，导航沿用 Resident 对话入口并要求显示 Chat 面板，由目标服务检查访问权限。人类、未知身份及系统提示不产生 Resident 跳转。在某个 Resident 自己的 Chat 中（Chat 的目标就是这个 Resident），它自己消息的头像和名称不是链接，也不可聚焦，点击不跳转；其他 Resident 的消息照常链接。连续消息分组、单条引用和正文操作保持不变。
- 历史消息的作者资源解析返回 `404 resource_not_found` 时，消息头保留原 Resident ID、头像和正文，并撤下作者跳转，提示“Resident 暂不可用”。解析失败本身不证明 Resident 已删除。网络故障或服务暂不可用不改变作者的链接语义；资源标签组件报告解析错误，由 Chat 负责自己的作者导航呈现。
- **新消息只增加新节点，已有消息复用。** 消息按 ID 和内容签名复用页面元素，连续 Agent 回复只更新末尾受影响的一组。
- **历史中的 milestone handoff 标记按普通正文显示。**
- **用户停在消息末尾时，新消息和图片加载造成的高度变化会继续滚到底部。** 用户向上翻阅后，运行状态刷新、新消息和布局变化都不会把视图拉回底部。
- **加载更早的历史后，原来看到的消息停在原位。**
- **过长的消息默认折叠。** 正文超过约 12 行的消息只显示开头 6 行，底部渐隐，下方有“展开全文”；展开后可以“收起”。行数按当前宽度下显示出来的高度计算，Chat 变宽变窄后重新判断。最新一条 Agent 回复和正在运行中的内容默认展开。展开和收起按消息 ID 只在当前页面记住，不改变消息，复制仍是整条正文。用户向上翻阅时，正在看的消息不会因为新回复到达、运行结束或宽度变化而折起。只有普通正文折叠；引用块、本轮计划与修改等卡片、提问、转发参考、门面的状态块和中间输出分组各有自己的显示。所有使用 Chat Workspace 的页面都这样显示（TFI portal 10-06）。
- **同一作用域隐藏再显示时保留阅读位置；切到另一个作用域时显示最新消息。** 用户明确重新进入一个隐藏的聊天时，可以把末尾重新定位到最新消息；打开或关闭相邻面板不会重新加载聊天。
- **已绑定 Resident 的 Chat 点击发送后立即显示消息并释放输入框（TFI portal 2026-10-14）。** 当前正文、图片、附件和引用形成带原消息 ID 的临时气泡，标为“发送中…”；输入框立即清空并保持可用，无需等待网络。后续输入按点击顺序提交。同一标签页中打开同一 Resident 的 Chat 共享这些临时消息。
- **服务端结果决定临时消息的去向。** 正式消息出现后按 ID 合为一条；确认入队后移除临时气泡，改在队列显示。明确拒绝（如无权限）保留气泡，在下方显示错误并提供重试和移除，不把内容塞回新草稿。超时或断线时显示“正在确认发送状态”，查询原消息 ID，不自动重发；确认前后续本地提交等待，输入框仍可继续编辑。状态与回执规则由共享 Resident 协议状态层负责（decision_18abbdef3da3）。
- **发送状态和失败提示显示在对应气泡下方；上传提示仍在输入区显示。** 等待回执期间，标题区的账号与 Resident ID 仍然显示并可复制；Session ID 从 Resident Menu 的 Settings 查看和复制，Stop 仍按当前输入执行。
- **人类消息在发送中、确认发送状态、发送失败和已受理时使用相同的气泡外观。** 消息外层保持无边框、无强调阴影，引用块保留自身的标记；运行中输出的强调样式只用于 Agent 消息。Resident Chat 与 Chatroom 由共享消息渲染器执行这条规则。

### 当前对话的历史查找

Chat Workspace 标题区提供搜索图标。未输入关键词时，锚定在图标下方的轻量列表只显示当前 Conversation 中右侧的用户消息，沿用正文的角色与收发方向判定，按新到旧排列；每项显示作者、时间与最多两行正文摘录。悬停条目时，复用现有提示展示该消息未截断的纯文字正文；空查询目录与关键词结果使用相同规则。输入关键词后查找当前对话中所有角色的消息片段，仅列出匹配项并高亮摘录中的关键词；清空关键词后恢复用户消息目录。列表使用纯文字，消息里的 HTML 和 Markdown 不在查找结果中执行。

空查询直接使用当前聊天已经加载的消息，并通过“加载更早片段”复用原有历史分页。Resident 聊天的关键词查找通过现有 SearchMessages 接口，只传当前 Resident ID，不枚举其他 Resident；结果按需分页。输入防抖 220 毫秒，无后台搜索轮询。查询失败保留搜索文字并提供重试，空结果明确显示无匹配。

点击结果在当前 Chat Workspace 定位到对应消息，不占用 Preview，也不切换聊天。目标尚未加载时通过原有历史入口逐页读取，直到找到消息、历史结束或分页不再前进；折叠的中间输出与长正文先展开，再滚动到目标并短暂高亮。切换 Conversation、关闭面板或销毁实例使尚未返回的查询失效，各 Chat 实例的搜索状态独立。方向键可选择结果，Enter 定位，Escape 关闭并回到搜索按钮。

共享组件负责搜索面板、匹配摘录与定位；宿主提供当前 Conversation 的消息读取能力。Lineage 导航只负责选择 Agent、Chatroom、收藏和 Workspace，历史查找归属于当前 Chat，不再保存独立的历史目标或渲染另一份历史对话。

### 消息下方的注记

Resident 聊天在消息正文下方附加几种只读注记，说明这条消息怎样到达或花了多少用量。注记来自会话快照中的字段，聊天不自行推断。

- **撤回自己的消息后可以重新编辑（2026-10-15）。** Resident 聊天中的撤回注记，仅在当前 User 是原消息作者时提供“重新编辑”。点击后以当前调用者身份用 GetMessage 读取原消息，再次核对消息 ID 与作者，将原文、图片和附件恢复到当前发送框；已有草稿保留并追加原文，附件按身份去重，已有引用优先，没有引用时才恢复原引用。读取期间切换 Resident 或会话后，旧结果不得进入新目标的草稿；同一消息正在读取时忽略重复点击。恢复只修改草稿，不自动发送、不撤销撤回，也不把原文重新展示到撤回注记中。这样保留已输入内容，同时避免恢复操作意外再次投递；依据已发布提交 81cc2f9fc12d047682590759765f980644afe94e。
- **Mailbox 群体消息列出它合并的每条消息。** 注记写“Mailbox · 合并了 N 条消息，作为一次输入处理”，下面依次是每条原消息的作者、时间和正文（每条最多 2000 字）；被合并的原消息标为“已并入 Mailbox 群体消息”。合并规则见 decision_15f7df737ed5。
- **随任务送达的背景更新单独标出。** 还在等待的背景消息（info）标为“背景更新 · 随下一条任务送达”；已经随某条请求送达的标为“背景更新 · 已作为背景随下面的消息一起送达，没有单独打断工作”，并显示在那条请求之前。
- **Family 门面的对话像普通 Resident 一样阅读。** 每条请求保留原发送者，后面跟着成员对它的回复。回复显示为门面的回复，并注明“由 <成员> 回复”；嵌套 Family 时追加“（经 <内层门面> → …）”。成员一侧的非 Agent 消息注明“来自 <成员>”。回复（包括运行中已经写出的中间输出）从成员的会话投影而来，不复制；回答不同请求的回复分属不同的回复组，不合并成一组（decision_44cf587c1721）。
- **Agent 消息可以带 token 注记。** 消息带有本轮用量时显示“tokens <总量> · in … · out … · reason …”。数值不足 1000 时显示整数，较大数值按 K、M 缩写并保留一位小数；为零的项省略。

### 消息菜单与复制

- **每条有正文的消息都通过右键打开消息操作菜单。** 消息区域不放额外的菜单按钮。菜单按右键所在消息的 ID 提供引用、复制、创建分支和转发等可用操作，连续 Agent 回复的中间输出与最终回复分别对应自己的消息；中间输出折叠后，最终回复仍可单独操作。菜单显示在鼠标附近，并自动避开视口边缘；按 Esc 或点击菜单外任意位置关闭，包括同一条消息正文、其他消息、Chat 空白区和输入框。菜单内部的操作仍可正常点击；右键另一条消息时切换到该消息的菜单。消息区内的输入控件保留浏览器原生右键行为。
- **消息阅读区统一处理右键，空白处不弹浏览器菜单。** 消息正文、头部与分隔线按实际消息提供操作；两条可操作消息之间、位于上一条消息横向范围内的行间距归上一条，下一条的分隔线仍归下一条。侧边与首尾空白、阅读区剩余空间、运行状态等没有消息身份的区域只关闭已有菜单，不借邻近消息提供引用、转发或复制。嵌入的编辑控件、发送框和 Chat 外部保留各自既有右键行为。
- **右键发送框直接粘贴剪贴板。** 文字插入光标处，图片和文件作为附件插入；没有自己文字粘贴处理的输入框按普通文字插入。浏览器不提供剪贴板读取接口时（从内网 HTTP 地址打开、不是 localhost 的页面），右键不拦截浏览器自带菜单，用其中的“粘贴”，它和 Ctrl/⌘ + V 一样走粘贴事件（TFI portal 2026-10-13）。浏览器拒绝读取时提示改用 Ctrl/⌘ + V。
- **右键消息里的网页链接时，菜单另提供“打开链接”。** 仅对本次点击的 HTTP/HTTPS 链接显示，点击在新标签页打开对应网页，且不向新页传递 opener；不会改变左键链接预览或消息的引用、转发、复制操作。右键普通正文不显示这个选项，再次右键其他链接时以新的链接为准。
- **发送框与 `/portal-help` 说明右键操作入口。** 通用发送框提示“右键消息可引用、转发”；帮助区分输入框右键粘贴、消息右键引用回复或 Forward 多选转发，以及网页链接右键打开。可用操作仍由当前会话能力决定。
- **`/portal-help` 把快捷键分为通用、Chat、Lineage 画布三组（TFI portal 2026-10-13）。** 通用组是全局搜索和回到上一个界面。Chat 组列出发送、输入历史、撤销粘贴与插入、`/` 命令菜单和 Chatroom `@` 提及列表的方向键、Enter/Tab、Esc，提问卡片的数字键，输入框右键粘贴和消息右键菜单，我的 Mailbox 对话的菜单键或 Shift+F10，以及 Resident 详情 Mailbox 标签中等待消息的 Alt+↑/↓ 排序。画布组在画布获得焦点时生效：`+`/`=`、`-`、`0`、`F` 缩放和适配，Shift/Ctrl/⌘ 点击和 Shift 拖动框选；画布上的 Esc（取消连线或清除多选）和节点旁 + 按钮的方向键（打开 Fork 方式菜单）不写进帮助（TFI portal 2026-10-16）。帮助只写已有界面测试覆盖的按键。选中消息文字后的“添加到上下文”和它的 Esc 不写进帮助（TFI portal 2026-10-16）。键盘操作写明用哪个键选中对象（如“按 Tab 选中这条对话，再按 Shift + F10”），不写“获得焦点”；我的 Mailbox 一条写明它在页面右侧、菜单用于置顶或取消置顶（TFI portal 2026-10-16）。
- **已受理、有正文的消息可以“引用回复”。** 菜单中的“引用回复”把这条消息放进输入框上方的引用条，显示作者和一行正文摘录，超出可用宽度用省略号，可以取消；一次只引用一条。Resident 点击发送时清空引用条，引用随临时气泡保留，失败后仍可查看；Chatroom 沿用成功后清空、失败时保留的提交规则。发出的消息在正文上方显示引用块（作者和一行摘录），与输入框引用条使用相同的单行省略规则；原文换行仅在显示时合并，不截断引用数据。可跳转的引用块右侧显示“↑”，悬停提示“跳到被引用的消息”，点击整块或键盘激活后定位并短暂高亮原消息（不在已加载的历史中时先加载）。用户引用和 Chatroom 中 Resident 对召唤消息的引用使用同一呈现；没有当前对话消息 ID 的摘录不显示箭头。引用只能指向当前对话中的消息，规则见 decision_c524c775e0be；在 Family 门面中，引用成员的回复或它发来的消息，Router 会直接交回那个成员（decision_44cf587c1721，TFI portal 10-06）。
- **转发从消息右键菜单中的 Forward 进入。** 有转发能力的 Resident 聊天为已受理、有正文的消息提供这个选项；点击后进入整段已加载对话的多选模式，显示每条消息的选择框。点击 Agent 消息时预选这一条；点击人类消息时沿用选择规则，预选这条消息及其对应的最后一条 Agent 回复，用户可以继续增删选择。标题区不另放转发图标。
- **多选模式右下角显示已选数量、“取消”和“转发”。** “取消”退出选择模式并清空选择；“转发”打开共享的目标选择面板，可选择 Resident 或聊天室。Resident 按项目、Lineage 逐级选择或直接定位 ID；聊天室通过 `ListChatrooms` 列出自己参加且可发言的聊天室，独立加载，Resident 联系人慢或失败不阻塞聊天室选择。两类目标均可附加说明；统一用 `ForwardMessages` 提交来源消息 ID，服务端重新读取正文。转发成功后退出选择模式，Resident 目标同时加入最近快捷入口，当前聊天目标、草稿和附件保持不变。聊天室目标加载失败或列表为空时不能发送；创建分支使用同一目标选择窗口时仍只允许 Resident。没有选中消息时“转发”不可用；当前会话不再允许转发时自动退出选择模式。
- **消息菜单使用紧凑的 12 像素字体和常规字重。** 菜单在页面浮层显示时保持相同字号、行高、主题颜色和操作行为，避免继承宿主页面的大号按钮样式。
- **“复制为纯文本”复制这条消息显示出来的正文；“复制为 Markdown”复制它的 Markdown 原文。** 两者按消息 ID 只复制这一条。
- **每组连续 Agent 回复的第一条还提供“复制全部回复为纯文本”和“复制全部回复为 Markdown”。** 复制点击时这一组已经收到的全部回复，各段之间空一行，包括折叠的中间输出。一组在遇到不同身份的 Agent、用户、Portal 或其他非 Agent 消息时结束。复制不包含其他组、临时运行活动和尚未加载的旧历史，也不会为此加载历史。
- **Resident 的人类消息提供“在当前 Lineage 中创建分支”和“在其他 Lineage 中创建分支…”。** 前者在该 Resident 所属 Lineage 中从这条消息创建分支；后者先让用户选择新分支所在的 Lineage 和父 Resident。分支的规则见 decision_5bf5bfbd52cb。
- **创建分支后留在当前页面。** 响应必须带回新 Resident ID 和目标 Lineage 的当前状态，缺少时报错。Society 页面收到后把新状态交给 HATG、选中新 Resident 并在图中定位它；没有宿主处理时只提示“分支已创建。”。页面不再整页跳转。
- **复制只写剪贴板。** 消息、选区、草稿和会话都保持不变。菜单显示在页面浮层上，复制仍按原实例和消息 ID 找到内容。所有页面使用这同一套菜单。

### 运行状态显示

Chat 点击 Stop 后，应在下一次页面绘制中显示“正在停止…”并禁用同一输入的重复 Stop；这只是当前 Editor 针对 Resident/消息 ID 的临时请求状态，不写入数据库、Segment、trace 或保存的页面状态，也不提前把服务端工作状态改为 stopping/cancelled。较旧快照和仅返回 running 的回执不能清除该提示。明确失败、对应输入终态、较新快照切换到下一条输入或 Editor 切换目标时清除；旧请求迟到的结果不能清除新输入的停止提示。

Chat 面板缩窄时，底部操作按钮在面板内自动换行；运行中的 Stop 必须保持可见和可点击，不能被面板分隔条遮挡。运行详情在窄容器中将名称和正文纵向排列，避免将正文挤成逐字换行。

- **运行状态以 Resident 的工作状态为准。** Family 门面使用服务端 `family_activity.work_state`，普通 Resident 使用 `work_state`；两者由共享协议客户端统一为显示状态。只有 `running` 和 `stopping` 显示为正在运行；只有 `queued` 时显示独立的排队标记，不显示为运行中。停止请求被接受后显示“正在停止”，直到服务端确认停止，旧的工具活动不会覆盖它。
- **首次打开或断线恢复时，只要 Resident 在运行，就显示运行中占位，即使还没有活动详情。** 完整快照和增量更新使用同一个运行区域；是否在运行只看工作状态，不看有没有活动详情。
- **工作状态、人工接单与执行保护分开显示。** Chat 与 Family 成员表消费 decision_18abbdef3da3 的共同状态投影；闭合保护显示 CLOSED 及原因，未确认不显示为已开放。人工 Open/Close 仍只操作 intake；发送与排队提示分别取服务端 `controls.can_send` 和 `send_hint`，不因执行保护闭合擅自撤销排队发送能力。
- **Family 门面的每条请求后面显示它自己的处理状态。** 状态块的样式与普通 Resident 的运行区域相同，按这条请求在成员处的进度依次显示“Family Router 正在选择成员”、“已交给 <成员> · 排队中（前面还有 N 条）”和该成员这一轮的实时活动与中间输出；完成后换成以门面名义的回复，中间输出收起为“展开 N 条中间输出”。排队中的块有“立即注入”、“纠正 Router”和“撤回”，运行中的块有 Stop，只作用于这一条请求。不同成员同时处理不同请求时，各块各自更新；门面不在对话末尾另显示一处运行区域。成员的事件会刷新正在查看门面的聊天（decision_44cf587c1721，TFI portal 10-06）。
- **Family 排队请求的“立即注入”作用于最终承接成员正在处理的工作。** 门面进度给出最终成员和原请求在该成员处的消息副本，嵌套 Family 也沿用这两个标识。点击时先读取成员当刻的活动工作和即时输入能力，再经现有输入协议提交同一消息副本；服务端重新核对状态与权限。能力未知、不支持、没有活动工作或接口失败时保留排队消息并说明原因。等待接收、已接收和安排到下一轮分别显示，不把等待回执当作已经送达。操作期间锁定重复动作；预检结束前若请求已改派、状态变化或用户切换会话，就取消尚未发出的动作。进度说明与按钮在窄面板中换行，按钮保持可见、可点击。
- **运行设置摘要显示在输入框下方，规则见 decision_8b2fa224616b。**
- **上下文压缩在状态条和运行详情中都可见。** Provider 压缩上下文期间，运行状态条显示“正在压缩上下文”。运行详情中有一条压缩活动：进行中标题为“Compacting context”，完成后为“Context compacted”。每个 Provider turn 开始时，运行详情以一条开始记录标出原因：压缩之后开始的 turn 显示“压缩后继续”，其他原因分别显示“开始执行”“继续执行”“恢复运行”和“后端服务更新后恢复运行”。这些标题由 `execution/event_projection.py` 给出。

### Session 迁移提示

Session 重启或跨账号迁移的请求、进度和结果由 Resident 服务保存（decision_c47a13e8b962）。聊天从同一个观察客户端读取状态，标题区、详情面板和“重新迁移”都使用这份状态。

- **标题区用一行显示迁移摘要，标题区的账号和 Resident 身份照常显示，Session ID 在 Resident Menu 的 Settings 中查看。** 进行中提供“查看迁移进度”；失败后提供“查看详情”和“已知悉”。完成后提示消失。
- **详情面板用用户能懂的文字说明失败原因。** 只有服务端明确确认原会话保留时，才显示“原会话已保留”。底层错误放在默认收起的“技术诊断”中，以纯文本显示。
- **已受理的迁移可以在详情面板中取消。** 取消通过 HATG `CancelSessionRestart` 按 `restart_id` 进行，原 Session 保留；只关闭面板不会取消迁移。
- **耗时按小时、分、秒显示，省略为零的单位。** 例如 7720 秒显示为“2 小时 8 分 40 秒”。进行中持续更新；失败后按服务端记录的结束时间固定；缺少起止时间时显示“耗时未记录”。
- **“已知悉”只在当前浏览器中关闭这一次失败提示。** 它按用户、Resident 和 `restart_id` 记住，同页其他实例和刷新后的页面都保持关闭；换用户、换 Resident 或新的失败会重新提示。浏览器存储不可用时，仍可在当前页面关闭。服务端的失败记录不变，随时可以从 Menu → Settings → Backend 重新查看。
- **“重新迁移”预选上次仍然有效的目标和上下文方案。** 公共控制器重新核对当前身份与权限，提交、未知受理确认和重试均沿用 decision_8b2fa224616b、decision_c47a13e8b962 的同一流程。RestartSession 作用于提交时的当前会话，不声明它接受来源 Session 的 expected_version 前提。
- **切换目标或销毁组件时释放迁移状态的监听，晚到的旧目标状态被忽略。**

### 输入、草稿与输入历史

- **输入框默认高 86 像素，最小 56 像素。** 用户拖动后的高度按实例保存，并受容器高度限制。
- **草稿按用户、页面命名空间和草稿作用域分开保存。** 无法识别用户时用 `anonymous`。Resident 会话的作用域为 `resident-session:<resident_id>`，页面也可以在界面数据中给出自己的作用域。
- **停止输入 180 毫秒后自动保存草稿。** 保存的内容包括文本、可以恢复的附件与 Refs、选区和输入框高度；消息的“引用回复”只在当前实例内存按会话保存，不写入持久草稿；全部为空时删除这份草稿。离开页面前立即保存尚未写入的编辑。
- **同一作用域的草稿以最后一次编辑为准。** 其他实例延迟的保存或关闭，不会覆盖更新的草稿。
- **还没有 Resident 的业务对象也可以保存草稿。** 页面用固定的作用域把草稿绑定到业务对象，如 WALL 讨论用 `wall:<工程>:<设计点 ID>`，实现对话用 `wall-work:<工程>:<设计点 ID>:<resident_id>`。整页重新加载后打开同一对象，编辑器恢复未发送的草稿。
- **发送后，只清理这次提交的草稿。** Resident 点击发送时清空已提交的正文、附件、Refs 和引用条；随后的回执或事件只更新对应气泡，不能清空新草稿、附件、Refs、引用条或抢走焦点。失败消息保留在聊天中，草稿恢复机制不把它覆盖到用户后来的编辑上。
- **只有已经得到文件 ID 或路径的附件进入保存的草稿。** 上传中、失败或没有稳定身份的附件只保留在当前页面。
- **输入法组合期间，Ctrl/⌘+Enter 不发送。** 组合结束时立即重新计算能否发送，用户可以马上点击发送或按快捷键。
- **没有打开斜杠命令菜单时，上下方向键浏览输入历史。** 历史是当前登录者在这个会话里发过的输入，从新到旧排列，由服务端直接给出：Resident Chat 和 Chatroom 都用 `ListInputHistory`，分别传 `resident_id` 和 `chatroom_id`，浏览器不从已加载的消息页推导，也不在本地保存（TFI portal 2026-10-16）。服务端只取发送者等于登录者、并且消息来源是用户的输入，所以 Resident 投递的任务、Mailbox 合并的请求、系统服务的消息和其他成员的输入都不在其中；早期没有来源记录的消息按存储的发送者判断。历史覆盖整条 trace，包括 Fork 继承的输入和清除上下文之前的输入，Chat 本身仍只显示最后一次清除之后的消息。Chatroom 中编辑过的消息取当前版本，撤回的消息返回撤回前的内容，撤回后仍能翻出来重发（TFI portal 2026-10-16）。列表由三段组成：先是登录者还在队列里等待执行的消息（TFI portal 2026-10-12；队列项只有预览、没有完整内容时不进入历史，避免把截断的文字再次发送），再是刚确认发送、服务端还没列出的消息（只在当前页面内存中，服务端列出后按消息 ID 合并；Chatroom 按服务端返回的 ID），最后是服务端的分页结果。打开会话时读第一页；按上箭头翻到末尾时读下一页，一次按键一个请求；Chat 中出现登录者的新输入时（包括另一台电脑发出的），重新读第一页，所以各台电脑看到的相同。发送失败的消息不进入历史。翻出的输入以“/”或“@”开头时不打开斜杠命令或提及菜单，方向键继续浏览历史。不提供服务端历史的输入框没有输入历史。
- **切换 Resident 时立即切换输入历史。** 每个会话的历史分开保存；新会话还在加载时，不会读到上一个 Resident 的历史。
- **Fork 出的 Resident 的输入历史包括它继承的输入。** 完整 Fork、最近 5 轮或 10 轮、从指定消息 Fork 和压缩后继承都用同一规则。压缩只影响新 Session 中模型看到的上下文，聊天显示和输入历史仍包含全部继承消息。
- **输入历史保留附件。** 选中一条历史时，图片和文件以附件的形式回到原位置，不变成路径文字；按向下键回到原草稿时，原草稿的附件一并恢复。重新发送时复用已有上传 ID 或路径，不重新上传。

### 斜杠命令

斜杠命令菜单只列界面数据给出的命令（会话合同的 `composer.slash_commands`，按 Provider 的声明推出，见 decision_8b2fa224616b）；没有给出或给出空列表时不显示菜单。输入 `/` 打开菜单，方向键选择，Enter 插入命令和一个空格，Escape 关闭。

### 引用（Refs）

Refs 让用户为下一条消息选择共享 Skill、第三方 Skill 和 Shared Agent。候选来源和发送后的处理见 decision_c616d197abbb。

- **第一次打开 Refs 时，组件按当前登录身份加载候选目录。** 所有页面使用这一行为。加载中显示“正在加载引用选项…”，结果到达后立即更新面板。
- **加载失败时显示失败提示和“重试”。** 只有成功加载且某一组确实为空时，该组才显示“无可选项”。失败不会清空已选的引用。
- **同一实例中，正在进行的请求和成功结果都会复用。** 重开面板保留已选引用、分组折叠状态和草稿。关闭面板不取消请求；实例销毁后忽略晚到的结果。
- **面板顶部的搜索框按名称、ID、路径和描述筛选，不区分大小写。** 筛选在已加载的目录中进行，不发新请求。有匹配的分组自动展开，没有匹配的分组隐藏；全部不匹配时显示“没有匹配的引用”。清空搜索恢复完整目录和原来的折叠状态。
- **搜索只影响显示。** 被筛掉的已选引用仍然保留；搜索文字在关闭再打开面板、目录刷新时保留，各实例互不影响。“Clear”清空的是引用选择。

### 图片、文件与选中文字

- **选择、粘贴或拖入的图片和文件，以不可编辑的引用节点插入在光标处。** 草稿中图片占位为 `[[portal-image:<id>]]`，文件为 `[[portal-file:<id>]]`。节点可以拖动，位置决定发送时在正文中的顺序，拖动不会重新上传。
- **发送时，上传完成的图片和文件以消息的媒体内容部分携带 `upload_id`。** 会话快照返回后，Chat Workspace 从媒体部分还原附件引用；上传图片使用受会话权限保护的 `/api/uploads/<upload_id>` 显示缩略图并打开预览，已有本地路径媒体仍按路径显示。
- **聊天中的文件引用保留用户插入的位置与次数。** 模型输入为工具读取追加的 `[file: ...]` 路径说明不另画成聊天附件。消息投影根据已受理的文字分段边界与文件身份核验完整的追加说明，核验成功后按原始媒体顺序恢复正文；首次快照、事件补读和历史读取共用此规则。用户正文中的路径标记及不能核验的内容保持原样，模型输入和持久 Segment 不因展示解包而改变。
- **有附件在上传时不能发送。** 上传失败的附件可以重试或移除，失败的附件不会被发送。
- **发送前用户移除已上传的附件时，组件同时删除服务器上的文件。** 删除引用节点、从托盘移除和撤销刚插入的附件都是如此。点击发送把附件交给本地提交后，清空输入框只清除本地编辑，保留消息引用的文件供提交、显示与显式重试使用；受理、入队和写入会话同样不删除文件。
- **从消息或 Preview 选中的文字形成一个引用附件。** 类型为 `text/x-portal-preview-reference`，保存完整引文、来源路径和来源消息 ID。

### 附件的可见范围

- **能查看一个会话的人，就能读取其中的图片和文件。** 聊天附件的上传记录通过 `resident_id` 绑定所属会话；图片预览、文件读取和消息中的引用都按会话可见性判断，不要求读取者是上传者。用户和 Resident 适用同一规则，由 SocietyService 统一检查。
- **在另一个会话中重新引用附件时，先检查来源会话的查看权限，再检查目标的发送权限。** 附件路径、上传记录和原消息保持不变，新消息以实际发送者署名，不需要复制或重新上传。
- **还没有绑定会话的草稿附件只有上传者能读取。** 来源记录缺失、文件身份不符或路径越界时拒绝读取。能查看附件不代表能覆盖或删除它。

### 队列

队列列出已发送、尚未开始处理的消息，让用户认出每一条并决定立即注入、删除或整理。它只是摘要，完整内容在消息发出后的会话中查看。

- **“立即注入”只在 Resident 的后端能在运行中接收输入时出现。** 界面数据的 `controls.active_turn_input` 为 `true` 时，每条排队消息显示“立即注入”：消息立即转入在途输入，当前执行可以接收时注入，否则退回普通队首，可查看、撤回或清除，等待下一轮处理。后端不支持时不显示这个按钮。
- **Resident Chat Workspace 标题栏的最右侧提供齿轮形 Menu 图标。** 点击在当前页面打开该 Resident 的共享 Menu，默认显示 Settings，不改变对话目标。标题栏不再单独显示“Session 操作”按钮；Provider / Session 切换从 Menu → Settings → Backend 进入，已有切换进度与失败提示继续使用共享组件。
- **Resident 聊天的排队区提供“合并所有 / Merge all”。** 每条等待中的消息仍有“立即注入”（当前一轮可以接收时）和“删除”。标题栏的“合并所有”与 Resident Menu → Mailbox 中全选后“合并所选”一致（decision_15f7df737ed5）：点击后重新读取当前 Resident 的 Mailbox 和整理权限，按待处理顺序提交全部请求、群体的消息 ID，排除背景 info，不受 Chat 摘要显示范围限制。已有群体由服务端展开，客户端不读取或重写原文。排队区中可合并的请求、群体不足两项时隐藏“合并所有”，不显示禁用按钮；单个群体即使包含多条原消息也只计为一项，背景 info 不计入。至少两项时显示按钮，读取时队列已不足两项则提示并刷新。读取和合并期间锁定队列动作，成功回执后刷新，失败保留队列并显示原因；切换会话后不提交尚未发出的合并，旧目标的回执或错误不影响新会话。数量旁仍在两条以上时显示“全部清除”。选择部分消息合并、拆分和调序继续由标题旁的 Mailbox 链接进入；其他 Chat 不提供 Resident 合并动作。标题和按钮在窄面板换行，按钮保持可见可点。

- **每条消息显示为一行摘要，超出部分用省略号。** 标题、列表、表格和代码块不产生排版效果，原始 HTML 作为文字显示；换行只在摘要中合并，原消息保持不变。
- **图片、文件和资源引用使用共享的附件和引用组件显示。** 队列数据保留有限长度的文字预览和结构化的媒体部分，不为显示再读取完整消息。
- **相邻消息之间用一条随主题变化的细横线分隔，第一条上方不加线，不给每条消息套卡片。** 作者和时间单行省略，不撑高行。“立即注入”和“删除”按钮在窄面板中仍然可见可点，不被摘要挤压。队列整体高度有限，多条时在区域内滚动。
- **队列超过一条时，标题栏数量旁显示“全部清除”。** 用户确认后，页面提交一次带 `resident_id` 的 `ClearMailbox` 指令，由服务端判断权限和哪些消息可以撤回；需要对该 Resident 有 contributor 权限，已经开始执行或正在注入的消息保留，接单状态不变（decision_c524c775e0be）。确认和请求期间队列按钮不可用，重复点击不会产生第二次请求；输入框和发送照常可用。页面在收到服务端回执后才更新队列，并按回执的 `cancelled` 提示清除数量。取消确认或请求失败时保留原队列。切换 Resident 后，未确认的清除不会提交，旧目标的回执不会影响当前对话。

### 回答中的文件链接

- **Resident 回复中的相对文件链接，按该 Resident 默认 Workspace 解析。** Workbench 用 Folder 的 `primary_root_id` 组成 Resident 虚拟路径，通过 Resident 文件接口读取并检查权限。读取成功后在对应格式的 Preview 中打开，无法预览时提供下载。文件形式的相对链接不会显示成网页链接卡片。绝对路径、显式根路径、统一资源地址和普通网址按各自原有方式处理。

### Which Resident 的推荐视图

- **Resident 聊天面板可以为特定 Resident 换上专用的消息区视图。** 页面通过 `conversationView(target, panel)` 提供视图，绑定的 `resident_id` 匹配时生效，离开后恢复普通聊天。Which Resident 用它显示当前用户最近的推荐查询、反馈、候选选择和纠正卡片，普通输入提交到推荐接口，由这个 Resident 处理（decision_8fe87d812a4c）。视图生成的结果消息没有正式消息 ID，不能转发或执行消息操作。
- **回复中的 `portal-resident-handoff` 代码围栏显示为交接卡片。** 只有完整的顶层围栏生效，其他代码块里的示例保持为代码。卡片校验 Resident 与 Lineage ID，链接只由校验过的 ID 构造，提供“打开对话”和“替我问一下”，推荐动作带“（推荐）”；“替我问一下”在当前对话发送固定格式的普通用户消息，不带草稿、附件和引用。所有共享 Chat 宿主（包括 Chatroom）使用同一实现。字段与语义见 decision_8fe87d812a4c。
- **个人助手门面对话中的 AMA 历史只是展示服务端投影。** 带 `family_history` 的消息标注为该 AMA 的历史（名称取自元数据），历史与门面消息之间显示分界和时间，分界同时截断消息分组；分页令牌原样回传，引用仍只给原消息 ID。客户端不另建历史会话（decision_44cf587c1721）。

### 聊天室

- **Chatroom 是一个使用同一套消息渲染和输入框的 Workspace 实例。** 它的界面数据由聊天室指令组装（decision_a6bebf4ac283）：附件上传的目标是聊天室 ID（`attachmentUploadContext` 中的 `upload_target`），不提供 Resident 运行状态、队列、Stop、Refs 目录和运行设置；消息的“引用回复”继续使用共享引用条和消息菜单。

## 实现

### 各部分保存什么

| 部分 | 保存和负责 |
| --- | --- |
| 服务端（SocietyService 等） | 会话历史、消息顺序、队列、运行状态和权限 |
| Workspace 实例 | 自己的草稿、附件、选区、滚动位置和按钮忙碌状态 |
| 宿主页面 | 当前目标，以及丢弃晚到的旧目标结果 |
| Conversation Store | 跨页面的会话摘要和未读 |
| Resident 协议状态层 | 同一 Resident 的本地提交、发送顺序、待确认查询，以及正式消息和队列的对齐 |

网络错误、无权限、目标不存在和一般协议错误都显示在当前面板内，仍然有效的草稿保留。

```text
服务端的会话快照 + 界面数据（portal.chat_workspace.v3）
                 │
                 ▼
     宿主页面交给一个 Workspace 实例
                 │
                 ▼
 消息 / 输入框 / 附件 / 控件 / 滚动位置
                 │  用户发送或执行动作
                 ▼
     Resident 输入与运行控制协议（decision_c524c775e0be）
                 │
                 ▼
     新的快照或按顺序到达的事件，再次更新界面
```

### Resident 聊天的数据来源

Resident 的会话、状态和可用操作由 SocietyService 直接提供，聊天组件直接使用它的快照、事件和回执。SocietyService 按当前用户的权限和 Resident 状态返回 `controls`，说明能否发送、能否停止、不能操作的原因和发送提示；Composer 的 `can_send`、`can_stop` 和提示直接取自 `controls`。没有 `controls` 时不开放发送。会话的名称、Session、能力入口和显示配置来自会话元数据，它和上一次的显示结果都不参与判断能否操作。

共享的协议客户端负责缓存快照、按游标补读事件、保证事件顺序、让多个聊天共用同一个订阅。状态变化通知会触发一次经过权限检查的补读，同时更新状态和 `controls`；身份或权限变化通知会触发重新读取。服务端在经过权限检查的 `resident_changes` 中注明变化的范围：只有收到 `identity` 等元数据变化，或事件流重新连接时，才重新读取界面数据；普通的运行和会话事件不触发。多个使用方共享同一次读取。

发送回执还没到达时，用户可以取消这个实例正在提交的那条消息（按消息 ID）。这只是本地操作，实际取消仍经过运行控制协议的检查。

### 运行详情的显示

原生命令/权限审批卡片在窄 Chat Panel 中必须完整容纳长 JSON 参数和审批按钮：卡片单列允许收缩，参数区的换行规则须高于 Markdown 通用 pre 规则，长路径与无空格文本不能撑宽面板。较长正文可在限定高度内滚动；取消和允许按钮始终位于卡片边界内。

执行事件的含义（身份、类型、状态、完整活动内容和输出文字）由 ExecutionService 的 `execution/event_projection.py` 给出；聊天不从摘要反推执行结果。`portal_chat_workspace_projection.py` 的 `runtime_detail` 在副本上做显示处理：运行中的输出保留末尾一段，已完成的输出按消息长度上限截断并标明，其他活动合并空白后按摘要长度截断。`runtime.details` 和消息附带的 `runtime_details` 都经过这个入口。显示处理不修改原始事件和执行存储，调整截断长度只影响显示。

### 历史分页与消息更新

Markdown 正文中的图片、文件和引用附件在渲染期间保持独立边界。临时附件占位符不得被资源识别并入地址、链接、提示属性或可见文字；即使资源地址与附件直接相邻，资源标记仍保留完整且唯一的资源身份，附件独立呈现并沿用自己的预览操作。资源标签仅识别正文中的真实地址。

共享消息渲染器按消息身份保留未变化的正文节点、选区和菜单。加载更早消息时，重新渲染新增页以及与原历史交界处受影响的消息组；人类短时连续发言和 Agent 连续回复的分组仍依据完整消息顺序计算。未受影响的历史不再执行 Markdown 渲染、附件绑定或正文尺寸测量。流式尾部更新使用相同的节点协调逻辑，仅替换变化的后缀。

分页保持用户正在阅读的位置；最终一页更新“加载更早消息”控件。目标、渲染选项或运行状态变化时，根据变化范围重新渲染，保留原有的消息折叠和选区规则。

### 长消息的折叠

- `messageListHtml` 只给按默认方式渲染的 Markdown 正文加折叠：`.messageContent` 带 `data-message-fold`（`collapsed` 或 `expanded`）和 `data-message-fold-size`（`long`、`short`，尚未测量时为空），后面紧跟“展开全文／收起”按钮（`data-message-fold-toggle` 为消息 ID，带 `aria-expanded`）。`renderMessageBody` 换了正文的消息（卡片、提问、转发参考、Which Resident 推荐）不加；宿主可以传 `foldLongMessages: false` 关闭。
- 只有 `long` 的正文会被折起：样式把它限制在 6 行，用 `overflow: clip` 裁剪、mask 渐隐，按钮也只在 `long` 时显示。裁剪不改变 DOM 中的文字，复制为纯文本仍读到整条正文；选中文字延伸到折起部分时，“添加到上下文”按钮停在正文可见部分的末尾。
- 每次渲染后测量新渲染的正文：先读出全部 `scrollHeight`，超过 12 倍行高记为 `long`，再统一写回，列表只排版一次。消息列表的 ResizeObserver 在宽度变化或从隐藏变为可见时重新测量全部正文，正文中的图片加载完成后重测这一条；用户在读历史时，以第一条顶部在视口内的消息为准保持阅读位置，并把此时在视口内、刚变长的消息记为展开。测量结果按消息 ID 缓存在实例中，重绘时直接写进标记，已有节点照常复用。
- 默认展开的消息：时间最新的一条 Agent 文字回复（卡片和提问不算；Family 门面的回复跟在所答请求之后，所以按时间而不是位置判断）、`pending` 的消息、Family 门面中成员正在处理的请求已经收到的输出（`live_output`），以及运行中最后一条非 Agent 消息之后的 Agent 输出。这个集合变化时（新回复到达、运行开始或结束，包括只更新运行状态的 `setRuntime`），只从变化的最早一条开始重绘后缀；用户在读历史、这条消息又在视口内时，它不随默认值折起，记为展开。
- 用户的选择按消息 ID 记在模块级的表中，本页面有效，不保存；同一页面上同一条消息的其他副本一起改变。展开时保持正文顶部的位置，收起时保持按钮的位置，然后按实际位置决定是否继续跟随最新消息。
- Workbench 布局变化（打开或关闭相邻 Panel）以第一条顶部在视口内的消息为锚点恢复位置；用户滚动之前，连续的布局变化沿用同一条消息，来回开关之后回到原处。

### 引用回复

- **引用卡片只展示一次引用，正文显示这条消息自身的内容。** 执行后的当前 Segment 保留完整模型输入；聊天读取时，消息展示投影依据这条消息已接受的 `quote` 校验正文开头的 `<quoted-message>` 包装，完整匹配作者、消息 ID 和摘录后移除这一层。原始正文长度仍与接收时的文本分段一致时直接保留正文；无引用、内容不匹配或包装损坏时保留当前全文。普通正文中的标签示例保留，结构化引用、实际模型输入和持久 Segment 均不因展示解包而改变。首次快照、事件补读和旧历史读取采用同一规则。
- 摘录生成与展示由共享 Chat Workspace 负责：Resident Chat 和 Chatroom 都通过 `messageQuoteExcerpt` 取得最多 1000 字符的正文摘录，使用同一引用条与引用块渲染。CSS 负责把摘录限制为一行并按宽度省略，保留原摘录文本；作者、取消按钮和跳转提示独立布局，窄栏不被长摘录撑宽。
- `ResidentChatPanel` 在消息右键菜单最前面给有正文、已受理（有 `message_id`、不是 `pending`）的消息加“引用回复”；`quoteMessage` 把消息 ID、作者和正文开头交给 `workspace.setQuote`。
- 引用条按会话（`historyScope`）记在实例内存中，不进草稿；`[data-composer-quote-host]` 在附件托盘和输入框之间，`updateControls` 时按当前会话重画。斜杠命令不带引用；发出的消息只带 `quote.message_id`。Resident 点击发送时将引用展示在临时消息中并清空引用条；失败时引用随气泡保留，旧回执不能清空后来选择的引用。
- `messageListHtml` 在消息头之后、正文之前画 `.messageQuote`。带 `message_id` 的是右侧附有“↑”提示的按钮：`revealMessage` 在 `.messageList` 的直接子节点中按 `data-message-key` 查找，找不到时调用 `onLoadOlder` 逐页加载（直到找到目标、历史结束或分页不再前进）；它在折起的中间输出组里时先展开，再滚动到视口中部并短暂标出。只有作者和摘录的引用块不能点击。引用块不在 `.messageContent` 中，复制和折叠只看正文。

### 界面数据的更新

- `applyUpdate` 只接受发给当前实例的更新，实例 ID 不符时拒绝。修订号或内容签名相同的更新默认跳过，`force` 可以强制重新应用。普通消息更新追加到现有消息；`reset` 或 `mode="reset"` 用服务端给出的消息整体替换本地消息。
- Reset 可以先清空视图；失败时宿主重新应用服务端的会话快照。发送、Reset 和事件更新之后，界面最终都以服务端的会话快照为准。
- 停止、Auto、历史、队列和运行设置只在界面数据声明了对应能力和动作时启用。动作带 `instruction` 时交给 Resident 指令客户端执行；否则只接受 POST 地址。组件只显示局部的忙碌和错误，发送、停止、重启、队列注入和取消的顺序与重试规则由服务端协议决定。

### 目标由谁决定

聊天组件只使用已经解析并检查过权限的目标，不根据 `surface` 或 `workspace_key` 推断 Resident 属于哪个 Lineage。业务页面负责目标的身份和创建，Lineage 和 Resident 服务负责成员和会话权限。草稿按作用域分开保存，这和会话是否私有无关。

例如，Paper 研究对话按“Paper Lineage、论文、当前用户”确定一个长期 Resident，这些 Resident 都属于同一个 Paper Lineage。Paper 页面默认只打开当前用户对应的那个；Lineage 的所有 owner 都能在 Society 页面阅读这些会话并发送消息，其他 owner 发送的消息署他们自己的名字。因此 Paper 页面不显示“仅自己可见”之类的说明。完整规则见 decision_528bf9985705。

### 还没有 Resident 时的草稿

有些页面在用户第一次发送时才创建 Resident。页面通过 `pendingHistoryScope` 提供一个稳定的业务作用域，如 WALL 用工程 ID 和设计点 ID。Resident 聊天面板在还没绑定 Resident 时用这个作用域保存草稿；绑定成功后切换到该 Resident 的标准会话作用域。

关闭面板、切换条目或绑定其他 Resident 后，之前发出的创建请求即使成功返回，也不会发送旧消息、覆盖当前草稿或建立过期的绑定。

尚未绑定 Resident 时，扩展菜单明确提示“发送第一条消息后可配置会话扩展。”，不显示虚假的配置加载状态或可保存的开关；打开菜单不创建 Resident。首次发送完成绑定后，扩展菜单保留 Watchboard 的安装与移除，并提供一行“Harness”入口：点击后关闭扩展菜单，在当前页面打开该 Resident 的 Menu，直接显示 Harness 分栏（decision_5bc3fdfc7eec）。Prompt 注入、允许开启 sub agent、失败后续跑一次、智能选择 Harness 和各项 Harness 功能只在这个分栏中设置。

Harness 分栏的“Prompt 注入”打开同一设置子页面；预设、类别时机、Provider placement、读写与预览合同以 decision_ef1d6c925955 为唯一正文。此处只规定 Chat 的接入：返回回到 Harness 设置列表，读取失败回到列表并显示原因，切换分栏或关闭 Menu 时关闭子页面，不在 Chat 复制注入策略。

### 接入 Workbench

从“我的 Mailbox”、Home 状态入口或 HATG 打开 Resident 时，当前 Chat 被隐藏应恢复显示，被关闭应按目标身份重建；桌面与窄屏使用相同规则。窄屏聚焦必须先恢复隐藏面板，再决定当前展示面板。普通页面重载仍保留用户的隐藏布局。

Chat 面板以支持多实例的面板包接入 Workbench，声明会话、运行设置、引用、快照和恢复能力。面板运行时响应 `connect`、上下文更新、`show`、`hide`、`snapshot`、`restore`、`disconnect` 和 `destroy`；关闭面板或切换目标时取消旧的订阅，正在进行的请求结果作废。

每个 Chat 面板（包括默认面板）保存自己的聊天目标，重新加载时各自恢复，不依赖页面地址或宿主当前的选择。保存的内容只有目标；旧格式的保存数据只取出 Resident 身份，消息、运行状态和权限都在重新加载后向服务端读取并检查。

首次加载或恢复失败时，面板显示局部的不可编辑错误状态，不另外弹出全局错误；主动调用加载的代码仍会收到失败结果。403 和 404 统一显示为“目标不可用”，并取消旧订阅。加载完成后的临时错误照常提示，有效的会话和草稿保留。

从其他页面跳转到对话时，地址带一次性参数 `open_chat=1`；Society 页面恢复并聚焦 Chat 面板后删除这个参数，之后刷新保持用户当前的面板布局。所有要求显示 Resident 对话的导航都先恢复并聚焦 Chat 面板，再切换对话目标。HATG 节点菜单中的“打开对话”先找已经打开这个 Resident 的聊天并聚焦它，保留未发送的草稿；没有时才打开新的。图中新增成员后，状态订阅立即包含新节点。

已知准确 Resident ID 的页面首次导航中，Resident 资料和第一页聊天历史可与目标归属解析并行读取；每个请求仍由服务端独立鉴权，只有导航解析成功后才挂载目标聊天。预取与面板共用已有的 Resident 协议和资料投影，不建立另一份消息缓存。导航在交给面板之前持有临时会话订阅，防止中途释放快照而重读历史；导航结束或失败时释放该订阅，由面板继续持有已打开的会话。首次初始化与恢复面板共用已有读取，主动刷新才要求新快照。身份切换先清除旧身份的数据和请求；等待新身份的读取共用一次请求，不再追加强制重读，旧身份的迟到响应继续丢弃。刷新时隐藏的 Chat 继续保持隐藏，不为它发起预取。预取不会提前确认已读，也不改变最终可见目标。

### 页面接入要求

Paper 与 Project 等嵌入式讨论只读加载时不创建 Resident。准备首次发送时，宿主用非空草稿显式调用 `POST /chat-workspace/api/prepare`，依据当前用户和工作区范围取得绑定；准备不投递消息，重复准备与随后只读刷新复用同一 Resident。调用 Resident 绑定接口时只传其声明的身份与运行参数，项目来源保留在 `metadata.project_id` 中；它不作为独立的 Resident 创建参数，也不改变既有 Lineage 的归属。

宿主页面需要提供：界面数据、切换目标时丢弃旧结果、上传处理、动作执行入口和错误显示位置。Resident 的发送和停止直接使用 SocietyService 的协议，页面和组件都不复制它的状态规则。修改聊天界面和 Composer 时更新本 Design；修改消息协议和执行顺序时更新 decision_c524c775e0be；修改跨页面提醒时更新 Conversation Store 或 Inbox 的 Design。

宿主可以通过 `submissionContext` 在每次发送前异步取得当前业务上下文；临时气泡先显示，协议状态层按提交顺序等待上下文准备完成后将它附在同一条规范输入中。读取失败在对应气泡下方显示错误，后来的草稿保留。宿主负责校验上下文仍属于原目标。没有该回调的宿主继续使用仅在首条输入附带的 `initialContext`。

悬浮面板类宿主（如 Mailbox 下方的个人助手面板）另用两个接口：`onInteractionChange(open, menu)` 在消息菜单打开和关闭时通知宿主，菜单移到 body 上时面板不会因指针离开而收起；实例的 `setPresented(presented)` 告诉 Chat 面板当前是否展示，未展示时可见性观察器不提交已读，再次展示后才确认。

### 用户提及输入

共享 @ 候选支持 User 与 Resident。User 候选显示名称、用户名和头像，选中后以不可编辑的名称节点显示，发送与草稿序列化为稳定的 `@用户名`。候选来源和提及后的业务行为由宿主负责；Chatroom 只提供房间成员，引用 Resident 消息时自动在输入框补上对应 @。

## 首次打开与失败恢复

Resident Chat 打开时并行读取 Resident 详情与 Conversation 快照。首次加载整体最多等待 30 秒；超时、请求失败或页面应用投影失败时，应退出加载遮罩、显示错误并保留未发送草稿；再次打开目标可以重新加载。
