# Portal Workbench 模块与运行架构

Portal Workbench 是 Portal 复杂页面中的可编排工作区。用户在 Agent Console、Lineage 编辑器或资源详情中看到的聊天、导航、预览、终端和领域编辑器，可以同时摆在这个工作区内；用户可以切换标签、拖动面板、调整分栏、暂时隐藏工具，并在重新打开页面后恢复空间组织。

本 Design 负责解释 Workbench 在页面中的位置、用户能操作的空间对象、内部运行组件、一次面板装配怎样流动、状态由谁保存以及故障怎样被隔离。具体聊天内容、资源权限、文件保存和图编辑规则仍由各自面板及其领域服务负责。实现 Panel 类型所需的精确注册字段和方法由 `decision_538e155e1102` 说明；本篇先建立理解那份协议所需的整体架构。

## 用户看到并操作的对象

- **工作台（Workbench）**是页面中容纳多个工具的主工作区域。它提供空间、标签、分栏和恢复能力，不解释工具中的业务内容。
- **面板（Panel）**是工作台中的一个工具区域，例如 Navigation 导航、Chat 对话、Preview 预览或 Terminal 终端。面板有标题、图标和稳定身份。
- **标签（Tab）**是面板在标签栏中的入口。多个标签可以共享同一块显示区域，当前选中的标签对应可见面板。
- **标签组（TabStack）**是一个标签栏及其下方的内容区。在可调整布局中，只剩一个标签时仍保留可唤起的标签栏；固定布局时隐藏布局标签头。
- **分栏（Split）**把工作区横向或纵向切成相邻区域。两个区域之间的分隔条可以用鼠标、触摸、笔或键盘调整。
- **隐藏轨**保存用户主动关闭的可选面板入口。隐藏表示暂时从布局中移走，面板仍可恢复。
- **活动轨（Activity Rail）**是一列快捷入口。它可以显示固定视图、最近活动、运行状态和未读点，并允许用户调整视图顺序。
- **移动端面板切换器**是在窄屏上出现的面板入口栏。移动端一次显示一个主面板，但所有已装配且未隐藏的面板仍可到达。

“折叠”与“隐藏”含义不同：折叠后的面板仍在原分栏中并保留窄条；隐藏后的可选面板离开当前布局，用户通过恢复入口把它放回。

## 支撑这些界面的运行概念

- **布局树（Layout tree）**是工作台的空间记录。它只包含分栏节点、标签组节点和面板位置。
- **面板包（Panel Package）**是一种面板类型的注册合同。它声明标题与图标、最小尺寸、单实例或多实例策略、能力、关注的上下文、命令、持久化版本和创建函数。
- **面板实例（Panel instance）**是某个面板包在一个工作台中的一次具名使用。两个 Chat 面板可以属于同一种包，同时拥有不同实例身份和局部状态。
- **面板运行对象（Panel runtime）**是实例背后的领域代码。它读取当前目标、处理交互，并在显示、隐藏或销毁时取得生命周期通知。
- **工作台上下文（Workbench Context）**是同一工作台内共享当前协作目标的通道集合。它传递 Resident、会话、文档或图选择的引用，不复制完整正文。
- **命令作用域（Command scope）**是当前工作台的命令集合。工具栏和快捷键读取同一份可见性、可用性与忙碌状态；全局资源搜索不列出工作台命令。
- **持久化封套（Persistence envelope）**是带面板包类型、包版本和状态结构版本的局部快照。封套只用于精确恢复当前结构，不授予业务对象权限。

## 设计点

### 打开、切换与移动

- 用户选择标签时，工作台显示对应面板。再次选择已经活动的标签不会重新挂载面板运行对象。
- 用户把标签拖到另一个标签组的标签区时，面板加入该标签组；拖到标签组左、右、上、下边缘时，工作台在对应方向创建分栏。
- 用户关闭可选面板时，面板进入隐藏轨并保留恢复入口。必需面板不会进入隐藏集合。
- 用户重置布局时，工作台恢复页面提供的默认布局和默认隐藏集合。面板声明的 `defaultHidden` 只决定首次装配时是否隐藏。
- 工作台只接受能够解释的布局。结构版本 2 只允许分栏、标签组和面板节点；恢复时会移除未知面板与重复面板，并补回页面要求的必需面板。
- 全部可选面板都被隐藏时，工作台仍显示恢复入口，用户不会得到无法操作的空白区域。

### 调整大小与折叠

- 用户拖动分隔条时立即看到尺寸变化。工作台只响应主鼠标键、触摸或笔输入，并通过指针捕获保证指针离开分隔条后仍能连续拖动。
- 拖动结束或取消时才提交持久化快照，连续移动不会把每一帧都写入存储。
- 键盘用户可以聚焦分隔条。方向键每次移动 24 像素，按住 Shift 时步长扩大四倍，Home 与 End 移到允许范围两端；每次键盘操作后保存布局。
- 分隔条公开无障碍的分隔线角色、方向和当前范围。
- 横向折叠区保留 44 像素，纵向折叠区保留 34 像素；相邻展开区横向至少保留 96 像素，纵向至少保留 72 像素。
- 嵌套分栏会合并子树最小尺寸约束。可用空间足够时，各展开区域保留子树所需的最小尺寸；空间不足时，按各子树的最小尺寸比例分配空间，并扣除折叠条和分隔柄。包含多个并排面板的子树据此取得所需空间，异常的历史权重或极端拖动不能让单个导航区挤占这些空间。

### 布局调整菜单

共享布局弹层使用与顶栏相同的字体变量，正文与控件为 13px，分组标题为 12px，主标题为 14px。控件显式继承字体，避免浏览器默认按钮字体与无效 font 简写造成混杂。

弹层优先展示可以隐藏的常驻面板开关、两列布局预设、已保存布局、命名保存与恢复默认。必需或不能隐藏的面板不显示无效开关。重复的工作区标题和拖拽说明不再占据空间；新建编辑器放在默认收起的区域，展开后仍可新建标签或在侧边打开。语言偏好由账号菜单和 Settings 管理，不混入布局菜单。常驻 Chat 面板在布局开关中固定显示本地化的“Chat Workspace”，使用独立的 `layoutTitle`；会话或 Resident 名称只更新内容标签的 `title`，切换会话、恢复布局或重绘菜单均不覆盖该面板名称。其他未提供 `layoutTitle` 的面板继续使用原有标题。布局能力、已有保存记录与面板打开协议不因排版变化而丢失。

工具栏省去当前布局名称和固定按钮的文字，只保留相应图标与悬浮说明；调整布局入口仍保留文字。当前布局名称进入调整布局按钮的提示，固定按钮继续提供状态与无障碍名称。

### 固定与解锁布局

- **用户通过“调整布局”旁的“固定”按钮固定当前工作台。** 固定后，图标高亮，悬浮提示与无障碍名称显示“解锁”，保留当前分栏比例、面板位置、活动标签和收起状态；解锁后可以继续编辑原布局。
- **固定模式隐藏面板的布局标签头和悬浮触发区，并释放标题占用的空间。** 面板不能拖动、关闭、折叠或重新排列；原分隔柄显示为细分隔线，不再接受指针或键盘尺寸调整。
- **布局固定不冻结面板中的业务工作。** 当前 Chat 的对话、草稿和阅读位置保持，Preview 可以继续操作当前显示的文档，图编辑仍由图面板负责。
- **固定后的多标签组通过工具栏中的内容选择器切换。** 选择器只切换该组的可见内容，不改变面板排列；手机端继续使用原移动面板切换器。
- **新增、重开已隐藏面板和展开已折叠面板前需要解锁。** 布局预设和重置命令同样暂不可用；打开新编辑面板的请求说明需要先解锁，已展开面板的内容打开仍可复用现有实例。
- **固定状态随当前用户的工作台布局保存。** 刷新或重新进入页面恢复该状态，其他用户和独立工作台不受影响；没有保存固定状态的工作台可正常编辑。
- **嵌套工作台继承外层的固定状态。** 继承只限制当前交互，不改写子工作台自己的固定偏好；外层解锁后，子工作台恢复自己的状态。
- **固定和解锁使用约 220 毫秒的面板外观过渡。** 固定时布局标签头向上淡出、边框与阴影收拢；解锁时反向展开。正文不参与透明度或缩放动画。
- **过渡不延迟布局约束生效。** 退出中的标签头仅覆盖内容且不可交互，不占据额外行高；正文一次进入最终尺寸，保持实例、输入焦点、选区和阅读位置。
- **快速反向切换会取消上一段过渡。** 工作台销毁时释放动画；开启系统减少动态效果时立即完成切换，并取消尚在播放的过渡。

固定能力由共享 Workbench 负责。布局命令与控制器入口共同检查当前工作台及其祖先的固定状态，页面无需声明独立分支。持久化字段 `layoutLocked` 记录本工作台的用户偏好，`isLayoutLocked()` 返回包含祖先约束的有效状态，`setLayoutLocked(boolean)` 和命令 `workbench.toggle-layout-lock` 提供统一入口。切换只修改布局外观与控件状态并通知尺寸变化，不重建布局树、不重新挂载 Panel runtime；隐藏的编辑标签同时退出键盘交互。内容区始终占据布局的最后一行；常驻标题、悬浮标题、多标签组和移动端共用这一规则，标题隐藏后不保留空行。

共享契约由两组 Node 用例验证，它们直接运行生产代码 `static/portal_workbench.js`：`tests/cases/test_workbench_state_lifecycle.py` 核对面板隐藏后重开时恢复方向、顺序和原分栏比例；`tests/cases/test_workbench_visibility_state.py` 在 jsdom 中运行完整控制器和渲染，核对折叠约束下的选择、聚焦和显示请求被拒绝。真实浏览器中的布局尺寸、焦点和页面组合外观目前没有自动化测试。

### 桌面、移动端与活动轨

带活动轨的页面使用公共 Workbench 页面布局组件，Lineage、投影独立页、Studio 预览和多视图组合共享同一份布局实现。布局组件同时拥有活动轨宽度、border-box 盒模型、相邻内容槽位与间距；页面不自行复制侧栏定位或以额外边距补偿。窄屏时由该组件把活动轨和内容转换为上下排列，隐藏活动轨时同时取消占位。业务页面提供入口与内容，应用面板在分配的空间内工作；布局规则变化只修改公共组件，不要求页面逐一同步尺寸。

- 桌面端恢复用户保存的预设、命名工作区、面板位置、活动标签、隐藏状态和折叠状态。
- 移动端把当前活动面板投影为唯一主视图，并在切换器中列出全部已装配且未隐藏的面板。用户无需先恢复桌面分栏。
- 活动轨在初始化或可用视图变化时修复保存顺序：删除未知项和重复项，再补入新增项。用户完成拖动后，活动轨保存完整的规范顺序并通知宿主。
- 活动轨按可用高度计算能显示多少活动项，并且不超过调用方上限。无法测量高度时使用调用方上限；调用方未给上限时最多显示 24 项。未显示的活动仍保留在数据集合中，由页面宿主提供完整集合入口。
- 每个活动项可以分别显示未读实心点与运行状态环，页面宿主同时把状态写入无障碍名称。条目默认提供移除按钮；调用方把 `dismissible` 设为 `false` 时只保留选择入口。键盘用户用 Enter 打开，用 Delete 或 Backspace 移除；工作台在重绘后把焦点移到相邻入口或宿主指定的后备视图。
- 页面宿主可以在动态项目列表之后提供固定动作。动作与滚动或裁剪区域分隔，不占用活动项容量；批量修改、撤销期限和业务反馈由持有数据的领域组件决定。

## 组件分别负责什么

| 组件 | 负责 | 不负责 |
|---|---|---|
| 页面宿主 | 选择可用面板、默认布局、稳定工作台身份和领域适配器 | 面板内部交互 |
| 布局模型 | 分栏、标签、焦点、隐藏、折叠和面板位置 | 聊天正文、文件正文、权限结果 |
| 面板注册表 | 保存每种 Panel Package 的稳定合同 | 创建页面业务数据 |
| 面板实例与 runtime | 展示一个领域工具并处理该实例的局部状态 | 改写其他实例状态 |
| Workbench Context | 在当前工作台中发布目标引用和变更序号 | 读取目标详情、判断领域请求新旧 |
| Command scope | 统一命令可见性、可用性、快捷键和忙碌状态 | 决定领域操作是否获服务端授权 |
| 页面状态存储 | 关联用户、页面、工作台与可恢复快照 | 保存领域真值或继承权限 |

## 一次面板装配怎样流动

```text
页面建立 Workbench 宿主
        ↓
登记可用 Panel Package
        ↓
读取默认布局或用户布局快照
        ↓
为布局中的每个面板创建实例与 DOM 根节点
        ↓
create → connect → restore → setContext
        ↓
可见实例调用 show；隐藏实例保留待恢复状态
```

页面先提供工作台身份、根节点、默认布局和初始上下文。工作台根据布局创建实例，再调用面板包的工厂得到 runtime。`connect` 建立实例与上下文、命令和外部适配器的关系；兼容的局部状态随后进入 `restore`；`setContext` 提供当前目标；只有进入可见集合的实例才调用 `show`。这个顺序保证面板在真正出现前已经得到运行环境、恢复状态和当前目标。

目标变化时，Workbench Context 只在值真正改变时发布新修订号。一次批量修改无论改变多少通道只增加一次修订号；订阅者收到工作台 ID、修订号、浅冻结值和发生变化的通道。每个面板再使用自己的领域适配器读取详情。

```text
Panel A 选择一个目标
        ↓
Workbench Context 发布新的目标引用
        ↓
订阅该通道的 Panel B、Panel C 收到通知
        ↓
各 Panel 独立读取详情并更新自己的界面
```

## 显示、隐藏与销毁

同一页面组合多个工作台时，外层视图选择由页面装配者拥有。装配者通过工作台的 `setVisible(boolean)` 同步全局顶栏中的该工作台工具与面板运行对象的 `show/hide`；实际活动集合同时服从外层可见性和工作台内部活动标签。外层隐藏不修改布局树、用户隐藏偏好或保存的工作区，也不搬移或重建面板节点。工作台默认可见（`visible: true`），不根据 DOM 祖先的隐藏属性推断外层生命周期，以保持既有调用方在隐藏容器中创建工作台时的面板激活行为。具有外层视图的装配者显式传入初始 `visible`，并通过 `setVisible` 同步后续选择；异步装配在实际创建工作台时读取装配者的当前选择，晚到结果不能覆盖已经切换的外层状态。

- 面板进入或离开活动集合时分别收到 `show` 和 `hide`。隐藏实例保留可恢复状态，面板可以暂停只服务于可见界面的轮询或观察。
- Workbench 在调用 runtime 的 `show`／`hide` 或 descriptor 的 `onShow`／`onHide` 前，先提交新的活动面板集合。生命周期回调可以同步调用 focus、show 或 hide；由此产生的重入 render 必须观察已提交集合，同一次真实可见性转换只调用一次对应回调，不能递归重复激活同一面板。
- Workbench 创建 Panel Package 时先使用未连接到页面的宿主；完成布局后再把面板根节点一次接入最终位置，避免初始化阶段出现无意义的断开与重连。
- 改变分栏、标签位置或响应式投影时，Workbench 把整次 DOM 重排作为一次事务。浏览器提供 `moveBefore` 时，已连接面板使用状态保持型原子移动；API 抛错或移动未生效时不得降级强行搬移。浏览器缺少该 API 时，普通 DOM 面板可以搬移原节点，并保留输入值、焦点和输入选区；这同样适用于 Home 从隐藏 staging 首次装配，不能因为缺少可选浏览器能力而把普通面板全部留在隐藏区。
- 兼容搬移由共享 Workbench 统一判断，不由页面增加浏览器分支。含自定义元素、自定义内建元素、Shadow DOM、iframe、object、embed、音视频、popover、打开的 dialog 或全屏内容的已连接面板，不允许普通搬移，以免断连触发生命周期释放或丢失浏览器内建状态。每次移动与回滚均核对父节点及连接状态；任一面板不能安全搬移时，回滚已经移动的面板、保留上一个完整布局、不保存失败布局，并发出 `portal:workbench-layout-error`。
- 窗口或布局尺寸变化时，工作台重新计算空间，并向每个面板根节点发送 `portal:workbench-resize` 事件。需要尺寸的面板观察自己的根节点，工作台不调用 runtime 的 `resize`。
- runtime 通过工作台桥发送通用事件。事件名为 `open-resource` 时，工作台委托统一 Editor Open Service；其他事件交给页面提供的回调解释。
- 关闭动态面板时，工作台先把实例移出可见集合，再注销该实例命令，仅对仍可见的实例调用 `hide`，再调用 `disconnect`、`destroy`，最后移除 DOM。关闭前先调用 runtime 的可选 `canClose()`；返回 `false` 或拒绝的 Promise 时保留原布局和实例。
- 销毁整个工作台时，对全部 runtime 执行同等清理，并释放 Context、命令作用域、窗口监听器、拖动状态和宿主 DOM。
- 初始化失败并替换面板内容为错误提示时，同样释放已建立的尺寸监听器。已排队的回调只操作仍连接的原实例元素，不能查询替换后的 DOM。重试重新建立监听器，恢复后仍可正常测量布局；关闭面板时释放图形控件和 Seed 检视器的监听器。
- 领域面板必须用取消信号、请求 ID 或目标修订号拒绝晚到结果。Workbench 管理布局与实例，不比较聊天、文件或图数据的业务版本。

Resident 删除提交后，Society 页面关闭所有指向该 Resident 的 Chat 和文件 Preview，清除对应深链接与对话缓存，并停止已删除文件的刷新。Chat 菜单、HATG 节点菜单和目录菜单共用这一清理行为；其他 Resident 的面板保持当前内容。关闭菜单后的刷新失败也不能保留已删除对象的可操作界面。

## 保存与恢复为何分成三层

工作台把三种变化原因分开保存：

1. **布局树**回答“面板放在哪里”，记录分栏、标签组、活动标签、隐藏和折叠。
2. **动态实例描述**回答“重载后要重新创建哪个面板”，只为声明 `restoreOnReload` 的实例保存面板包类型、实例 ID、资源绑定和位置。
3. **面板状态封套**回答“该实例可以恢复哪些局部状态”，保存 `{packageType, packageVersion, schemaVersion, value}`。

所有组件化页面的 Workbench 默认自动恢复上次离开时的布局，包括嵌套子 Workbench 的位置、尺寸比例、标签顺序、活动标签、隐藏和折叠状态。共享运行时以 `portal.workbench.<workbench-id>.user.<user-id>.v1` 为用户逻辑键，`PortalState.storage` 在实际 localStorage/sessionStorage 键前统一加 `tfi.installation.<storage_namespace>:` 安装隔离前缀，不需要各页面重复实现保存逻辑；显式提供的用户存储继续生效。用户尚未确定时只使用内存，身份确定后恢复该用户记录；旧的无用户浏览器键不读取、不迁移。首次进入没有记录或用户主动选择恢复默认时才使用预设，页面初始化的数据加载不能无故重开用户关闭的 Panel。明确请求另一业务对象的深链接仍可打开对应 Panel。

没有必需 Panel 时，用户关闭全部 Panel 后的 `layout: null` 是合法、可持久恢复的空布局，不代表初始化失败或缺少布局记录。首次恢复、刷新和用户身份切换后的恢复都必须保留隐藏状态，显示与关闭最后一个 Panel 时相同的空状态及重新打开入口；不得补出无标签的空 Stack、空白面板框，也不得自动恢复默认布局。此规则同样适用于嵌套子 Workbench；声明为必需的 Panel 仍须保持可见。

布局操作完成后自动保存，鼠标拖动中的每一帧不写本地存储；`pagehide` 与销毁前提交最后快照。分栏保存同一比例单位，只改变被拖动的相邻区域，不让其他兄弟区域因混入像素权重而被压缩。相同视口恢复原尺寸，不同视口按原比例和组件最小尺寸适配。状态只保存在当前浏览器，不提供跨设备布局同步；无需跨重载恢复的宿主仍可显式使用内存存储。命名的“保存工作区”是另存一个可选择的预设，不是记住当前布局的前提。

恢复时，工作台要求面板包类型与状态结构版本都精确匹配当前合同，再把值交给恢复函数与 runtime。缺少版本、版本不同、未注册类型、类型不匹配或结构无效的单个状态会被忽略，默认布局和其他面板继续启动。历史状态必须在运行前由独立迁移工具转换，Workbench 运行时不声明或调用迁移钩子。资源是否存在、当前用户能否读取和正文是否更新，均由面板重新访问领域服务确认。

这种分层使布局变化只影响 Workbench，状态编码变化只影响对应 Panel Package，聊天或预览行为变化只影响其 runtime。Workbench 通过宿主节点上的 `--portal-workbench-*` 变量公开边框、圆角、背景、阴影、面板内距、单标签可见性与分隔柄外观；页面可以配置这些稳定变量，但不得用页面样式选择 `.portalWorkbench*` 内部结构。共享组件因而唯一拥有内部 DOM 与默认呈现，页面只表达自己的组合需求。Panel Package 的逐字段合同、生命周期方法、命令合同和持久化钩子见 `decision_538e155e1102`；Agent Console 怎样组合这些面板见 `decision_ce44377c3257`。

## Lineage 与 HATG 前端控制器

Society 页面取消离开时保持现有工作台；从浏览器的后退/前进缓存返回时，继续使用同一组 Panel 实例、布局与未发送草稿，不依赖刷新重新装配。

页面宿主负责判断整个页面是否结束，Panel 与 Workbench 只在各自实例被明确销毁时释放。`beforeunload` 仍可能被取消，因此不触发工作台销毁；`pagehide` 的 `persisted` 为真表示页面进入浏览器缓存，只保存状态并保留实例；为假才释放工作台、页面监听器与刷新协调器。缓存恢复沿用原实例，避免可见页面保留外壳却失去内容与命令。

Society Workbench 的初始状态由 `lineage_workbench_state.js` 创建；`lineage_workbench_controller.js` 创建唯一的页面持久化控制器并封装 `PortalPageState`。`lineage_workbench.js` 负责业务加载、渲染和 Panel 编排，不再声明大型状态字面量或直接操作底层页面存储。

HATG Panel 的初始状态由 `hatg_panel_state.js` 创建；监听分组和 page-state 读写由与 Society Workbench 共用的 `lineage_workbench_controller.js` 提供：Workbench 创建控制器时使用自己命名空间的页面状态，HATG Panel 创建控制器时传入 Workbench 提供的持久化控制器，经组件适配器读取和保存草稿；它不拥有 Society 页面存储。控制器模块由承载 HATG 的页面（`lineage.html`）直接加载，HATG 的其余模块由 `portal_hatg_loader.js` 在 HATG Panel 首次显示时按顺序载入（decision_ce44377c3257“HATG Panel 的加载”）；状态与控制器模块都先于对应主文件就绪，缺失依赖时立即失败。运行时不保留旧状态定义、旧变量名或双写兼容路径。


### 安装隔离与失效绑定

安装命名空间由站点配置领域投影，身份规则见 `decision_15aab18c0ab3`；逻辑键继续区分用户、页面与版本。同安装升级、构建和站点改名不更换命名空间。无安装归属的历史裸键不自动读取或迁移，原字节与未发送草稿保留；不清空浏览器存储。同安装的有归属草稿与布局正常恢复。

原生面板重新读取绑定对象并确认当前请求返回 404 时，发布 `binding-unavailable`。Workbench 保留当前错误面板，但从下次保存的 `openEditors` 与 `panelStates` 中排除该实例；Society 同时取消对应 Resident 的页面上次选择回退。其他实例和独立草稿不变。403、限流、网络失败、5xx 或无关辅助请求失败不判定对象已删除。只有当前目标修订可更新状态，后续成功读取绑定发布 `binding-ready` 后可再次保存。

页面可传入 `initialPanelStates`，按实例 ID 提供本次明确导航的局部状态，仅在初次恢复时消费一次。构造函数会自动加载的实例还必须在 `restorePanel` 中先应用明确 URL 绑定，避免先发旧对象请求再覆盖快照。此配置不修改存储结构版本或面板包的精确封套匹配规则。
