# Portal Resource Chip 的统一引用呈现与资源打开

Portal 的聊天、知识正文、文章和预览中经常出现 `decision_4348ed990621`、`resident_1a2b3c4d5e6f` 这样的统一资源地址。Resource Chip（资源引用标记）把正文中独立出现的地址显示成一个可以识别、聚焦和点击的小标记；鼠标停留时，旁边弹出一张卡片说明它指向什么；点击时，在当前页面预览这项资源，或前往它的页面。读者因此可以从正文直接查看资源，不需要知道每种资源页面的地址。

本篇说明哪些文字会变成资源引用标记、标记和悬停卡片的样子、点击后怎样打开，以及页面怎样接入。地址解析和当前用户的权限由 ResourceService 负责；内容读取之后的显示和编辑由预览链路负责（decision_61e50306cc79）；各页面只决定哪些正文启用资源引用标记、预览显示在哪里。

## 基本概念

| 名称 | 含义 |
| --- | --- |
| 统一资源地址 | TFI Portal 中资源的稳定标识。根地址由已登记的资源类型和 12 位小写十六进制码组成，例如 `decision_4348ed990621`；嵌套地址在根地址后加上受限的内部路径，例如 `workspace_1a2b3c4d5e6f/file/report.md`。 |
| 导航引用 | 由某个领域管理、能定位到 Portal 页面，但不属于统一资源的记录 ID。当前只有测试框架的运行记录：`testrun_` 加 16 位小写十六进制码，指向 `/wall?run=<ID>`。 |
| 资源引用标记（Chip） | 统一资源地址或导航引用在正文中的紧凑样式，保留原来的文字，同时带有指向规范页面的链接。 |
| 资源名称标签 | 只需要识别资源、不需要点击的场合（例如消息作者）使用的非链接文字，显示资源名称。 |
| 悬停卡片 | 鼠标停留或键盘聚焦时出现的浮层，显示标题、资源类型、所属项目、状态和根 ID。 |
| 资源路由约定 | 服务端发布给页面的一份约定（`window.PortalResourceRoutes`，当前写出格式 `tfi.resource-portal-routes.v1`，读取仅接受该精确格式），列出每种资源类型的规范页面、哪些类型点击后直接前往页面，以及导航引用的格式和目标。 |

## 设计点

### 哪些文字会变成资源引用标记

- **只有规范的统一资源地址和登记过的导航引用会被转换。** 其他文字保持原样，不按相似的名称去猜测资源或运行记录。
- **正文中独立出现的地址才转换。** 已经是链接的文字、代码块、文件定位（例如 `path:12`）和明显的命令行不转换。行内代码只有在整段内容恰好是一个资源地址时才转换，并沿用原来的代码元素；包含其他程序文字的行内代码保持原样。
- **根地址与嵌套地址含义不同。** 根地址指一项正式资源；嵌套地址中的路径继续参与解析和内容读取。
- **`/r/<地址>` 和知识条目的页面地址都还原为同一个资源地址。** 预览只从明确的字段或规范的 Portal 地址中取得资源地址，相对文件路径、普通网址和名称不会被当成资源。
- **导航引用保留它自己的身份。** 它不登记到 ResourceService，也不使用统一资源的解析、权限和内容接口；它的格式、页面路径、参数和显示名称由资源路由约定发布。
- **资源名称标签不会被改成可点击的标记。** 标签初始显示根 ID，通过当前登录会话读取资源引用、取得标题后显示名称；读取不到时保留 ID。标签的 `title` 保留根 ID，`aria-label` 同时包含名称和 ID，同名的资源仍能用 ID 区分。

这些规则保证正文增强不会改变代码示例、文件路径和命令的含义。

### 行内对齐

资源引用标记与周围文字垂直居中对齐。同一行包含较高的图片缩略图时，标记仍紧随文字，不下沉到整行底部；`@` 与其后的 Resident 标记也遵循这条规则。Chat Workspace、Chatroom 和知识正文共用这一样式，保留行内复制、超长地址省略及链接交互。

### 悬停卡片

- **鼠标停留 180 毫秒后显示卡片，键盘聚焦时立即显示。** 鼠标离开、失去焦点或开始点击时关闭卡片。整个页面共用一张卡片。
- **卡片内容来自当前用户的资源引用。** 统一资源通过当前登录会话读取完整地址的资源引用，服务端检查地址和权限。导航引用不读取资源引用，卡片直接显示约定中的名称和 ID；目标页面打开后再按自己的规则检查权限和是否存在。
- **卡片显示加载中、可用和不可用三种状态。** 可用时显示标题、类型、项目、状态和根 ID；不可用时仍显示原地址和类型，并说明点击不会跳转。标记的 `aria-label` 随结果更新，卡片通过 `aria-describedby` 关联到当前标记。
- **成功的读取缓存 60 秒，最多 200 项。** 同一地址同时发起的读取合并为一次；失败的读取立即从缓存中移除，权限恢复、服务恢复或资源重新出现后可以再试。用户移到另一个标记后，旧的读取结果不会覆盖新的卡片。

### 点击后怎样打开

```text
用户点击资源引用标记
      ↓
是导航引用？
  ├─ 是 → 直接前往约定的页面，不访问 ResourceService，也不打开预览
  └─ 否 → 重新读取资源引用（不使用悬停缓存）
            ↓
      当前用户仍能访问？
        ├─ 否 → 留在原页面，在局部显示提示
        └─ 是 → 这种类型在约定中是“直接前往页面”的类型？
                  ├─ 是 → 前往规范页面
                  └─ 否 → 当前页面有预览宿主接管？
                            ├─ 否 → 前往规范页面
                            └─ 是 → 生成预览文档并在宿主中显示
```

- **点击时重新检查资源。** 普通左键点击先重新读取资源引用，成功后才继续，避免根据过时的悬停结果打开已删除或已迁移的资源。处理期间标记带有 `aria-busy`，同一个标记不会被重复处理。
- **修饰键保留浏览器习惯。** Ctrl 或 Command 加左键在新标签页中打开规范页面（带 `noopener`）；Shift、Alt 和非左键使用浏览器原生行为。
- **导航资源直接前往资源引用返回的页面。** 服务端路由契约的 `navigation_resource_types` 包括 Resident、Family、Lineage、Test、Workbench 与 Workspace；这些根资源即使能提供 JSON 内容，普通点击也进入领域页面，嵌套文件地址仍按文件内容预览。导航地址由资源引用提供，`PortalNav.agentEntryDefaults` 只为入口补齐标签默认值并保留原地址。
- **显式页面链接保留视图意图。** 对资源链接完成当前权限与身份核验后，规范 URL 决定资源身份及其最新归属。原链接和规范 URL 为同源、同页面且指向同一资源时，合并原链接的非身份查询参数和页内锚点，例如打开 Chat、定位消息或选择画布对象；身份参数仍使用服务端的规范值，不能把迁移前的 Lineage 覆盖回来。指向其他资源或其他页面时不沿用旧视图参数。已有链接与自动生成的引用标记共用此规则，不按聊天来源或特定 Family 分支处理。
- **Test Run 直接前往 Run Console。** 正文中的 `testrun_<ID>` 和规范的 `/wall?run=<ID>` 链接使用同样的标记外观，点击后直接前往 `/wall?run=<ID>`，不访问 ResourceService，也不打开预览。参数重复、与页面其他身份参数冲突或格式不符的地址不会被识别为导航引用。
- **其他资源在当前页面预览。** 不是新标签页打开时，资源引用标记通过共享的 `PortalPreview.request` 询问页面中登记的预览宿主（decision_61e50306cc79），页面不需要先加载 Chat 或复制 Chat 的回调；页面也可以用 `onResourcePreview` 指定特定的预览面板。宿主返回 `false` 或出错时，前往规范页面。
- **预览文档来自资源引用。** Chip 把已核验的地址及引用事实交给资源来源，沿用 decision_61e50306cc79「读取、保存与冲突／统一资源」的文档能力、文本上限、媒体按需读取和下载规则；不另设一份读取或编辑权限合同。
- **不同的失败显示不同的提示。** 可以重试的服务错误，与资源不存在、无权访问、地址无效分别提示；资源引用标记不会编造标题、替代地址或媒体类型。

## 接口

| 函数 | 作用 |
| --- | --- |
| `isRootId(value)` | 判断是否为根资源地址。 |
| `resourceTypeFromAddress(address)` | 从地址的根部分读出资源类型。 |
| `resourceChipHtml(address, extraClass)` | 生成资源引用标记的 HTML，转义身份、class 和提示文字。统一资源生成指向 `/r/<编码后的地址>` 的链接并写入 `data-resource-address`；导航引用生成领域页面的链接并写入 `data-navigation-reference`。 |
| `resourceChipElement(address, extraClass)` | 用同样的规则创建页面元素。 |
| `resourceLabelHtml(address)` | 为根地址生成带 `data-resource-label` 和 `data-resource-chip-skip` 的名称标签；其他输入只转义为普通文字。名称由 `bind` 在内部读取。 |
| `linkifyHtml(html)` | 在脱离页面的模板中转换一段 HTML，只返回结果，不绑定事件。 |
| `bindResourceLinks(root, options)` | 接管已有的规范资源链接或导航引用链接，使它们不改变外观也能使用同样的打开流程。 |
| `enhance(root, options)` | 依次转换正文、规范化已有的标记和资源链接，并绑定交互。 |

- **重复绑定不会重复执行。** 程序生成和 Markdown 后处理得到相同的 class、地址字段和默认链接；绑定以元素上的标记保证只绑定一次，重复渲染或多层调用时一次点击只执行一次。再次绑定可以更新这个元素的预览回调，监听器仍只有一个。
- **后插入的标记自动接管，普通文字需要显式增强。** 全局的 DOM 变化监听只接管之后插入的、已经渲染成标记的元素；新出现的普通文字需要页面调用 `enhance`，组件不会任意改写整个页面。
- **文件链接组件把资源链接交给资源引用标记。** 文件链接组件（`portal_file_links.js`）分类链接时查询同一份资源路由约定；统一资源和导航引用的地址由资源引用标记处理，不再作为普通网页链接卡片显示。

## 页面怎样接入

Chat、Knowledge、Article 和通用预览在渲染正文后调用 `enhance(root, options)`；已经生成规范资源链接的模板只调用 `bindResourceLinks` 即可。需要连接特定面板时传入 `onResourcePreview`，页面不重写识别、读取或点击处理。

| 部分 | 负责 |
| --- | --- |
| 页面 | 选择哪些正文启用资源引用标记，提供预览宿主。 |
| ResourceService | 资源是否真实存在、当前用户能否访问。 |
| 资源引用标记 | 外观、悬停卡片、点击处理和前往哪里。 |
| 预览链路 | 渲染器和文档编辑。 |

消息中保存的旧标题或地址只用于显示，点击时仍按当前用户重新检查。新增资源类型时，优先扩展服务端的资源路由约定（`resources/portal.py`）和内容能力；新增一种非资源的稳定页面身份时，只有当某个领域确实管理它的生命周期、并且有规范的页面入口，才在同一份约定中登记为导航引用。页面不复制地址格式、悬停读取、不可用提示或领域导航；某种资源独有的业务操作留在对应的工作台中。
