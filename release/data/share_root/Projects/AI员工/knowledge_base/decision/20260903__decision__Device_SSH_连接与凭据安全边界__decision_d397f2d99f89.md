# Device SSH 连接与凭据安全边界

Portal 用 Device resource 表示一台可管理设备或设备中的硬件单元。用户和自动化程序可以查看设备连接信息、保存 SSH 密码、测试连通性，并在有权限时打开本地终端。本文解释设备身份、父子设备如何共享连接入口，以及连接元数据与秘密凭据怎样分开保存。

## 基本概念

**Device resource（设备资源）**是一份具有稳定 ID 的设备记录。它可以表示服务器，也可以表示服务器中的 GPU。稳定 ID 形如 `device_...`，名称和文件路径变化时，ID 仍用于引用同一设备。

**SSH** 是通过网络登录远程设备并运行命令的协议。一次 SSH 连接通常需要目标主机地址、端口、用户名，以及私钥或密码等凭据。

**连接元数据**是可以安全展示的连接说明，例如主机地址、端口和用户名。**秘密凭据**是可以直接用于登录的密码或私钥内容。Portal 把两者分开：设备记录可以保存元数据和服务端文件路径引用，密码保存在独立的受限秘密文件中。

**宿主设备**是提供实际 SSH 入口的设备。GPU 等子设备可以通过父子关系指向宿主服务器。用户请求连接子设备时，Portal 沿父链找到真正提供主机地址的设备，再使用该设备的凭据。

**权限系统**决定谁能执行 Device 操作（decision_b820faf42218）。设备在 R 树上挂在“共享”下，全员对它有 viewer；默认模板中 RunResourceAction 要求对目标设备有 contributor，设备的创建者和管理员满足，其他主体需要实例中增加的表项或临时凭证。连接参数和秘密文件仍由设备组件校验。

## 用户和调用方看到的能力

| 能力 | 可见结果 |
| --- | --- |
| 查看设备 | 名称、类型、父子关系和非敏感 SSH 可用性摘要 |
| 保存凭据 | 为实际连接设备保存或覆盖密码；响应不回显密码 |
| 删除凭据 | 移除实际连接设备的密码；响应说明当前是否仍有凭据 |
| 测试连接 | 返回是否可达、延迟、测试时间和非敏感失败说明 |
| 打开终端 | 浏览器显示远程 shell 输出，并允许发送输入和窗口控制 |

当用户操作 GPU 子设备时，结果同时保留“用户请求的设备”和“真正建立 SSH 连接的设备”。这样，页面可以继续显示用户选择的 GPU，同时明确连接由宿主服务器提供。

## 设计点

### 设备身份

- **每台设备使用规范且稳定的 Device ID。** 文件名中的 ID 必须与记录声明的 ID 一致，名称和路径不能替代资源身份。
- **服务器和 GPU 使用显式父子关系。** GPU 子设备记录宿主 Device ID 及自身硬件身份，注册时验证父设备和拓扑。
- **一条损坏记录不会阻断整个设备目录。** 扫描器单独报告无效文件，其余合法设备仍可被发现和读取。

### 连接信息与秘密

- **设备只有声明主机地址后才能成为 SSH 入口。** 端口、用户名和服务端配置路径可以与主机地址一起保存。
- **密码不会写进 Device resource。** Resource 清单、接口响应和普通日志都不能回显密码。
- **私钥内容不会写进 Device resource。** 设备记录只允许引用服务端已有的私钥文件和 SSH 配置文件。
- **权限过宽的密码文件不能用于连接。** Portal 在读取前检查文件权限，避免其他系统用户读取秘密。

### 父子设备连接

- **连接解析从用户请求的设备开始。** 当前设备有主机地址时直接使用；否则沿父链寻找最近的可连接设备。
- **密码始终绑定真正提供 SSH 入口的设备。** 多个 GPU 可以共享宿主服务器密码，无需为每个 GPU 复制秘密。
- **无效父链会使连接失败。** 父设备不存在、关系形成循环或整条链都没有主机地址时，Portal 不会猜测其他设备。

### 凭据管理

- **保存和删除密码经 RunResourceAction 执行。** 服务端验证调用身份，由权限系统按 RunResourceAction 的要求判定，设备组件不另设权限检查。
- **重复保存同一密码后，仍保留这一份密码。** 响应只确认保存成功，并标明请求设备和实际连接设备。
- **重复删除后，设备仍处于无密码状态。** 凭据不存在时返回明确状态，不泄露过去保存过的内容。

### 连接测试

- **调用方可以选择 1 至 15 秒的测试超时。** 超时值超出范围时，服务端拒绝请求。
- **测试只返回非敏感连通性信息。** 连接成功、拒绝、认证失败和超时都会转成页面可用的状态，不返回密码或私钥内容。
- **首次遇到的主机密钥可以被记录。** 已记录主机的密钥后来发生变化时，SSH 校验失败，避免静默连接到身份不同的设备。

### 本地终端

- **本地终端只为具有入口权限的人类登录会话创建。** 受限普通用户不能绕过后端门禁直接建立终端。
- **终端会话绑定创建它的人类用户。** 其他用户仅知道终端 ID 也不能接管。
- **关闭终端不会删除保存的设备密码。** 终端进程状态和长期凭据状态分别管理。

### 设备注销与状态

- **注销只删除目标设备及其自有密码。** 其他 Device 记录和秘密保持不变。
- **仍被子设备引用的宿主不能注销。** 调用方需要先处理父子关系，避免留下无法解析的设备。
- **GPU 运行状态使用规范 Device ID 关联。** 状态数据中的 ID 必须与缓存键一致，子设备通过明确父关系归入宿主服务器。

## 设备记录结构

Device backend 是保存和校验设备身份记录的服务端组件。新写入使用 `tfi.device.v1`；读取仅接受精确的当前格式，不接受其它名称或版本，并拒绝格式中没有定义的字段。读取不自动改写原记录。

设备记录可以包含：

| 信息组 | 内容 |
| --- | --- |
| 身份 | Device ID、设备种类、名称和说明 |
| 生命周期 | 当前生命周期、创建时间和更新时间 |
| 位置与网络 | 主机名、物理位置和非敏感网络说明 |
| 访问方式 | SSH 主机、端口、用户和服务端路径引用 |
| 监控 | 与该设备关联的监控说明 |
| GPU 子设备 | 父 Device ID、GPU identity 和型号 |

GPU identity 是宿主服务器内部用于区分 GPU 的稳定硬件标识。注册子设备时，服务端检查父 ID 存在、关系不会形成循环，并确保名称或文件路径没有被误当成资源关系。

## 连接解析怎样工作

```text
调用方请求某个 Device
  → ResourceService 验证调用身份与动作参数
  → Device backend 读取设备记录
  → 当前设备有 SSH 主机地址？
       ├─ 有：它就是实际连接设备
       └─ 没有：沿父链寻找最近的 SSH 入口
  → 读取实际连接设备的非敏感元数据
  → 按需读取该设备的受限密码文件
  → 执行测试或创建终端
  → 只投影非敏感结果
```

协议结果使用 `resource_id` 表示调用方最初请求的 Device ID，使用 `via_resource_id` 表示实际提供 SSH 入口的 Device ID。字段名在这里出现，是为了精确说明接口；页面面向用户时应把它们表达为“所选设备”和“通过宿主连接”。

## 密码的保存与使用

密码根目录权限为 0700，表示只有目录所有者可以进入。每个密码文件权限为 0600，表示只有文件所有者可以读写。服务端拒绝以下输入：

- 空密码；
- 超过 1024 字节的密码；
- 含回车、换行或空字节的密码。

写入通过同目录临时文件和原子替换完成。秘密文件权限异常时，终端连接报错；ssh.test 将其视为没有可用密码并以 BatchMode 尝试连接。

SSH 子进程需要密码时，Portal 把秘密文件路径交给受控的 `SSH_ASKPASS` 辅助程序。这个辅助程序仅在认证时读取密码，从而避免把明文放进进程命令行、Resource 清单或浏览器状态。

## Resource action 协议

Resource action 是资源类型为自己声明的专用操作，调用方通过 HATG 指令 `RunResourceAction`（decision_ad3e21094f14）执行。ResourceService 验证有效调用者和参数；所需等级由当前权限模板中 RunResourceAction 的要求决定，Device provider 执行相应动作。

### `ssh.credential.save`

请求包含目标 Device 和新密码。服务端先解析实际连接设备，再覆盖该设备的密码文件。成功响应只返回请求 Device ID、实际连接 Device ID 和 `credential_saved: true`。

### `ssh.credential.delete`

服务端解析实际连接设备并删除其密码文件。文件不存在时返回明确缺失状态；响应不包含历史密码。

### `ssh.test`

请求可以提交 `timeout_seconds`，其合法范围为 1 至 15 秒。服务端使用解析后的主机、用户、端口、SSH 配置路径和私钥路径，并在需要时读取保存密码。

SSH 进程以非交互模式运行，主机密钥策略为 `accept-new`：首次出现的主机密钥可写入 known hosts，已知主机密钥变化则失败。结果包含 `reachable`、延迟、非敏感消息、测试时间、请求 Device ID 和实际连接 Device ID。

## 注册、注销和地址解析

Device provider 在注册前检查记录格式、资源 ID 和父子拓扑。注册可以同时保存 SSH 元数据、把可选密码写入独立秘密文件，并按请求立即执行连接测试。返回结果不会包含密码。

注销前检查是否仍有子设备引用目标。通过后只删除目标设备记录及其自有秘密，并由 Resource provider 接入统一 mutation 授权链。mutation 表示会改变资源状态的操作。

Device resolver 支持根 Device 地址和已经定义的 GPU 嵌套地址。解析结果提供 Portal 资源链接与非敏感 SSH 可用性摘要，不返回密码。

## 本地终端

浏览器只发送终端输入、窗口控制和结束指令，并接收输出与状态。服务端负责读取 SSH 凭据、启动进程和维护生命周期。浏览器断开或 SSH 进程退出时，终端状态随之更新；长期保存的 Device secret 不会被自动删除。
