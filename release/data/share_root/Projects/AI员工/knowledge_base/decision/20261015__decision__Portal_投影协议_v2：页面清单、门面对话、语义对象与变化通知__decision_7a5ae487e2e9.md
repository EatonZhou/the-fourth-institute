# Portal 投影协议 v2：页面清单、门面对话、语义对象与变化通知

投影界面（Portal 中称为工作台，Workbench）把一个或多个 Lineage 的协作能力、领域资源和正式产物组织成面向某种工作的页面。Lineage 是语义核心：谁负责什么、哪个流程做什么、产物是什么，都由 Lineage、领域服务和资源登记决定；投影界面选择其中一部分，组织成视图与操作。用户在界面上使用一个真实功能，就是在调用对应的 Lineage 流程、领域接口或资源；用户在界面上与 AI 交谈，就是在与 Lineage 中某个 Resident 交谈。

投影协议把这种对应关系封装成标准接口。任何满足协议的界面都能与 Portal 连接，包括 Portal 内生成的页面，以及以后由外部开发的 Workbench。本篇规定 v2 协议的分层、页面清单、对话区、语义对象、动作和变化通知，以及投影界面模板的统一基座与可自由配置的部分。

v1 的规则保持有效并作为 v2 的基础，见 decision_f67ae5e70793 与 `management_portal/workbench_projections/sdk.md`：页面绑定普通 Lineage，调用者始终是当前登录用户，改变状态的指令由宿主确认，AI 结果按输入消息 ID 和输入状态追踪，产物按领域对象查询。v1 的单页面工作台视为“只有一个功能区、没有对话区”的 v2 页面，继续运行。

实现状态：片段形式的宿主能力首版已发布，第一个 v2 工作台是 Portal 开发投影（decision_13e1a748cf04）；投影应用包的构建、发布与宿主加载已实现；这一实现状态不代表所有真实使用闭环均已验收。WALL 的领域身份与动作继续由 decision_06defc47e960 维护；它与 Test 的页面组合入口见 decision_13e1a748cf04。

## 协议分层

| 层 | 回答的问题 | 内容 |
| --- | --- | --- |
| 传输与身份 | 界面怎样与 Portal 通信、以谁的身份 | Portal 内：宿主注入 SDK，sandbox iframe 与宿主之间用独立通道传消息；外部：预留 |
| 绑定 | 界面连到哪些 Lineage、角色与流程入口 | v1 绑定，新增保留角色 `facade` |
| 页面清单 | 界面由哪些功能区组成、怎样联动 | 侧栏功能区、对话区、情境通道 |
| 语义对象 | 界面上显示的东西对应什么事实、处于什么状态 | `{ref, kind, status, source, observed_at}` |
| 动作 | 用户操作落到哪里执行 | 本地交互、领域确定性操作、AI 流程、对话，以及对象上的反馈 |
| 变化 | 事实改变后界面怎样知道 | 宿主代为观察，按 ref 通知面板 |

前两层沿用 v1；后四层是 v2 新增的部分。语义层（绑定到变化）与传输层分开定义，使同一组语义可以由不同传输承载。

## 传输与身份

Portal 内的投影面板运行在 sandbox iframe 中，宿主在页面脚本之前注入 `window.Projection`。iframe 的隔离、内容安全策略、90 秒活动预算、人工确认的暂停与恢复、`projection.*` 错误码全部沿用 v1。

外部 Workbench 在协议中预留位置：以后通过 HTTP 和用户访问令牌承载与本篇第 2 至 6 节相同的语义，调用者仍是令牌所属的用户，不能自报 actor。外部界面无法使用 Portal 宿主确认框，变更确认的方式在实现外部接入时另行设计；当前版本不开放外部传输。

## 绑定与对话角色 `facade`

绑定沿用 v1 的 `别名 → { lineage_id, residents: { 角色名: resident_id }, events: { 流程别名: Event Source ID } }`。

v2 增加保留角色名 `facade`，表示投影界面对话区所连的 Resident。它可以是任意一个绑定的 Resident；推荐使用 Family 门面（decision_44cf587c1721）。使用门面时，用户在对话区说的话就是发给这个 Family 的请求，路由、成员分工和新增成员由 Family 自己处理，界面不需要知道 Family 内部有哪些成员。`facade` 遵守 v1 的绑定校验：被删除或移出 Lineage 时对话区显示 `projection.resident_unbound`，不自动替换成其他 Resident。

## 页面清单

v2 工作台的每个修订版本由一份页面清单和若干面板源码组成。新建清单使用 `tfi.projection.v2`，读取仅接受该精确格式，既有版本和原始摘要绑定保持。清单与源码一起保存、一起发布，发布规则与 v1 相同：草稿不影响在线页面，发布只选定一个已保存的修订版本。

```yaml
schema: tfi.projection.v2
chat:                         # 可选，强烈建议提供
  binding: main
  role: facade
sidebar:                      # 侧栏功能区，按顺序显示
  - id: architecture
    title: 架构与协议
    icon: <图标名>
    pattern: architecture     # 可选，典型投影范式标签
    source: panels/architecture.html
  - id: progress
    title: 阶段进展
    pattern: progress
    source: panels/progress.html
context:                      # 面板间共享的情境通道
  - channel: focus
    publishers: [architecture]
    subscribers: [progress]
```

- `sidebar` 中每一项是一个功能区。`id` 在清单内唯一，也是深链接和用户布局保存使用的稳定键。
- `pattern` 标明这个功能区属于哪类投影范式，供生成、评审和后续统计使用；宿主不根据它改变行为。初始取值参考 article_c30f093138b5 的六类指南：`architecture`（层次化架构与协议探索）、`experience`（围绕真实任务的功能体验）、`mechanism`（运行机制与可调情境）、`comparison`（共同场景下的方案比较）、`progress`（阶段进展与注意力分配）、`evolution`（未来演化与依赖路径）。具体领域可以登记自己的取值。
- `source` 指向功能区的实现，有两种形式：`package: <入口名>` 指向投影应用包构建出的入口（见“投影应用包”），是正式工作台的标准形式；`panels/<名>.html` 指向简易片段，遵守 v1 的片段约束（不包含 `html`、`head`、`body`、`nav`，不另造品牌、全局侧栏或页面模板，不覆盖 `:root` 和基础主题变量，按钮、表单、工具栏和分区使用 Portal 公共控件类名），只适合简单页面和快速草稿。
- `context` 声明情境通道：哪些功能区发布、哪些功能区订阅。`subscribers` 只决定哪些功能区在通道变化时收到 `onFocus` 通知；清单中的任何功能区都可以读取通道当前值，只有 `publishers` 可以发布。

## 投影界面模板

投影界面使用与 Society 页面相同的 Workbench 基座（decision_4348ed990621、decision_538e155e1102）。宿主负责外壳和公共能力，面板负责业务内容。

### 页面模板必须在代码层复用

Portal 内的投影页面、内置组合页面和 Studio 预览必须使用与 Lineage 相同的公共页面布局组件。复用包括 Activity Rail 及其内容占位、盒模型、间距和窄屏布局，不能只调用同一个侧栏按钮工厂，再在页面样式中分别重写侧栏宽度、定位或内容偏移；外观相似不代表复用了模板。

页面布局组件是侧栏几何与相邻内容区域的唯一拥有者。侧栏边框、内边距必须计入已分配空间，活动轨不得覆盖内容、标签或操作入口；缩放、窗口调整和窄屏横向活动轨切换由这套公共规则共同处理。外层已经提供活动轨时，内层投影省略自己的活动轨和相应占位，由同一布局合同安排内容，不增加第二套侧栏或局部补偿边距。无活动轨的嵌入式 Panel 直接使用宿主提供的内容槽位。

页面只提供视图入口、内容槽位和业务状态；功能区 iframe 继续自行组织业务内容，不控制宿主模板的宽度和定位。需要新的页面形态时，应扩展与该职责相符的公共模板并由所有对应入口复用。验收应对照 Lineage 检查实际 DOM/CSS 复用、相同视口下侧栏尺寸与内容边界，并检查窄屏、预览和嵌套无轨模式，不能以单张截图或增加 padding 代替模板接入。

| 区域 | 归属 | 内容 |
| --- | --- | --- |
| 顶栏、主题、基础控件、确认框、错误与空状态 | 宿主 | 与 Portal 其他页面一致 |
| 左侧活动轨 | 宿主，复用 Society 页面的 Activity Rail | 按清单 `sidebar` 生成；可拖动排序，显示未读与运行状态 |
| 功能区 | 投影面板 | 每个功能区是一个 Panel Package 实例，内部是一个 sandbox iframe，承载新生成的业务组件 |
| 对话区 | 宿主原生的 Chat Workspace | `facade` Resident 的同一个对话，与在 Society 页面打开的是同一条会话 |
| 布局保存 | 宿主 | 沿用 Workbench 三层保存，按用户分别保存分栏、活动项与折叠状态 |

功能区的切换方式与 Society 页面侧栏相同：切换时面板实例进入隐藏状态，保留内部状态、筛选和草稿，可以暂停只服务于可见界面的轮询；再次显示时补读一次数据，不重新装配。包含 iframe 的面板不能普通搬移，调整布局时依赖浏览器的状态保持型原子移动；浏览器缺少该能力时，投影面板不参与拖动换位，布局保持原状。

对话区直接复用 Portal 的 Chat Workspace，不在 iframe 中重建聊天组件，也不用 `inputResult` 轮询拼出对话。

**输入焦点连续性。** 功能区异步加载、尺寸变化、隐藏恢复和保存状态恢复不得抢占用户正在使用的 Chat 或其他输入控件。保存的图节点焦点属于阅读状态，恢复它不自动转移键盘焦点；图重绘只有在替换前文档确实拥有焦点且活动元素属于图节点时，才恢复对应节点的 DOM 焦点。用户主动点击、键盘导航及关闭详情返回继续按当前操作管理焦点。语义对象 `Projection.focus()` 与浏览器输入焦点分别管理。

**对话加载与工作台读取并行。** 打开已发布投影页面时，宿主同时读取工作台定义和按当前用户校验门面绑定；取得已授权的真实 Resident 后立即加载原生投影和会话，不等待工作台详情、功能区代码或资产就绪。原生数据仓库拥有请求合并和快照，Chat 装配接管已有订阅，不另设投影专用缓存。装配前目标必须与本次工作台定义中的绑定一致；并发发布导致目标不同则明确报告绑定变化，不能显示另一会话。无门面对话的工作台继续装配，门面不可用不阻断其他功能区；页面读取失败或退出时释放提前加载的订阅，晚到结果不得恢复已退出的页面。其他功能区使用为投影专门生成的组件，不嵌入 Portal 的预览、文件或 HATG 面板；这样生成、修订和反向整理都只涉及投影自己的源码。

可以自由配置的部分是：功能区的数量、内容和 `pattern`，情境通道的连接，对话区的位置与默认折叠状态，以及面板内部的布局、图示、演示和本地交互。宿主固定的部分是：外壳、活动轨、对话组件、确认与身份、语义对象的显示规则。

## 体验入口的宿主页面导航

功能区可以把真实成果关联到可直接打开的 Portal 页面。Projection.openPage(url) 只申请导航：页面身份与地址由 Portal Shell 的登记目录解释，目标页面继续按当前用户鉴权，导航成功不等于目标内容可读或业务操作成功。应用不自行操作父文档、打开网络通道或执行资源动作。

地址必须是根相对或当前 Portal 同源 HTTP(S) 地址，最多 4096 个 UTF-16 码元。协议相对、其他源、用户凭据、空白与控制字符、反斜杠、路径编码与越级段均拒绝；只接受显式登记的精确 GET 文档路径，不把 API、下载、登出或宽泛路径前缀当作页面。输入与登记失败返回 projection.page_url，导航目录不可用返回 projection.page_unavailable。

当前已装配 v2 工作台的 /workbenches/view?id=<当前ID>&region=<区域ID或facade> 进入现有区域或原生门面对话，不重新装配 iframe、不丢弃草稿和 focus。没有 region 时与显式 region=facade 等价，聚焦已装配的原生门面对话；没有 Chat 时明确报目标未装配错误，不空转成功；只接受唯一 id 和至多一个 region，不接受额外查询或锚点。未知或未装配目标返回 projection.page_target。布局拒绝切换返回 {opened:false, mode:"local", url}，不得宣称成功或改用整页刷新。原地成功返回 opened:true。

其他已登记页面由宿主当前标签发起普通导航，查询与锚点交给目标页面解释；返回 mode:"page" 只表示导航已发起，原文档退出后 SDK Promise 不保证继续可观察。这一取舍保留目标页面自身身份与加载流程，不把任意页面嵌入投影 sandbox。既有 openPanel、openLineage 与反馈确认/取消语义保持。

## 投影应用包

投影界面要帮助人理解一个复杂系统，往往需要可交互的图、动画演示、时间轴回放和多视图联动，实现复杂度可能接近一个完整的前端应用，例如 Portal 自己的 Lineage 图编辑区。单段 HTML 片段、只能内联脚本、不能引用库的形式无法承载这种软件，因此正式工作台的功能区由投影应用包实现。

- **源码是一个前端工程。** 应用包放在 Git 仓库中（工作台登记它的仓库资源与目录），包含依赖声明和构建脚本，可以多文件、模块化、带测试。工程使用常规前端工具链（例如 TypeScript 与 Vite），每个功能区构建出一个入口。
- **构建产物是发布的对象。** 工作台修订记录应用包的提交和构建产物的内容哈希；保存修订时由宿主在隔离环境中解析当时可用的依赖、记录完整性并构建，产物按内容哈希保存。发布只选定一个已构建成功的修订，构建失败的修订不能发布。草稿与发布分离的规则与 v1 相同。
- **宿主从同源路径加载产物。** 功能区 iframe 仍是 sandbox，CSP 只允许本次修订的构建产物和宿主登记库，允许 Web Worker 与 Canvas/WebGL；`connect-src` 仍为 `none`，不能联网，不能访问宿主页面。数据、身份、确认和变化通知全部通过 Projection SDK，规则不变。
- **宿主提供登记库。** 宿主提供经过审查的常用库，至少包括图与可视化（D3）、自动布局（ELK 或 dagre）、网络图（Cytoscape），以及 Portal Lineage 图编辑区的画布与连线底层能力。应用包也可以把自己的 npm 依赖打包进产物，依赖须通过许可、完整性与体积检查，实际安装版本记录在构建回执中。
- **体积按应用计算。** 单个功能区产物的默认上限为 8 MB（压缩前），工作台可以登记更高上限；上限约束加载时间，不约束功能复杂度。
- **内容标题由应用包组织。** 应用包在功能区内部将标题与本区筛选、操作组成自己的工具栏；宿主保留 Workbench 标签和无障碍区域名称，应用包装配成功后不再额外插入一行同名内容标题。加载或装配失败仍保留宿主标题与错误提示，简易片段维持宿主标题。

- **主题与公共控件由宿主提供。** 宿主向应用包提供 Portal 主题变量、公共控件样式和图标，跟随主题切换；应用包不另造品牌和全局导航，不覆盖基础主题变量。应用内部的画布、图元、面板和交互方式自由设计。

v1 的单片段工作台和 v2 的片段功能区继续可用，作为简易形式。

## 语义对象

面板中可被指认、讨论或操作的内容使用统一的对象描述：

```text
{ ref, kind, status, source, observed_at }
```

| 字段 | 含义 |
| --- | --- |
| `ref` | 对象地址：Resource ID 或其嵌套地址（如 `decision_*`、`plan_*`、`article_*`），仓库文件路径加可选行号，或 Lineage 中的 Resident、Event Source 等节点 ID |
| `kind` | 对象在该面板中的角色，例如模块、协议、设计点、改进点、任务、证据；由领域或面板约定 |
| `status` | `current`（当前实现）、`proposed`（拟议方案）、`simulated`（模拟演示）、`verified`（已验证结果） |
| `source` | 判断依据的入口，例如测试运行、代码位置、设计条目；没有依据时为空 |
| `observed_at` | 读取或观察这项事实的时间 |

- 同一个 `ref` 可以在多个功能区出现，表达形式可以不同，但身份与 `status` 必须一致，不能在两个视图中对同一事实给出相互矛盾的状态。
- 宿主在确认框、反馈卡片和对话区的上下文引用中统一显示 `status`，让用户分辨“这是拟议方案”和“这是已经实现的行为”。模拟演示上的操作只作用于演示，不能触发真实指令。
- `source` 为空时界面显示“未知”或“缺少依据”，不能显示为零、完成或通过。
- 面板只能引用当前用户有权读取的对象；无权读取的对象不出现在摘要、数量或连线中。
- 面板用 `Projection.resource("resolve", ref)` 核对一个对象引用或证据地址：以当前用户身份解析，返回是否可读、资源类型、标题和页面链接，不返回正文。地址不存在或无权读取时，按缺少依据显示；需要正文时再用 `read`。

## 动作

用户在投影界面上的操作分为四类，与 v1 的对应表一致：

| 动作 | 执行位置 |
| --- | --- |
| 本地交互：筛选、选择、草稿、比较、布局 | 面板内部；需要持久的偏好写入 `Projection.state()` |
| 领域确定性操作 | 所属领域的已授权接口或资源动作 |
| 固定职责的 AI 功能 | `TriggerEvent` 触发绑定的流程入口，按输入消息 ID 追踪结果 |
| 对话 | 发给 `facade` Resident，结果显示在对话区 |

v2 新增两个 SDK 原语，把界面上的对象情境交给宿主统一处理：

- `Projection.focus(obj)` 与 `Projection.onFocus(fn)`：发布和订阅情境通道中的当前对象。宿主把它转成 Workbench Context 的通道修订号；订阅的功能区收到对象引用后各自读取详情，用修订号拒绝晚到的结果。
- `Projection.feedback({ref, anchor, scene, text})`：用户在某个对象、某一步或某个演示情境上表达意见。宿主把对象、`status`、锚点和情境作为上下文引用，连同文字发给 `facade`，回复在对话区显示。这条消息与用户在对话区直接输入的消息属于同一个对话，遵守同一套确认与追踪规则。用户在对话区也可以手动带上当前情境。

反馈确认由投影宿主拥有，沿用同一个原生确认与取消流程。主体先显示讨论对象名称、状态、真实绑定收件团队和用户将发送的完整文字；宿主标签、状态说明和按钮遵循 Portal 当前界面语言（decision_27253e25f016），名称和发送正文保留原文；五字段、收件身份及 anchor/scene 作为默认折叠的技术情境，按需展开。应用可提供仅用于展示的 subject 名称（非空字符串、最多 240 个 UTF-16 码元），不能改变对象身份、权限或收件人；缺省时宿主解析资源标题，再退到真实引用。收件名称由宿主按当前用户读取真实绑定身份；名称和正文只作纯文本显示。详情中的 JSON 格式化不改变最终发送上下文，确认发送仍经原生 Chat；取消、来源变化、隐藏与身份复核保留既有发送边界。

反馈只是交给门面的一条消息。它涉及软件行为时进入相应开发工作，涉及表达方式时更新投影；怎样分派由门面背后的 Lineage 决定，界面不在本地分类或改写。

## 变化通知

- `Projection.watch(refs)` 请求宿主观察一组对象。宿主复用资源索引和本地文件变化观察（decision_f55bac7fc199）产生通知，只告诉面板“哪些 ref 变化了、新的观察时间”，面板自己重新读取。
- 每个功能区的 watch 是一个完整订阅组，新调用替换旧组；HTTP observe 单次最多接收 128 个引用，宿主去重后顺序分批，每批继续以当前用户检查工作台和资源权限。全部批成功后才安装新组及监听器；任何一批失败均拒绝本次注册，保留已安装的旧组及其停止句柄。调用方不能以连续 watch 调用模拟分批，因为每次调用都会替换整组。
- 变化刷新也按同一规则分批，整组成功只通知一次；任一批失败只传递错误码与空 refs，不发布部分成功结果。observed_at 是最后完成批次的观察时间，不代表跨批原子快照，也不保证早先批次的权限在未来不变；后续变化、重连及显示均重新核验。
- 面板隐藏时暂停刷新，显示时重新核验完整组。隐藏、替换订阅、停止与销毁使旧刷新代次失效；已发出的 HTTP 可以完成，但不会继续后续批次或通知。销毁还会使在途注册失效，禁止回写订阅。停止成功才清空组及监听器。若 stop 的请求已被同一 SDK 的后续 watch/stop 取代，且宿主明确回报取消，旧 stop 正常结束但不清空新组。权限、网络以及没有后续请求的取消仍是失败，保留已安装组并向调用方报错，允许重试。
- 应用包共享生命周期必须保留异步清理结果：在途重复清理共用同一个 Promise，成功只执行一次，失败允许重试。hide/destroy 等不等待结果的调用路径也要记录真实清理失败；显式 await 的调用方仍接收原始错误，不能以忽略所有取消或所有 Promise 拒绝替代错误处理。
- 面板仍然不能直接订阅流式 HATG 指令；AI 工作的进度继续按输入消息 ID 读取。
