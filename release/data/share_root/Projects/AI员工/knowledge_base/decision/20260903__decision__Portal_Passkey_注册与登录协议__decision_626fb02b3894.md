# Portal Passkey 注册与登录协议

Passkey 为 Portal 的人类用户提供一种由设备确认身份的登录方式。用户可以在登录页选择 Passkey，也可以在账号安全设置中登记和删除自己的 Passkey。本文负责解释用户实际经历的操作、浏览器与 Portal 怎样共同验证身份，以及相关接口、状态和失败语义。

## 基本概念

**Passkey（通行密钥）**是一组配对的加密凭据。手机、电脑或安全密钥保存私钥，Portal 只保存对应公钥。登录时设备用私钥为本次挑战签名，Portal 用公钥验证；私钥不会交给 Portal。

**认证器**是保存私钥并执行签名的设备能力，可以来自操作系统、密码管理器或实体安全密钥。认证器通常要求用户通过指纹、面容、设备密码或触摸确认本人在场。

**WebAuthn** 是浏览器连接网站与认证器的标准协议。Portal 先向浏览器发出一次性挑战，浏览器再让认证器处理，最后把签名结果交回 Portal。本文把这段“开始并验证”的完整交互称为一次**认证过程**。

一次认证过程涉及这些概念：

| 概念 | 含义 |
| --- | --- |
| 挑战 | Portal 为当前操作随机生成的一次性数据，防止旧签名被重复使用 |
| 过程令牌 | 浏览器在验证阶段交回的随机标识，用来找到服务端保存的挑战 |
| Portal 站点身份 | 浏览器和认证器共同确认“正在为哪个网站签名”的范围 |
| 站点域名 | Portal 站点身份中的域名部分，协议字段名为 RP ID |
| 来源地址 | 当前页面使用的协议、主机名和端口组合，协议字段名为 origin |
| 凭据 ID | 一枚 Passkey 的公开稳定标识，用于找到对应公钥；它不是私钥 |
| 可发现凭据 | 认证器能在用户没有先输入用户名时找到的 Passkey |
| 用户句柄 | Portal 为账号生成的随机内部标识，供认证器关联账号，不向安全设置页面公开 |

## 用户怎样使用 Passkey

### 注册一枚 Passkey

已登录用户从账号安全设置开始注册。Portal 先要求用户重新证明自己仍掌握当前账号：用户输入当前密码；账号启用动态口令时，还要输入当前动态口令或一枚未使用的恢复码。验证通过后，浏览器打开系统的 Passkey 对话框。用户在设备上确认，Portal 验证设备返回的结果并把公钥凭据加入当前账号。

### 使用 Passkey 登录

用户在登录页选择 Passkey，无需先输入用户名。浏览器让用户从设备可用的 Passkey 中选择并完成本人确认。Portal 根据凭据 ID 找到账号，验证签名和站点身份，再检查账号目前是否允许登录。全部通过后，Portal 创建与密码登录相同的浏览器登录会话。

### 查看和删除 Passkey

账号安全设置展示当前账号的 Passkey 列表。每一项包含便于识别的名称、创建时间、最近使用时间以及设备提供的公开类型信息。用户可以删除自己的 Passkey。当前删除操作依赖已有登录会话，不会再次要求密码或动态口令。

## 设计点

### 入口与可用性

- **登录入口与密码登录并列。** 支持 WebAuthn 的浏览器显示 Passkey 登录入口；不支持的浏览器隐藏该入口，并禁用安全设置中的新增操作。
- **系统对话框由浏览器和设备控制。** Portal 页面负责发起操作、转换数据和展示结果；用户取消设备对话框时，页面显示失败反馈。
- **Passkey 登录无需先填写用户名。** Portal 使用可发现凭据，并在验证阶段从凭据 ID 恢复所属账号。

### 注册与账号归属

- **只有当前登录用户可以为自己注册 Passkey。** 注册开始前必须完成账号再认证，浏览器不能替其他用户名登记凭据。
- **每个账号最多保存十枚 Passkey。** 容量在最终写入事务中检查，达到上限时拒绝新增。
- **同一凭据 ID 在 Portal 中只能属于一个账号。** 已属于当前账号时报告重复注册；属于其他账号时报告冲突。
- **认证器私钥始终留在设备一侧。** Portal 只保存验证签名所需的公钥和公开管理信息。

### 登录结果

- **设备签名通过后仍要检查账号状态。** 账号必须处于可登录状态，并且位于当前部署允许的用户集合中。
- **Passkey 成功登录后创建统一浏览器会话。** 后续页面只识别已登录的人类用户，不需要知道本次使用了密码还是 Passkey。
- **Passkey 登录直接完成，不追加 Portal 的动态口令步骤。** 认证器已经在本次 WebAuthn 过程中完成用户验证。

### 管理与生命周期

- **安全设置只显示当前用户的公开凭据信息。** 页面不会得到公钥原始存储、用户句柄或任何认证器私钥。
- **用户只能删除自己账号中的凭据。** 凭据不存在或属于其他账号时，删除失败且不会改动其他记录。
- **账号停用会阻止既有 Passkey 登录。** 停用保留凭据，以便账号恢复；管理员永久删除账号时才删除该账号的全部 Passkey。
- **凭据或待处理挑战无法读取时，Portal 拒绝登录。** 存储损坏不会触发放行，页面也不会收到内部公钥或设备响应细节。

## 组件与状态

| 组件 | 责任 |
| --- | --- |
| 登录页与安全设置页 | 发起操作，调用浏览器 WebAuthn 能力，展示可理解的成功或失败反馈 |
| 浏览器 WebAuthn 接口 | 在 Portal 与认证器之间传递挑战和签名结果 |
| 认证器 | 保存私钥，确认用户在场并生成签名 |
| `PortalPasskeyService` | 创建和消费待处理认证过程，校验站点身份及 WebAuthn 结果 |
| `PortalPasskeyStore` | 保存用户句柄、公钥凭据和使用状态 |
| 浏览器会话服务 | 在登录验证成功后创建统一的 `db_session` 登录会话 |

`db_session` 是浏览器后续请求携带的签名登录 Cookie。它代表已经验证的人类账号；Passkey 服务只负责建立这个会话，不负责 Project、Lineage 或 Resource 的业务授权。

## 一次认证过程怎样流动

```text
用户点击注册或登录
  → Portal 创建一次性挑战和过程令牌
  → 浏览器把挑战交给认证器
  → 用户在设备上确认
  → 认证器返回凭据与签名结果
  → Portal 一次性消费过程令牌
  → Portal 校验挑战、站点身份、用户确认和签名
  → 注册时保存公钥；登录时创建浏览器会话
```

Portal 把“取得选项”和“验证结果”分成两次请求，是因为认证器操作发生在浏览器中间。服务端保存开始阶段的挑战、操作类型、站点域名、来源地址和五分钟期限。验证阶段必须找到完全匹配的记录；过期、重复使用、操作类型错误或注册用户不匹配都会失败。

待处理记录最多保留 1000 条。服务重启会丢失这些短期记录，用户可以重新开始注册或登录；已经保存的 Passkey 不受影响。

## 站点身份与安全入口

Portal 从可信请求信息计算站点域名和来源地址。站点域名取当前可信主机名，来源地址由可信协议与主机组成。Router 和 ASGI 的可信代理处理确定协议，应用读取其结果，不另行解析转发头；信任边界见 decision_85222f2d316b。

除 `localhost`、`127.0.0.1` 和 `::1` 开发入口外，Passkey 认证过程必须通过 HTTPS 运行。请求缺少主机信息、协议不是 HTTP 或 HTTPS，或者验证阶段的站点身份与开始阶段不一致时，Portal 会在写入凭据或创建登录会话前拒绝操作。

## 凭据记录与持久化

每个账号首次使用 Passkey 时获得一个随机 32 字节用户句柄，后续注册保持稳定。每条凭据记录保存：

- 凭据 ID 和公钥；
- 防止异常重复签名的计数器；
- 最长 80 个字符的展示名称，空名称使用默认值；
- 认证器报告的传输方式、设备类型和备份状态；
- 创建时间与最近使用时间。

凭据数据库只允许服务账号读取。写入在事务内重新检查容量和全局唯一性，再提交变化用户记录，避免并发注册绕过十枚上限或把同一凭据写给两个用户。

## 接口协议

### 开始注册

`POST /api/account/passkeys/registration/options` 要求有效浏览器会话和同源请求。“同源”表示请求来自当前 Portal 页面使用的协议和主机。请求包含当前密码；账号启用动态口令时，还要包含当前动态口令或未使用的恢复码。

成功响应返回浏览器创建凭据所需的选项和过程令牌。选项使用当前账号、稳定用户句柄和已有凭据排除列表，并要求设备创建可发现凭据和执行用户验证。站点身份不可信或再认证失败时，不创建待处理过程；账号容量在最终写入时检查。

### 完成注册

`POST /api/account/passkeys/registration/verify` 要求有效浏览器会话、同源请求、过程令牌和浏览器返回的凭据结果。Portal 校验挑战、站点域名、来源地址及用户验证标志，再提取公钥。

写入前会再次检查凭据唯一性和账号容量。成功后记录 `passkey_registered` 安全审计事件，并只返回适合页面显示的公开状态。

### 开始登录

`POST /api/auth/passkeys/options` 无需已有登录会话，但必须来自同源页面。接口不接收用户名，也不预先给浏览器限制某个凭据列表。返回选项要求认证器选择可发现凭据并完成用户验证。

### 完成登录

`POST /api/auth/passkeys/verify` 消费登录过程令牌，并根据浏览器返回的凭据 ID 读取公钥记录。Portal 校验挑战、来源地址、站点域名、签名、用户验证标志和可选用户句柄。

凭据不存在或任何验证失败时，接口使用统一认证失败响应，不透露账号是否存在或具体哪项检查失败。成功后更新凭据使用状态，记录 `passkey_login_succeeded`，再创建 `db_session`。

### 读取和删除

`GET /api/account/security` 返回当前用户的 Passkey 启用状态、数量和公开列表。列表包含凭据 ID、名称、创建时间、最近使用时间、设备类型与备份状态。

`POST /api/account/passkeys/delete` 要求有效浏览器会话和同源请求。删除成功后记录 `passkey_deleted`；删除最后一枚凭据后，公开状态中的启用值变为 false。当前接口不执行额外再认证。
