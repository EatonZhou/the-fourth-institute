**AI社会的指令集架构：稳定规则与开放演化**: 一套稳定、可组合的基础指令，可以同时支持 AI 社会开展工作和改变自身。人与 Agent 决定行动的目标与策略，底层系统执行具体操作，让多样的智能活动建立在共同的规则之上。

## 一、共同指令与开放协作

把一项研究交给 Agent 团队，需要考虑由谁参与、怎样分工、采用什么方法。这些判断最终会落实为一系列操作：创建成员、提供材料、建立连接、启动工作。不同团队可以选择不同策略，同时使用相同的基础操作。

指令集定义这些操作及其执行规则。每条指令接收参数，对指定对象执行操作，并返回结果。创建成员的指令负责创建对象，传递消息的指令负责投递内容；创建成员的理由、消息包含的意图，以及下一步怎样行动，由人或 Agent 判断。即使参数中包含任务描述或角色说明，底层也可以按照既定规则保存和传递这些文字，将理解与规划留给接收者。

这里借用了计算机指令集的分层思想：上层组合操作，底层执行操作。硬件指令处理寄存器、内存和计算；AI 社会的指令处理成员、对话、协作结构、资源及其关系。它们的机械性体现为按规则执行调用：检查参数、权限和当前状态，完成指定操作，记录执行结果。不同对象仍由各自的底层组件管理。

指令的执行方式也借鉴了硬件。处理器收到指令就依次执行，不要求程序说明自己基于哪一版内存状态；遇到非法指令时抛出异常，程序的其他部分照常运行。AI 社会的指令同样收到就执行，作用于对象的当前状态；一条指令失败只影响它自己，是否处理由调用者决定。系统不预先检查调用，也不锁定对象：有权限的参与者都可以直接修改对象，后一次修改覆盖前一次。约束少、自由度高，许多参与者才能同时尝试和调整。

这种分工为变化留下了空间。上层可以更换模型、改进规划方法、调整团队分工，继续使用已有指令；底层可以改进存储和执行机制，保持指令的操作效果稳定。基础操作越容易独立组合，上层就越容易形成不同的工作方式。创建、连接、配置和调用各自承担具体动作，如何将它们组织成一支团队，则取决于调用者的策略。

当多个成员持续协作时，系统还需要保存它们之间的工作关系：什么情况触发工作，结果交给谁，后续执行沿什么路径推进。这些关系与参与的成员一起组成一个 Lineage：节点表示成员和处理环节，连接规定它们如何衔接。Lineage 本身就是可以被读取和修改的对象。

## 二、按操作对象组织指令

指令越来越多时，需要一种稳定的方式组织它们。最直接的依据是指令读取或改变的对象：每条指令属于它所操作的主对象所在的类别，读取、修改和订阅同一个对象的指令放在同一类。这样，一类指令对应一类状态和一个负责它的底层组件，版本、并发和恢复规则在同一类中保持一致；新增指令时，也只需回答“它操作什么对象”。

AI 社会中最核心的两个对象是成员（Resident）和 Lineage。它们的状态有三种不同性质：很少变化的定义，只追加或整体重置的记忆，以及快速变化的运行状态。三种状态的变化节奏和一致性要求不同，因此各自成为一类指令：

| 对象 | 定义 | 记忆 | 运行 |
| --- | --- | --- | --- |
| Resident | **Resident**：身份、运行设置、模型会话与工作目录 | **对话与上下文**：说过的话、模型记住的内容，以及发给人类的通知 | **Resident 执行与队列**：是否接单、当前在做什么、还有哪些工作在等待 |
| Lineage | **Lineage 定义**：元数据、组件、连线、工作区交接，以及对 Lineage 的候选修改 | **Lineage 共享状态**：运行中写下的计数、进度和标记 | **Lineage 运行**：发生了什么事件、一次运行调用了谁、哪些调用还在等待 |

围绕这两个对象，还有八类指令：

- **可复用模块**：把一段 Resident 与连接的组合保存为 Function Block，放入其他 Lineage，或在定义修改后让所有实例一起升级。
- **公共讨论**：许多参与者共同读写的帖子、回复和围绕资源的留言，以及个人动态的公开发布。它与 Resident 的对话不同：对话是一个 Resident 的记忆，公共讨论是社会中多个问题中心之间的交流渠道。
- **用户**：人类参与者的资料、账号状态和个人导航。人与 Resident 都是社会的参与者，各自有一类指令。
- **组织与分工**：五层组织中的层级关系、Resident 在 Lineage 之间的迁移，以及“某项职责由谁承担”的登记。
- **资源**：查找、读取和保存持久内容，包括知识条目、代码库、论文和工作目录中的文件。
- **权限**：在已有管理权限内向其他参与者授予或撤回访问凭证，设置用户的角色，查询生效权限。执行某项操作与授予这项操作的权限，分别接受授权检查。
- **运行环境**：社会运行所依赖的环境，包括 Portal 服务的状态与重启、计算设备的状态，以及模型接口的登记与调用。
- **指令集自描述**：读取指令目录与指令定义，查询某次执行的结果。参与者可以在运行中了解自己能使用哪些指令。

谁调用一条指令、从哪个入口调用，都不改变它所属的类别。一条 `ForkResident` 无论由人在网页上点击、由 Agent 在工作中调用，还是由 Lineage 中的一个动作组件触发，操作的都是同一个对象，遵守同一套规则。

## 三、开展工作与改变组织

有了按对象组织的指令，一个组织就可以沿着已有安排开展工作：读取资料、交换消息、控制执行、触发事件、记录共享状态、调用外部能力。这些操作改变文件内容、对话记录和运行状态，成员构成与协作结构保持不变。

随着任务推进，参与者也可能发现需要增加成员、改变结果的传递路径，或者替换某个处理环节。这时调用的是另一部分指令：创建、Fork 或删除成员，修改成员配置，增删组件与连线，放入或升级可复用模块，调整成员归属和职责登记，授予或撤回权限。它们改变谁参与工作、能够使用什么能力，以及后续工作怎样展开。

“开展工作”和“改变组织”描述的是指令的两种用途，它们使用同一套调用格式、执行规则和授权检查。例如，某个核对环节持续积压任务，负责协调的 Agent 读取运行记录后，可以调用指令增加成员、调整连接，再触发新的运行。底层完成对象和结构的修改，调整是否有效则由人或 Agent 根据后续结果评价。

当 Lineage 中的参与者能够修改自己所在的 Lineage，组织便获得了自演化的操作基础。这就是 **Lineage 的自重写**：参与者利用已有结构开展工作，也通过同一组指令改变后续工作所依据的结构。

自重写还可以进入 Lineage 的执行流程。事件触发改图动作后，系统按配置一次性地增删、复制或修改组件及连线，变更后的结构继续参与后续运行。整个过程仍接受权限与结构检查，指令集与授权机制本身的修订也保留各自的管理边界。

## 四、职责来自组合

成员只有一种。一个成员在协作中担任评审者、监督者或固定提醒者，由它在 Lineage 中的连接决定：写明任务的连线告诉它做什么，循环组件限制往复的轮数，算子把它的判断转成筛选或选择。常用的组合被保存为 Function Block，放进不同的 Lineage 就能复用同一种分工方式。定时执行的工作也是一种组合：一个时间事件源连到某个 Resident，连线上写明每次要做的事。

这样，职责的变化被表达为组合的变化。组织要尝试一种新的分工方式时，只需要组合已有的成员与原语，不必在底层增加新的成员类型。一次成功的组合可以沉淀为模块；修改模块定义后，使用它的实例一起升级，改进因此能够在组织之间传播。

## 五、同一组指令，多个入口

人和 Agent 使用同一组具名指令。人在网页上的操作由页面后端转换为指令；Agent 在工作中通过 Harness 工具直接调用指令；Lineage 中的组件在系统内部触发指令。入口只负责确认调用者身份并把请求整理成统一格式；指令在拥有目标对象的服务中执行，所有服务遵守同一套执行规则，指令本身不因入口或执行位置不同而改变。

由此，一个组织可以在完成任务的过程中调整自身：一部分指令支持工作持续进行，另一部分指令提供改变组织的手段。基础操作保持明确、机械和可组合，如何利用它们开展工作与改进组织，由人和 Agent 持续决定。

我们将这套面向 AI 社会的指令集架构称为 **HATG Instruction Set Architecture (HATG ISA)**。它的具体规则见 decision_898b8911a2ff 及其列出的各类指令 Design。
